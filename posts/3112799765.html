先把认证和授权分开讲¶

认证与授权的区别¶

认证(Authentication)和授权(Authorization)是信息安全领域两个关键且常被混淆的概念：

graph TD A[访问控制系统] --> B[认证 Authentication] A --> C[授权 Authorization] B --> B1[确认"你是谁"] B --> B2[验证身份] B --> B3[处理用户凭证] B --> B4[先于授权发生] C --> C1[确定"你能做什么"] C --> C2[验证权限] C --> C3[控制资源访问] C --> C4[依赖于认证] style A fill:#f9f9f9 style B fill:#e3f2fd style C fill:#e8f5e9

认证解析

认证是验证用户身份的过程，回答”你是谁？”这一问题：

  • 目的：确认用户的真实身份
  • 方式：通过用户知道的(密码)、拥有的(令牌)或固有的(生物特征)要素进行验证
  • 结果：确认身份或拒绝访问
  • 时机：在用户尝试访问系统时进行
  • 示例：登录表单、指纹识别、短信验证码

授权解析

授权是确定用户权限的过程，回答”你能做什么？”这一问题：

  • 目的：控制已认证用户的访问权限
  • 方式：检查用户权限、角色或属性与资源访问策略的匹配
  • 结果：允许或拒绝特定操作
  • 时机：在用户通过认证后，尝试访问资源时进行
  • 示例：管理员可以删除内容，普通用户只能查看

认证与授权关系流程¶

sequenceDiagram participant 用户 participant 认证系统 participant 授权系统 participant 资源服务器 用户->>认证系统: 提供身份凭证 认证系统-->>认证系统: 验证凭证 alt 认证成功 认证系统->>用户: 提供身份令牌 用户->>资源服务器: 请求资源(携带令牌) 资源服务器->>授权系统: 检查用户权限 授权系统-->>授权系统: 评估访问策略 alt 有权限 授权系统->>资源服务器: 允许访问 资源服务器->>用户: 返回资源 else 无权限 授权系统->>资源服务器: 拒绝访问 资源服务器->>用户: 返回403禁止访问 end else 认证失败 认证系统->>用户: 返回401未授权 end

安全相关术语表¶

📝常见安全术语
  • 认证因素(Authentication Factor): 用于验证身份的要素，分为知识因素(你知道的)、所有因素(你拥有的)和固有因素(你是什么)
  • 多因素认证(MFA): 使用两种或更多不同类型的认证因素进行身份验证
  • 凭证(Credential): 用于证明身份的信息，如用户名密码、证书等
  • 会话(Session): 用户与应用间的交互状态
  • 令牌(Token): 代表授权或身份的便携式数据单元
  • 声明(Claim): 关于实体(通常是用户)的陈述或属性
  • 权限(Permission): 执行特定操作的授权
  • 角色(Role): 权限的命名集合
  • 最小权限原则: 用户只被授予完成其任务所需的最小权限
  • 职责分离: 敏感操作需要多人协作完成，防止单点滥用

基于令牌的认证¶

基于令牌的认证是现代Web应用和移动应用中广泛采用的机制，特别适合分布式系统和微服务架构。

JWT (JSON Web Token)

JWT是一种紧凑、自包含的机制，用于在各方之间安全地传递信息作为JSON对象：

JWT优缺点分析:

优势

  • 无状态: 服务器无需存储会话信息，适合分布式系统
  • 跨域支持: 可在不同域的系统间轻松传递
  • 自包含: 包含所有必要信息，减少数据库查询
  • 性能: 验证过程快速，减轻服务器负担
  • 标准化: 遵循RFC 7519，工具和库支持广泛

劣势

  • 令牌大小: 可能较大，增加请求头大小
  • 无法撤销: 一旦签发无法在过期前撤销(除非使用黑名单)
  • 敏感数据: 载荷虽然编码但非加密，不应存储敏感信息
  • 密钥管理: 密钥泄露会导致安全风险
  • 续期复杂: 刷新令牌机制增加了复杂度

OAuth 2.0与OpenID Connect

OAuth 2.0是一个授权框架，允许第三方应用代表资源所有者访问资源。OpenID Connect是构建在OAuth 2.0之上的身份认证层。

sequenceDiagram participant User as 用户 participant Client as 客户端应用 participant Auth as 授权服务器 participant Resource as 资源服务器 User->>Client: 请求登录 Client->>User: 重定向到授权服务器 User->>Auth: 认证并授权客户端 Auth->>User: 重定向回客户端(带授权码) User->>Client: 重定向(携带授权码) Client->>Auth: 请求令牌(授权码+客户端凭证) Auth->>Client: 返回访问令牌和刷新令牌 Client->>Resource: 请求资源(携带访问令牌) Resource->>Client: 返回受保护资源 Note over Client,Auth: 令牌过期后 Client->>Auth: 使用刷新令牌获取新访问令牌 Auth->>Client: 返回新的访问令牌

OAuth 2.0主要授权流程:

OAuth 2.0授权流程类型

  1. 授权码流程 (Authorization Code Flow)

    • 适用场景: 服务器端Web应用
    • 特点: 最完整、最安全的流程
    • 过程: 客户端获取授权码，然后使用授权码交换令牌
    • 安全优势: 访问令牌永远不会暴露给前端

  2. PKCE增强的授权码流程

    • 适用场景: 移动应用、单页应用
    • 特点: 通过代码验证器和代码挑战增强安全性
    • 优势: 防止授权码拦截攻击

  3. 隐式流程 (Implicit Flow)

    • 适用场景: 传统JavaScript应用
    • 特点: 无需后端交换，令牌直接返回给前端
    • 缺点: 安全性较低，已不推荐使用

  4. 资源所有者密码凭证流程

    • 适用场景: 高度受信任的应用
    • 特点: 用户直接向客户端提供账号密码
    • 风险: 客户端可获取用户凭证，仅适合特殊场景

  5. 客户端凭证流程

    • 适用场景: 机器对机器通信
    • 特点: 无用户参与，仅客户端凭证认证
    • 用途: 服务器间API调用

单点登录(SSO)¶

单点登录允许用户使用一组凭证访问多个相关但独立的系统：

SSO实现方法:

  1. 基于Cookie的SSO

    • 适用于同域应用
    • 使用共享Cookie存储认证信息
    • 简单但受同源策略限制

  2. 基于令牌的SSO

    • 适用于跨域应用
    • 使用JWT等令牌在应用间传递身份信息
    • 灵活性高，不受同源策略限制

  3. 基于SAML的SSO

    • 企业级解决方案
    • 使用XML断言传递身份信息
    • 标准化程度高，适合企业环境

  4. 基于OpenID Connect的SSO

    • 现代Web应用常用方案
    • 基于OAuth 2.0扩展
    • 支持多种客户端类型，实现简单

授权机制：RBAC、ABAC 与最佳实践¶

授权决定用户可以访问哪些资源以及可以对这些资源执行哪些操作。

主要授权模型¶

API安全特定问题¶

⚠️API安全最佳实践

  1. 传输安全

    • 全程强制HTTPS
    • 正确配置TLS (最低TLS 1.2)
    • 实施HTTP严格传输安全(HSTS)

  2. 输入验证

    • 验证所有客户端输入
    • 验证内容类型和长度
    • 使用白名单而非黑名单
    • 参数绑定验证

  3. 速率限制

    • 限制请求频率
    • 基于IP/用户的限制
    • 根据敏感度分层限制
    • 渐进式限制策略

  4. 敏感数据处理

    • 传输中加密
    • 存储中加密
    • 不在URL中传递敏感信息
    • 数据最小化原则

  5. 令牌管理

    • 安全生成令牌
    • 适当的有效期
    • 安全存储和传输
    • 撤销机制

常见攻击与防护¶

CSRF攻击
跨站请求伪造(CSRF)攻击:

在CSRF攻击中，恶意网站诱导用户向已认证的站点发送非预期请求。

防护策略:

  1. CSRF令牌: 在表单中嵌入随机令牌
  2. SameSite Cookie: 设置Cookie的SameSite属性为Strict或Lax
  3. 验证Origin/Referer: 检查请求来源
  4. 双重提交Cookie: Cookie与请求参数匹配验证

XSS攻击
跨站脚本(XSS)攻击:

XSS攻击允许攻击者在目标站点注入恶意脚本，在其他用户的浏览器中执行。

防护策略:

  1. 输入验证: 验证并清理用户输入
  2. 输出编码: 在页面输出前编码内容
  3. 内容安全策略(CSP): 限制可执行脚本来源
  4. HttpOnly Cookie: 防止JavaScript访问敏感Cookie
  5. X-XSS-Protection: 启用浏览器XSS筛选器

会话相关攻击:

包括会话固定、会话劫持、会话重放等威胁。

防护策略:

  1. 会话ID重生成: 认证成功后创建新会话

  3. 会话超时: 设置合理的绝对和非活动超时

落地建议¶

先分清认证和授权的边界，再选协议。内部系统用 SSO，对外开放用 OAuth2/OIDC。
