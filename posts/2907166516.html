16-感知模块-视觉感知

相机是感知里成本最低、信息最丰富的一路，但也是最容易栽在光照和深度上的一路。这篇从驱动接入讲起，走到检测、车道线、红绿灯，再到 2D-3D 映射。
📅 2026-11-04· 更新于 2026-11-04 · 4237 字 · 约 11 分钟 ✍ zeek.zhao #实战#apollo

相机是感知里成本最低、信息最丰富的一路，但也是最容易栽在光照和深度上的一路。这篇从驱动接入讲起，走到检测、车道线、红绿灯，再到 2D-3D 映射。点云那一路见 15-感知模块总览与点云感知，两篇对着看更清楚。

1. 四类任务撑起视觉感知¶

视觉感知拿相机图像当输入，识别障碍物、车道线、红绿灯和可行驶区域。论成本和信息量，它是感知来源里最划算的一路。Apollo 的视觉感知建在深度学习检测模型上，主要干四件事：

任务 输出 常用模型
目标检测 2D/3D 包围框 YOLO 系、Faster R-CNN
车道线检测 车道线点集/多项式 语义分割（SCNN、LaneNet）
红绿灯识别 灯色与状态 检测+分类网络
可行驶区域 区域掩码 分割网络

多相机各管一摊：前向远焦看远处，比如信号灯；前向广角管近距离全景；侧向相机服务变道决策；后向相机留给倒车。

2. USB 与网络，两套驱动¶

Apollo 的相机驱动分两块：

  • modules/drivers/camera：通过 USB 接口（V4L2）读取图像
  • modules/drivers/video：通过网络接口读取 H.265 编码视频流

CameraComponent 初始化 USB 相机后循环抓帧，发 Image 消息。CompressComponent 订阅下来，用 cv::imencode（默认 JPEG）压成 CompressedImage，把传输带宽降下去。

Video 模块的 CompCameraH265Compressed 组件经 SocketInput 收网络相机数据。它的特点是拿 FPGA 当硬件触发源，做多相机硬件时间同步，保证多路图像在时间上对得上。

3. 从图像到 3D 候选目标¶

视觉障碍物检测的整条链路：

graph LR A[图像] --> B[预处理: 缩放/归一化] B --> C[模型推理 GPU] C --> D[后处理: NMS] D --> E[2D 框] E --> F[2D-3D 映射] F --> G[3D 候选目标] G --> H[跟踪]

拆开说几点：

  1. 图像先经缩放、归一化与颜色空间转换等预处理，再送进深度学习模型
  2. Apollo 支持多种检测模型——两阶段的 Faster/Cascade R-CNN、单阶段的 YOLO/SSD、Transformer 类的 DETR，模型与权重文件都能通过配置切换
  3. 后处理做非极大值抑制（NMS），去掉冗余框
  4. 结合相机内参把 2D 框映射到车辆坐标系，生成 3D 候选目标，供融合使用

配置这头牵着模型文件、输入尺寸、置信度阈值和类别映射。置信度阈值平衡漏检和误检，输入尺寸牵着精度和速度，类别映射得跟下游模块一致。多相机还要把相机编号和外参设对。改完配置别急着下结论，拿 DreamView 看检测效果，一点点调到合理区间。

4. 车道线：从边缘到曲线拟合¶

车道线检测帮车弄清自己在道路上的位置，也帮着规划行驶路径。结果会映射到世界坐标系，作为规划模块的输入（见 20-规划模块）。

  • 传统方法：Canny 边缘检测、Hough 变换、RANSAC 曲线拟合
  • 深度学习方法：基于 FCN 的分割（SCNN、LaneNet）、检测式（LaneATT、CondLaneNet）

链路是：图像预处理 → 车道线特征提取 → 分割 → 后处理 → 拟合输出。车道线用点序列、多项式（c0 位置、c1 航向角、c2 曲率、c3 曲率导数）或样条来表示。

难点集中在这几处：遮挡（车和行人挡住）、光照变化（强光、阴影、夜间）、标记退化（磨损缺失）、类型多（实线、虚线、双黄线、导流线），还有曲率变化（弯道坡道）。

5. 红绿灯靠地图先验圈区域¶

信号灯识别是视觉感知里的专项，Apollo 的做法很吃高精地图：

sequenceDiagram participant C as 相机 participant M as 高精度地图 participant D as 信号灯检测器 participant R as 信号灯识别器 C->>D: 图像数据 M->>D: 信号灯位置先验 D->>D: 生成 ROI 并检测 D->>R: 信号灯区域 R->>R: CNN 分类识别灯色 R->>R: 多帧时序验证 R-->>C: 信号灯状态输出

优化手段有几个：拿地图先验圈信号灯区域，多帧融合压误识别，针对光照做自适应曝光，对信号灯区域高分辨率处理。识别结果直接给规划模块做通行或停车决策（见 21-决策模块与场景决策）。

6. 四个短板都有补法¶

局限 表现 应对
光照敏感 强光/逆光/夜间性能下降 HDR 相机、多帧融合、与激光雷达融合
深度估计弱 单目难以准确测距 融合激光点云与雷达观测修正距离
天气退化 雨雾雪场景失效 毫米波雷达全天候补盲（见 17-感知模块-雷达感知）
遮挡 目标部分/完全遮挡 多传感器持续融合、跟踪外推

10.0 之后又有新东西：环视图像用 BEV+Transformer 转到鸟瞰视角，配合多传感器持续融合，遮挡障碍物的检测强了一截。视觉天生不擅长异形障碍物——绿植入侵、施工围栏这些，就靠激光雷达加相机的占据栅格网络来补。视觉和激光走”大感知”多任务联合优化的整体思路，见 15-感知模块总览与点云感知。

要我说，视觉的短板大多能靠融合和标定工程补，唯独夜间强光这种退化还是得靠硬件顶上去——HDR、多帧这些手段，纯算法很难兜住。

7. 带宽、同步、动态范围、调试顺序¶

  • 带宽：高分辨率高帧率图像数据量大，用压缩、按需调整分辨率、USB 3.0 及以上接口
  • 时间同步：FPGA 硬件触发实现多相机精确同步；无硬件触发时做时间戳校正
  • 动态范围：HDR 相机与自适应曝光应对强弱光切换
  • 调试流程：先确认驱动话题频率正常，再在 DreamView 中看检测框、车道线、信号灯渲染，最后检查 2D-3D 投影是否与点云目标空间一致（不一致优先排查标定，见 18-传感器标定与坐标转换）

调试我会按驱动频率 → DreamView 渲染 → 投影一致性的顺序走，跳步最容易冤枉算法。

8. 自己跑一遍这五步¶

  1. 单独启动相机驱动，用 cyber_monitor 确认 /apollo/sensor/camera/*/image 频率
  2. 启动视觉感知，在 DreamView 中观察 2D 检测框与车道线输出
  3. 调整置信度阈值，观察漏检/误检的变化并记录平衡点
  4. 将激光点云投影叠加到图像，验证相机-激光外参精度
  5. 在仿真中构造红绿灯场景，观察信号灯识别与规划停车决策的联动

操作步骤¶

把视觉感知跑起来，按下面这个顺序做最省心：

  1. 确认相机硬件连上，USB 相机看 ls /dev/video* 有没有设备节点，网络相机先 ping 通相机 IP
  2. 选对驱动配置：USB 走 modules/drivers/camera，网络 H.265 走 modules/drivers/video，把 channel_name 写成统一的命名空间
  3. 单独启动驱动，用 cyber_monitor 看图像话题频率是不是配置的帧率（比如 30fps）
  4. 启动视觉感知组件，在 DreamView 里打开相机渲染，看 2D 框、车道线、信号灯有没有画出来
  5. 用 cyber_recorder 录一段典型场景（路口、匝道、夜间），回放时逐帧检查检测结果
  6. 调阈值：置信度太高漏检、太低误检，在录制的包上找到平衡点再固化到配置
  7. 把激光点云投影叠加到图像，确认 2D 框和 3D 目标空间位置一致；不一致先查外参标定（见 18-传感器标定与坐标转换）
  8. 构造红绿灯场景，验证识别结果能传到规划模块触发停车或通行（见 21-决策模块与场景决策）
  9. 最后跑一遍评估脚本，记录 mAP、车道线准确率等基线指标，方便回归对比

使用流程¶

视觉感知在整条链路里的位置，一句话串起来：

车道线和信号灯是两条支线：车道线走分割/拟合输出多项式曲线，直接给规划；红绿灯靠高精地图先验圈 ROI，检测+分类+多帧验证后给决策。三条支线最后在融合层汇总成一份感知结果。调试时也要顺着这条链逐段看输出，别直接跳到最终结果。

多相机场景要把每路相机的内参、外参、编号配齐，时间戳走 FPGA 硬件触发对齐；没有硬件触发时至少做时间戳校正，不然融合时的空间对不上。

注意事项与常见坑¶

  1. 像素格式写错：pixel_format 配成相机不支持的格式，驱动起来但出不了图，先查相机支持列表
  2. 分辨率帧率超带宽：1920×1080@30 未压缩数据量很大，必须走压缩，否则 cyber 通道堵
  3. 网络相机 IP/端口不通：camera_ip/camera_port 写错或对端防火墙拦了，SocketInput 一直重连
  4. 触发参数不对：trigger_param（如 f2ff）跟硬件帧同步协议对不上，多路相机时间错开
  5. 解压颜色通道错：cv::imdecode 出的是 BGR，忘了 cvtColor 到 RGB，图像整体偏色导致检测精度掉
  6. 外参没更新：换了相机支架或标定文件过期，2D-3D 投影和点云对不上，先重标再看算法
  7. 置信度阈值一刀切：一个阈值套所有场景，夜间漏检、白天误检，应按场景分别评估
  8. 类别映射不一致：模型输出的类别 ID 和下游期望的不同，融合后目标类型错乱
  9. NMS 阈值太大：冗余框没压干净；太小则相邻目标被误删，需按目标密度调
  10. 车道线拟合过拟合：噪声点也被拟进曲线，弯道处车道线抖动，加平滑和有效性筛选
  11. 红绿灯多帧验证窗口太短：单帧误识别直接输出，建议 3~5 帧一致性再确认
  12. 地图先验未覆盖：新路口没有高精地图数据，信号灯 ROI 生成不了，退化为全图检测
  13. 强光逆光硬伤：纯算法很难补，优先上 HDR 相机或多帧融合，别只调模型
