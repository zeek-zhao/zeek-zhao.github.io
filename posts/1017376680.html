ORM 基础

[!info] 本页概览
本文讲解对象关系映射（ORM）基础：从 JDBC 手写访问到 MyBatis、JPA/Hibernate 的演进，配真实可运行示例与选型建议。

核心概念

  • ORM（Object Relational Mapping）：把关系型数据库表映射为对象，屏蔽 SQL 与对象的差异，提高开发效率。
  • JDBC：Java 访问数据库的标准接口，是各类 ORM 框架的底层基础。
  • MyBatis：半自动 ORM，SQL 由开发者掌控，灵活可控，国内使用广泛。
  • JPA / Hibernate：全自动 ORM，以实体对象为核心，自动生成 SQL，适合标准化 CRUD。

JDBC 基础

[!note] JDBC 要点

  • 必须使用 PreparedStatement 防 SQL 注入，严禁字符串拼接 SQL。
  • 连接是昂贵资源，生产环境必须用连接池（HikariCP / Druid）。

MyBatis

JPA / Hibernate

[!warning] JPA 注意

  • 关联查询默认懒加载，跨事务访问易抛 LazyInitializationException。
  • 复杂报表 SQL 不适合 JPA，可搭配 @Query 原生 SQL 或直接走 MyBatis。

常见坑

  1. N+1 查询：循环查子表导致大量 SQL，用 join fetch / 批量抓取解决。
  2. 实体字段与表列映射不一致：忘记 @Column 导致字段名不匹配。
  3. 大结果集全量加载：分页必须走数据库分页（Pageable / LIMIT）。
  4. 事务边界失控：@Transactional 滥用导致长事务、锁竞争。

最佳实践

  • 简单 CRUD 用 JPA，复杂 SQL 用 MyBatis，两者可共存。
  • 所有 SQL 参数化；开启 SQL 日志与慢查询监控。
  • 实体不直接暴露给前端，用 DTO 隔离。
  • 结合 19-运维监控 观察 ORM 生成的 SQL 质量，结合 07-SQL 优化 持续优化。
