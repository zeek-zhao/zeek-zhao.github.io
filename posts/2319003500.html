JVM基础

[!info] 本页概览
本文讲解 JVM 基础：内存结构（堆/栈/方法区/程序计数器/本地方法栈）、对象创建与生命周期、GC 算法与垃圾回收器、类加载机制、JVM 常用参数，配示例与诊断命令。

核心概念

  • JVM = Java Virtual Machine：一次编译到处运行的关键。
  • 内存区域：堆（对象实例）、虚拟机栈（局部变量/方法调用）、方法区（类元数据/常量）、程序计数器、本地方法栈。
  • GC：自动回收堆中无用对象。
  • 类加载：加载 → 链接（验证/准备/解析）→ 初始化。

内存结构

[!note] 对象分配
对象优先在 Eden 分配；Eden 满触发 Minor GC；幸存对象在 S0/S1 间复制；年龄足够（默认 15）晋升老年代；大对象直接进老年代。

GC 算法与收集器

算法 思想 适用
标记-清除 标记存活对象，清除未标记 老年代基础
标记-复制 复制存活对象到另一半，整块清理 新生代（S0/S1）
标记-整理 存活对象向一端移动，清理边界外 老年代
分代收集 新生代复制、老年代标记整理/清除 HotSpot 默认

常用收集器：

  • Serial：单线程，客户端小堆。
  • Parallel：多线程吞吐优先，默认 JDK8。
  • CMS：并发标记清除，低延迟但碎片。
  • G1：JDK9+ 默认，分区式，可预测停顿，大堆推荐。
  • ZGC：超低延迟，TB 级堆，JDK15+ 可用。

类加载机制

[!note] 双亲委派
类加载先交给父加载器，父无法加载才自己加载；保证核心类（java.*）不被自定义类篡改。

常见坑

  1. 堆溢出 OOM：-Xmx 不足或内存泄漏；dump 分析（-XX:+HeapDumpOnOutOfMemoryError）。
  2. 栈溢出 StackOverflowError：递归无终止条件。
  3. Metaspace 溢出：动态生成类过多（反射/代理/CGLIB）。
  4. GC 频繁：对象过大/集合持有强引用/未释放资源；用 jstat 观察。
  5. JDK 版本与 GC 默认值不同：JDK8 默认 Parallel，JDK9+ 默认 G1。
  6. 大对象直接进老年代：-XX:PretenureSizeThreshold 避免频繁拷贝。
  7. System.gc() 不当：显式触发 Full GC 影响性能，生产不建议主动调用。

最佳实践

  • 生产 JVM 参数：-Xms 与 -Xmx 设相同值避免动态扩容抖动。
  • 开启 OOM dump 与 GC 日志便于事后排查。
  • 对象生命周期管理：短生命周期对象尽量留在新生代。
  • 避免过度创建对象（装箱、字符串拼接），减少 GC 压力。
  • 深拷贝/大对象谨慎，必要时用 -XX:+UseG1GC 控制停顿。
