06-Docker仓库配置

把 Nexus 配成私有 Docker Registry，处理 HTTP/HTTPS、仓库规划、客户端与 K8s 接入及排错。
📅 2026-11-14· 更新于 2026-11-14 · 603 字 · 约 2 分钟 ✍ zeek.zhao #工具#nexus3

Docker 仓库配置

接着上一篇 05-npm仓库配置 把 npm 理顺，这篇看容器镜像。Nexus 也能当私有 Docker Registry：proxy 缓存 Docker Hub、hosted 存内部镜像、group 聚合访问，思路还是那套。

1. Docker 客户端默认不认 HTTP，先把这关过了¶

默认 Nexus HTTP 端口 8081；Docker 客户端对 非 HTTPS registry 默认拒绝，需配置：

HTTP 我只用在测试环境，还得配 "insecure-registries"；生产必须上 HTTPS（13-高可用与SSL），别偷这个懒。

2. 三个库加一个专用端口就齐了¶

参数 说明
Connector registry 专用端口（如 5000/5001）
Force basic auth 强制认证（hosted 建议开启）
Use subdomain 按仓库子域路由（如 hosted.nexus.example.com）

hosted 那边的 Force basic auth 我一般都打开，私有镜像不设防心里不踏实。

3. 配好 daemon.json 就能 pull/push¶

走 group 拉的时候，hosted 和 proxy 是合在一起的：拉 company/nginx 命中 hosted，拉 nginx 命中 proxy 缓存，客户端不用关心镜像到底在哪。

4. K8s 靠 imagePullSecrets 拉私有镜像¶

5. 镜像很占盘，清理策略别省¶

  • Docker 镜像体积大，proxy 缓存按 Cleanup Policy 清（10-Cleanup与任务调度）；
  • docker pull 的 manifest + layer 都可能落 Blob，磁盘需充足。

6. 报错基本绕不开证书、权限、缓存¶

问题 解法
x509: certificate signed by unknown authority HTTPS/证书问题（13-高可用与SSL）
unauthorized 登录/权限不足（09-权限与匿名访问）
拉不到公网镜像 proxy 远程可达性/缓存过期
push 413 nginx client_max_body_size 调大

其他格式（Raw/PyPI 等）：07-Raw与其它仓库。
