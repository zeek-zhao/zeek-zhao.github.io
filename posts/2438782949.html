并发 goroutine 与 channel

[!info] 本页概览
Go 的并发模型是 CSP：不要通过共享内存来通信，而要通过通信来共享内存。goroutine 是轻量级线程，channel 是 goroutine 间通信的管道。本文讲解 goroutine 启动、channel 发送接收、select 多路复用与并发安全。

核心概念

  • goroutine：由 Go 运行时调度的轻量级执行单元，创建成本约 2KB 栈，可轻松创建数十万个。go func() 启动。
  • channel：类型化管道，ch <- v 发送、v := <-ch 接收；未缓冲 channel 会阻塞直到对方就绪（同步）。
  • select：同时等待多个 channel 操作，任一就绪即执行。

常见坑

  1. goroutine 泄漏：无缓冲 channel 只有发送方没有接收方，发送 goroutine 永久阻塞。确保配对或加超时/取消。
  2. 对已关闭的 channel 发送：panic send on closed channel。
  3. 死锁：所有 goroutine 都在等待且无进展，运行时检测并 fatal。常见于忘记消费/忘记关闭。
  4. 共享变量无同步：多个 goroutine 读写同一变量是数据竞争。用 channel 传递数据，或加锁（见 20-并发模式与sync包）。
  5. go 语句后函数立即返回：go f() 不等待 f 完成，main 结束会杀掉所有 goroutine。需要等待用 WaitGroup。
  6. channel 作为返回值方向：函数签名用 <-chan/chan<- 明确方向，防止误用。

最佳实践

  • 公式：”生产者-消费者”用 channel；”等待完成”用 WaitGroup；”谁先到达”用 select。
  • channel 关闭权在发送方，且只在确实不会再发送时 close。
  • 命名规范：接收 channel 用 jobs、done 等清晰名字。
  • 启动 goroutine 前想好退出路径（done channel / context，见 19-Context与超时控制）。
  • 用 go test -race 检测数据竞争。
