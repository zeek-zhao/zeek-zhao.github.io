解决Docker容器内无法访问外网问题

容器访问不了外网时按层次排查的十种方法：重建 docker0、开启转发、host 网络、SELinux、DNS、防火墙抓包与重装。

解决Docker容器内无法访问外网问题

环境不同，成因也不同，所以这类问题没有一条命令能通吃。我的排查习惯是从最轻的入手：先确认宿主机能不能上网，再看转发、DNS、防火墙，最后才动重装。下面十种方法按我实际遇到时的优先级列出来，命令原样保留，照着顺序试基本能定位到问题层。

先重建 docker0 网络，排除网桥本身的问题¶

最直接的办法是把 Docker 的网桥拆掉重建。执行前要清楚这会中断现有容器网络，生产环境要挑窗口。

开启宿主机 IPv4 转发，解决最经典的 WARNING¶

如果启动时看到 WARNING: IPv4 forwarding is disabled. Networking will not work.，基本就是转发没开。改完配置记得重启 network 和 docker，并用 sysctl 确认值从 0 变成 1。

直接用 host 网络启动容器做快速验证¶

--net=host 让容器共享宿主机网络栈，适合先验证「是不是 Docker 网络层的问题」。我用它做临时验证，不会长期放在生产里，因为端口和隔离性都变了。

关掉 SELinux，排除强制访问控制拦截¶

SELinux 在 enforcing 状态下可能拦住容器的网络访问。先 getenforce 看状态，临时关闭用 setenforce 0，永久生效要改配置文件再重启。

删掉 Docker 网络状态缓存再重启¶

如果网络配置改乱了，直接清掉 /var/lib/docker/network/* 让 Docker 重建网络状态，也是一种省事的办法。它会丢弃已有自定义网络信息，操作前要评估影响。

换 DNS：宿主机层面与容器层面要分开看¶

先确认宿主机 DNS 是否正常。把 resolv.conf 指向国内通用 DNS 或 Google DNS，再用一个临时 alpine 容器 ping 域名验证。

如果宿主机正常、容器不正常，那就是容器内部 DNS 与宿主机不一致的问题，一般不多见，但确实存在。进容器后先看 /etc/resolv.conf 的内容，把多余的 options 行注释掉即可。

网上有说法是程序重启后还得手动改一遍，根因在 /etc/resolvconf/resolv.conf.d/tail 会默认覆盖 /etc/resolv.conf 的最后一行。这一步我没有实测过，先记在这里供参考：

尝试开启防火墙的 IP 伪装¶

firewalld 环境下可以检查并开启 masquerade，同时把 docker0 加进 trusted zone 来解决 DNS 问题。不过我实际测试时直接关防火墙也没解决，所以这条权当备选。

重装 Docker：最后的无奈之举¶

上面全部无效，才考虑重装 Docker。我的判断是：走到这一步之前，一定要把前面的抓包结果和网络侧限制确认清楚，否则重装完大概率还是同样的问题。

我自己的问题记录（未解决）¶

我的环境是基于电信网，在局域网 Windows 上装了 CentOS 7.6 虚拟机。宿主机能正常访问外网，容器不行，而且容器里 DNS 解析有问题；直接访问 IP 时，tcpdump 抓 docker0 只看到请求、没有任何响应。

目前临时用 --net=host 顶着解决外网访问问题，根因还在继续查。我把这个现象记下来，是因为它很可能是宿主机虚拟网络或上游策略的问题，而不是 Docker 本身的配置错误。
