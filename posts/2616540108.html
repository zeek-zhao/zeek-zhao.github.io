测试

[!info] 本页概览
本文讲解 Java 测试体系：单元测试（JUnit 5）、断言与生命周期、Mockito 模拟、集成测试、Spring Boot Test、测试覆盖率与测试金字塔，配可运行示例与最佳实践。

核心概念

  • 测试金字塔：大量单元测试 → 适量集成测试 → 少量端到端测试。
  • 单元测试：测单个方法/类，快、独立、可重复。
  • JUnit 5：平台（Platform）+ Jupiter（编程模型）+ 旧引擎。
  • 断言：assertEquals/assertTrue/assertThrows/assertAll。
  • Mockito：模拟依赖（Mock/Stub/Verify），隔离被测单元。
  • 覆盖率：行/分支/方法覆盖率（JaCoCo），关注关键路径。

覆盖率与测试质量

[!note] 覆盖率不是一切
追求高覆盖率容易变成”为了覆盖而覆盖”。关注核心业务逻辑、分支边界、异常路径；用 mutation testing（如 PIT）评估测试有效性。

常见坑

  1. 测试依赖真实环境：单元测试不要连真实 DB/网络；用 Mock/内存库（H2）。
  2. 测试之间共享状态：静态变量/单例污染；@BeforeEach 重置。
  3. Mock 过度：把被测对象内部也 Mock 掉，测试失去意义。
  4. 时间相关测试不稳定：用固定时钟/参数化，避免真实 sleep。
  5. 只测快乐路径：边界、异常、并发场景同样重要。
  6. 测试命名含糊：方法名描述行为：add_shouldReturnSumWhenPositive。
  7. CI 跳过测试：-DskipTests 别长期使用，测试是质量门禁。

最佳实践

  • 每个 public 方法至少一个测试：正常、边界、异常三态。
  • 断言用 assertAll 收集多个期望。
  • 依赖注入构造器，便于替换 Mock 实现。
  • 测试代码放 src/test/java，遵守同类包结构。
  • 结合 16-Spring Boot 入门 的 @WebMvcTest/@DataJpaTest 做切片测试。
