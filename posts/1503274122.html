01-SELinux简介与设计目标

发表于2026-10-24|selinux
|浏览量:

[!info] 本节目标
理解 SELinux 是什么、为什么需要它，以及它的设计目标。

1. 起源与发展

SELinux 由美国国家安全局（NSA）联合多家机构开发，最初基于 Flask 安全架构，于 2000 年开源。2003 年起集成进主流 Linux 内核，Red Hat 企业版率先默认启用，随后 Fedora、CentOS、Android 等系统相继采用。

2. 为什么需要 SELinux

传统 Linux 使用自主访问控制（DAC），权限由文件属主决定，一旦进程被攻破即可访问同属主资源，存在权限过宽问题。SELinux 通过强制访问控制（MAC）为每个进程与资源定义安全策略，即使进程被攻破，也只能访问策略允许的少数对象。

3. 设计目标

SELinux 的设计目标是实现最小权限、隔离与完整性保护。系统默认拒绝所有未显式允许的访问，管理员逐项授权，从而压缩攻击面，限制横向移动，保护敏感数据。

4. 核心思想

SELinux 以安全上下文标签为核心，将主体（进程）与客体（文件、端口、进程）打上标签，依据策略决定是否允许访问。标签机制与策略分离，便于集中管理与审计。

5. 启用方式

多数发行版默认启用 SELinux，可通过配置文件切换 enforcing、permissive 与 disabled 三种模式。启用前需确认文件系统支持并正确打标签，避免启动失败。

6. 应用现状

SELinux 广泛应用于服务器、桌面与移动平台。容器与虚拟化场景中它提供额外隔离层，配合 Kubernetes 与 Docker 生态形成纵深防御体系，是 Linux 安全体系的重要组成部分。

7. 适用场景与局限

SELinux 适合高安全要求的多租户服务器、边界防护设备与合规审计场景，可有效限制被攻破进程的横向扩散。但其配置复杂度较高，理解成本大，对快速迭代的应用可能产生适配负担。实践中应根据资产价值与威胁模型决定启用程度，避免为追求全面开启而忽视维护成本。正确认识其能力边界，才能发挥最大安全价值。
