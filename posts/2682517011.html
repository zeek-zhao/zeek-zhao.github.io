11-Apollo Cyber RT框架

Cyber RT 是百度自研的高性能自动驾驶运行时框架，替代 ROS 解决实时性、性能与可靠性瓶颈。本篇讲解其设计动机、分层架构、核心概念（Node/Channel/Component/Scheduler）与基础使用。
📅 2026-10-25· 更新于 2026-10-25 ✍ zeek.zhao #系统#apollo
ℹ️本节目标
理解 Cyber RT 的诞生背景与设计目标，掌握其分层架构与核心概念（Node、Channel、Component、Scheduler、协程），能使用 cyber 命令行工具进行基础操作。Cyber 的调度、时间、异步等深度机制由第四阶段专题承载。

1. 为什么需要 Cyber RT¶

Apollo 早期版本（1.0-3.0）基于 ROS。随着系统规模扩大，ROS 在自动驾驶场景下的局限逐渐暴露：

局限 具体表现
实时性不足 调度依赖操作系统，消息延迟波动大，缺乏优先级调度
性能瓶颈 进程间通信开销大，高带宽传感器数据（点云/图像）传输效率低
可靠性问题 错误隔离不完善，单点故障易扩散；缺乏故障检测恢复机制
资源管理局限 缺乏精细的资源分配与隔离，难以适应车载受限环境

Apollo 3.5 起引入自研的 Cyber RT（Runtime）框架，全面替换 ROS。

1.1 设计目标¶

  • 高性能：低延迟、高吞吐通信，支持点云/图像级大流量数据；共享内存零拷贝
  • 确定性实时：基于协程的调度，可预测的任务执行时序，优先级保障关键任务
  • 可靠性：模块间故障隔离，组件级错误检测与恢复
  • 灵活性：组件化架构、插件式扩展、分布式部署能力
  • 资源隔离：CPU 亲和性、优先级配额、过载保护
🔥学习提示
一句话概括 Cyber RT：用协程调度 + 共享内存通信 + 组件化编程模型，为自动驾驶定制的高性能运行时。后面的消息通信、组件开发都建立在这三个支点上。

2. 核心概念¶

概念 说明
Node 节点，通信基本单位；创建并管理 Writer/Reader/Service/Client
Channel 通道，消息传递的逻辑媒介（类似话题 Topic）
Writer / Reader 向通道发布 / 从通道订阅消息
Component 数据驱动的可复用计算组件（见 12-Cyber消息通信与组件开发）
TimerComponent 定时器驱动的组件，按固定周期执行
Scheduler 调度器，基于协程管理任务执行
CRoutine 协程，Cyber 任务的最小执行单位
Shared Memory 共享内存传输，大流量数据零拷贝
Service / Client 请求-响应式服务通信
Parameter 全局参数服务

3. 分层架构¶

  • 应用层只面向框架层标准接口编程，不触碰底层实现——这正是各模块可独立开发测试的原因
  • 运行时层是性能核心：协程调度降低上下文切换开销；进程内直接传指针、进程间共享内存、跨机走网络，传输路径自动选择
  • 硬件抽象层保证框架可从工控机移植到 Orin 等 ARM 平台

3.1 调度器与协程（概览）¶

Cyber RT 的调度器基于协程实现：组件回调以协程方式执行，协作式切换在用户态完成，避免线程频繁切换的内核开销。支持两种调度策略：

  • 经典调度（Classic）：全局优先级队列统一调度
  • 编排调度（Choreography）：特定任务绑定特定 CPU 核心，提高缓存亲和性与确定性

调度策略通过配置文件指定，可设置核绑定与任务优先级。协程模型让开发者以同步方式写异步逻辑，是 Cyber RT 高性能的关键。调度系统、时间系统、异步机制的源码级解析见第四阶段专题（25-31 篇）。

3.2 通信机制概览¶

层级 传输方式 适用
进程内 共享指针直接传递，零拷贝 同进程高频数据
进程间 共享内存 同主机模块间（点云/图像）
跨机 优化的网络协议 多机部署

消息通信模型与代码级用法见 12-Cyber消息通信与组件开发。

4. 与 ROS 的对比¶

维度 Cyber RT ROS
通信性能 共享内存优先，高效零拷贝 TCP/UDP 中间件，开销较大
调度机制 协程调度，低开销切换 依赖 OS 线程调度
实时性 优先级调度，确定性保障 实时性弱，不确定性高
资源管理 细粒度控制与隔离 依赖 OS，粒度较粗
生态 聚焦自动驾驶，生态内聚 通用机器人生态丰富

选型参考：产品化自动驾驶优先实时性选 Cyber RT；科研教学与快速原型可利用 ROS 生态。从 ROS 迁移的要点：节点 → Node/Component、话题消息 → Cyber proto 定义、launch → Cyber launch 配置，迁移后验证消息频率、延迟与数据一致性。

📝2026 年更新
  • Apollo 10.0 打通了 ROS 软件生态，开发者可以将 ROS 工具与已有 ROS 代码更低成本地接入 Apollo 系统，软件复用成本显著下降
  • Apollo 9.0 起支持包化模块开发（package-based module development），模块以独立包形式开发部署，不再强制依赖完整源码仓库，Cyber 组件的打包发布更加工程化
