04-任务状态机

发表于2026-10-24|FreeRTOS
|浏览量:

[!info] 本节目标
深入理解任务状态机与状态迁移规则。

1. 任务状态总览

任务在运行、就绪、阻塞与挂起四种状态间迁移。运行状态独占 CPU，就绪状态等待调度，阻塞状态等待事件或延时，挂起状态由显式调用控制。理解状态机是分析系统行为的前提。

2. 运行与就绪

正在执行的任务处于运行态，同一时刻单核只有一个运行任务。其他可运行任务处于就绪态，按优先级排列在就绪链表。调度器从就绪链表头部选择任务切换执行。

3. 阻塞态

任务调用延时或等待队列、信号量、事件组等 API 时进入阻塞态。阻塞可以带超时，超时后自动返回就绪。阻塞是让出 CPU 的主要方式，配合事件等待实现任务同步。

4. 挂起态

挂起由 vTaskSuspend 触发，任务不再参与调度，仅能通过 vTaskResume 恢复。挂起与阻塞不同，不依赖事件或超时。挂起适合调试暂停与临时停用任务。

5. 状态查询与跟踪

uxTaskGetState 查询任务状态，vTaskGetInfo 获取完整信息。调试器与跟踪工具可视化状态迁移，帮助定位调度异常。任务状态统计也是系统负载分析的基础数据。

6. 状态迁移场景

典型迁移包括：运行任务调用延时进入阻塞，超时后回就绪；等待信号量失败进入阻塞，信号量给出后回就绪；运行任务被高优先级任务抢占进入就绪。正确设计状态路径保证系统响应。

7. 状态机设计要点

任务状态机是业务逻辑的骨架，明确各状态入口、出口与数据依赖。避免忙等轮询，善用阻塞让出 CPU。状态迁移与共享数据同步结合设计，确保并发安全与行为可预期。
