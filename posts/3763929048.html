异常处理

[!info] 本页概览
本文讲解 Java 异常体系：Throwable/Exception/RuntimeException/Error，受检与非受检异常、try-catch-finally、try-with-resources、自定义异常、最佳实践与反模式。

核心概念

  • 异常体系：Throwable → Error（JVM 级，不可恢复）与 Exception（可处理）。
  • 受检异常（checked）：编译期强制处理（IOException、SQLException），必须 throws 或 catch。
  • 非受检异常（unchecked）：RuntimeException 子类（NPE、IllegalArgumentException），不强制处理。
  • finally：无论是否异常都执行，常用于释放资源。
  • try-with-resources：自动关闭 AutoCloseable 资源。

[!note] 自动关闭
所有实现 AutoCloseable 的资源（流、连接、锁）都可用 try-with-resources 自动关闭，比 finally 手动 close 更安全（close 异常不覆盖业务异常）。

自定义异常

常见坑与反模式

  1. 吞异常：catch (Exception e) {} 空捕获，掩盖问题，严禁。
  2. catch 到 Exception 太宽：应捕获具体异常类型。
  3. finally 中 return 覆盖异常：finally 里 return 会吞掉 try 中的异常。
  4. 丢失原始异常：throw new XxxException(e.getMessage()) 丢失栈；用 new XxxException(msg, e)。
  5. 在循环中 try-catch 包裹整个大块：定位困难；精细到可能失败的语句。
  6. 受检异常滥用：业务校验类错误用非受检异常更简洁。
  7. 用异常控制流程：不要用异常做正常分支判断，性能差且难读。

最佳实践

  • 方法契约明确：受检异常用于”可恢复的强制关注点”，非受检用于”编程错误”。
  • 日志记录原始异常栈：logger.error("msg", e)。
  • 自定义异常命名以 Exception 结尾，提供构造器链。
  • 资源释放用 try-with-resources。
  • 尽早抛出、尽早失败（fail-fast），校验参数用 Objects.requireNonNull。
