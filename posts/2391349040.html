进阶专题与框架生态

ℹ️本页概览
本文讲解 Java 进阶专题与生态：内存模型与并发进阶、网络编程（Netty）、微服务框架（Spring Cloud）、消息队列、缓存（Redis）、搜索（Elasticsearch）、云原生（容器/Serverless），配选型建议与学习路线。

核心概念¶

  • 进阶能力分层：语言熟练 → 并发/JVM 深入 → 框架生态 → 架构设计。
  • Java 内存模型（JMM）：主内存 + 工作内存；happens-before；volatile 语义。
  • 微服务生态：Spring Cloud（注册中心/网关/配置/熔断）、Dubbo。
  • 中间件：消息队列（Kafka/RabbitMQ）、缓存（Redis）、搜索（ES）。
  • 云原生：Docker/K8s、可观测性、Serverless。

JMM 与并发进阶¶

📝AQS 与锁框架
ReentrantLock/Semaphore/CountDownLatch 都基于 AQS（AbstractQueuedSynchronizer）：同步状态 + CLH 队列 + CAS。理解 AQS 是并发进阶核心。

常见坑¶

  1. 并发问题靠加锁硬扛：理解无锁（CAS）/不可变/并发集合更优。
  2. 微服务过度拆分：分布式事务与运维成本剧增；先单体再按需拆分。
  3. MQ 不加幂等：重复消费导致数据错误；消费端幂等设计。
  4. 缓存与 DB 不一致：更新顺序、过期兜底、删缓存而非更新缓存。
  5. Netty 业务线程阻塞：IO 线程只做编解码，耗时代码交给业务线程池。
  6. 版本兼容：Spring Boot 2 vs 3（Jakarta 命名空间）、JDK 17 差异。

最佳实践¶

  • 进阶学习以源码 + 官方文档为主，辅以实战项目。
  • 中间件选型先列需求（吞吐/一致性/运维能力）再选。
  • 分布式系统重视可观测性与容错设计（重试、超时、熔断）。
  • 结合 12-JVM基础、18-性能调优 持续深化。
