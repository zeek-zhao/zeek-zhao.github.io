04-BitBake构建引擎基础

发表于2026-10-24|yocto
|浏览量:

[!info] 本节目标
理解 BitBake 如何解析配方、调度任务并生成构建产物。

1. BitBake 是什么

BitBake 是 Yocto/OpenEmbedded 的任务执行引擎，类似 Make 但面向软件包与层模型。它解析配方（Recipe）、收集依赖关系、并行调度编译任务，并支持缓存以加速重复构建。

2. 基本调用

3. 任务类型

任务 说明
do_fetch 获取源码
do_unpack 解包源码
do_patch 应用补丁
do_configure 配置
do_compile 编译
do_install 安装到暂存目录
do_package 打包
do_image 生成镜像

4. 依赖关系

BitBake 根据 DEPENDS、RDEPENDS 等变量构建依赖图，调度任务执行。并行度由 BB_NUMBER_THREADS 控制，合理设置可提升构建速度。

6. 环境与日志

构建日志位于 tmp/log/cooker 与各配方工作目录下的 log.* 文件，是排查构建问题的主要依据。

7. 变量与函数基础

BitBake 变量支持多种赋值方式：立即赋值、延迟赋值、追加与覆盖。函数分为 shell 函数与 Python 函数，通过 python 关键字声明 Python 函数。任务函数内可使用 BitBake 提供的环境与工具，如 oe_runmake 封装 make 调用。理解变量展开时机与函数调用约定，是编写可靠配方的关键，详见 Recipe 语法篇。

8. 并行与调度

BitBake 按依赖关系并行调度任务，并行度由 BB_NUMBER_THREADS 控制。高并行可缩短构建时间，但会增加资源消耗与下载压力。任务间通过 stamp 文件与签名机制判断是否可复用，避免重复执行。合理设置并行度与缓存策略，可在资源与速度间取得平衡，具体加速方法见构建缓存与 sstate 篇。

9. 任务执行机制

BitBake 任务按依赖图调度，每个任务由函数体与输入变量共同决定。任务执行记录于 stamp 文件，输入变化时签名更新并触发重建。理解任务机制对排障至关重要：构建异常时查看 temp/log.do_task 日志，比较签名差异定位重建原因。掌握任务与签名机制，是深入使用 BitBake 的基础。
