03-开发环境搭建（Docker）

发表于2026-10-24|apollo

[!info] 本节目标
使用官方 Docker 镜像搭建 Apollo 开发环境，掌握容器启动、环境变量与常用工具链。

1. 前置条件

需要 Ubuntu 主机（或虚拟机）并安装 NVIDIA 驱动与 Docker。Apollo 官方镜像体积较大，建议预留足够磁盘空间并配置国内镜像加速。

4. 常见配置

  • 磁盘空间不足时清理旧镜像：docker system prune
  • 更换镜像源：配置 /etc/docker/daemon.json 的 registry-mirrors
  • 资源限制：dev_start.sh 中可调整容器内存与 CPU 参数

[!note] 延伸
环境搭好后进入源码编译见 04-源码编译与部署；仿真与调试见 24-调试与可视化工具。

5. 磁盘与镜像管理

Apollo 镜像与构建缓存占用大量磁盘空间，建议预留 50GB 以上。常用管理命令包括：docker images 查看镜像、docker ps 查看运行容器、docker system prune 清理无用镜像与缓存。配置镜像加速可显著提升拉取速度：在 /etc/docker/daemon.json 中配置 registry-mirrors 后重启 docker 服务。若主机显卡驱动较新而镜像内核模块不匹配，可能出现 GPU 不可用，应查阅官方文档确认驱动版本要求。

6. 常见环境问题

容器启动后常见问题包括：权限不足，可通过将用户加入 docker 组解决；端口冲突，可通过修改 dev_start.sh 中的端口映射解决；挂载目录失败，需确认源码目录路径与权限正确。进入容器后务必先执行 apollo_base.sh 初始化环境，否则部分命令不可用。环境验证通过后即可进入源码编译阶段。

7. 网络与代理配置

开发环境常需访问 GitHub 与 Docker Hub，网络不稳定时建议配置代理。在容器中设置代理需同步配置 http_proxy 与 https_proxy 环境变量，并注意 Docker 构建代理的单独配置。镜像拉取失败可切换镜像源，源码下载失败可使用镜像仓库。网络问题排查时先确认 DNS 与连通性，再检查代理与防火墙配置。
