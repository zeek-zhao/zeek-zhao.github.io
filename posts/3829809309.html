告警与 Watcher

[!abstract] 是什么
监控的最后一环：数据异常时主动通知。Elastic Stack 提供 Watcher（ES 侧）与 Alerting（Kibana 侧）两种告警能力。

Kibana Alerting（推荐入门）

Stack Management → Rules 创建规则：

规则类型 用途
Elasticsearch query 查询结果满足条件即触发
Threshold 指标/计数超过阈值
Index threshold 索引聚合结果阈值（如错误数）
APM latency 服务延迟异常

示例：过去 5 分钟 ERROR 数超过 100

  1. 创建 Index threshold 规则：
    • 索引：logs-*，时间字段 @timestamp；
    • 聚合：count，条件：count > 100，检查窗口：5m；
  2. 配置动作（Actions）：Email / Webhook / Slack / Serverless；
  3. 设置”每 15 分钟最多告警 1 次”防轰炸。

[!note] 告警动作
动作可同时接多个渠道；Webhook 适合接企业 IM（钉钉/企微/飞书自定义机器人）。

Watcher（ES 侧，适合服务端场景）

Watcher 通过 ES REST API 创建告警（高级、可脚本化）：

[!note] Watcher 四要素
trigger（何时检查）→ input（取什么数据）→ condition（是否触发）→ actions（怎么办）。

告警管理规范

要点 建议
阈值可解释 基于基线（如 P95 的 2 倍）而非拍脑袋
分级 WARN（邮件）→ CRITICAL（IM+电话）→ PAGE
防风暴 全局静默窗口、按服务分组、事件折叠
可观测 告警本身记录到日志/看板，复盘命中率

[!tip] 常用阈值示例

  • 集群状态非 green 持续 10m；
  • 磁盘使用率 > 85%（磁盘水位预警）；
  • 5 分钟 5xx 占比 > 5%；
  • 接口 P95 延迟 > 2s（结合 APM）。

[!warning] 注意
告警渠道凭据（webhook URL、邮箱密码）勿明文写在公开文档；优先用 Kibana Connector 集中管理。
