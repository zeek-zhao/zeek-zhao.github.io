UART串口原理与通信实战

UART 大概是嵌入式工程师最熟悉也最容易低估的接口。我调试时第一反应永远是先把串口打通，它简单、可靠，几个参数对了就能打印日志。但真要把波特率误差、电平匹配和流控制这些细节理顺，还是得系统过一遍。这篇从数据帧结构一路写到编程实例和故障排查，把我平时踩过的坑也标在了对应章节里。

一图看懂：UART 用起始位到停止位组成数据帧，异步点对点通信。

graph LR TX[发送端] --> FR["数据帧 起始位 数据位 校验位 停止位"] FR --> BAUD[波特率匹配] BAUD --> RX[接收端] RX --> MODE[轮询 中断 DMA 三种处理]

1. 异步点对点串口：UART 的定位与演进¶

说白了 UART 就是两根线加一个约定好的波特率，没有时钟线反而让它最容易上手，也最容易因为参数不一致翻车。

UART（Universal Asynchronous Receiver/Transmitter，通用异步收发器）是一种广泛应用于嵌入式系统和计算机外设通信的串行通信协议。作为计算机历史上最早的外设通信接口之一，UART以其简单性、可靠性和通用性，成为连接微控制器与外部设备的重要桥梁。

1.1 UART的发展历史¶

  • 1960年代初期：串行通信接口最早在电传打字机和计算机终端中使用
  • 1969年：RS-232C标准发布，定义了串行通信的电气特性
  • 1970年代：UART作为集成电路出现，如Intel 8250
  • 1980年代：PC采用16550 UART芯片，增加缓冲功能
  • 1990年代：嵌入式微控制器集成UART外设
  • 2000年代至今：USB转UART接口普及，UART仍是嵌入式系统的标准接口

1.2 UART的基本特性¶

UART是一种点对点的串行通信协议，具有以下主要特性：

  • 异步通信：发送方和接收方使用各自的时钟，不需要共享时钟信号
  • 双线传输：基本实现只需RX（接收）和TX（发送）两条数据线
  • 起始位和停止位：用于标记数据帧的开始和结束
  • 可配置性：支持灵活的数据位数、停止位、奇偶校验等配置
  • 全双工通信：可以同时发送和接收数据
  • 多种波特率：支持多种通信速率，常见为9600、115200bps等
  • 简单性：硬件实现简单，易于编程控制
  • 无寻址机制：基本UART没有设备寻址能力，是点对点通信
  • 非差分信号：标准UART使用单端信号，抗干扰能力有限

UART凭借其简单且灵活的特性，被广泛应用于从简单调试到复杂设备间通信的各种场景。尽管现代系统出现了许多更高速的通信接口，UART仍然是嵌入式系统中不可或缺的基础通信方式。

2. 起始位到停止位：UART 数据帧与波特率¶

收发双方必须先把波特率、数据位、停止位和校验都约定一致，我遇到过的乱码十有八九是参数没对上。

2.1 基本通信方式¶

UART采用异步串行通信方式，数据以位(bit)为单位按时间顺序依次传输。其基本通信原理为：

  1. 空闲状态：线路处于高电平（逻辑1）
  2. 数据发送：
    • 发送起始位（逻辑0）标记数据帧开始
    • 依次发送数据位（通常为5-9位）
    • 发送可选的奇偶校验位
    • 发送停止位（逻辑1，可以是1、1.5或2位）标记数据帧结束
  3. 接收过程：
    • 检测到起始位后，接收器开始采样
    • 根据预设波特率在每个位的中间时刻采样
    • 接收完所有位后，进行可能的校验，并送入接收缓冲区

UART通信的一个重要特点是，发送方和接收方必须预先约定好通信参数（波特率、数据位数、校验方式、停止位数），否则将无法正确通信。

2.2 数据帧结构¶

标准UART数据帧由以下部分组成：

  1. **起始位(Start Bit)**：

    • 固定为逻辑0（低电平）
    • 表示数据传输开始
    • 长度为1位

  2. **数据位(Data Bits)**：

    • 可以是5、6、7、8或9位
    • 通常使用8位（一个字节）
    • 可以选择LSB（最低有效位）或MSB（最高有效位）先传

  3. **奇偶校验位(Parity Bit)**：

    • 可选部分，用于错误检测
    • 可以是奇校验、偶校验、固定0、固定1或无校验
    • 长度为1位（如果使用）

  4. **停止位(Stop Bit)**：

    • 固定为逻辑1（高电平）
    • 表示数据传输结束
    • 长度可以是1位、1.5位或2位

2.3 波特率与时钟¶

波特率（Baud Rate）是UART通信中的关键参数，表示每秒传输的符号数。在UART中，通常一个符号对应一个位，因此波特率也等同于位率（bit rate）。

2.3.1 常用波特率

标准波特率包括：

  • 1200、2400、4800、9600、19200、38400、57600、115200 bps等

较低波特率提供更好的信号完整性和更长的通信距离，较高波特率则提供更快的数据传输。

2.3.2 波特率生成

2.3.3 采样率

接收器通常以波特率的16倍(16×采样)或8倍(8×采样)对接收信号进行采样，以确保在位的中间点进行采样，提高抗干扰能力。

2.4 奇偶校验与错误检测¶

UART提供基本的错误检测机制，帮助确保数据完整性：

2.4.1 奇偶校验（Parity Check）

  • **奇校验(Odd Parity)**：校验位使数据位加校验位中”1”的总数为奇数
  • **偶校验(Even Parity)**：校验位使数据位加校验位中”1”的总数为偶数
  • **固定校验(Mark/Space Parity)**：校验位固定为1（标记）或0（空格）

2.4.2 帧错误（Framing Error）

当接收器未在预期位置检测到停止位时，发生帧错误，通常表示波特率设置不匹配或线路干扰。

2.4.3 溢出错误（Overflow Error）

当接收缓冲区已满但仍有新数据到达时，发生溢出错误，表示软件未及时读取数据。

2.4.4 噪声错误（Noise Error）

在16×采样模式下，如果在一个位期间的多个样本不一致，则检测到噪声错误。

3. 数据寄存器与移位器：UART 控制器架构与电平标准¶

TTL、RS-232 和 RS-485 的区别在电平不在协议，我接线前一定先确认两边电平标准，3.3V 直接怼 5V 或 RS-232 会出问题。

3.1 UART控制器架构¶

典型的UART控制器包含以下核心组件：

  1. 数据寄存器：

    • 发送数据寄存器(TDR)：存放待发送的数据
    • 接收数据寄存器(RDR)：存放接收到的数据

  2. 移位寄存器：

    • 发送移位寄存器：将并行数据转换为串行输出
    • 接收移位寄存器：将串行输入转换为并行数据

  3. 波特率发生器：

    • 可编程分频器：根据系统时钟生成所需波特率

  4. 控制寄存器：

    • 配置数据位数、停止位、校验方式等
    • 启用/禁用发送器和接收器
    • 启用/禁用中断

  5. 状态寄存器：

    • 指示发送器和接收器状态
    • 报告错误条件（帧错误、奇偶校验错误等）
    • 指示缓冲区状态（满/空）

  6. 中断控制逻辑：

    • 生成各种中断信号（接收完成、发送完成等）

3.2 UART信号线及连接¶

3.2.1 基本信号线

最简单的UART连接仅需两条信号线：

  • **TX (Transmit)**：发送数据的线路
  • **RX (Receive)**：接收数据的线路

完整的UART接口可能还包括以下信号线：

  • **RTS (Request to Send)**：流控制信号，表示设备准备好接收数据
  • **CTS (Clear to Send)**：流控制信号，表示对方可以发送数据
  • **DTR (Data Terminal Ready)**：表示终端设备已准备好通信
  • **DSR (Data Set Ready)**：表示数据设备已准备好通信
  • **DCD (Data Carrier Detect)**：表示检测到载波信号
  • **RI (Ring Indicator)**：表示检测到振铃信号

3.2.2 连接方式

两个UART设备连接时，TX和RX需要交叉连接：

  • 设备A的TX连接到设备B的RX
  • 设备A的RX连接到设备B的TX

3.3 电气标准与接口¶

UART通信协议定义了逻辑时序，但没有规定具体的电气特性。在实际应用中，UART常与以下电气标准结合使用：

3.3.1 TTL/CMOS电平

  • 直接使用微控制器的电平信号（通常为3.3V或5V）
  • 逻辑”1”为VCC电平（高电平）
  • 逻辑”0”为GND电平（低电平）
  • 适用于短距离、同电平系统间通信
  • 无噪声抑制能力，传输距离通常限制在几厘米到几米

3.3.2 RS-232标准

  • 广泛应用于PC和工业设备的串行接口标准
  • 使用反相逻辑：
    • 逻辑”1”为-3V至-15V（通常为-12V）
    • 逻辑”0”为+3V至+15V（通常为+12V）
  • 提供更好的噪声抗扰度和更长的传输距离（最多15米）
  • 需要电平转换芯片（如MAX232）将TTL电平转换为RS-232电平

3.3.3 RS-485标准

  • 用于工业环境的串行通信标准
  • 使用差分信号传输，具有极高的抗噪能力
  • 支持多点通信（最多32个节点）
  • 传输距离可达1200米
  • 常用于工业现场总线和远距离通信

3.3.4 其他衍生标准

  • RS-422：与RS-485类似的差分传输标准，但通常用于点对点通信
  • TTL-USB转换器：使用专用芯片（如CH340、CP2102、FT232）将UART转换为USB接口
  • 蓝牙SPP：通过蓝牙连接提供虚拟串口服务

4. 全双工、轮询与 DMA：UART 的传输与处理模式¶

简单应用轮询就够，数据量一上来我就换中断或 DMA，轮询最省事但也最吃 CPU。

4.1 传输模式¶

UART支持多种传输模式，适应不同应用场景的需求：

4.1.1 全双工(Full Duplex)模式

  • 同时可以发送和接收数据
  • 需要独立的TX和RX线
  • 是UART最常用的工作模式
  • 适用于需要双向实时通信的应用

4.1.2 半双工(Half Duplex)模式

  • 可以发送和接收数据，但在同一时刻只能进行一种操作
  • 通常使用单线加方向控制实现
  • 适用于RS-485等总线系统
  • 需要额外的方向控制逻辑

4.1.3 单工(Simplex)模式

  • 数据只能朝一个方向传输
  • 仅使用TX或RX其中一条线
  • 适用于单向数据传输场景，如简单传感器

4.2 数据处理模式¶

UART数据处理有几种典型实现方式：

4.2.1 轮询模式

  • 优点：简单，不需要中断处理
  • 缺点：占用CPU时间，效率低
  • 适用场景：简单应用，数据量小

4.2.2 中断模式

  • 优点：CPU效率高，响应及时
  • 缺点：中断处理复杂度增加
  • 适用场景：一般数据通信，中等数据量

4.2.3 DMA模式

  • 优点：CPU负担最小，适合大数据量传输
  • 缺点：初始化复杂，资源占用多
  • 适用场景：大数据量传输，如串口屏、数据记录

4.3 多处理器通信模式¶

除了基本通信模式，一些高级UART还支持多处理器通信：

4.3.1 地址标记模式

  • 允许在公共总线上连接多个UART设备
  • 每个数据帧的第9位作为地址/数据标记
  • 设备只处理地址匹配的或广播的数据帧
  • 适用于简单的总线网络

4.3.2 LIN总线模式

  • Local Interconnect Network，用于汽车内部网络
  • UART的扩展，使用单主多从模式
  • 包含同步字段和增强的错误检测
  • 低速(20kbps)，低成本

4.4 低功耗模式¶

现代UART控制器通常提供以下低功耗特性：

  • 自动唤醒：检测到起始位时从低功耗模式唤醒
  • 空闲检测：检测到一定时间无活动后自动进入低功耗模式
  • 时钟门控：在不需要时关闭UART时钟
  • 部分唤醒：只有地址匹配时才完全唤醒接收器

特性 UART USB

9. 不通、乱码与流控失效：UART 排错思路¶

UART 不通我先查三样，TX/RX 有没有交叉、地有没有共、波特率是不是一致，这三项能解决绝大多数问题。

9.1 常见UART通信问题¶

9.1.1 无法通信

当UART设备无法通信时，常见原因包括：

  • 硬件连接问题：

    • TX/RX交叉连接错误
    • 地线未连接
    • 引脚损坏

  • 配置不匹配：

    • 波特率不一致
    • 数据格式不匹配(数据位、停止位、校验位)
    • 流控制设置不一致

  • 电平不兼容：

    • 3.3V与5V系统互连时无电平转换
    • RS-232与TTL电平混用

解决方案：

  • 使用万用表检查硬件连接
  • 确认并统一通信参数
  • 添加必要的电平转换电路

9.1.2 数据错误

数据错误的常见原因：

  • 波特率误差过大：

    • 晶振偏差导致时钟不准
    • 使用不标准的波特率值

  • 噪声干扰：

    • 信号线过长
    • 电源噪声
    • 附近高功率设备干扰

  • 缓冲区溢出：

    • 接收处理不及时
    • 缓冲区设计不足

解决方案：

  • 使用标准波特率，确保时钟准确
  • 缩短信号线，加装屏蔽或滤波
  • 增大接收缓冲区，优化处理代码

9.1.3 流控制问题

使用流控制时的常见问题：

  • 硬件流控制线未连接：CTS/RTS引脚悬空
  • 软件流控制字符被误识别为数据
  • 流控制机制配置不一致

解决方案：

  • 检查流控制线连接
  • 确保XON/XOFF字符不出现在数据流中
  • 统一流控制策略

    • 伺服驱动器命令接口
    • 传感器数据采集
    • 调试和监控接口

10.3 虚拟串口技术¶

随着技术发展，UART被虚拟化应用于多种场合：

  • USB-UART转换：

    • 使用FTDI、CH340、CP2102等芯片
    • 为现代计算机提供串口功能
    • 驱动程序提供虚拟COM端口

  • 蓝牙SPP配置文件：

    • 通过蓝牙提供虚拟串口
    • 无线替代传统串口线缆
    • 兼容现有串口应用程序

  • TCP/IP串口服务器：

    • 将串口数据封装到网络数据包
    • 远程访问串口设备
    • 虚拟网络串口软件

  • 操作系统虚拟串口：

    • Linux的/dev/ttyS、/dev/ttyUSB设备
    • Windows的COM端口虚拟化
    • 应用程序间通信的虚拟串口对

10.4 未来发展趋势¶

UART技术的未来发展方向：

  • 更高速率：

    • 超过现有速率限制的高速UART
    • 改进的时序和信号处理

  • 增强安全性：

    • 带加密功能的UART控制器
    • 安全引导和身份验证特性

  • 低功耗优化：

    • 针对电池供电设备的更高效UART
    • 智能功耗管理

  • 智能特性：

    • 自适应参数设置
    • 先进的错误检测和恢复
    • 协议感知处理

11. 落地建议：参数一致优先于一切优化¶

调试 UART 我有个固定顺序：先确认双方波特率、数据位、停止位和校验完全一致，再查 TX/RX 有没有交叉、地有没有共，最后才看电平匹配和流控制。这套走完还不通，再去翻控制器的寄存器配置——把这几个参数钉死，UART 几乎不会出问题。
