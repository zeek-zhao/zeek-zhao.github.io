07-高精地图HD Map

发表于2026-10-25|apollo
|浏览量:

[!info] 本节目标
理解高精地图在自动驾驶系统中的定位与作用，掌握 Apollo 地图数据结构（map.proto）、Map 模块核心组件（HDMap/PncMap/RelativeMap）与地图查询、制作、调试的完整流程。

1. 什么是高精地图

高精地图（HD Map）是精度达到厘米级的道路环境数字化表示。与传统导航地图只关心”从 A 到 B 怎么走”不同，高精地图精确描述每一条车道、每一根杆、每一盏信号灯的位置与语义，是自动驾驶系统的先验信息源。

特征 传统导航地图 高精地图
精度 米级（3-5 m） 厘米级（10-20 cm）
更新频率 季度/年度 日/周级（部分要素实时）
数据量 相对较小 巨大（约 1-2 GB/公里）
表示方式 二维路网 + POI 三维结构化场景
交通规则 有限 完整（限速、转向、让行等）
主要用途 人类导航 机器定位与决策

高精地图对系统的四大价值：

  1. 超视距感知：获取传感器范围之外的道路形状、坡度、曲率，不受天气与光照影响
  2. 厘米级定位：传感器观测与地图匹配，将定位误差压缩到厘米级
  3. 规则辅助决策：限速、转向许可、让行规则直接来自地图，不依赖实时识别
  4. 规划约束：车道中心线与边界构成轨迹生成的可行域

2. 地图核心要素

Apollo 地图以车道（Lane）为中心组织要素：

要素 内容 主要使用方
车道 Lane 中心线、左右边界、宽度、限速、前后继/邻接关系 规划、定位
道路 Road Section 划分、所属车道集合 路由、规划
路口 Junction 多边形区域、重叠关系 通行决策
信号灯 Signal 位置、子灯（Subsignal）、停止线关联 感知关联、决策
停车标志 StopSign / 让行标志 YieldSign 位置与关联车道 决策
人行横道 Crosswalk / 减速带 SpeedBump / 清除区 ClearArea 区域多边形 感知过滤、规划避让
停车位 ParkingSpace 多边形、朝向 泊车规划
重叠区 Overlap 元素间的拓扑连接关系 路由、参考线生成

[!tip] 学习提示
理解 Overlap 是读懂 Apollo 地图拓扑的关键：车道与车道、车道与路口、车道与信号灯之间的连接关系全部通过 Overlap 表达，路由模块正是沿 Overlap 链查找可达路径的。

3.1 坐标系

  • 全局坐标系（XYZ）：UTM 或 ENU 局部投影坐标，地图要素的绝对位置
  • 车道坐标系（SL）：S 为沿车道中心线的弧长，L 为相对中心线的横向偏移。规划模块在 SL 坐标系下生成轨迹，map_xysl 工具提供两种坐标互转

4. Map 模块架构

Map 模块（modules/map/）负责地图的加载、管理与查询，核心组件：

  • HDMap/HDMapImpl：加载地图构建内存表示，内部用哈希表（按 ID 查询）+ R 树空间索引（按位置查询）保证查询效率
  • PncMap：将路由响应转换为规划可直接使用的连续 RouteSegments
  • RelativeMap：无高精地图场景下的备选方案，用感知输出的车道线 + 导航线动态构建局部地图（导航模式）

[!warning] 常见调试问题

  • 加载失败：检查 --map_dir 路径与文件格式（.bin/.txt 需与加载接口匹配）
  • 要素缺失：检查制图流程是否覆盖该要素类型（如信号灯漏标）
  • 坐标偏移：核对地图坐标系配置与定位输出坐标系一致；用 DreamView 叠加点云与地图可快速发现错位

地图质量直接决定定位与规划质量，建议在调试 08-定位模块 与规划前先完成地图对齐检查。

规划 PncMap 提供 RouteSegments → 参考线 → 轨迹；查询限速/停止线等约束

[!note] 2026 年更新
Apollo 9.0 起支持包化模块开发（package-based module development），地图作为包资源随模块分发，开发者可不再依赖完整源码仓库部署地图数据；同时相对地图与”无图化”趋势在低成本场景持续演进，但厘米级先验地图仍是 L4 高阶能力的基石。
