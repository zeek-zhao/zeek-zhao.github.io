Linux基础术语与核心概念

刚接触 Linux 时，最让人晕的不是命令记不住，而是文件描述符、inode、作业控制这些词到底在说什么。我刚开始也是靠死记命令，后来把这些概念串起来，排障时才发现思路清楚多了。

这篇按文件系统、通配符、IO 重定向、进程线程、权限和监控这条线，把 Linux 里最常用的术语和对应命令过一遍，每条都配上能直接敲的命令。

1. Linux 是什么：内核、发行版与目录标准¶

1.1 Linux简介¶

Linux是一种自由和开源的类Unix操作系统，基于Linux内核，由芬兰程序员林纳斯·托瓦兹（Linus Torvalds）在1991年首次发布。Linux具有以下特点：

  • 多用户、多任务：支持多个用户同时登录系统并执行不同任务
  • 开源免费：源代码公开，允许任何人查看、修改和分发
  • 可移植性：可运行在多种硬件平台上
  • 安全性高：权限控制严格，系统架构相对安全
  • 网络功能强大：内置强大的网络功能，适合作为服务器

1.2 Linux发行版¶

Linux发行版是Linux内核与各种应用软件的集合，常见的发行版包括：

  • Debian/Ubuntu系列：以易用性和稳定性著称
  • RedHat/CentOS/Fedora系列：广泛用于企业服务器环境
  • Arch Linux：滚动更新，高度可定制
  • SUSE/openSUSE：在欧洲企业中较为流行
  • Gentoo：源码编译，高度优化

1.3 Linux文件系统层次结构标准(FHS)¶

我排查路径问题时经常回来对照这张 FHS 表，尤其是 /etc、/var 和 /proc 这三个目录：

目录 用途
/ 根目录，所有目录的起点
/bin 基本命令二进制文件
/boot 引导加载程序文件，内核等
/dev 设备文件
/etc 系统配置文件
/home 用户主目录
/lib 共享库文件
/mnt 临时挂载点
/opt 可选应用软件包
/proc 进程和内核信息的虚拟文件系统
/root root用户的主目录
/sbin 系统二进制文件
/tmp 临时文件
/usr 用户应用程序和数据
/var 变量数据（如日志）

2. 文件系统：一切皆文件、inode 与两类链接¶

2.1 Linux文件类型¶

在Linux中，一切皆文件。Linux支持多种文件类型，我排查时习惯先敲一句 ls -l 看首字符，比翻文档快；可通过ls -l命令查看，第一列的字符表示文件类型：

  • - : 普通文件
  • d : 目录
  • l : 符号链接
  • c : 字符设备文件
  • b : 块设备文件
  • p : 命名管道
  • s : 套接字文件

2.2 inode与数据块¶

Linux文件系统使用inode和数据块来存储文件：

  • inode（索引节点）：存储文件的元数据（权限、所有者、时间戳等），但不包含文件名
  • 数据块：存储文件的实际内容
  • 目录：特殊文件，包含文件名到inode号的映射

2.3 硬链接与软链接¶

Linux支持两种链接类型：

  • 硬链接：多个文件名指向同一个inode，删除一个不影响其他链接，不能跨文件系统，不能链接目录

  • 软链接（符号链接）：类似Windows的快捷方式，实际是指向另一个文件路径的特殊文件，可跨文件系统，可链接目录

3. glob 通配符：shell 帮你展开的文件名匹配¶

3.1 什么是glob通配符¶

glob是一种文件名通配符语法，用于匹配文件名或路径。它不是正则表达式，但概念类似，主要用于命令行中的文件名匹配。

3.2 常用通配符¶

通配符 描述 示例
* 匹配任意数量的字符 *.txt 匹配所有.txt文件
? 匹配单个字符 file?.txt 匹配file1.txt, fileA.txt等
[abc] 匹配括号内任意字符 file[123].txt 匹配file1.txt, file2.txt, file3.txt
[a-z] 匹配范围内任意字符 file[a-z].txt 匹配filea.txt到filez.txt
[!abc]或[^abc] 匹配不在括号内的任意字符 file[!1-3].txt 匹配除file1.txt, file2.txt, file3.txt之外的fileX.txt
{pattern1,pattern2} 匹配多个模式 file.{txt,md} 匹配file.txt和file.md

4. 文件描述符与 IO 重定向：0、1、2 三个默认通道¶

4.1 文件描述符基础¶

文件描述符是一个非负整数，表示进程打开的文件。每个进程默认有三个标准文件描述符，踩过的坑是忘了 2>&1 的顺序，结果错误日志还是丢在屏幕上：

文件描述符 名称 描述 符号

5. 进程与线程：地址空间、状态与调度单元¶

5.1 什么是进程¶

进程是程序的运行实例，具有自己的地址空间、资源和状态，每个进程有唯一的进程ID (PID)。我用 ps 看进程时习惯先确认状态列，D 状态的进程往往才是卡顿元凶。

5.2 进程的创建¶

Linux中创建新进程的主要方式：

  • fork(): 创建当前进程的副本(子进程)
  • exec(): 替换当前进程的映像
  • 通常的过程是先fork创建子进程，然后exec加载新程序

5.3 进程状态与生命周期¶

进程有多种状态：

  • R (Running): 运行中或可运行
  • S (Sleeping): 可中断睡眠，等待某个条件
  • D (Disk Sleep): 不可中断睡眠，通常在I/O操作中
  • T (Stopped): 已停止，通常由信号引起
  • Z (Zombie): 僵尸进程，已终止但父进程未回收
  • X (Dead): 死进程（通常不可见）

5.4 进程控制与信号¶

信号是进程间通信的简单形式，用于控制进程行为：

信号 数值 描述 快捷键/常见用途
SIGHUP 1 挂起 终端断开连接时发送
SIGINT 2 中断 Ctrl+C
SIGQUIT 3 退出 Ctrl+\
SIGKILL 9 立即终止 无法捕获或忽略，强制结束进程
SIGTERM 15 终止 kill命令默认信号
SIGSTOP 19 停止 Ctrl+Z

5.7 什么是线程¶

线程是进程内的执行单元，共享同一地址空间和资源，但有独立的执行流和栈：

  • 轻量级：线程创建和上下文切换成本低于进程
  • 资源共享：同一进程的线程共享内存和文件描述符
  • 通信简单：线程间可直接访问共享数据
  • 独立调度：线程是CPU调度的基本单元

5.8 进程与线程的区别¶

特性 进程 线程
定义 程序的独立实例 进程中的执行流
资源 拥有独立的地址空间和资源 共享所属进程的地址空间和资源
通信 需要IPC机制（管道、信号、套接字等） 可直接访问共享数据
创建成本 较高 较低
上下文切换 成本较高 成本较低
安全性 高（一个进程崩溃不影响其他进程） 较低（一个线程崩溃可能导致整个进程崩溃）

6. IPC：管道、信号、共享内存与套接字¶

6.1 常见IPC方法¶

Linux提供多种进程间通信机制：

  1. **管道(Pipes)**：单向数据流，通常用于相关进程间通信

  2. **命名管道(FIFO)**：类似管道，但存在于文件系统中，允许不相关进程通信

  3. **信号(Signals)**：上文已详细介绍

  4. 共享内存：多个进程共享一块内存区域，最快的IPC方式

  5. 消息队列：结构化数据交换

  6. **信号量(Semaphores)**：用于进程同步

  7. **套接字(Sockets)**：可用于同一主机或网络上的进程通信
