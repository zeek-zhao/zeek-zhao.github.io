05-源码编译与部署

掌握 Apollo 基于 Bazel 的源码编译流程：构建目标、产物组织、常见构建问题排查，以及从打包到目标平台部署的完整链路。
📅 2026-10-25· 更新于 2026-10-25 ✍ zeek.zhao #系统#apollo
ℹ️本节目标
在 04-开发环境搭建（Docker） 搭好的环境中完成源码编译，理解 Bazel 构建体系、构建目标与产物组织，掌握编译问题的排查方法与部署流程。

1. Bazel 构建基础¶

Apollo 使用 Bazel 作为构建系统，关键概念：

  • WORKSPACE：定义外部依赖
  • BUILD 文件：声明构建目标（cc_library、cc_binary、cc_test 等）与依赖关系
  • bazel-bin：构建产物目录，可安全删除重建

常用命令：bazel build 编译、bazel test 运行测试、bazel clean 清理。增量编译时 Bazel 只重编变更部分，可显著节省时间。

2. 编译准备¶

  • 确认源码版本与 Docker 镜像版本匹配（10.0/11.0 建议 pin commit）
  • 检查磁盘空间（Bazel 缓存与产物占用大）与内存

3. 构建目标与命令¶

目标 命令 说明
全量编译 ./apollo.sh build 编译全部模块，首次 30–60 分钟
指定模块 ./apollo.sh build --modules=cyber,common,dreamview,canbus 只编译指定模块
单个目标 bazel build //modules/perception:all Bazel 原生目标
并行加速 ./apollo.sh build -j$(nproc) 按核数并行
清理 bash scripts/apollo_clean.sh 清理构建缓存

构建产物位于 /apollo/bazel-bin，模块二进制与配置文件按目录组织，例如组件动态库路径形如 /apollo/bazel-bin/modules/example/libexample_component.so。

6. 常见构建问题¶

问题 原因与解法
空间不足 清理 bazel 缓存或扩容
内存不足 限制并行度：bazel build --jobs=4
依赖缺失 检查 dev_start.sh 挂载与镜像版本是否匹配
编译中断 断点续编：重复执行原构建命令即可
分支切换后报错 外部依赖变更需清理重建：bash scripts/apollo_clean.sh

7. 构建缓存与增量编译¶

  • 源码变更后缓存自动失效重编，正常开发无需手动清理
  • 频繁切换分支会导致缓存膨胀，建议定期清理
  • bazel-bin 产物目录可安全删除重建，不影响源码

8. 部署流程¶

部署分为四个环节：

  1. 构建：产出模块二进制（bazel-bin 下的可执行文件与 .so）
  2. 打包：将二进制、配置文件与依赖环境制作成运行镜像或安装包
  3. 分发：部署到目标车辆计算平台（如 NVIDIA Orin）
  4. 运行：统一版本、环境变量与配置文件，通过启动脚本拉起

生产环境还需考虑日志收集、版本回滚与远程监控。

⚠️部署一致性
部署时务必统一：源码版本、镜像版本、配置文件三者一致。目标平台架构（x86/ARM Orin）不同时，需在对应架构上交叉编译或原生编译。
