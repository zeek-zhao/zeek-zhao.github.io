Java 代码格式化：google-java-format 与 Spotless

ℹ️本页概览
本文讲解 Java 生态格式化：google-java-format（GJF）、Spotless（Gradle/Maven 集成）、Eclipse Formatter，配真实配置示例与 CI 集成。

核心概念¶

  • google-java-format（GJF）：Google 官方 Java 格式化器，单一风格、几乎零配置。
  • Spotless：通用格式化插件（Gradle/Maven），可接 google-java-format / eclipse formatter / prettier 等。
  • Eclipse Formatter：传统 IDE 风格，可自定义（阿里规约常配合使用）。
  • 理念：Java 生态多 IDE，团队必须统一格式化，避免 diff 噪音。

常见坑¶

  1. GJF 版本与 JDK 兼容：新版 GJF 要求 JDK11+；CI 与本地版本一致。
  2. Lombok 兼容：GJF 默认兼容 Lombok，但自定义注解处理器可能受影响。
  3. import 分组不一致：统一使用 Spotless importOrder 而非手写。
  4. 生成代码：MyBatis generator / OpenAPI 生成类加入 spotless target 排除。
  5. IDE 保存格式化 vs 命令行不一致：IDE 必须配同一插件/格式文件。

最佳实践¶

  • 用 Spotless 统一 Gradle/Maven，CI 强制 spotlessCheck。
  • 新增代码即时格式化；存量代码单独”格式化提交”。
  • 配合 阿里规约 定义团队 Java 规范。
