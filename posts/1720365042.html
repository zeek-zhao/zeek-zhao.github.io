Linux下GPIO三种操作方式与设备树配置

GPIO 是嵌入式里最基础的一根线，用法却分了三代：老脚本还在 echo sysfs，新项目已经被要求改用 libgpiod。我在实际用的时候一般先分清是要快速验证还是要进产品，选路差别很大——这条路走错了，后面中断和批量操作会很别扭。

GPIO是可以配方向、读电平、触发中断的引脚¶

1.1 什么是GPIO¶

GPIO (General Purpose Input/Output，通用输入/输出) 是嵌入式系统中最基本的一种接口，可以用于读取外部输入信号或输出控制信号。

📝GPIO的主要特点
  • 可配置为输入或输出
  • 可读取或设置高低电平状态
  • 支持中断功能(边缘触发或电平触发)
  • 每个GPIO口通常可单独配置和控制

1.2 电路上GPIO一头接CPU、一头接外设¶

graph LR CPU[CPU/SOC] --> GPIO_MOD[GPIO模块] GPIO_MOD --> PIN1[GPIO引脚1] GPIO_MOD --> PIN2[GPIO引脚2] GPIO_MOD --> PIN3[GPIO引脚3] GPIO_MOD --> PINN[GPIO引脚N...] PIN1 --> |输出模式| LED[LED灯] PIN2 --> |输入模式| BTN[按钮] PIN3 --> |可配置| DEV[外部设备]

1.3 编号用 (N-1)×32+X 线性推算¶

在Linux系统中，GPIO通常以线性编号方式编址，计算公式通常为：

$$
GPIO编号 = (N-1) \times 32 + X
$$

其中，N为GPIO组号，X为组内引脚编号。例如GPIO4_14对应的编号为(4-1)×32+14=110。

我一般先按这个公式把编号算出来，再去 /sys/class/gpio 里对号入座，省得在引脚名和编号之间来回猜。

三种操作方式：sysfs、shell脚本与libgpiod¶

Linux系统提供了三种主要的GPIO操作方式：

  1. sysfs接口方式 (传统方式，即将废弃)
  2. 基于shell脚本的直接操作方式
  3. libgpiod库方式 (推荐方式)

下面我们详细介绍这三种方式的操作方法及优缺点。

2.1 sysfs：靠文件读写控制GPIO，已被标记过时¶

sysfs接口是Linux内核提供的一种用户空间访问GPIO的方式，通过文件系统操作来控制GPIO。

sysfs的目录结构：export、unexport与gpioN

graph TD ROOT["/sys/class/gpio/"] --> EXPORT["export (写入GPIO编号以导出)"] ROOT --> UNEXPORT["unexport (写入GPIO编号以取消导出)"] ROOT --> GPIO["gpioN/ (导出后创建的GPIO目录)"] GPIO --> DIR["direction (设置方向:in/out)"] GPIO --> VAL["value (读写值:0/1)"] GPIO --> EDGE["edge (设置中断触发方式)"] GPIO --> ACT["active_low (设置有效电平)"]

操作流程：导出、设方向、读写、取消导出

sequenceDiagram participant App as 应用程序 participant Sysfs as /sys/class/gpio participant Kernel as Linux内核 participant Hardware as GPIO硬件 App->>Sysfs: 1. 写入GPIO编号到export文件 Sysfs->>Kernel: 通知内核导出GPIO Kernel->>Sysfs: 创建gpioN目录及相关文件 App->>Sysfs: 2. 设置direction (in/out) Sysfs->>Kernel: 配置GPIO方向 Kernel->>Hardware: 设置硬件寄存器 Note over App,Sysfs: 如果设置为输出模式 App->>Sysfs: 3a. 写入value (0/1) Sysfs->>Kernel: 设置输出值 Kernel->>Hardware: 设置引脚电平 Note over App,Sysfs: 如果设置为输入模式 App->>Sysfs: 3b. 读取value Sysfs->>Kernel: 获取输入值 Kernel->>Hardware: 读取引脚电平 Hardware->>Kernel: 返回电平状态 Kernel->>Sysfs: 返回值 Sysfs->>App: 返回0或1 App->>Sysfs: 4. 写入GPIO编号到unexport文件 Sysfs->>Kernel: 通知内核取消导出 Kernel->>Sysfs: 删除gpioN目录及相关文件

  • 适合系统初始化脚本和简单测试
  • 方便与其他系统命令集成

  • 不适合中断处理和复杂控制逻辑
  • 与sysfs接口共享相同的过时问题

2.3 libgpiod：内核4.8引入的推荐接口¶

libgpiod是Linux内核从4.8版本引入的新GPIO接口，旨在替代过时的sysfs接口。它提供了C语言API和命令行工具。

设备树才是GPIO的底层描述，用户接口只是抽象¶

在嵌入式Linux系统中，设备树(Device Tree)是描述硬件的重要机制，GPIO的底层配置通常需要在设备树中完成。理解设备树配置对于完整的GPIO开发至关重要。

实测下来，先把 gpio-line-names 填好，后面用 gpioinfo 对照引脚能省不少时间。

3.1 设备树用控制器节点加phandle引用描述GPIO¶

设备树中的GPIO通常以以下方式表示：

graph TD DT[设备树] --> GPIO_C[GPIO控制器节点] GPIO_C --> PINS[引脚定义] GPIO_C --> PROPS[控制器属性] DT --> DEV[设备节点] DEV --> GPIO_PROP[GPIO属性] GPIO_PROP --> REF["引用(phandle + 引脚号 + 标志)"]

控制器节点描述地址、中断与引脚数量

GPIO控制器节点描述了一个GPIO控制器的基本属性，包括：

  • 寄存器地址范围
  • 中断信息
  • GPIO引脚数量
  • 引脚复用信息

3.2 属性与标志位决定GPIO怎么被引用¶

常用的控制器属性：cells、controller、ngpios、ranges、line-names

属性名 描述
#gpio-cells 定义引用GPIO所需的单元格数量，通常为2（引脚号和标志）
gpio-controller 标识该节点是GPIO控制器
ngpios 控制器管理的GPIO数量
gpio-ranges 定义GPIO编号范围的映射
gpio-line-names 为GPIO线分配名称，便于识别

标志位：高低有效与推挽开漏

在设备树中引用GPIO时，通常使用标志位指定GPIO的特性：

标志位 值 描述
GPIO_ACTIVE_HIGH 0 高电平有效（默认）
GPIO_ACTIVE_LOW 1 低电平有效
GPIO_PUSH_PULL 0 推挽输出（默认）
GPIO_OPEN_DRAIN 2 开漏输出
GPIO_OPEN_SOURCE 4 开源输出

3.7 设备树经内核GPIO子系统映射到用户接口¶

graph TD DT[设备树] --> KERNEL[内核GPIO子系统] KERNEL --> SYSFS[sysfs接口] KERNEL --> GPIOD[libgpiod/字符设备] SYSFS --> USER[用户空间应用] GPIOD --> USER

设备树中的GPIO配置是底层硬件描述，它通过内核GPIO子系统提供统一的抽象，最终通过sysfs或libgpiod等接口暴露给用户空间应用程序。这些接口使用不同的编号方式引用GPIO，内核会进行自动映射。

我一般按这张表挑：要进生产环境就直接看 libgpiod 那一列，别在 sysfs 上继续加功能。

命名、阶段选型与四个常见坑¶

5.1 命名用「功能_信号_方向」¶

在大型项目中，建议采用统一的GPIO命名和管理规范：

graph TD A[GPIO命名规范] --> B[功能前缀_信号名称_方向] B --> C1["LED_STATUS_OUT"] B --> C2["BTN_POWER_IN"] B --> C3["PWR_USB_EN"]

5.2 按开发、产品、初始化分阶段选型¶

  1. 开发阶段：使用shell脚本或sysfs进行快速原型开发和测试
  2. 产品阶段：使用libgpiod库实现稳定、高性能的GPIO操作
  3. 系统初始化：在系统启动脚本中使用shell方式初始化GPIO状态

5.3 四个坑：资源泄漏、权限、过度轮询、缺防抖¶

  • 忘记释放GPIO资源：程序结束前应取消导出或释放GPIO
  • 忽略权限问题：某些系统可能需要root权限操作GPIO
  • 过度轮询：频繁读取GPIO状态会消耗大量CPU资源，应使用中断或适当延时
  • 未考虑防抖：按钮等输入需要软件防抖处理

按钮输入我一般加个软件防抖，不然轮询读到的电平会来回跳，看着像误触发。

结论：新项目直接上libgpiod¶

简单测试和初始化用 shell 脚本，中小型应用可以先用 sysfs 顶着，但专业产品和性能关键场景应该直接上 libgpiod。sysfs 自 4.8 起已标记为过时，新项目别再从它起步——开发阶段用 shell 快速验证，进产品换 libgpiod，性能、批量操作和中断支持都到位。
