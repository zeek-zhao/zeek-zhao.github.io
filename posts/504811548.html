1. 概述¶

1.1 MCP 是什么¶

MCP（Model Context Protocol，模型上下文协议）是 Anthropic 于 2024 年提出的开放标准协议，用于统一 AI 应用与外部数据源、工具之间的通信。它定义了三种核心原语：

  • Resources：向模型暴露只读数据（文件、数据库记录等）
  • Tools：向模型暴露可执行的操作（调用 API、运行命令等）
  • Prompts：向模型暴露可复用的提示模板

客户端（如 Claude Desktop、Cursor、Marvis）通过 MCP Server 与外部系统交互。Jenkins MCP 就是把 Jenkins 的 REST API 包装成一组 MCP 工具，让 AI 助手直接用自然语言操作 Jenkins。

1.2 Jenkins MCP 能做什么¶

  • 查询 Jenkins 实例状态、执行节点健康度、队列长度
  • 分页列出 / 查看任务（Job）详情
  • 查看构建（Build）信息、构建产物（Artifacts）
  • 触发 / 定时触发 / 停止 / 取消构建
  • 读取构建产物内容（文本或 base64）
  • 查看当前认证用户、修改构建名称与描述
🔥典型场景
  • 「查看 NightlyBuild-Sa525m-LE3.0-YP4.0 最近构建是否成功」
  • 「把 Checksec-Module 的任务列表拉出来看看」
  • 「触发一次 Manifest-Review 构建」
  • 「生成一份今天所有 NightlyBuild 任务的状态报告」

1.3 术语速查¶

术语 含义
Job / 任务 Jenkins 中一个可执行的流水线或项目，如 Checksec-Module
Build / 构建 Job 的一次具体执行，有唯一 buildNumber
Node / 节点 执行构建的机器（Agent），如 RSZ-SW-LOCAL-SZ-10.22.67.203
Executor / 执行器 节点上并行执行构建的槽位
Queue / 队列 等待执行器空出的构建请求
Artifact / 产物 构建生成的输出文件（日志、包、报告等）
API Token Jenkins 用户级访问令牌，用于 REST API 认证

2. 两种接入方案原理与对比¶

2.1 方案 A：服务端插件直连（官方 MCP Server 插件）¶

flowchart LR A[AI 客户端] -->|HTTP / SSE| B[Jenkins MCP Server 插件] B --> C[Jenkins 核心 / REST API]
  • 在 Jenkins 上安装官方 MCP Server 插件
  • 插件暴露 HTTP 端点 /mcp-server/mcp
  • 客户端通过 SSE（Server-Sent Events） 直连该端点
  • 鉴权复用 Jenkins 凭据体系

2.2 方案 B：npx 桥接（本地 MCP Server 进程）¶

flowchart LR A[AI 客户端] -->|stdio| B[npx 启动的 MCP Server 进程] B -->|REST API + Token| C[Jenkins 实例]
  • 在本机用 npx 启动一个 Jenkins MCP Server 进程
  • 客户端与该进程通过 stdio（标准输入输出） 通信
  • 进程内部调用 Jenkins REST API，使用 API Token 认证
  • Jenkins 侧无需安装任何插件、无需重启服务

2.3 对比表¶

维度 方案 A：插件直连 方案 B：npx 桥接
前置条件 需 Jenkins 管理员权限安装插件 仅需用户 API Token + 本机 Node.js
是否重启 Jenkins 需要（插件安装后重启） 不需要
通信方式 HTTP/SSE，跨机器可用 stdio，本机进程
多客户端共享 可以（所有客户端连同一端点） 每个客户端各自起进程
鉴权 插件内配置凭据 + 端点鉴权 Token 写在客户端 env 中
网络暴露面 端点暴露在 Jenkins 对外路径 无新增网络暴露
运维成本 中（插件升级、端点安全） 低（npx 即用即走）
适合场景 多人共享、服务端统一管理 个人本地接入、快速验证
📝本次结论
目标 Jenkins（2.541.3）未安装 MCP Server 插件（端点 /jenkins/mcp-server/mcp 返回 404，插件列表无 mcp-server），因此实际采用 方案 B：npx 桥接 + API Token，一次连接成功（状态 authenticated，14 个工具）。

3. 环境准备与前置检查¶

3.1 必需条件¶

条件 要求 说明
Jenkins 实例 Web 页面可正常访问 本文：https://swd-nas.rollingwireless.com/jenkins/
Jenkins 账号 具备查看 / 操作权限 本文：zeek.zhao

3.2 前置检查清单（四步）¶

  1. 确认页面可访问：浏览器打开 Jenkins 首页，确认标题为 Dashboard - Jenkins、页面正常渲染
  2. 确认版本：查看页面右上角版本徽标（本文实例为 2.541.3）
  3. 确认 MCP 插件是否已安装：访问 https://<jenkins>/mcp-server/mcp
    • 返回 404 Not Found → 插件未安装，需走 npx 桥接（本次情况）
    • 返回 405 / JSON 错误 → 端点存在，可走服务端直连
  4. 确认登录用户：右上角头像 / 用户名（本次为 zeek.zhao，无登录墙）

3.3 权限矩阵（建议核对）¶

操作类型 所需权限
查看状态 / 任务 / 构建 / 产物 Overall Read + Job Read
触发构建（triggerBuild / scheduleBuild） Job Build
停止 / 取消构建 Job Cancel / Build 对应权限
修改构建名称 / 描述 Job Configure 或 Build 对应权限
⚠️权限不足的典型表现
调用返回 403 Forbidden。API Token 的权限与账号一致，不会比 Web 登录更高。

4. 路线一：官方 MCP Server 插件（服务端直连）¶

📝本路线本次未采用（插件未安装），作为标准做法收录备查。若后续获得插件安装权限，推荐优先使用本方案实现多人共享。

4.1 安装插件¶

  1. 进入 Manage Jenkins → Plugins → Available plugins
  2. 搜索 MCP Server（Jenkins 官方 / 社区维护的 mcp-server 插件）
  3. 勾选后点击 Install
  4. 安装完成后按提示重启 Jenkins 使插件生效
🔥离线安装
若 Jenkins 所在内网无法访问插件更新中心，可手动下载 .hpi 文件，在 Manage Jenkins → Plugins → Advanced settings 中上传安装。

4.2 配置全局凭据¶

  1. 进入 Manage Jenkins → Credentials → System → Global credentials
  2. 点击 Add Credentials
  3. 类型选择 Username with password 或 Secret text
  4. 填入用于 API 调用的用户名与 Token（可复用 中创建的 Token）
  5. 在 MCP Server 插件配置页绑定该凭据，并可选设置允许访问的 Job 白名单

5. 路线二：npx 桥接（推荐，本次采用）¶

5.1 方案原理¶

通过 npx 在本机启动一个 Jenkins MCP Server 进程，客户端与进程通过 stdio 通信；进程内部以 REST API + API Token 访问 Jenkins。Jenkins 侧零改动、零插件、零重启。

flowchart LR A[Marvis / Claude Desktop / Cursor] -->|stdio| B["npx -y jenkins-mcp-server"] B -->|"JENKINS_URL / JENKINS_USERNAME / JENKINS_API_TOKEN"| C[Jenkins REST API]

5.2 生成 API Token¶

⚠️Token 安全（先读）
Token 仅在生成瞬间完整展示，之后无法再次查看。请立即保存到本地凭据管理器，切勿提交到 Git 仓库、粘贴到聊天群或写入公开文档。本文示例一律使用占位符 <your-api-token>。

步骤：

  1. 登录 Jenkins，进入个人主页 https://<jenkins>/user/<username>/security
    • 📝版本差异
      Jenkins 2.541.3 中 /me/configure 与 Account 页均无 API Token 区域，需走 Security 页。低版本可能位于 /me/configure，请按实际页面查找。
  2. 找到 API Token 区域 → 点击 Add new token
  3. 名称填入 marvis-mcp（本次实际使用名称）→ 点击 Generate
  4. 复制生成的 Token 值（本次为 32 位十六进制字符串，非旧版 11 位格式）
  5. 无需额外 Save，Token 即时加入 “Current token(s)” 列表

6.4 健康检查指标解读¶

指标 来源 说明
queueLength getStatus 等待中的构建数，长期 >0 表示资源紧张

7. MCP 工具逐个详解（14 个）¶

🔥参数速记
任务名用 jobFullName（完整路径）；构建号用 buildNumber（缺省默认最近一次构建）；所有参数以工具 description 为准。

7.1 getStatus —— 实例状态与健康度¶

  • 参数：无
  • 返回结构：
  • 典型调用：getStatus
  • 对应 REST API：GET /computer/api/json
  • 用途：巡检节点健康、确认执行器容量

7.2 whoAmI —— 当前认证用户¶

  • 参数：无
  • 返回结构：当前用户信息（用户名、ID 等）
  • 典型调用：whoAmI
  • 对应 REST API：GET /whoAmI/api/json
  • 用途：确认 MCP 使用的身份与权限上下文

7.3 getJobs —— 分页列出任务¶

  • 参数：
    参数 类型 必填 说明
    parentFullName string 否 父文件夹完整路径
    skip integer 否 跳过条数，默认 0
    limit integer 否 最大返回条数，默认 10，上限 10
  • 返回结构：
  • 典型调用：getJobs(limit=10)；翻页 getJobs(skip=10, limit=10)
  • 对应 REST API：GET /api/json?tree=jobs[name,url,color,buildable]
  • 用途：遍历全部 64 个任务、统计任务类型

7.4 getJob —— 单个任务详情¶

  • 参数：jobFullName（string，必填）
  • 返回结构：Job 完整 JSON，含 description、buildable、color、builds 列表、lastBuild、lastSuccessfulBuild 等
  • 典型调用：getJob(jobFullName="NightlyBuild-Sa525m-LE3.0-YP4.0")
  • 对应 REST API：GET /job/<JOB>/api/json
  • 用途：查看任务配置概要、最近构建、启用状态

7.5 getBuild —— 构建信息¶

  • 参数：
    参数 类型 必填 说明
    jobFullName string 是 任务完整路径
    buildNumber integer 否 构建号，缺省为最近一次
  • 返回结构：Build 完整 JSON（number、result、timestamp、duration、building、url、artifacts 等）
  • 典型调用：getBuild(jobFullName="Checksec-Module")；getBuild(jobFullName="Checksec-Module", buildNumber=123)
  • 对应 REST API：GET /job/<JOB>/<N>/api/json
  • 用途：查最近构建结果、耗时、产物列表

7.6 listBuildArtifacts —— 列出构建产物¶

  • 参数：jobFullName（必填）、buildNumber（可选，缺省最近）
  • 返回结构：artifact 列表（fileName、relativePath、size 等）
  • 典型调用：listBuildArtifacts(jobFullName="Compilation-Module")
  • 对应 REST API：GET /job/<JOB>/<N>/api/json?tree=artifacts[*]
  • 用途：确认构建输出了哪些文件（日志、镜像、报告）

7.7 readBuildArtifact —— 读取构建产物内容¶

  • 参数：
    参数 类型 必填 说明
    jobFullName string 是 任务完整路径
    artifactPath string 是 产物相对路径，如 target/app.jar、reports/test.xml
    buildNumber integer 否 构建号，缺省最近
    format enum 否 text（默认）/ base64（二进制文件用）
  • 典型调用：
    • 读文本：readBuildArtifact(jobFullName="Compilation-Module", artifactPath="logs/build.log")
    • 读二进制：readBuildArtifact(jobFullName="Compilation-Module", artifactPath="output/app.bin", format="base64")
  • 对应 REST API：GET /job/<JOB>/<N>/artifact/<PATH>
  • 用途：直接读取构建日志、测试报告内容，无需下载到本地

7.8 triggerBuild —— 触发构建¶

  • 参数：
    参数 类型 必填 说明
    jobFullName string 是 任务完整路径
    parameters object 是 构建参数（含文件路径等），无参数任务传 {}
  • 典型调用：triggerBuild(jobFullName="Manifest-Review", parameters={})
  • 对应 REST API：POST /job/<JOB>/build 或 POST /job/<JOB>/buildWithParameters
  • 用途：按需触发流水线

7.9 scheduleBuild —— 定时触发构建¶

  • 参数：
    参数 类型 必填 说明
    jobFullName string 是 任务完整路径
    scheduleTime string 是 自然语言时间，如 in 5 minutes、at 3:30 PM、2024-12-20 15:30
    parameters object 是 构建参数
    description string 否 定时构建的描述
  • 典型调用：scheduleBuild(jobFullName="NightlyBuild-Sa525m-LE3.0-YP4.0", scheduleTime="in 5 minutes", parameters={})
  • 对应 REST API：通过 Jenkins 队列 / 定时器机制
  • 用途：延迟触发、预约构建

7.10 stopBuild —— 停止构建¶

  • 参数：jobFullName（必填）、buildNumber（可选，缺省最近）
  • 典型调用：stopBuild(jobFullName="NightlyBuild-Sa525m-LE3.0-YP4.0", buildNumber=456)
  • 对应 REST API：POST /job/<JOB>/<N>/stop
  • 用途：中止卡死 / 误触发的构建

7.11 cancelQueuedBuild —— 取消排队构建¶

  • 参数：
    参数 类型 必填 说明
    jobFullName string 是 任务完整路径
    queueId integer 否 队列项 ID；不传则取消该任务全部排队项
  • 典型调用：cancelQueuedBuild(jobFullName="NightlyBuild-xxx", queueId=789)
  • 对应 REST API：POST /queue/cancelItem?id=<queueId>
  • 用途：撤回还在排队的构建请求

7.12 getQueueInfo —— 队列信息¶

  • 参数：jobFullName（string，可选；不传返回全部队列项）
  • 返回结构：排队项列表（id、task、why、blocked 等）
  • 典型调用：getQueueInfo()；getQueueInfo(jobFullName="NightlyBuild-xxx")
  • 对应 REST API：GET /queue/api/json
  • 用途：查看哪些构建在等待执行器

7.13 getQueueItem —— 查询队列项状态¶

  • 参数：queueId（integer，必填；来自 triggerBuild 返回）
  • 返回结构：队列项是否已转为构建（executable 字段）、排队原因
  • 典型调用：getQueueItem(queueId=789)
  • 对应 REST API：GET /queue/item/<queueId>/api/json
  • 用途：触发后轮询是否已进入执行

7.14 updateBuild —— 修改构建名称 / 描述¶

  • 参数：
    参数 类型 必填 说明

    description string 否 新的描述
  • 典型调用：updateBuild(jobFullName="Manifest-Review", buildNumber=10, displayName="review-20261023", description="手动标注")
  • 对应 REST API：POST /job/<JOB>/<N>/description 等

9.2 分场景详解¶

场景一：端点 404

处理：走 npx 桥接方案；或申请安装 MCP Server 插件。

场景二：401 Unauthorized

  • 检查 Token 是否与用户名匹配（Token 绑定生成它的用户）
  • 检查 Token 是否复制完整（32 位十六进制）
  • 重新在 https://<jenkins>/user/<username>/security 生成

场景三：403 Forbidden

  • 用 Web 登录验证该账号是否能在页面操作目标 Job
  • 若页面可以而 MCP 不行，检查使用的用户名是否正确

场景四：npx 进程反复退出

  • 手动前台运行看报错输出
  • 检查 env 变量名是否与文档一致（JENKINS_URL / JENKINS_USERNAME / JENKINS_API_TOKEN）
🔥万能调试法
先用 curl 确认 Token 可用（见 ），再排查客户端配置，可以快速二分定位问题。

10. 安全注意事项¶

⚠️最高优先级
以下安全要求适用于所有接入 Jenkins MCP 的环境。
  1. Token 即密码：JENKINS_API_TOKEN 的权限与账号相同，泄露等于账号泄露
  2. 仅生成时可见：Jenkins 不会再次展示 Token，丢失只能删除重建
  3. 禁止入库 / 入文档：Token 不得提交到 Git、写入共享文档、粘贴到聊天
  4. 最小权限：如需触发 / 停止构建，请使用专用低权限账号，而非管理员账号
  5. 定时轮换：建议每季度或人员变动时轮换 Token；误泄露立即删除重建
  6. 网络最小暴露：npx 桥接不新增 Jenkins 网络暴露面；插件方案务必开启端点鉴权
  7. 本机安全：客户端配置文件含明文 Token，注意文件权限与设备安全
📋Token 泄露应急流程
  1. 登录 https://<jenkins>/user/<username>/security
  2. 在 Current token(s) 中删除泄露的 Token
  3. 重新生成新 Token（名称可继续用 marvis-mcp）
  4. 更新所有客户端配置并重启
  5. 排查泄露途径（截图 / 聊天 / 仓库历史），防再次发生
