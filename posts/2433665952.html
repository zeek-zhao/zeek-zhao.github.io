04-安全上下文

发表于2026-10-24|selinux
|浏览量:

[!info] 本节目标
掌握安全上下文的结构、查看与配置方法。

1. 安全上下文结构

安全上下文由四个字段组成：用户（user）、角色（role）、类型（type）与级别（MLS 范围）。例如 unconfined_u:object_r:etc_t:s0 表示用户、角色、类型与级别，其中类型字段是 TE 规则的核心。

2. 查看上下文

使用 ls -Z 查看文件上下文，ps -Z 查看进程上下文，id -Z 查看当前 shell 上下文。context 显示为 user:role:type:level 形式，便于快速识别对象归属域。

3. 用户字段

SELinux 用户映射系统用户，如 unconfined_u、system_u、user_u。用户与角色、域关联，控制登录用户的初始上下文与可用角色。用户映射通过 semanage user 管理。

4. 角色字段

角色定义用户可进入的域集合，常用角色有 system_r（系统进程）、object_r（客体专用）、unconfined_r（非受限用户）。角色机制支持 RBAC 模型，细化权限边界。

5. 类型字段

类型是 TE 模型的核心：进程类型称为域（domain），文件类型称为对象类型。规则描述域可对类型执行的操作。类型命名常带 _t 后缀，如 httpd_t、var_log_t。

6. 级别字段

级别用于 MLS/MCS 模型：s0 为默认单层，敏感度与范畴组合表达分类分级。容器场景常用 MCS 的 s0:c 系列标签隔离容器，详细见 MLS 篇。

7. 上下文管理

文件上下文由策略中的文件上下文规则定义，chcon 可临时修改，restorecon 恢复策略默认值。生产环境推荐使用 semanage fcontext 定义持久规则，避免手工标签漂移。

7. 上下文查看与验证

使用 ls -Z、ps -eZ、id -Z 分别查看文件、进程与当前用户上下文，验证配置是否生效。上下文不符时优先检查 fcontext 规则与 restorecon 应用情况。编写脚本批量比对预期上下文可自动化巡检，及时发现标签漂移。上下文是策略判断的核心输入，养成先查上下文的排障习惯能大幅缩短定位时间。
