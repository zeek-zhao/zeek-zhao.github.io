devops-jenkins-开发指南

1. Jenkins 简介

Jenkins 是一个开源的自动化服务器，可用于自动化各种任务，如构建、测试和部署软件。Jenkins 提供了数百个插件，支持构建、部署和自动化几乎任何项目。

1.2 Jenkins 优势

  • 丰富的插件生态系统：超过1500个插件，可轻松集成各种工具
  • 分布式构建能力：可以将构建和测试负载分配给多个计算节点
  • 流水线即代码：使用声明式或脚本式 Jenkinsfile 定义部署流水线
  • 扩展性：可以编写自定义插件和脚本来扩展功能
  • 自动化触发：支持各种构建触发方式
  • 社区支持：活跃的社区提供资源和支持

2.1 主节点职责

  • 处理HTTP请求并提供Web界面
  • 管理配置和授权
  • 调度构建任务到代理节点
  • 监控代理节点并接收构建结果
  • 存储和提供构建历史和制品

2.2 代理节点职责

  • 执行主节点分配的构建任务
  • 每个代理可以有多个执行器（并发执行的任务数量）
  • 可以标记特定环境或工具的可用性（标签）

4. Jenkins Pipeline

4.1 Pipeline 概述

Pipeline 是一套插件，支持实现和集成持续交付流水线到 Jenkins。Pipeline 提供了一组可扩展的工具，用于通过 Pipeline DSL 将简单到复杂的交付流水线建模为”代码”。

4.4 Pipeline 语法元素

4.4.1 Sections（章节）

Pipeline 中的主要组成部分：

  • agent - 定义执行位置
  • stages - 包含一个或多个 stage 指令
  • steps - 在 stage 内定义要执行的步骤
  • post - 定义 Pipeline 或 stage 执行完成后的处理

4.4.2 Directives（指令）

  • environment - 定义环境变量
  • options - 定义 Pipeline 或 stage 特定的配置
  • parameters - 定义参数化构建的参数
  • triggers - 定义自动触发的方式
  • tools - 配置自动安装和添加到 PATH 的工具
  • when - 控制 stage 是否应该执行

Git Webhook 配置

  1. 在 Jenkins 中：

    • 进入项目配置
    • 在构建触发器中选择”GitHub hook trigger for GITScm polling”或”GitLab webhook trigger”

  2. 在 GitHub/GitLab 中：

    • 进入仓库设置 > Webhooks
    • 添加 webhook：http://jenkins-server/github-webhook/ 或 http://jenkins-server/gitlab-webhook/
    • 选择事件类型（通常是 push 事件和 pull request 事件）

    • 使用模板化的 Jenkinsfile

  2. 文档化：

    • 为每个 Pipeline 添加注释
    • 创建 README 文档
    • 维护共享库的使用指南

  3. 监控与日志：

    • 实施构建监控

    • 设置关键指标告警

  4. 灾难恢复：

    • 定期备份 Jenkins 主目录
