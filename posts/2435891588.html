任务与看板管理

[!abstract] 一句话
Tasks 负责聚合查询、Kanban 负责可视化推进、QuickAdd 负责快速捕获——三个插件各司其职又互相咬合，让你在纯 Markdown 笔记库里跑出一套 GTD 级任务系统。

Tasks：让全库任务可查询

Tasks 插件的核心思想是：任务可以写在任何笔记里（不必集中在一处），然后用查询块把它们聚合起来。任务就是普通的 Markdown 复选框 - [ ]，配合 emoji 属性标记日期、优先级和重复规则：

常用属性：📅 截止日期（due）、🛫 开始日期（start）、✅ 完成日期（completion）、⏫/🔼/🔽 优先级、🔁 重复规则。完成一个带重复规则的任务时，Tasks 会自动标记完成并生成下一期的任务。

[!tip]
建议建一篇”任务中心”笔记，用多个查询块分区：今天待办 / 本周计划 / 按项目分组 / 逾期清单，每次打开这一篇就能纵览全局。大型知识库记得加 limit 并定期归档完成任务，否则查询会变慢。

Tasks 与 09-Dataview数据查询 也能配合：Dataview 的 TASK FROM ... WHERE !completed 语法可以按文件夹/标签范围查询任务，适合做更自定义的统计报表。

Kanban：看得见的进度条

Kanban 插件把一篇 Markdown 文件渲染成看板。创建方式：命令面板执行 “Kanban: Create new board”，或在文件头部写入：

看板由泳道（列，如”待办/进行中/已完成”）和卡片组成。卡片本质是 Markdown 列表项，天然支持 笔记链接、#标签、日期（点击日历图标选择，支持 @today+3days 相对日期）和子任务清单。拖拽卡片跨列即更新状态，一切改动都实时写回 Markdown 文件——这意味着看板数据可以正常同步、版本管理和被其他插件读取。

典型用法：

  • 内容创作流程：构思 → 草稿 → 编辑 → 已发布，卡片里链接文章笔记
  • 个人 GTD：收集箱 → 下一步行动 → 等待中 → 已完成，配合情境标签
  • 项目管理：每个项目一块独立看板，避免单块过载

[!warning]
单个泳道卡片过多会拖慢渲染。开启”归档已完成卡片”，或把大型看板按主题拆分。看板与纯文本视图可随时通过右上角按钮互切，不必担心被”锁死”在可视化界面里。

QuickAdd：一秒捕获，零摩擦录入

有了查询和看板，最后一块拼图是”往里放东西够不够快”。QuickAdd 提供四种动作类型：

  1. 模板（Template）：选模板 + 指定输出文件夹和命名格式，一键生成笔记
  2. 捕获（Capture）：把一段文字追加到指定笔记的指定位置。例如配置”文件：Daily/{{DATE:YYYY-MM-DD}}.md，格式：- [ ] {{VALUE:任务}} #task，位置：标题’## 待办事项’下方”，之后任何灵感都能一键写进今日日记
  3. 宏（Macro）：把模板、捕获、Obsidian 命令、用户脚本串成一条流水线，比如”打开今日日记 → 插入日报模板 → 打开任务视图”一个宏搞定
  4. 多选（Multi）：把以上动作组织成嵌套菜单

QuickAdd 模板变量支持 {{VALUE:变量名}}（运行时询问）、{{DATE:YYYY-MM-DD}}（日期）、{{NAME}}（文件名），也支持完整的 Moment.js 格式。进阶用户可以在宏中挂 JavaScript 用户脚本，调用 quickAddApi.inputPrompt、quickAddApi.suggester 甚至完整 Obsidian API：

三件套如何咬合成一套系统

一个推荐的工作流闭环：

  1. 收集：手机或电脑上随时用 QuickAdd 捕获命令把任务追加进收集箱笔记（自动带 #task 和日期）
  2. 组织：Tasks 查询块把收集箱的未完成任务按项目/优先级聚合展示；需要推进的重点项目放进 Kanban 看板
  3. 执行：每天从任务中心的”今日待办”挑任务，完成的打勾（重复任务自动续期），看板上拖卡片反映阶段变化
  4. 回顾：周记里用 Dataview 统计本周完成情况，逾期任务由 before today 查询自动曝光

[!note] 2026 更新
Obsidian 1.9+ 的官方 Bases 视图也可以做”看板/表格”式的任务面板（属性驱动、零代码），如果你的任务字段已规范写入属性，可以尝试用 Bases 替代部分 Kanban 场景；但 Tasks 的日期语义查询（today/before/this week）和重复任务自动化目前仍无可替代。2026-03 起 Obsidian 官方社区目录上线了插件自动审查机制，这三个插件都是长期活跃维护的高口碑项目，可放心纳入核心工具链。

性能与一致性建议

  • 任务分散在全库是 Tasks 的设计初衷，但查询要收敛：用 path includes、标签过滤限定范围
  • 统一任务语法：建一份自己的”任务规范笔记”，约定日期 emoji、优先级、项目标签的写法，避免查询漏网
  • QuickAdd 配置存在 .obsidian/plugins/quickadd/data.json，多设备同步时记得包含该文件
  • 定期归档已完成任务和旧看板卡片，保持索引轻盈

任务管理的本质不是工具堆叠，而是”捕获零摩擦、组织有结构、回顾有闭环”。三件套恰好补齐了这三个环节，剩下的就是让系统长在你自己的日常节奏里。
