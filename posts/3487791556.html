Make与CMake

[!info] 本页概览
工程规模变大后，手工敲编译命令不可维护。Make 通过 Makefile 描述依赖关系与构建规则；CMake 是跨平台更现代的构建系统生成器。本文讲解两者核心用法与工程组织方式。

核心概念

  • Make：根据文件时间戳判断哪些目标需要重新编译，按规则执行命令。规则格式：目标: 依赖 + Tab 缩进的命令。
  • CMake：不直接编译，而是根据 CMakeLists.txt 生成 Makefile / Ninja / Visual Studio 工程，再由底层工具构建。跨平台、生态丰富（FetchContent、CTest、CPack）。

常见坑

  1. Makefile 中命令必须 Tab 缩进：用空格缩进会报 missing separator 错误。
  2. 忘写头文件依赖：只改了头文件，Make 不知道需要重编。CMake 会自动扫描头文件依赖，Make 手写规则易漏。
  3. CMake 缓存陈旧：改了 CMakeLists.txt 里的开关，旧 build 目录缓存未更新。删掉 build 目录重建。
  4. 相对路径与当前目录：CMake 中源文件路径相对 CMAKE_CURRENT_SOURCE_DIR，别用 shell 当前目录假设。
  5. -j 并行构建资源过载：-j4 按核数合理设置，过大可能 OOM。

最佳实践

  • 新项目直接用 CMake（配 Ninja 生成器），跨平台且 IDE 支持好。
  • CMake 设 CMAKE_EXPORT_COMPILE_COMMANDS 导出 compile_commands.json 供 IDE/工具使用。
  • 构建类型明确区分：Debug（-g -O0）与 Release（-O3）。
  • 单元测试用 CTest 集成，复杂依赖用 FetchContent 或包管理器（vcpkg/conan）。
