权限方案

[!abstract] 谁能做什么
Jira 用 项目角色 + 权限方案 控制访问；通知方案控制”谁收到什么邮件”。

1. 项目角色（Project Role）

⚙ → System → Project roles：

[!note] 角色与组
角色绑定用户/组：Developers → 组 dev-pay。权限方案引用角色而非组，换人只需改组。

2. 常用权限

⚙ → System → Permission Schemes → Edit：

权限 含义 典型授予
Browse Projects 查看项目 Users
Create Issues 创建问题 Users
Edit Issues 编辑问题 Developers
Assign Issues 指派 Developers
Resolve Issues 解决 Developers
Close Issues 关闭 Developers
Delete Issues 删除 Admins
Administer Projects 项目配置 Administrators
Schedule Issues 排期 Project leads

3. 方案关联项目

4. 通知方案（Notification Scheme）

[!tip] 防邮件轰炸
通知按角色/关注者精确发送；评论通知可只给参与人（Participants），避免全项目成员收到。

5. 全局权限

⚙ → System → Global permissions：

权限 默认
Jira Administrators 管理员组
Jira Users（可使用 Jira） 登录组
Browse Users / Groups 内部

6. 安全实践

  • 管理员账号不用业务邮箱、开启 2FA；
  • 权限方案最小化：业务项目不要给删除/管理权限；
  • 定期审计：导出项目权限矩阵，清理离职账号；
  • 敏感字段（薪资等）用字段权限（Field permissions）限制。

[!warning] 常见误区

  • 权限配在”组”上但组和角色混用导致混乱——统一用角色；
  • 匿名可浏览 = 数据泄露，生产务必关闭 Anonymous 权限。
