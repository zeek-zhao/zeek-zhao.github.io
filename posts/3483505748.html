最佳实践

前面十几篇把各个点都讲过了，这篇接着 15-常见问题排错 往下，把它们收拢成一套能直接照搬的做法。核心就是几件事：仓库先规划再创建、制品按生命周期治理、安全基线卡住、运维排成固定节奏。照这几条走，基本不会出乱子。

1. 仓库先规划命名和拓扑再创建¶

  • 客户端只配 group URL，变更后端不感知；
  • 仓库格式一经创建不可改，命名先规划。

我一般在建仓库前先花十分钟把命名和拓扑定死，因为格式创建后改不了，前期偷懒后面就是一堆迁不掉的烂名字。

2. 不同类型制品走不同生命周期¶

阶段 规范
Release 不可覆盖（Disable redeploy），版本号语义化
Snapshot 可覆盖、可短留（30-60 天清理）
代理缓存 60-90 天清理，保持热度
私有历史 不按时间清（合规/回滚）

配套：Cleanup Policy + 定时任务 + Compact（10-Cleanup与任务调度）。

3. 安全基线照最小权限来配¶

☐ HTTPS（TLS 1.2+）全链路
☐ 匿名只读或关闭；匿名永无写权限
☐ 内容选择器限制私有路径
☐ deployer 角色最小权限（按仓库授权）
☐ LDAP/SSO 统一账号，定期审计
☐ API Key 代替密码，Key 定期轮换
☐ 管理端口仅内网

📝供应链安全
  • 代理仓库指向可信源（官方/镜像）；
  • 敏感仓库禁止匿名；
  • 大制品下载做校验（checksum 集成）。

4. 发布交给流水线别手动传¶

5. 运维排成日周月季的固定节奏¶

每日 02:00 Cleanup + Compact
每周 备份验证（恢复演练月月做）
每周 健康检查（状态端点/磁盘/日志）
每月 权限审计 + 角色清理
每季 容量评估（Blob 增长/配额）

6. 文档和团队规范要跟上¶

  • 维护仓库清单（名称/用途/URL/负责人）；
  • 客户端配置模板（settings.xml/.npmrc/daemon.json）进团队 wiki；
  • 变更走审批：新建仓库/清理策略/开放匿名需评审。

7. 这几件事再顺手也别做¶

❌ 手动删 Blob 目录文件
❌ 多个写实例共享 Blob
❌ 匿名开写权限
❌ release 库允许随意覆盖
❌ 清理策略一次性开全（先小范围验证）

🔥落地清单
  • 仓库拓扑文档化；
  • 安全基线对照检查；
  • 备份+恢复演练；
  • 监控告警上线；
  • CI 发布流水线走 Nexus。
📝关联阅读
工具链完整闭环：Jenkins（构建）+ Gerrit（代码评审）+ Jira（项目管理）+ Nexus（制品）。

先把命名和拓扑定下来，再按生命周期和安全基线逐项对照，最后把运维节奏固化进日历，这套实践就算落地了。
