38-发布与版本管理

发表于2026-10-24|Zephyr
|浏览量:

[!info] 本节目标
掌握 Zephyr 版本与发布管理。

1. 发布概述

Zephyr 采用固定周期发布，长期支持版本管理。发布节奏与维护策略明确，版本兼容性规范。版本管理支撑工程稳定。

2. 版本策略

主版本与次版本演进，LTS 长期支持。发布周期与特性规划，兼容性保证。版本策略指导升级。

3. Git 工作流

分支管理与提交规范，合入流程。west manifest 版本锁定，依赖管理。Git 工作流协作开发。

4. 应用版本管理

应用版本标识与发布配置，固件版本管理。版本号与构建关联，更新兼容。应用版本支撑 OTA。

5. 兼容性

API 兼容与迁移指南，废弃特性管理。升级路径规划，编译警告处理。兼容性保障升级平滑。

6. 发布流程

构建与测试验证，发布说明编写。标签与归档管理，安全公告处理。发布流程质量保障。

7. 实践建议

跟踪版本发布节奏，升级评估兼容。manifest 锁定版本，测试验证升级。文档记录版本决策。

8. 常见问题

版本管理问题集中在升级评估与依赖锁定。Zephyr 每半年发布稳定版，LTS 版本适合长期产品，升级前要阅读发布说明与迁移指南，评估 API 变更影响。west manifest 锁定各仓库 revision，不锁版本会导致构建不一致，团队协作务必提交 manifest 更新。应用自身版本号与固件版本管理要规范，与 OTA 版本检查配合。废弃 API 的编译警告是迁移信号，不要长期忽略。维护多个产品线时，用 manifest 分支区分稳定与开发基线。

9. 小结

版本管理要同时关注上游节奏与自身工程：按 LTS 与稳定版策略规划升级，用 west manifest 锁定依赖版本，规范应用版本号并与 OTA 联动。清晰的版本策略能降低维护成本，支撑产品长期演进。
