ROS2 与 ROS1 桥接迁移

[!info] 本节目标
理解 ROS1 与 ROS2 差异，掌握 ros1_bridge 桥接与渐进式迁移策略。

1. ROS1 vs ROS2

维度 ROS1 ROS2
架构 Master 中心化 DDS 去中心化
通信 TCPROS/UDPROS DDS
语言 C++03/Python2 C++17/Python3
构建 catkin colcon/ament
参数 parameter server 节点内参数
时间 rospy/roscpp Time rclcpp/rclpy Time
通信质量 无内置 QoS 完整 QoS

[!note] 迁移趋势
官方已停止 ROS1 主流维护（Noetic 维护至 2025），新项目建议直接用 ROS2。

2. 桥接工具

工具 说明
ros1_bridge 官方桥，动态/静态桥接话题服务
roscpp/rosbag 工具 单侧转换
ros1_to_ros2 工具/脚本辅助迁移
自研桥 按需定制

[!warning] 双环境
ros1_bridge 需在同一终端同时 source ROS1 与 ROS2 环境，且仅支持同架构。

3. 动态桥 vs 静态桥

方式 特点
动态桥 自动发现两端话题映射，通用但延迟高
静态桥 配置 YAML 精确映射，性能好、可控

[!tip] 性能
静态桥性能明显优于动态桥；大流量/控制指令推荐静态桥。

4. 迁移策略

阶段 任务 验证
盘点 依赖与接口清单 迁移矩阵
接口 重写 msg/srv/action 编译
工具 CLI/launch/配置 手动测试
节点 逐包迁移 桥接对比
收尾 移除桥 全链路测试

[!note] 迁移顺序
先迁无外部依赖的工具与消息，再迁算法节点；保留桥接期间新老系统并行验证。

5. 代码迁移要点

ROS1 写法 ROS2 写法
ros::init rclcpp::init
NodeHandle Node 子类
advertise/subscribe create_publisher/subscription
ros::spinOnce rclcpp::spin / Executor
rosparam declare_parameter/get_parameter
rospack ament_package
catkin_make colcon build

[!warning] API 差异
ROS2 无全局参数服务器；时间 API 变化（Time::now() 需节点上下文）；回调生命周期管理不同。

6. 数据迁移

[!tip] 兼容
rosbags 库可在不同 ROS 版本间转换 bag；消息类型差异需手工调整。

7. 常见问题

问题 排查
bridge 不建 双环境未同时 source、消息不兼容
类型转换失败 msg 定义不一致
延迟高 用静态桥、调 QoS
迁移后行为不同 时间/QoS/线程模型差异

[!note] 延伸
消息接口见 13-自定义消息接口；新系统开发参考全套教程；替代方案见 01-ROS2概述与生态。

8. 迁移项目管理

迁移项目建议按”盘点-试点-分批-验证”推进：先盘点存量 ROS1 包的类型、依赖与使用频率，选定低风险模块试点跑通桥接流程，再分批迁移高价值模块，每个批次都做功能回归。迁移期间双栈并行，新功能直接基于 ROS2 开发。团队培训与文档同步推进，统一新老接口约定。迁移完成标志不是代码全部重写，而是 ROS1 依赖清零且功能等效。项目复盘记录迁移成本与经验，供后续套件参考。

[!note] 建议
迁移是渐进过程，不必一步到位；混合运行期桥接配置见本篇，容器化降低环境差异见 31-ROS2与Docker。
