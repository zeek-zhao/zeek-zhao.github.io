指针与内存模型

[!info] 本页概览
Go 有指针但没有指针算术，内存由 GC 自动管理。本文讲解指针用法、逃逸分析、内存布局、GC 工作原理与内存优化思路。

核心概念

Go 指针：*T 类型指向变量地址，& 取地址、* 解引用。Go 禁止指针算术（不能 p+1），保证内存安全。GC（三色标记清除 + 并发）自动回收堆内存。

逃逸分析

逃逸影响：堆分配增加 GC 压力。减少逃逸的手段：

  • 返回结构体值而非指针（小对象）
  • 预分配并复用缓冲区
  • 避免在循环内创建闭包捕获大对象

GC 与内存

  • Go GC 是并发三色标记清除，STW 时间目标毫秒级。
  • 调优：GOGC（默认 100，堆增长到 2 倍时触发 GC）、GOMEMLIMIT（Go 1.19+ 软内存上限）。
  • 监控：runtime.ReadMemStats、pprof heap。

常见坑

  1. 指针指向循环变量：for _, v := range xs { ptrs = append(ptrs, &v) } 在 Go 1.22 前全部指向同一变量，取出的都是最后一个值。1.22+ 已修复，老代码注意。
  2. *T 方法集与接口：只有 *T 实现的方法，T 值不满足接口（见 07-接口）。
  3. 指针拷贝共享状态：两个变量持有同一指针，一处修改处处可见，封装时注意。
  4. 过度使用指针：小对象（int、小结构体）用指针反而增加分配与 GC 压力，值传递更快。
  5. unsafe 滥用：unsafe.Pointer 绕过类型系统是最后手段，慎用。
  6. 忽略 GC 峰值：大对象/高分配率导致 GC 停顿，用 GOMEMLIMIT 与对象池控制。

最佳实践

  • 默认传值，需要修改或大结构体才传指针；只读共享可用指针但注释。
  • 接口存储大对象时考虑指针，避免大值拷贝装箱。
  • 用 go test -race + pprof 发现数据竞争与内存问题。
  • 关注逃逸报告，热路径避免无谓堆分配。
  • 理解 GC 参数：调整 GOGC/GOMEMLIMIT 前先用数据论证。
