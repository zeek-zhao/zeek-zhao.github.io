25-Groovy与Jenkins Pipeline

发表于2026-10-25|groovy
|浏览量:

[!info] 本节目标
Jenkins Pipeline 用 Groovy 编写持续交付流水线，学习基础语法与结构。

1. Pipeline 概述

Jenkins Pipeline 将持续交付流程定义为代码，Jenkinsfile 放在仓库中版本管理。Pipeline 脚本基于 Groovy，利用其动态与 DSL 能力表达构建、测试、部署流程。

Pipeline 作为代码带来可版本化、可审计、可复用的持续交付实践。

2. Jenkinsfile 基础

Jenkinsfile 定义 pipeline 对象，包含 agent、stages、steps 等核心块。agent 指定执行环境，stages 组织阶段，steps 执行具体步骤。

声明式语法结构清晰，适合标准 CI/CD 场景；脚本式语法更灵活，适合复杂编排。

3. 步骤与构建集成

Pipeline 步骤涵盖源码拉取、构建、测试、制品归档、部署通知等。与 Gradle、Maven 集成通过 sh 或工具步骤执行构建命令。

Groovy 生态项目用 gradle build 步骤执行测试与打包，测试报告与制品自动收集。

4. 环境与参数

environment 块定义环境变量，parameters 定义构建参数，credentials 管理敏感凭据。字符串插值规则与 Groovy 一致。

敏感凭据避免在 Groovy 双引号字符串中插值，防止泄露到日志。

5. 高级特性

并行 stage、条件 stage、post 钩子、共享库让流水线工程化。共享库用 Groovy 封装通用逻辑，跨项目复用。

Pipeline 状态持久化支持 Jenkins 重启恢复，理解 CPS 执行模型有助于排查疑难问题。

6. Pipeline 最佳实践

Jenkinsfile 保持声明式优先；阶段划分清晰；错误处理用 catchError 与 post；流水线代码与业务代码同仓库管理。

本地用 Jenkins 测试运行器或 IDE 插件验证语法，减少 CI 试错成本。

7. Pipeline 实战要点

标准发布流水线：检出源码、单元测试、静态扫描、打包、制品归档、部署到测试环境、通知团队，阶段清晰可审计。

凭据统一通过 Jenkins 凭据管理注入环境变量，禁止硬编码与日志输出，保证供应链安全。

流水线失败时 post 钩子发送通知并归档现场日志，快速定位失败阶段，缩短恢复时间。
