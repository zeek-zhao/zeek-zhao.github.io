Git 子模块与子树

本文讲解 Git Submodule 与 Subtree：原理、命令、优缺点、选择建议，配真实示例。

对比

维度 Submodule Subtree
内容存储 指针（gitlink） 直接合入历史
克隆体验 需 –recurse-submodules 无额外步骤
修改提交 在子模块内提交 本仓库提交
回源推送 天然支持 需 subtree push
历史 独立 合并

常见场景

常见坑

  1. 忘记 –init 导致空目录：克隆后 submodule 目录为空，需 update –init。
  2. 子模块卡在旧提交：父仓库指针不会自动前进，需显式更新并提交。
  3. subtree 历史膨胀：–squash 减少历史噪音。
  4. 修改未回源：本地改了子模块不 push 源仓库，他人拿不到。
  5. 滥用子模块：同语言生态优先包管理器。

最佳实践

  • 优先包管理器；子模块/子树用于特殊场景。
  • 子模块固定版本 + 显式升级 + 文档说明。
  • 大规模仓库另见 08-大规模仓库管理。
