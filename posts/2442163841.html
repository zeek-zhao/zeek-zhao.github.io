23-SELinux与Docker

发表于2026-10-24|selinux
|浏览量:

[!info] 本节目标
掌握 Docker 容器运行时的 SELinux 标签与卷权限处理。

1. Docker 与 SELinux

Docker 守护进程在 SELinux 启用系统上自动为容器生成隔离标签，默认使用 svirt 域与 MCS 范畴，实现容器间与容器对宿主资源的强制隔离。

2. 卷标签处理

挂载宿主目录时使用 -v 目录:/数据:Z 让 Docker 自动设置正确标签；:z 为共享标签，供多容器共享。手动 chcon 的标签会在重打标时丢失，不推荐。

3. 权限被拒场景

容器内服务无法读写卷、无法绑定端口或无法连接网络时，常见原因为标签不匹配或端口类型未配置。结合宿主 audit 日志确认具体拒绝规则。

4. 特权与安全

–privileged 会关闭大部分隔离，包括 SELinux 限制，应避免在生产使用。需要特定能力时使用 –cap-add 精确授权，保持受限域保护。

5. 布尔值与规则

涉及容器网络全局放开的布尔值需谨慎开启。更优做法是使用自定义模块为特定容器域授权，保持默认 deny 原则，缩小攻击面。

6. 排障流程

容器问题排查顺序：宿主 audit 日志、容器引擎日志、端口与卷标签检查、布尔值状态。修复后复现场景验证，确保告警消失且功能正常。

7. 常见布尔值

container_connect_any、container_manage_cgroup 等布尔值影响容器能力。默认应保持关闭，仅在有明确业务需求时开启并记录。容器网络需要访问外部服务时优先使用网络策略与白名单。布尔值开启后需重启容器验证，同时检查宿主审计日志确认无异常放行。

8. 安全基线建议

保持引擎默认标签与受限域，限制特权容器数量，卷标签显式管理。监控容器拒绝事件并纳入告警。定期升级引擎与策略包修复安全漏洞。安全基线文档化并定期复核，确保容器环境持续安全。
