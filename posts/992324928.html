Nginx SSL 与 TLS 配置

上一篇 08-URL重写与跳转 里跳转的目标多半是 https，这篇就把 HTTPS 真正配起来。HTTPS 的核心就两件事：证书和私钥的路径配对，再把 80 端口的流量 301 到 443。我一般先把证书链凑齐再谈优化，链不全的话浏览器照样报红，后面 TLS 参数调得再漂亮也白搭。

HTTPS 先配好证书和私钥¶

说明：

  • 证书链（cert）与私钥（key）路径
  • http2 提升并发性能
  • 证书需含完整链（如中间证书）

证书优先用 Certbot 自动签¶

TLS 只留 1.2/1.3 和强套件¶

我的习惯是协议和套件写死白名单，别留 TLSv1.0/1.1 这类老东西被扫描告警：

安全建议：

  • 仅启用 TLSv1.2/TLSv1.3
  • 禁用弱加密（RC4/DES/3DES）
  • 开启会话缓存提升握手性能
  • 证书密钥权限 600

HTTP/2 靠 HTTPS 才能开¶

HTTP/2 收益：

  • 多路复用（单连接并发请求）
  • 头部压缩（HPACK）
  • 服务器推送（谨慎使用）

注意：

  • HTTP/2 需要 HTTPS
  • 旧客户端兼容性（自动降级 HTTP/1.1）

多域名用 SNI 或分开配 server¶

证书统一在 Nginx 终结¶

价值：

  • 证书统一管理在 Nginx
  • 后端无需处理 TLS
  • 内网流量非加密（信任域内）

证书到期必须有人盯¶

证书管理：

  • Let’s Encrypt：自动续期（90 天）
  • 企业证书：到期前人工续期
  • 监控证书到期（脚本/监控平台）

续期脚本示例（cron）：
0 0 * * * certbot renew –quiet –deploy-hook “nginx -s reload”

这几个坑我踩过¶

  1. 证书链不完整：浏览器报链错误，合并中间证书。
  2. 私钥权限：权限过宽，Nginx 拒绝读取。
  3. TLS 版本过低：TLSv1.0/1.1 被安全扫描告警。
  4. 证书过期：未续期导致 HTTPS 故障。
  5. 混合内容：HTTPS 页面引 HTTP 资源，浏览器拦截。

自动续期加到期告警¶

生产环境我基本都交给 Certbot 自动续期，再挂一条到期告警兜底，别等用户报打不开才想起证书这事。

  • 生产用 Let’s Encrypt 自动续期。
  • TLS 1.2+ 与强加密套件。
  • 开启 HTTP/2 与会话缓存。
  • 证书到期监控告警。
  • 结合 14-高可用与集群 多机证书同步。
