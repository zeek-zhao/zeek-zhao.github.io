分支模型¶

Git 流行的分支管理模型：

Git Flow

适合有计划发布周期的大型项目：

  • master: 存放稳定发布版本
  • develop: 开发分支，日常集成
  • feature/*: 功能分支，从 develop 分支创建，完成后合并回 develop
  • release/*: 发布分支，准备发布版本
  • hotfix/*: 热修复分支，从 master 创建，修复后合并到 master 和 develop

GitHub Flow

简化的流程，适合持续部署：

  • main: 主分支，随时可发布
  • feature/*: 功能分支，完成后通过 PR 合并到 main

暂存区让你精确控制每次提交包含什么¶

Git 的暂存区（Stage）是 Git 独特的工作机制之一，允许开发者在提交前精确控制要包含的更改。

部分暂存文件¶

这会将文件的更改分割成多个”区块”（hunks），并询问你要如何处理每个区块：

  • y: 暂存该区块
  • n: 不暂存该区块
  • s: 拆分区块
  • e: 手动编辑区块
  • q: 退出

仓库太大就从查找、清理、预防三步治理¶

随着项目的发展，Git仓库可能会变得非常大，尤其是在不小心提交了大型二进制文件后。这可能导致克隆和操作变慢，甚至在某些平台(如GitHub)上超出仓库大小限制。

仓库大小限制¶

不同的Git托管平台对仓库大小有不同的限制：

  • GitHub: 单个仓库限制为100GB，单个文件限制为100MB
  • GitLab: 免费版单个仓库无硬性限制，但推荐不超过10GB
  • Gitee: 免费版单个仓库限制为500MB
