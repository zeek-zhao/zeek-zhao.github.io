预处理器与宏

[!info] 本页概览
预处理器在编译前对源码做文本变换：处理 #include、#define 宏、条件编译与 #pragma。本文讲解常用指令、宏的陷阱与最佳实践。

核心概念

预处理器（preprocessor）是编译的第一阶段，它以 # 开头的指令对源码做纯文本替换，不感知 C/C++ 语法。常见用途：包含头文件、定义常量/宏、条件编译跨平台、防止重复包含。

宏的经典陷阱

宏的其他问题：

  • 参数副作用被多次求值：SQUARE(i++) 中 i 被求值两次，行为未定义。
  • 宏没有类型检查，容易把不同类型混入。
  • 宏展开污染命名空间。

常用预定义宏

宏 含义
__FILE__ 当前文件名
__LINE__ 当前行号
__DATE__ / __TIME__ 编译日期/时间
__cplusplus C++ 编译器中为版本号
_WIN32 Windows 平台定义

常见坑

  1. 宏参数不加括号：#define SQUARE(x) x*x 在 SQUARE(1+2) 时结果错误，参数与整体都要加括号。
  2. 宏与分号：#define PRINT(x) printf("%d", x) 在调用处多写分号或在 if 后调用时可能破坏语法。
  3. #define 替换函数名：如 #define max(a,b) ... 与 std::max 冲突，导致莫名编译错误。
  4. #include 循环包含：A 包含 B、B 包含 A，若缺守卫会无限递归，编译报错。

最佳实践

  • 常量用 constexpr（C++）或枚举替代宏；函数用内联函数（inline）或模板替代宏。
  • 必须用宏的场景：头文件守卫、条件编译（平台差异）、__FILE__/__LINE__ 的日志封装。
  • 宏名全部大写，避免与变量冲突；宏展开式整体用括号包裹。
