04-动态类型与类型系统

发表于2026-10-25|groovy
|浏览量:

[!info] 本节目标
掌握 Groovy 的类型模型，理解动态语言的类型行为。

1. 动态类型

Groovy 变量在运行时持有真实类型，def 声明只是不指定类型而非无类型。方法调用基于运行时类型动态分发，这就是多态的基础。动态类型让代码灵活，但类型错误延迟到运行时才暴露。

理解动态类型的关键是区分声明期与运行期：声明期不做检查，运行期对象方法必须真实存在，否则抛出 MissingMethodException。

2. 类型推断

Groovy 3+ 引入静态类型推断，局部变量可以通过显式类型声明获得编译期检查。配合 @TypeChecked 注解，可以按需开启静态检查，兼顾动态灵活与静态安全。

@CompileStatic 注解让代码在编译期完成类型绑定，显著提升性能，适合对性能敏感的核心逻辑。

3. 鸭子类型

Groovy 遵循鸭子类型哲学：对象只要实现所需方法就能被使用，无需实现特定接口。这让测试替身、动态代理与适配器模式实现极其简单。

鸭子类型与接口互为补充：接口用于契约约束，鸭子类型用于快速组合。大型项目中两者结合使用。

4. 类型转换

asType 方法实现显式类型转换，如对象 as String、列表 as Set。Groovy 在赋值与参数传递时自动尝试类型转换，数字到字符串、字符串到数字等常见转换自动完成。

集合类型转换常用：List 转 Set 去重，Map 转自定义对象，数组转 List 等。转换失败会抛出 ClassCastException。

5. 泛型与擦除

Groovy 支持泛型语法，但运行时擦除与 Java 一致。动态调用时泛型边界由运行时对象实际类型决定，@CompileStatic 下泛型检查更严格。

与 Java 集合互操作时注意泛型擦除问题，必要时显式转换。

6. 类型系统实践建议

脚本与测试代码优先利用动态特性提升效率；库与框架 API 建议提供显式类型或使用 @TypeChecked 保护边界；性能关键路径使用 @CompileStatic。

团队约定：动态代码配足测试，确保运行时类型行为符合预期；IDE 的类型提示能帮助发现大部分笔误。
