📅 2026-10-22· 更新于 2026-10-24 ✍ zeek.zhao #GitLab#CI/CD#Pipeline

CI/CD Pipeline 配置

ℹ️本篇目标
掌握 .gitlab-ci.yml 的核心语法：Pipeline、Stage、Job、关键字与常见模式，从零写出可运行的流水线。

1. Pipeline 基本概念¶

  • Pipeline：一次完整流水线，由多个 Stage（阶段）组成。
  • Stage：阶段的并行/串行划分，同阶段 Job 默认并行执行。
  • Job：最小执行单元，运行在 Runner 上。

默认 Stage 顺序：build -> test -> deploy，可通过 stages 自定义。

2. 最小示例¶

🔥关键字最小集
先掌握 stages、stage、script、only/except、rules、artifacts、cache、variables 即可覆盖 80% 场景。

3. 常用关键字详解¶

  • image：Job 运行镜像（Docker executor 下生效）。
  • artifacts：Job 产物，可传递到后续 Job 或下载。
  • cache：跨 Job 复用依赖目录，加速构建。
  • rules：现代推荐的条件控制（替代 only/except）：

4. 内置变量速查¶

变量 含义
CI_COMMIT_SHA / CI_COMMIT_SHORT_SHA 提交完整/短 SHA
CI_COMMIT_BRANCH 当前分支名
CI_PIPELINE_SOURCE 触发来源（push/merge_request_event/schedule/web）
CI_REGISTRY_IMAGE 容器镜像仓库地址
CI_JOB_NAME / CI_JOB_ID 当前 Job 名称/ID
CI_PROJECT_PATH 项目命名空间路径
📝变量查看
可在 Job 日志中执行 env | grep CI_ 查看全部内置变量；敏感值用项目 Settings -> CI/CD -> Variables 配置（勾选 Masked/Protected）。

5. 常见模式¶

⚠️Pipeline 不触发排查
常见原因：Runner 未注册/离线、项目未启用 CI（Settings -> General -> Visibility -> CI/CD 勾选）、.gitlab-ci.yml 语法错误、rules 全部不命中。详见 14-常见问题排查。

6. 调试技巧¶

  • 使用 gitlab-ci-local 或 CI Lint（CI/CD -> Editor，右侧 Lint 校验）本地校验 YAML 语法。
  • 在 Job 前加 debug Job：script: ["env"] 查看变量与运行环境。
  • Pipeline 编辑器中点 Run pipeline 手动测试。
