devops-概述

什么是 DevOps

DevOps 是”Development”（开发）与”Operations”（运维）的组合词，是一种文化、一场运动或实践方法，强调在软件开发过程中开发团队与运维团队的协作与沟通。它旨在建立一种文化与环境，使构建、测试、软件发布能够快速、频繁且更加稳定地进行。

DevOps 可以定义为：通过平台（Platform）、流程（Process）和人（People）的有机整合，以协作（Collaboration）、自动化（Automation）、精益（Lean）、度量（Measurement）和共享（Sharing）文化为指引，旨在建立一种可以快速交付价值并且具有持续改进能力的现代化 IT 组织。

DevOps 的价值

DevOps 的核心价值在于提供高效的软件交付方式，通过以下关键指标体现：

  1. 部署频率：应用和服务向生产环境部署代码的频率
  2. 变更前置时间：代码从提交到成功运行在生产环境的时长
  3. 服务恢复时间：线上应用和服务出现故障到恢复运行的时长
  4. 变更失败率：应用和服务在生产环境部署失败或导致服务降级的比例

高效能的组织不仅做到了高效率，还实现了高质量。实施 DevOps 的好处包括：

  • 缩短上市时间
  • 提高部署频率
  • 减少故障率
  • 加快恢复速度
  • 提升团队协作效率
  • 改善员工工作体验
  • 增强创新能力

DevOps 的三大支柱

DevOps 的实施基于三大支柱：人（People）、流程（Process）和平台（Platform）。这三个支柱之间的两两组合，构成了实施 DevOps 的”正确姿势”。

人 + 流程 = 文化

DevOps 文化强调打破开发和运维之间的壁垒，建立协作、共享责任和持续学习的文化氛围。核心文化要素包括：

  • Collaboration（协作）：打破部门边界，强调团队协作
  • Automation（自动化）：自动化重复性工作，减少手动错误
  • Lean（精益）：消除浪费，提高价值流
  • Measurement（度量）：以数据驱动决策
  • Sharing（共享）：知识和经验共享

流程 + 平台 = 工具

平台承载企业内部的标准化流程，固化的每一种流程都是解决实际问题的工具。一个完善的DevOps工具链需要覆盖软件开发生命周期的各个阶段：

  • 规划与需求管理工具
  • 代码管理与版本控制工具
  • 构建与持续集成工具
  • 测试自动化工具
  • 部署与发布工具
  • 配置与基础设施管理工具
  • 监控与反馈工具

平台 + 人 = 培训赋能

通过平台工具和实践培训，赋能团队成员掌握DevOps技能和思维方式。平台在DevOps中表现出三个主要效应：

  • 吸附效应：平台会不断吸收中小型的工具，逐渐成为一个能力集合体
  • 规模效应：平台的成本不会随使用方的扩展而线性增加，能够实现规模化
  • 积木效应：平台具备基础通用共享能力，能够快速搭建新的业务实现

DevOps 生命周期

DevOps 生命周期是一个持续循环的过程，包括以下阶段：

    A[持续规划<br>Continuous Planning] --> B[持续开发<br>Continuous Development]
    B --> C[持续集成<br>Continuous Integration]
    C --> D[持续测试<br>Continuous Testing]
    D --> E[持续部署<br>Continuous Deployment]
    E --> F[持续运维<br>Continuous Operations]
    F --> G[持续监控<br>Continuous Monitoring]

1. 持续规划（Continuous Planning）

  • 敏捷需求管理
  • 用户故事映射
  • 迭代规划
  • 价值流分析

2. 持续开发（Continuous Development）

  • 代码版本控制
  • 分支策略
  • 代码审查
  • 开发环境统一

3. 持续集成（Continuous Integration）

  • 自动化构建
  • 单元测试
  • 代码质量分析
  • 构建物管理

4. 持续测试（Continuous Testing）

  • 自动化测试
  • 测试环境管理
  • 安全测试
  • 性能测试

5. 持续部署（Continuous Deployment）

  • 环境管理
  • 配置管理
  • 自动化部署
  • 发布策略

6. 持续运维（Continuous Operations）

  • 基础设施即代码
  • 配置自动化
  • 容器化与编排
  • 云原生应用管理

7. 持续监控（Continuous Monitoring）

  • 应用性能监控
  • 基础设施监控
  • 用户体验监控
  • 安全监控
  • 日志分析与告警

DevOps 成熟度模型

DevOps 成熟度评估模型帮助组织了解自身 DevOps 实践的现状，并指导改进方向。典型的成熟度分级如下：

  1. 初始级（Regressive）：几乎没有尝试任何DevOps实践
  2. 基础级（Basic）：做了一些DevOps实践，正在起步阶段
  3. 成熟级（Standard）：能成熟运用各种DevOps实践
  4. 优化级（Optimized）：不仅能运用各种DevOps实践，还能根据团队和组织情况进行优化改进
  5. 领先级（Leading）：是行业里面DevOps的先行者、创新者、探索者、领导者

业务敏捷

业务敏捷强调通过快速响应和适应变化来创造商业价值。在DevOps中，业务敏捷通过以下框架实现：

  • Why：代表目标，核心业务目标或用户需求
  • Who：代表影响对象，通过影响谁来实现目标
  • How：代表影响方式，如何影响用户以实现目标
  • What：代表需要交付的功能，带来期望的影响

卡诺模型与需求分类

卡诺模型将产品需求划分为五种类型，帮助团队优先级排序：

  1. 兴奋型：超乎用户想象的需求，可遇不可求的功能
  2. 期望型：用户满意度随此类需求增多而线性增长
  3. 必备型：产品必须具备的功能
  4. 无差别型：做了和没做一样的功能
  5. 反向型：无中生有类需求，不具备使用条件或用户不需要

DevOps 与 BizDevOps

DevOps 的发展趋势是向上游延伸，将业务团队包括进来，形成 BizDevOps。BizDevOps 的核心理念：

  • 对齐业务和开发目标、指标
  • 把握安全、合规指标
  • 及时对齐需求，减少无用开发
  • 体现 DevOps 的价值
  • 让开发团队接触业务，调动积极性

DevOps 实施挑战与最佳实践

实施挑战

  1. 组织结构问题：传统组织结构不适应DevOps方法
  2. 技术债务：遗留系统和架构不支持快速部署
  3. 文化抵抗：人员对变革的抵触
  4. 技能缺口：缺乏跨领域的技能
  5. 工具链复杂性：工具繁多，集成困难

最佳实践

  1. 从小处开始：选择小型项目先试点
  2. 聚焦价值流：识别和优化端到端价值流
  3. 建立度量体系：使用DORA指标衡量进步
  4. 自动化优先：优先自动化重复性任务
  5. 持续学习：建立学习型组织文化
  6. 领导支持：获取高层支持和资源投入

总结

DevOps 不仅仅是一套工具或实践，而是一种文化、一场变革运动，旨在通过人员、流程和平台的紧密结合，实现软件交付的高效率和高质量。随着DevOps的不断发展，它已经从最初的开发与运维协作，发展到了涵盖业务、开发、运维等全链路的BizDevOps模式。

在实施DevOps的过程中，组织需要关注价值流、关注现状，通过交互式流程和反馈、协作和可视化、自动化和持续优化、遵循极简原则，逐步提升DevOps能力和成熟度，最终实现业务价值的快速交付。
