日志分析实战案例

[!abstract] 本篇目标
用一条完整链路：Filebeat 采集 Nginx 日志 → Logstash 解析 → ES 存储 → Kibana 大盘，解决”谁在访问、慢了没有、错在哪”。

0. 环境假设

  • ES / Kibana / Logstash / Filebeat 均本地单机（参考 01-Elasticsearch核心概念与安装）；
  • Nginx 日志路径：/var/log/nginx/access.log（combined 格式）。

4. Kibana 大盘

  1. 创建数据视图：nginx-access-*，时间字段 @timestamp；
  2. 制作面板：
面板 配置
访问量趋势 date_histogram(@timestamp, 1h) + count
Top 请求路径 terms(request, size 10)
状态码分布 terms(response)
P95 延迟 percentiles(request_time)（需在 grok 中解析耗时）
来源地区 geoip 字段 → Maps
  1. 组装 Dashboard 并设置自动刷新（如 30s）。

5. 常见扩展

  • 错误监控：response >= 500 的过滤面板 + 告警规则；
  • 慢请求：给 Nginx 配 $request_time 变量写入日志，grok 解析后做百分位面板；
  • 业务埋点：JSON 格式日志用 json filter 直接解析，无需 grok。

6. 复盘清单

  • 字段没解析出来？用 stdout { codec => rubydebug } 调试管道；
  • Kibana 无数据？查数据视图/时间范围/索引名三件套；
  • 数据延迟？查 Filebeat 进度与 Logstash 队列。
