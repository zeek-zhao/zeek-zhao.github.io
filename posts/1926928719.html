本文汇总 Go 工程的规范与最佳实践：目录结构、命名、格式、错误处理规范、配置管理、日志与代码评审，帮助你写出”像官方库”的 Go 代码。

Go 社区有强烈共识（gofmt 强制格式、Effective Go 官方指南），团队统一风格可极大降低维护成本。

命名规范

项 规范
包名 小写、简短单数：http、db
导出标识符 首字母大写：ParseConfig
私有标识符 首字母小写：retryCount
接口 动词 + -er：Reader、Logger
缩写 全大写：ID、URL、HTTP（但 Id 不推荐）

常见坑

  1. 格式不统一：go fmt/gofmt 是铁律，goimports 自动整理导入。CI 检查 gofmt -l .。
  2. 包命名含下划线：Go 风格下划线只用于测试文件与特殊场景，正常包名不加。
  3. 忽略 lint：启用 golangci-lint（errcheck、staticcheck、govet）。
  4. import 分组混乱：标准库 → 第三方 → 本地包，分组空行。
  5. 魔术数字/字符串：配置与常量集中定义。
  6. 重复代码：提炼函数与接口，遵守 DRY 但不过度抽象。

最佳实践

  • 每个导出符号写文档注释（以符号名开头：// ParseConfig parses ...），配合 go doc。
  • 提交前 go vet ./... + go test ./... + golangci-lint。
  • 代码评审关注：错误是否处理、并发是否安全、API 是否易用。
  • 接口放消费方（见 07-接口）；避免全局可变状态。
  • 参考官方风格：Effective Go、Go Code Review Comments（go.dev 官方文档）。
