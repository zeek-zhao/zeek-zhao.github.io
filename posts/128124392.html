数学公式与图表渲染

[!abstract] 一句话：公式选 MathJax 还是 KaTeX，图表用 Mermaid，关键都在于”主题配置打开 + Markdown 引擎不越权转义”。

数学公式：两个引擎怎么选

Hexo 站点渲染 LaTeX 公式主要靠两个引擎：MathJax 功能最全（支持宏、化学方程式、自动编号），但体积大、渲染稍慢；KaTeX 轻量极速，覆盖常用语法，缺点是部分高级环境不支持。博客场景 KaTeX 通常足够，学术论文摘录多则选 MathJax。

Butterfly 主题开启方式（在主题配置文件中）：

per_page: true 时需在用公式的文章 frontmatter 加一行 mathjax: true，避免全站加载公式脚本。

公式书写规范

[!warning] 最经典的坑：Markdown 转义
LaTeX 中的下标 a_1、星号 *、反斜杠会被 Markdown 引擎当作语法转义，导致公式渲染错乱。解决办法有三层：其一，确认 Hexo 的 Markdown 渲染器使用 marked 或开启 katex 支持的版本，并配置好 mathjax/katex 选项让公式块跳过 Markdown 处理；其二，公式内部避免裸写 _ 与 *，必要处用 \_ 转义；其三，多行公式放进 $$...$$ 独立代码区域，少混入正文段落。渲染异常时，先用最简单的 $x^2$ 测试链路，再逐步排除转义问题。

Mermaid 图表：文本即图

Mermaid 允许用文本描述生成流程图、时序图、甘特图等，对技术写作极其友好——图表本身就是代码，可版本控制、可修改复用：

Butterfly 开启 Mermaid 渲染：

在含图文章的 frontmatter 加 mermaid: true 即按需加载。注意图表代码块内不要再嵌套 Markdown 语法；若文章含多个 Mermaid 图，部分模板要求在文末补一个 {% mermaid %}{% endmermaid %} 标记确保脚本初始化，这是主题层的实现细节，遇到最后一个图不渲染时可以一试。

从 Obsidian 迁移的兼容问题

Obsidian 用户会同时写公式和图表，同步到 Hexo 时有几点差异要处理。Obsidian 的行内公式分隔符默认也是 $，一般无缝；但 Obsidian 支持的 \[ ... \] 块级公式写法 Hexo 引擎可能不认，建议统一为 $$。Mermaid 方面，Obsidian 内置的 Mermaid 版本与 Hexo 引入的 CDN 版本可能有语法差异（新图表类型），发布前用 hexo server 本地预览逐图确认。批量迁移时，可在同步脚本里对公式定界符做正则归一化。

按需加载与性能

公式与图表脚本都不小（KaTeX 约 300KB，Mermaid 约 1MB），坚持 per_page 按需加载原则，只在真正使用的文章引入。如果全站只有寥寥几篇公式文，也可以完全不用主题集成，改为在这几篇的 frontmatter 之外手写 <script> 引入 CDN 版本，控制粒度更细。相关性能权衡见 13-性能优化与构建加速。
