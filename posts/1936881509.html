04-源码编译与部署

发表于2026-10-24|apollo
|浏览量:

[!info] 本节目标
掌握 Apollo 源码编译与部署流程，理解各构建目标与产物。

1. 编译准备

编译前确认源码版本与 Docker 镜像版本匹配，检查磁盘空间与内存。Apollo 使用 Bazel 构建系统，首次构建耗时较长。

2. 构建目标

目标 命令 说明
全部 bash scripts/apollo_build.sh 编译全量模块
指定模块 bazel build //modules/perception:all 只编译感知模块
清理 bash scripts/apollo_clean.sh 清理缓存

构建产物位于 /apollo/bazel-bin，模块二进制与配置文件按目录组织。

3. 常见构建问题

问题 原因与解法
空间不足 清理 bazel 缓存或扩容
内存不足 限制并行度：bazel build –jobs=4
依赖缺失 检查 dev_start.sh 挂载与镜像版本
编译中断 断点续编：重复执行原构建命令

4. 部署要点

编译完成后可打包模块镜像用于目标平台部署。部署时需统一版本、环境变量与配置文件，具体见 39-车规级平台部署 与 17-车载计算平台。

[!note] 延伸
部署前先用仿真验证见 25-仿真平台（Sim Control）；问题排查见 37-常见问题排查。

5. Bazel 构建基础

Apollo 使用 Bazel 作为构建系统，理解其基本概念有助于编译调试。WORKSPACE 定义外部依赖，BUILD 文件声明目标与依赖关系，bazel-bin 存放构建产物。常用命令包括：bazel build 编译、bazel test 运行测试、bazel clean 清理。增量编译时 Bazel 只重编变更部分，可显著节省时间。若源码目录与镜像版本不一致，可能出现编译错误，务必保持两者版本匹配。

6. 部署流程细化

部署分为构建、打包、分发、运行四个环节。构建阶段产出模块二进制；打包阶段将二进制、配置文件与依赖环境制作成运行镜像；分发阶段将镜像部署到目标车辆计算平台；运行阶段配置环境变量与启动脚本。生产环境部署还需考虑日志收集、版本回滚与远程监控，相关要点见车规级平台部署篇。

7. 构建缓存与增量编译

Bazel 增量编译依赖缓存正确性：源码变更后缓存自动失效重编，外部依赖更新后需执行清理重建。频繁切换分支会导致缓存膨胀，建议定期清理。编译产物目录 bazel-bin 可安全删除重建，不会影响源码。理解构建缓存机制可显著减少无效重编时间。
