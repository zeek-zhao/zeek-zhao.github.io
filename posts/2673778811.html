25-Cyber启动系统详解

发表于2026-10-25|apollo
|浏览量:

[!info] 本节目标
理解 Cyber RT 从 mainboard 进程启动到组件就绪的完整链路：框架初始化、launch/DAG 配置解析、动态库加载与组件创建。读完本篇，你应能定位任何一次”模块起不来”问题的根源。

本篇是第四阶段 Cyber RT 深度剖析的开篇，负责讲清”系统如何被拉起来”——后续的调度（26-Cyber调度系统详解）、时间（27-Cyber时间系统与定时器）、数据（29-Cyber数据系统详解）都建立在启动系统之上。组件的使用层 API 已在第二阶段 12-消息通信与组件开发 讲过，本篇只讲内部机制。

1. 启动系统总览

Cyber RT 启动系统采用四层设计：

核心组件职责：

组件 源码位置 职责
mainboard cyber/mainboard/mainboard.cc 进程入口，解析命令行参数
ModuleController cyber/mainboard/module_controller.cc 驱动模块加载循环
ClassLoader cyber/class_loader/ dlopen/创建类实例
DagManager cyber/mainboard/dag_manager.cc 解析 DAG 配置
GlobalData cyber/common/global_data.cc 进程名、任务名、通道 ID 全局注册表

[!note] 2026 年更新
Cyber RT 引入于 Apollo 3.5（2019 年），是专为自动驾驶设计的首个开源高性能运行时框架：组件依赖以 DAG 图组织，运行时生成轻量用户级任务，按优先级与资源可用性调度。GitHub 主分支已演进至 10.0/11.0 代际（公开 tag 止于 v9.0.0），启动链路的整体结构保持稳定。

4. launch 与 DAG 配置

启动配置分两层：launch 文件（XML，进程级）→ DAG 文件（proto，组件级）。

4.1 launch 文件

  • <module>：一个待加载模块
  • <dag_conf>：DAG 配置路径
  • <process_name>：进程名，用于系统监控（cyber_monitor/Dreamview 显示）

4.2 DAG 文件

DAG 描述”这个进程里有哪些组件、各自订阅哪些通道”：

字段含义：

  • module_library：组件所在动态库（.so）路径
  • components：组件列表，一个进程可加载多个组件
  • readers：声明组件输入通道，框架据此自动创建 Reader 并装配数据链路

[!tip] DAG 与调度的关系
DAG 中的 readers 决定了 DataVisitor 的配置，而 DataVisitor 的唤醒回调正是调度器创建协程任务时的通知源。换句话说，DAG 是数据拓扑，调度配置（/apollo/cyber/conf/profilexxx.pb.txt）是执行拓扑，两者在任务名上对齐。

7. 启动错误处理与诊断

7.1 错误类型

类别 典型原因 表现
配置错误 DAG 路径不存在、channel 缺失 ModuleController::Init 返回 false
库加载错误 .so 缺失、符号未定义、依赖库缺失 dlopen 失败日志
组件初始化错误 用户 Init() 返回 false Component Init() failed.
资源错误 内存不足、端口/共享内存冲突 各子系统创建失败

7.2 排查命令

[!warning] 常见坑

  • CLASS_LOADER_REGISTER_CLASS 忘写或写在匿名命名空间外被裁剪，会报 CreateClassObj failed。
  • DAG 中 readers 通道名与上游 Writer 不一致，组件能启动但 Proc 永远不触发——用 cyber_channel hz 验证数据是否到达。
  • 一个进程加载多个组件时，组件名（Node 名）重复会引发 DataVisitor 注册冲突。

8. 启动性能优化

启动时间的关键路径是：动态库加载 → 组件 Init → Reader/任务创建。可选优化：

  1. 并行加载：launch 中无依赖关系的模块并行启动（cyber_launch start 天然多进程并行）。
  2. 懒加载：重资源（模型、地图）延迟到首次使用时加载，缩短 Init 时间。
  3. 减少 .so 依赖链：依赖越深 dlopen 越慢，可用预链接/LTO 减小体积。
  4. 内存预分配：高频消息通道的对象池在 Init 期建好，避免运行期抖动。
  5. 依赖排序：DAG 之间有数据依赖的模块按拓扑序启动，避免上游未就绪导致下游空转重试。

9. 小结

启动系统 = mainboard 进程壳 + cyber::Init 基础设施 + launch/DAG 配置描述 + ClassLoader 插件机制 + 组件自动装配。它把”写一个类”变成”接入一个系统”的全部粘合剂集中在 Component::Initialize 里完成：Node、Reader、DataVisitor、协程任务一气呵成。理解这条链路后，任何启动失败都能迅速定位到具体环节；而协程任务被创建之后的世界，就是下一篇 26-Cyber调度系统详解 的主题。
