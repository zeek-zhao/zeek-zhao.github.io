20-Apollo Cyber RT框架

发表于2026-10-24|apollo
|浏览量:

[!info] 本节目标
理解 Apollo Cyber RT 框架：设计目标、核心概念与总体架构。

1. 为什么需要 Cyber RT

早期 Apollo 基于 ROS，存在性能、可靠性与二次开发限制。Cyber RT 是百度自研的高性能实时通信框架，用于替代 ROS 支撑自动驾驶数据流。

2. 核心概念

概念 说明
Node 功能单元容器
Reader/Writer 消息订阅/发布
Component 可复用的计算组件
Scheduler 协程调度器
Shared Memory 共享内存传输

3. 架构分层

Cyber RT 分为传输层、调度层与应用层：传输层负责消息传递（共享内存、DDS 等），调度层负责任务调度（协程并发），应用层提供 Node/Component 编程模型。

4. 设计优势

Cyber RT 采用协程与无锁队列，降低调度开销；支持共享内存零拷贝传输；组件化开发便于复用。相比 ROS 的改进见 38-Apollo与ROS对比。

[!note] 延伸
消息通信细节见 21-Cyber消息通信；组件开发见 22-Cyber组件开发。

5. 调度器与协程

Cyber RT 的调度器基于协程实现：组件回调以协程方式执行，支持优先级与依赖调度，避免线程频繁切换开销。调度策略可通过配置调整，如设置核绑定与任务优先级。协程模型使开发者以同步方式编写异步逻辑，简化并发编程，是 Cyber RT 高性能的关键之一。

6. 从 ROS 迁移思路

从 ROS 迁移到 Cyber RT 时，需将节点转换为 Node 或 Component，将话题与消息类型转换为 Cyber 对应定义，将 launch 文件转换为 Cyber launch 配置。Apollo 提供迁移示例与工具帮助开发者平滑过渡。迁移后需验证消息频率、延迟与数据一致性，详细对比见 Apollo 与 ROS 对比篇。

7. 框架对比与选型

Cyber RT 适合高实时、高频数据流场景，但生态相对内聚；ROS 生态丰富适合研究原型。选型需结合项目目标：产品化自动驾驶优先实时性，科研教学可选用 ROS。理解框架本质差异后，迁移与二次开发将更加顺畅，详细对比见 Apollo 与 ROS 对比篇。
