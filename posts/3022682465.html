环境变量与配置文件

[!info] 本页概览
本文讲解环境变量机制与 Shell 配置文件：PATH、export 作用域、.bashrc/.bash_profile/.profile 加载顺序、source 用法，以及脚本读取配置文件的模式。

核心概念

  • 环境变量：export 后传递给子进程；env 查看、printenv 单查。
  • 配置文件：登录/非登录 shell 加载不同文件，理解加载顺序才能正确放置配置。
  • 配置与代码分离：脚本从文件/环境读配置，不硬编码。

常见坑

  1. 配置放错文件：非登录 shell 不读 .bash_profile；统一把交互配置放 .bashrc。
  2. PATH 被覆盖：export PATH=/opt/bin 会丢原有 PATH；应 $PATH:/opt/bin 追加。
  3. 子进程不继承未 export 变量：VAR=1; bash -c 'echo $VAR' 为空。
  4. cron 无环境：cron 不加载 .bashrc，脚本内显式 source 或设置 PATH。
  5. 配置文件含敏感信息：权限 600，不进版本库。
  6. source 与执行的区别：./conf 会开子 shell 修改不保留；必须 source。
  7. set -u 下未定义变量报错：用 ${VAR:-default} 提供默认。

最佳实践

  • 交互个性化（别名/提示符）放 .bashrc，环境变量 export 也放 .bashrc（多数发行版 profile 会 source 它）。
  • 应用配置统一环境变量 + 默认值模式（12-Factor）。
  • 部署脚本在开头固定 PATH：export PATH=/usr/local/bin:/usr/bin:/bin。
  • 敏感配置用 .env 文件（600 权限）或密钥管理服务。
  • 修改配置后立即 source 验证，不用重开终端（生产服务器避免影响他人）。
