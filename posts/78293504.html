日志与调试

[!info] 本节目标
掌握 ROS1 日志系统、可视化调试工具（rqt_console/graph）、rosbag 数据调试与常见问题排查方法论。

1. 日志系统

ROS 日志由 rosout 话题统一收集，节点日志写入 ~/.ros/log/。

[!tip] 查看日志
节点崩溃时可查 launch 日志定位崩溃原因；output="screen" 则直接看终端。

2. 日志级别

级别 函数（C++/Python） 颜色
DEBUG ROS_DEBUG / logdebug 灰
INFO ROS_INFO / loginfo 白
WARN ROS_WARN / logwarn 黄
ERROR ROS_ERROR / logerr 红
FATAL ROS_FATAL / logfatal 红

[!note] THROTTLE
*_THROTTLE(period, ...) 限制打印频率，防止高频循环刷爆日志。

3. rqt_console 日志查看器

功能：

  • 实时查看 rosout 日志（按级别/节点/消息过滤）。
  • 点击日志跳转到 rqt_graph 定位节点。
  • 汇总节点错误次数。

4. rqt_graph 通信拓扑

[!tip] 调试第一步
系统不工作时先看 rqt_graph：若话题线缺失，说明发布或订阅缺失；若只有发布没有订阅，检查订阅者是否启动。

6. rosbag 数据调试

[!warning] 回放时间
回放真实数据做算法调试时，设置 use_sim_time=true 让算法使用 bag 时间，保持数据同步。

8. 常见问题排查流程

症状 排查步骤
无话题数据 节点是否运行 → 话题是否发布 → 类型是否匹配 → 频率是否正常
节点崩溃 看 launch 日志尾部 → 报错栈 → 依赖/参数缺失
TF 报错 谁发布 TF → 时间是否同步 → 树是否完整
通信延迟大 带宽 → 队列 → 网络 → 大消息压缩
卡死 CPU 占用 → 死锁（多线程共享变量）→ 回调阻塞

[!tip] 最小复现
复杂问题先做”最小复现”：只启动相关节点 + rosbag 录数据，隔离环境定位根因。
