03-CMake与qmake构建

两种构建系统的对比与工程配置
📅 2026-10-24· 更新于 2026-10-24 ✍ zeek.zhao #qt#技能
ℹ️本节目标
掌握 CMake 与 qmake 构建系统的配置方法。

1. 构建系统概述¶

构建系统负责将源码编译为可执行文件与库，Qt 支持 qmake 与 CMake 两种主流方案。qmake 是 Qt 原生构建工具，配置简单；CMake 是通用构建系统，生态庞大且 Qt6 官方推荐，两者可混合存在但新项目优先 CMake。

2. qmake 基础¶

qmake 使用 .pro 工程文件描述配置，核心变量包括 QT 指定模块、SOURCES 源文件、HEADERS 头文件、TARGET 目标名与 CONFIG 构建选项。qmake 自动处理依赖与平台差异，适合中小型项目与学习场景。

3. CMake 基础¶

CMake 使用 CMakeLists.txt 配置，Qt6 提供 find_package 与 Qt 组件导入机制。核心指令包括 project 声明工程、add_executable 定义目标、target_link_libraries 链接 Qt 库与 AUTOMOC 自动处理元对象编译，结构清晰可扩展。

4. 关键差异对比¶

qmake 与 Qt 集成更紧密但功能有限，CMake 通用性与生态更强。CMake 支持复杂依赖、测试集成与安装规则，Qt6 官方示例全面迁移 CMake。跨平台团队建议统一 CMake 降低维护成本。

5. 多目标与模块配置¶

CMake 通过 add_subdirectory 组织多目标工程，qmake 通过 SUBDIRS 模板实现类似功能。模块配置指定 Widgets、Quick、Network 等组件，按需引入可减小二进制体积并明确依赖。

6. 构建优化与调试¶

构建类型区分 Debug 与 Release，CMake 通过 CMAKE_BUILD_TYPE 设置，qmake 通过 CONFIG 指定。增量构建、并行编译与缓存可显著提升效率。构建错误先看路径与依赖问题，再查编译输出定位。

7. 迁移与最佳实践¶

qmake 工程迁移 CMake 可借助工具辅助，逐步替换配置项。最佳实践包括明确构建类型、统一命名、文档化依赖与使用 CMake presets 固化配置，详见打包发布篇。

本节小结¶

本节从 qmake 与 CMake 两种构建系统出发，对比了配置语法、依赖管理、多目标组织与调试发布能力。CMake 作为 Qt6 官方推荐方案具备更强的生态与扩展性，适合新项目与大型工程；qmake 配置简单，适合快速原型与学习验证。实际开发中建议团队统一构建系统，配合预设文件与 CI 集成，把构建配置当作工程资产持续维护，可显著降低环境差异带来的问题。
