SQL 优化

[!info] 本页概览
本文讲解 SQL 优化方法论：慢 SQL 定位、索引优化、查询改写、分页优化、批量写优化、大表治理与优化案例，配可运行示例。

核心概念

  • 优化流程：抓慢 SQL → 分析执行计划 → 定位瓶颈 → 改写/建索引 → 验证。
  • 三大瓶颈：全表扫描（缺索引）、回表过多、临时表/文件排序。
  • 目标：减少扫描行数、减少回表、减少排序与临时表。

常见坑

  1. 只看 EXPLAIN 不看实际耗时：行数估算不准，用 profiling 或压测验证。
  2. 过度优化：加索引前先确认查询频率与写入代价。
  3. 缓存了错误的统计信息：ANALYZE TABLE 更新统计信息。
  4. 连接池打满不优化 SQL：先治理慢 SQL 再扩连接数。
  5. 忽略字符集与排序规则：JOIN 两表 collation 不同无法用索引。

最佳实践

  • 建立慢 SQL 看板，每天治理 Top N。
  • 新上线 SQL 评审：EXPLAIN 检查 type/rows/Extra。
  • 压测环境复现，优化前后对比耗时与扫描行数。
  • 结合 04-索引与执行计划、08-备份恢复 做完整治理闭环。
