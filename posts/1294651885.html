49-KITTI与Waymo数据集实战

数据集全景看过了，这篇动手。KITTI 和 Waymo 两个基准，从下载、目录结构、格式解析一路走到坐标转换、数据加载器和评估。
📅 2026-10-02· 更新于 2026-10-02 · 5271 字 · 约 14 分钟 ✍ zeek.zhao #实战#apollo

数据集全景看过了，这篇动手。KITTI 和 Waymo 两个基准，从下载、目录结构、格式解析一路走到坐标转换、数据加载器和评估。先看 KITTI——文本标注加 bin 点云，上手最快。全景见 48-自动驾驶数据集总览。

1. KITTI：从下载到评估¶

1.1 采集平台与评测项目¶

KITTI 采集车的配置：2 灰度 + 2 彩色 Point Grey Flea 2 相机（1382×512，10Hz）、1 台 Velodyne HDL-64E（64 线，约 130 万点/秒，120m）、OXTS RT3003 GPS/IMU（100Hz，厘米级）。采集地点是德国卡尔斯鲁厄的市区、乡村和高速。

评测项目覆盖立体视觉、光流、场景流、深度、视觉里程计/SLAM、物体检测（2D/3D/BEV）、目标跟踪、道路/车道检测、语义分割。

1.2 下载与存储¶

存储上，目标检测约 15GB、视觉里程计约 25GB、原始数据约 200GB，全量预留 250GB。

1.3 目录结构¶

1.4 数据格式详解¶

点云：每点 4 个 float32（x, y, z, intensity），雷达坐标系 x 向前、y 向左、z 向上。

标注（每行一个物体，15 个字段）：

字段 含义
type Car/Van/Truck/Pedestrian/Cyclist/Tram/Misc/DontCare
truncated 截断程度 0-1
occluded 0完全可见 / 1部分遮挡 / 2严重遮挡 / 3未知
alpha 观测角 (-π, π)
bbox 2D 框 x1 y1 x2 y2
dimensions 3D 尺寸 h w l（米）
location 3D 位置 x y z（相机坐标系，米）
rotation_y 绕 Y 轴旋转角 (-π, π)

1.5 坐标系转换：点云投影到图像¶

KITTI 涉及三个坐标系：雷达系 → 相机系（Tr_velo_to_cam）→ 矫正相机系（R0_rect）→ 图像系（P2）。

投影有两个常踩的坑：忘了 R0_rect，或者先除深度再变换。location 用的是相机坐标系，不是雷达坐标系，训练 3D 检测时得统一转换。

1.6 PyTorch 数据加载器¶

数据增强要点：随机水平翻转要同步处理图像、点云 x 坐标、2D 框、rotation_y（θ → π−θ）和 alpha；点云则可做随机旋转、缩放、抖动。

1.7 KITTI 评估¶

  • 难度分级：Easy（高≥40px 完全可见）/ Moderate（≥25px 部分遮挡）/ Hard（≥25px 严重遮挡截断）。
  • IoU 阈值：汽车 0.7，行人/骑行者 0.5。
  • 指标：2D/3D/BEV 各自的 AP；里程计任务用平均平移误差(%)与每米旋转误差(deg/m)。

1.8 常见问题¶

问题 对策
类别不平衡（Car 远多于行人） 加权损失、过采样、Focal Loss/OHEM
远处小目标漏检 FPN 多尺度、小目标损失加权、软 NMS
测试集性能低于验证集 检查数据泄露、用官方划分、增强鲁棒性

2. Waymo：TFRecord 那一套¶

2.1 数据集组成¶

子集 内容 大小
感知（Perception） 5 相机 + 5 雷达 + 3D 框/跟踪 ID 训练集约 600GB
运动（Motion） 10 万+ 情景，轨迹 + 高精地图 + 交通灯 约 1.5TB
领域适应 晴天/雨天/夜间域迁移数据 约 120GB

传感器是 1 顶置 64 线加 4 环视雷达，5 个高清相机；采集于旧金山湾区、凤凰城、华盛顿等地，覆盖多种天气与时段。

2.2 环境配置¶

数据要在官网申请许可后经 Google Cloud（gsutil）下载，每个段（segment）是一个 TFRecord 文件，含约 200 帧（20Hz × 10s）。

2.3 感知数据加载¶

有个地方容易卡住：Waymo 点云是基于 range image 存储的，得用官方工具转换；强度和伸长度（elongation）在 range image 的通道 3、4。

2.4 Motion 数据与可视化¶

每个 Scenario（20 秒）包含：时间戳序列、tracks（各交通参与者的状态序列：位置/尺寸/朝向/速度）、map_features（车道中心线/标线/路缘/停止标志/人行横道/减速带）、dynamic_map_states（交通灯）、sdc_track_index（自车）、tracks_to_predict（预测目标）。

2.5 Waymo 评估¶

  • 检测：AP 与 APH（考虑朝向精度的 AP）；难度 LEVEL_1（5 点以上雷达）/ LEVEL_2（含 1-4 点与不可见目标）。
  • 跟踪：MOTA/MOTP/MOTAH。
  • 预测：minADE、minFDE、重叠率 mAP。

3. 怎么选、怎么跑¶

维度 KITTI Waymo
上手难度 低（文本标注+bin 点云） 中（需 TF + 官方 devkit）
数据规模 约 15K 帧 20 万帧级
环境多样性 德国晴天为主 美国多城全天候
地图/轨迹 无高精地图 含高精地图与交互轨迹
适合 快速入门、算法原型 时序/预测/大规模验证

上手我会从 KITTI 起步，文本标注加 bin 点云，不必一上来就跟 TFRecord 较劲。跑通之后再按这条路径往下走：

  1. 先用 KITTI mini 子集跑通”加载→可视化→投影”全链路；
  2. 用 OpenPCDet/MMDetection3D 训练 PointPillars 复现基线（KITTI Car Moderate 3D AP ≈ 70）；
  3. 迁移到 Waymo，用官方 metrics 对齐排行榜口径；
  4. 补充 nuScenes/Argoverse 2 做跨基准泛化验证（见 48-自动驾驶数据集总览）。

优化也有几个现成的方向：训练侧用预训练权重、混合精度（FP16）、多阶段训练；推理侧做模型剪枝、INT8 量化、TensorRT、自定义 CUDA NMS。有个可对照的案例：某 3D 检测系统经骨干替换（EfficientNet-B0）、动态体素化、FPN、量化后，3D AP 从 65.3% 提至 71.8%，推理 120ms → 45ms。

操作步骤 使用流程¶

把两个数据集从零跑到能出指标，建议按这条主线走：

  1. 确认许可与存储：KITTI 非商用需引用论文；Waymo 需官网申请并经 gsutil 下载。全量 KITTI 预留 250GB、Waymo 感知+运动预留 2.5TB。
  2. 下载并校验：用上面的 wget -c 断点续传下载 KITTI 五个包，解压后对照目录结构检查；Waymo 用 gsutil -m cp -r 批量拉 segment，下载完校验文件大小。
  3. 跑通单帧解析：先拿一帧 KITTI 跑 parse_kitti_line + load_calib + project_velodyne_to_image，确认标注和点云对得上；Waymo 拿一个 segment 跑 waymo_frame_to_points，确认 range image 转换正常。
  4. 可视化核对：用 visualize_lidar_on_image 把点云投到图上，肉眼看点是否贴在物体上；这一步能快速发现坐标系或标定错误。
  5. 搭 Dataset/DataLoader：按目标框架（PyTorch/TF）封装加载器，接上数据增强；翻转增强务必同步图像与标注（用 flip_kitti_sample）。
  6. 训练基线：用 OpenPCDet/MMDetection3D 训练 PointPillars，先在 KITTI mini 上 overfit 一个 batch 验证流程，再上全量。
  7. 本地评测：用官方 devkit 跑 KITTI 的 evaluate_object；Waymo 用 metrics_pb2 配 LEVEL_1/LEVEL_2，确保与排行榜口径一致。
  8. 提交前自检：用 sanity_check_predictions 检查置信度、类别与坐标有限性，避免格式错误被拒。
  9. 跨基准迁移：KITTI 跑通后迁到 Waymo，再补 nuScenes/Argoverse 2 做泛化验证（见 48-自动驾驶数据集总览）。

注意事项与常见坑¶

两个数据集实战里最容易翻车的点：

  1. 下载链接失效或坏档：KITTI 的 S3 直链偶发 403，务必用 wget -c 断点续传，下完对照文件大小校验；坏档会导致训练中途解析失败。
  2. 投影漏 R0_rect：KITTI 点云投影必须经过 Tr_velo_to_cam → R0_rect → P2 三步，漏掉矫正矩阵点会整体偏移。
  3. 先除深度再变换：归一化必须放在 P2 投影之后、矩阵乘法之前提前除会破坏齐次坐标含义。
  4. location 坐标系搞错：KITTI 的 location 是相机系，不是雷达系；训练 3D 检测时和点云统一到一个坐标系，否则框和点错位。
  5. 点云 dtype 用错：KITTI bin 必须 float32，reshape 成 4 列；用 float64 或列数不对，点云会乱成一团。
  6. 翻转增强不同步：随机水平翻转要同时改图像、点云 x、2D 框、rotation_y 和 alpha，漏一个模型就学到错误对应。
  7. Waymo 版本绑定：tensorflow==2.6.0 要配 waymo-open-dataset-tf-2-6-0，版本不匹配会报 protobuf 兼容错误。
  8. Waymo 点云来源搞混：range image 存的是球面投影，必须用 convert_range_image_to_point_cloud 转换，不能直接当笛卡尔坐标用；强度在通道 3、伸长度在通道 4。
  9. 评估难度档位错配：Waymo AP/APH 要分 LEVEL_1/LEVEL_2，KITTI 分 Easy/Mod/Hard；提交前确认 config 里加了两档，否则指标对不上排行榜。
  10. 存储估算不足：Waymo 全量约 2.5TB，运动子集就 1.5TB，提前规划分批下载和磁盘余量，别下到一半没空间。
