35-native模拟器

发表于2026-10-24|Zephyr
|浏览量:

[!info] 本节目标
掌握 native 模拟器平台。

1. native 概述

native 平台将 Zephyr 编译为宿主可执行文件，native_posix 与 native_sim。无需硬件运行系统，调试工具丰富。native 适合逻辑与协议开发。

2. native_sim

native_sim 是新一代 native 平台，替代 native_posix。配置简化，宿主工具支持。推荐新项目使用。

3. 构建运行

west build -b native_sim 构建，可执行文件运行。宿主系统交互，退出与信号处理。运行环境简单。

4. 调试增强

gdb 原生调试，valgrind 内存检查。ASAN 地址消毒，确定性执行。调试工具强大。

5. 限制与注意

无限快时钟模型，忙等会卡死。无硬件中断注入，时序模拟受限。理解限制避免误用。

6. 测试应用

native 平台运行 ztest 与 twister 测试，快速验证。逻辑测试与协议栈测试。CI 高效执行。

7. 实践建议

逻辑与协议优先 native 验证，硬件相关用真实板。确定性调试利用优势，文档记录平台限制。

8. 常见问题

native 平台最需要注意”无限快时钟”模型：宿主 CPU 原生执行，忙等循环会占满 CPU 导致所有线程卡死，等待中断的代码可能永远不返回。时序相关、硬件竞态与真实中断场景无法在 native 上验证，应使用 QEMU 或真实硬件。native_sim 与 native_posix 存在差异，新项目优先 native_sim。地址消毒与 valgrind 能发现内存问题，但部分内核机制（用户态、栈保护）在 native 上不可用。把 native 定位为逻辑与协议栈的快速验证平台，是最高效的使用方式。

9. 小结

native 平台让 Zephyr 应用以宿主程序方式运行，具备编译快、调试方便、可用 sanitizer 的优势。其”无限快时钟”与缺少真实中断的局限决定了它最适合逻辑与协议验证，不适用于时序与硬件相关测试。

10. 进一步阅读

官方 Testing 文档包含 native 平台的使用限制与配置说明，Boards 页面提供 native_sim 与 native_posix 的差异对比。建议尝试 native 上的网络虚拟化与时间戳模拟功能，结合 sanitizer 运行 ztest 测试套件，体验无硬件的快速迭代开发。
