Maven与Gradle

[!info] 本页概览
本文讲解 Java 构建工具：Maven（pom.xml、生命周期、依赖管理、仓库）、Gradle（构建脚本、任务、依赖）、以及构建工具选型与常见坑，配示例配置。

核心概念

  • 构建工具：编译、打包、依赖管理、测试执行的自动化流水线。
  • Maven：XML 配置（pom.xml），约定优于配置，生命周期：validate → compile → test → package → install → deploy。
  • Gradle：基于 Groovy/Kotlin DSL，增量构建更快，Android 默认构建工具。
  • 坐标：groupId:artifactId:version 唯一定位依赖。
  • 仓库：本地仓库（~/.m2）、中央仓库（Maven Central）、私有仓库（Nexus）。

[!note] 依赖冲突
Maven 采用”最短路径优先 + 先声明优先”。常见冲突：多个版本被引入。排查用 mvn dependency:tree，用 dependencyManagement 统一版本。

Maven vs Gradle

维度 Maven Gradle
配置语言 XML（声明式） Groovy/Kotlin DSL（编程式）
构建速度 较慢（无增量优化） 增量构建，通常更快
学习曲线 平缓 较陡（DSL 灵活）
生态 极其广泛 与 Android/Spring 现代项目流行
多模块 支持良好 支持良好
灵活性 低（约定固定） 高（可编程定制）

常见坑

  1. 版本冲突/NoSuchMethodError：依赖版本混乱；用 dependencyManagement 或 BOM 统一。
  2. 本地仓库缓存：改版本不生效先 mvn clean，必要时删 ~/.m2 对应目录。
  3. proxy 下载失败：配 settings.xml 镜像（阿里云/腾讯云 mirror）。
  4. 编码问题：pom 加 project.build.sourceEncoding UTF-8。
  5. jar 与 war 混淆：Spring Boot 用 jar + 内嵌容器；传统 war 需外置 Tomcat。
  6. 打包不包含依赖：Spring Boot 需要 spring-boot-maven-plugin repackage，否则 java -jar 报”no main manifest attribute”。
  7. Gradle 守护进程内存：gradle.properties 调 org.gradle.jvmargs=-Xmx2g。

最佳实践

  • 统一依赖版本：Maven 用 dependencyManagement；Gradle 用 platform/BOM。
  • 私有依赖用公司 Nexus 私服，配 settings.xml 镜像加速。
  • CI 中缓存依赖目录（/.m2、/.gradle）加速构建。
  • 多模块项目拆分 domain/service/web，明确依赖方向。
  • 结合 16-Spring Boot 入门 与 19-测试 构建标准工程。
