[!info] 本节目标
掌握 FreeRTOS 与 C++ 结合开发实践。

1. C++ 与 RTOS 结合

C++ 提供面向对象、模板与 RAII 能力，与 FreeRTOS 结合可构建模块化嵌入式应用。现代 C++ 特性需注意实时性与内存约束，合理使用可提升开发效率与代码质量。

2. 任务封装

将任务封装为类，任务函数作为静态入口调用成员函数。类实例生命周期管理任务句柄，析构时删除任务。继承与多态支持任务变体，模板减少重复代码。

3. 内存与异常

嵌入式环境通常禁用异常与 RTTI，减少代码体积与不确定性。动态内存使用堆管理，优先静态或对象池。new 与 delete 可重定向到 pvPortMalloc 保证一致性。

4. RAII 与互斥

使用锁对象 RAII 封装互斥量，作用域结束自动释放，减少忘记释放风险。队列与信号量封装为类型安全接口。同步原语封装提升代码可读性与安全。

5. 模板与接口

模板实现类型安全队列与通用任务接口，编译期检查减少运行错误。接口抽象适配不同硬件平台。过度模板化增加编译时间与代码膨胀，权衡使用。

6. 中断与回调

C++ 静态成员函数适合中断回调，避免成员函数指针问题。回调对象生命周期管理避免悬空。extern C 接口衔接 C 组件与 C++ 代码。

7. 实践建议

团队约定 C++ 使用规范，禁用异常与动态库依赖。编译选项与链接脚本适配 RTOS 环境。测试覆盖对象生命周期与并发路径。混合 C/C++ 工程保持接口清晰。

8. C++ 工程规范与工具链

C++ 工程需要工具链完整支持标准库与运行时初始化，链接脚本适配堆与静态对象构造。启动代码完成全局构造后进入调度器，时序注意构造顺序。编译选项关闭异常与 RTTI 减小体积，静态断言与编译期检查补偿缺失的运行期检查。命名空间与模块组织提升可维护性。团队制定编码规范约束模板深度与继承层次，代码审查关注生命周期与并发安全，测试覆盖对象交互路径。
