2. 官方学习路径分四步¶

  1. 新手：developer.apollo.auto 云端体验（免安装浏览器仿真）+ 入门课程
  2. 进阶：社区官网文档，完成”五步入门”与定速巡航场景仿真调试
  3. 源码研究：克隆仓库 → Docker 构建 → 按模块阅读 docs/
  4. 实战：D-KIT 开发套件文档（封闭园区自动驾驶搭建：感知设备集成、标定、虚拟车道线制作）

官方课程集中在技术学习板块，包括自动驾驶技术基础、Cyber 实践之 talker-listener 通信、GNSS 融合定位、深度强化学习在运动规划中的应用、Apollo 仿真引擎核心原理等。

9. 从打底到读源码¶

路子大致是这样：先用官方课程加吴恩达、李宏毅的视频打底，配合《动手学深度学习》跑通第一个感知模型；再用 Docker 跑通 Apollo Demo，靠 DreamView 看懂数据流；然后选一个方向深入，去读对应模块的源码。最后持续跟论文和新版本发布说明，注意版本一致性——这套教程基于 10.0/11.0 代际认知。我的建议是别一上来就啃源码，云端仿真和入门课程先走一遍，能省不少无用功。

注意事项与常见坑¶

  1. 照旧教程配新版环境：Apollo 8.0 文档双轨、11.0 换软件包安装，旧教程大概率失效。
  2. 只依赖 GitHub release tag：tag 止于 v9.0.0，10.0/11.0 在 master 上，要 pin commit。
  3. 一上来就啃源码：没有 DreamView 数据流直觉，读源码效率极低。
  4. 数据集贪大求全：Waymo 全量数据对存储和带宽都是负担，先从小数据集跑通流程。
  5. 把所有资料都收藏：资料多不等于学得好，按方向收敛到一条主线。
  6. 忽视中文社区价值：英文文档常滞后，实际排障以中文社区与论坛为主。
  7. 博客文章不核对版本：Apollo 源码解析文章多基于旧版本，读代码要对照实际 commit。
  8. 反爬页面用脚本抓：知乎等站点自动请求会被拦截，只作浏览器可达的参考链接。
  9. 论文只看不记：读综述建地图、盯一条主线（UniAD），比堆数量有用。
  10. 工具链版本混用：PyTorch / ONNX / TensorRT 版本要对齐，否则模型转换踩坑。
