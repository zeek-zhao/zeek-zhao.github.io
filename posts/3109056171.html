09-面向对象

Groovy 的类写起来比 Java 省事，属性自带访问器、构造器可省，继承与多态沿用 Java 又更灵活。
📅 2026-11-11· 更新于 2026-11-11 · 629 字 · 约 2 分钟 ✍ zeek.zhao #groovy#语言

顺着 08-与Java互操作 往下看，既然 Groovy 能无缝用 Java 的类，那它自己定义类又是什么样？我第一次写的时候最直观的感受就是省字——Java 里那些样板代码，这里大多能省略。这篇讲类定义、属性、继承和多态。

类定义比 Java 省，new 还能省括号¶

Groovy 类定义跟 Java 类似，但更简洁：属性不用显式写 getter/setter，构造器可以省，默认还白送一个无参构造。类默认 public，字段默认 private 并自动生成访问器。

new 创建实例，括号也能省。它还支持命名参数构造，我初始化对象时喜欢用这个，读起来清楚。

属性就是自动带访问器的字段¶

Groovy 属性用字段声明就自动生成 getter/setter，点号访问其实调的是访问器。封装和访问的代码都跟着变短。

想只读就用 final 或只定义 getter；@PackageScope 这类注解可以控制字段可见性。

继承照搬 Java，接口还能有默认方法¶

继承语法跟 Java 一致，extends 继承类、implements 实现接口。动态语言的多态更灵活，方法重写按运行时类型分发。

接口可以有默认方法，Groovy 3+ 支持 Java 8 风格，也能用 trait 做更丰富的混入。

抽象类定骨架，闭包能补实现¶

抽象类定义骨架、子类填细节，模板方法模式在这里写起来很简洁。抽象方法用 abstract 声明，具体方法放公共流程。

Groovy 还允许用闭包或元编程在运行时补上抽象方法的实现，子类数量能少一些。

运行时分发让鸭子类型成立¶

Groovy 方法调用看运行时类型，动态分发让多态表现更充分。鸭子类型下，不同类只要方法签名对得上就能互换。

方法解析顺序是：具体方法、属性访问、methodMissing、GroovyObject 钩子。我调试动态行为时基本就是顺着这条链排查的。

多用组合少用继承，核心 API 加静态检查¶

设计类我优先组合而非继承，trait 是更安全的混入路径；类职责保持单一，属性机制能省掉不少样板代码。

大项目建议给核心 API 上 @TypeChecked 或 @CompileStatic，动态的灵活和可维护性两边都占。
