性能调优

ℹ️本页概览
本文讲解 Java 应用性能调优：性能分析思路、常用工具（jstat/jmap/jstack/Profiler）、JVM 参数调优、代码层优化、数据库与缓存、常见性能问题案例，配示例与最佳实践。

核心概念¶

  • 性能指标：延迟（Latency）、吞吐（Throughput）、QPS、响应时间、GC 停顿、CPU/内存占用。
  • 调优流程：发现问题 → 定位瓶颈 → 制定优化 → 验证效果 → 回归监控。
  • 瓶颈类型：CPU、内存、IO（磁盘/网络）、锁竞争、GC。
  • 原则：先测量再优化，禁止凭感觉优化；小步验证。

常见性能问题与对策¶

问题 症状 对策
GC 频繁 YGC 次数多、CPU 高 堆调大、减少对象创建、检查大对象
Full GC 停顿 长暂停、响应超时 老年代空间/晋升阈值；G1 分区调优
内存泄漏 堆缓慢增长、OOM dump 分析强引用链（集合静态持有等）
死锁 线程 BLOCKED、服务挂起 jstack 定位两把锁交叉
CPU 高 单核跑满 火焰图定位热点；算法优化/缓存
IO 阻塞 磁盘/网络等待高 异步化、批量、连接复用

常见坑¶

  1. 未测量就优化：先采集数据，用数据说话。
  2. -Xmx 无限调大：堆大 GC 停顿大；合理压测取平衡。
  3. 日志过度：生产 Debug 日志爆量拖垮 IO；用异步日志（Log4j2 Async）。
  4. 深拷贝/反射滥用：热点路径避免反射，用字节码增强或直接调用。
  5. N+1 查询：ORM 懒加载循环访问；用 join fetch/批量查询。
  6. 线程池参数混乱：任务队列无限、线程数过多；按业务模型配置。
  7. 缓存穿透/击穿/雪崩：空值缓存、互斥锁、多级缓存+过期抖动。

最佳实践¶

  • 建立压测基线（JMH 微基准、JMeter 接口压测），优化前后对比。
  • 监控先行：GC 日志、Prometheus+JVM 指标、慢 SQL 日志。
  • 优化点优先级：数据库/IO > 算法/数据结构 > GC > 微调参数。
  • 缓存尽量靠近读取端（本地缓存 → Redis → DB 多级）。
  • 结合 12-JVM基础 理解 GC，11-多线程与并发 正确并发。
