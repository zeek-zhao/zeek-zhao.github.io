综合实战：任务看板应用

[!info] 本页概览
综合运用全套 Vue 知识，从零构建”任务看板”应用：需求设计、目录结构、核心代码（路由、状态、组件、请求、测试、部署），演示真实项目全流程。

需求与设计

功能：

  1. 登录与权限（路由守卫）
  2. 任务看板（列表/新增/状态流转）
  3. 任务详情（动态路由）
  4. 全局状态（Pinia）+ 请求封装
  5. 测试与部署

技术栈：Vue 3 + Vite + TypeScript + Vue Router + Pinia + Axios + Vitest。

常见坑

  1. 状态流转未持久化：本地状态刷新丢失；接入后端 API 或 localStorage 兜底。
  2. 过滤逻辑重复：多处 filter 时抽 getter/computed 统一。
  3. 表单未做防抖/校验：连续提交重复创建；提交 loading + 校验。
  4. 路由守卫异步初始化：token 校验涉及异步请求时 await 后再放行。
  5. 组件过度耦合 store：纯展示组件用 props/emit，容器组件连 store。
  6. 缺少错误态：加载失败要有重试与提示，避免白屏。

最佳实践

  • 看板类应用核心是状态机（todo/doing/done），用 store 集中管理。
  • 组件拆分遵循”展示/容器”分层。
  • 数据流单向：父 → 子 props，子 → 父 emit，全局 → store。
  • 完成即测：store 单测 + 关键组件测试 + E2E 冒烟。
  • 上线后监控：错误上报 + 性能指标（见 20-性能优化）。
