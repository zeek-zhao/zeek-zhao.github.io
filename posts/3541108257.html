打包发布

[!info] 本页概览
本文讲解 Python 项目打包发布：pyproject.toml 现代规范、构建 wheel/sdist、发布到 PyPI、pip install -e . 本地开发，以及常见打包陷阱。

核心概念

  • pyproject.toml：现代 Python 打包标准（PEP 621），替代 setup.py/setup.cfg。
  • wheel（.whl）：预构建分发格式，安装快。
  • sdist（.tar.gz）：源码分发，可在任意环境构建。
  • 发布流程：构建 → 检查 → 上传 PyPI → 打版本 tag。

常见坑

  1. 忘加包发现配置：setuptools 找不到 mycli 包，报”no packages found”；配置 [tool.setuptools.packages.find]。
  2. pip install -e . 后 import 不到：检查包目录与 __init__.py 命名是否匹配。
  3. README 引用相对路径：PyPI 展示失败；用绝对 URL 或内嵌。
  4. 发布后忘记 python -m build 清理：dist/ 残留旧版本，上传前 rm -rf dist build *.egg-info。
  5. __init__.py 写死版本：__version__ 与 pyproject 双维护易不同步，用动态读取或构建工具注入。
  6. 密码/令牌入库：上传凭证用环境变量，不提交到 git。

最佳实践

  • 从项目第一天就维护 pyproject.toml 与 src/ 布局。
  • CI 发布：GitHub Actions 打 tag 自动 build + twine upload。
  • 用 uv build/uv publish（若用 uv）简化流程。
  • 发布前在干净虚拟环境 pip install dist/*.whl 冒烟测试。
  • 开源项目加 LICENSE、CHANGELOG.md、SECURITY.md。
