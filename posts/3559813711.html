日志与调试工具

[!info] 本节目标
掌握 ROS2 日志系统、日志级别控制、ros2 doctor 诊断与常用调试工具链。

1. 日志系统

ROS2 日志输出到 stdout（默认）并可通过 RCLCPP_INFO / get_logger().info 控制。

级别 用途
DEBUG 调试细节
INFO 常规信息
WARN 警告
ERROR 错误
FATAL 致命

[!note] 按节点设置
--log-level pkg:=level 只对该包节点生效；全局用 --log-level level。

2. 日志 API

[!tip] 结构化日志
生产系统可接入 ROS2 日志外部重定向（如 rsyslog、文件），或使用 --ros-args --log-file。

3. ros2 doctor

检查项 说明
网络/环境 DDS 配置
系统 依赖、版本
权限 用户组（dialout 等）

[!warning] 常见环境问题
未 source setup.bash、ROS_DOMAIN_ID 冲突、多网卡 DDS 选择错误。

4. 话题与节点调试

[!tip] –field
ros2 topic echo --field data 只打印字段，减少刷屏；--once 只取一帧。

5. 服务/动作调试

6. 其他调试工具

工具 用途
ros2 param list/get/set 参数调试
rqt_graph 节点/话题图
rqt_console 日志可视化
rqt_reconfigure 动态参数
ros2 bag record/play 数据回放（见 35/36 相关）
ros2 run tf2_tools view_frames TF 树

[!note] rqt 系列
rqt_graph 图形化查看通信拓扑，rqt_console 集中查看日志，排查断链最直观。

7. 调试流程建议

[!tip] 系统日志
内核/系统级问题看 dmesg；进程崩溃用 gdb 或 core dump；内存用 top/htop。

8. 常见问题

问题 排查
日志不输出 --log-level 设置、输出重定向
话题间歇 QoS、网络、回环
doctor 报网络错 多网卡/防火墙/DDS 配置
节点假死 回调阻塞、线程不足

[!note] 延伸
更多排查见 36-常见问题排查；性能分析见 35-性能优化与Benchmark。

8. 调试方法论

调试遵循”先定位后修复”原则：先用 ros2 doctor 检查环境与系统健康，再用 node/topic/service 列表确认拓扑，最后用 echo/hz/delay 观察数据流。日志级别按场景调整，开发期用 debug，现场用 info 或 warn 控制输出量。疑难问题善用 rosbag 录制现场数据离线复现，配合 rqt_console 与 rqt_graph 分析。每次修复后记录根因与解决方案，沉淀为团队排障手册，减少重复踩坑。

[!note] 建议
调试能力决定开发效率，掌握系统化方法后可快速定位大多数问题；常见问题速查见 36-常见问题排查。
