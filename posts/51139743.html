实战：从零到上线完整流程

项目定位与目标¶

开始动手前先明确要做什么。本实战案例的目标是：用 Hexo 把 Obsidian 个人知识库以网站形式优雅展示，依托 GitHub Pages 免费托管、GitHub Actions 自动部署，达成”在 Obsidian 里写笔记，git push 后网站自动更新”的体验。这个目标决定了全部技术选型：内容源在 Obsidian、构建层用 Hexo、托管走 GitHub、自动化靠 Actions。

第二阶段：主题选型与配置¶

知识库型站点对主题的要求高于普通博客：需要目录导航、搜索、分类体系、移动端适配。经过对知识库类主题的调研比较，Butterfly 在功能丰富度、文档质量与社区活跃度上综合最优，选定为主题。安装与基础配置流程见 05-主题推荐与对比 与 06-Butterfly主题全面指南：

随后依次完成：基础外观（配色、头像、banner）、首页布局、文章页优化（TOC、代码高亮、复制按钮）、自定义 CSS（不改主题源码，用 inject 注入样式）、响应式检查。侧边栏定制与分类标签体系的建立参考 07-Butterfly自定义侧边栏 与 08-Butterfly分类与标签系统。

🔥配置节奏
主题配置不要追求一次到位。先跑通”能看 → 能搜 → 好看”三步，每完成一块就 hexo server 验证一次，用测试文章验证效果再继续，避免大量配置堆叠后找不到问题出在哪。

内容规划上，建议启动时就放入两类种子内容：一篇”关于本站”说明知识库定位；一两个完整的知识主题示范（如一个 MOC 索引页加几张原子笔记），检验双链与分类体系在真实内容下的表现。文章的模板语法（label、note、tabs、gallery）参考 Butterfly 的标签系统，写一篇包含各元素的综合测试文备用。

第四阶段：自动部署上线¶

配置 12-GitHub Actions自动部署 的完整链路：

  1. 生成专用 Ed25519 密钥对，公钥填部署仓库 Deploy Key（勾选写权限），私钥填源码仓库 Secret DEPLOY_KEY。
  2. 部署目标设定为 git@github.com:zeek-zhao/zeek-zhao.github.io.git 的 gh-pages 分支。
  3. 提交 .github/workflows/deploy.yml（工作流全文见第 12 篇），推送到 main 触发首次自动构建。
  4. 在 GitHub 仓库 Settings > Pages 中确认发布分支为 gh-pages。

几分钟后访问 username.github.io，站点正式上线。首次上线重点检查：域名可达、搜索可用、图片加载、移动端排版。国内访问慢的话，此时再决定是否迁移 Cloudflare Pages 并绑定自定义域名（见 11-部署方式总览）。

第六阶段：日常运维¶

上线后的运维循环被压到极简：写作 → Obsidian 标记 status → npm run build → git push → 自动上线。定期任务则交给 Actions 的 schedule 定时触发与通知系统：失效链接检查、SEO 检测、性能指标监控。出问题查 21-常见问题排查，重大主题升级前在本地分支验证。

📝2026 更新
静态站生成器领域 Hugo/Astro 势头正盛，Hexo 靠深厚的中文主题生态（Butterfly、NexT 等）依然保持旺盛生命力，对以内容为中心的个人知识库而言仍是稳妥选择。同时注意 Node.js 版本管理：新项目直接用 Node 18/20 LTS，老项目升级时先在 CI 中验证构建兼容性。

里程碑清单¶

最后用一份清单确认交付完整性：

  • 环境与依赖装齐，hexo server 本地跑通
  • Butterfly 主题配置完成，测试文章渲染正常
  • Obsidian 同步管线就绪，status 过滤与双链转换验证通过
  • Actions 自动部署成功，username.github.io 可访问
  • 搜索、RSS、sitemap、评论按需就位
  • 性能基线测量完成（Lighthouse 分数记录在案）
  • 运维文档写好（哪怕只是 README 里的命令清单）

走完这条流水线，你拥有的不只是一个博客，而是一套可持续运转的个人知识发布系统。
