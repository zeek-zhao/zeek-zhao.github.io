备份与升级

[!abstract] 保命策略
Jira 数据 = 数据库 + 附件/索引/配置。备份恢复必须演练；升级遵循”先备份、测试环境验证、再上生产”。

1. 备份什么

内容 位置
元数据（问题、项目、配置） 数据库（PostgreSQL/MySQL）
附件 jira.home/data/attachments/
头像/图标 data/avatars/
索引 caches/、plugins/（可重建）
配置 dbconfig.xml、jira-application.properties

2. 数据库备份（推荐主方案）

[!note] 一致性
数据库与附件要同一时间点备份：先停服务或短暂只读，再备份附件+库，避免附件与元数据错位。

3. Jira 自带备份（XML）

⚙ → System → Backup（或 Backup Manager）：

[!warning] 限制
XML 备份恢复在大实例上很慢、附件超过阈值可能失败；生产建议用数据库+附件 tar 方案，XML 作补充。

4. 备份脚本（cron）

5. 升级步骤

[!tip] 升级前必做

  • 读 release notes（schema 迁移、配置变更、插件兼容）；
  • 测试环境用备份数据演练升级；
  • 升级插件顺序：先 Jira 版本，再兼容插件；
  • 跨大版本分步升级（8→9 直接升风险高）。

6. 恢复验证清单

[!warning] 红线
每月至少一次恢复演练；备份脚本要监控成功/失败告警。
