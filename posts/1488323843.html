ros2 05-命令行工具

发表于2026-10-24|ros2
|浏览量:

命令行工具

[!info] 本节目标
熟练使用 ros2 命令行工具进行节点、话题、服务、动作、参数的全方位检查与操作。

1. ros2 命令总览

2. 节点命令

命令 说明
ros2 node list 列出所有节点
ros2 node info <node> 显示该节点的发布/订阅/服务/动作/参数

3. 话题命令

[!tip] 常用组合
ros2 topic list -t 同时显示类型；ros2 topic info -v 显示 QoS 详情（排障利器）。

4. 服务命令

[!warning] YAML 语法
ros2 service call 的参数必须是合法 YAML；复杂嵌套用单引号包裹，如 "{pose: {x: 1.0, y: 2.0}}"。

5. 动作命令

[!note] 反馈显示
加 --feedback 实时显示动作反馈；--goal 可修改目标超时等。

6. 参数命令

[!tip] 参数持久化
用 ros2 param dump 导出，在 launch 中通过 --params-file 加载，实现参数可复现。

7. 包与 launch 命令

8. 诊断命令

[!warning] daemon 缓存
ros2 node list 依赖后台守护缓存；若列表不刷新，执行 ros2 daemon stop 后重试。

9. 综合排查示例

现象 排查命令
话题无数据 ros2 topic info -v 看 QoS、ros2 topic hz 看频率
找不到节点 ros2 node list、ros2 daemon stop
服务调用失败 ros2 service list、ros2 service type
参数不生效 ros2 param list、launch 参数文件

[!note] 延伸
各命令背后的通信机制见 03-核心概念；更多调试技巧见 20-日志与调试工具。

8. 命令行效率技巧

命令行是 ROS2 新手最直观的入口，也是进阶者的日常伴侣。

调试时先 ros2 node list 与 ros2 topic list 确认系统拓扑，再针对性使用 topic info -v 查看 QoS 与连接，最后用 topic echo 观察数据内容，这一顺序能快速定位绝大多数通信问题。ros2 interface show 可随时查看消息字段定义，写代码前先确认字段名。别名可缩短高频命令输入，但脚本中应使用完整命令保证可读性。掌握命令行后，可结合 rqt_graph 图形化确认节点关系，两者互补。

[!note] 建议
命令行工具是 ROS2 诊断的第一手段，深入理解各子命令后再进入编程章节，排查效率会显著提升；更多排障见 36-常见问题排查。
