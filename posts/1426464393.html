GitLab 简介与架构

[!info] 本篇目标
理解 GitLab 是什么、能解决什么问题，以及它背后的核心组件架构，为后续安装部署和日常运维打下基础。

1. 什么是 GitLab

GitLab 是一个开源的 DevOps 生命周期平台，它不只是 Git 代码托管工具，还集成了 CI/CD、代码评审、容器镜像仓库、依赖管理、安全扫描、监控、Wiki 与 Issue 追踪 等能力。与 GitHub、Gitea 相比，GitLab 最突出的特点是：

  • 单一应用（Single Application）：从代码提交到部署上线的完整链路都在一个平台内闭环，无需拼装多款工具。
  • 内建 CI/CD：.gitlab-ci.yml 声明式 Pipeline，天然与 MR 集成，支持 Review Apps。
  • 企业级能力：成熟的权限模型、审计日志、合规框架，适合内网私有化部署。
  • 开源可选：社区版（CE）免费，企业版（EE）提供更多高级能力。

2. 核心组件架构

GitLab 采用 单体 Rails 应用 + 微服务化周边组件 的架构。以 Omnibus 安装的典型单机拓扑为例：

  • Nginx：统一入口，处理 TLS、访问控制与静态文件。
  • GitLab Workhorse：位于 Rails 之前的 Go 组件，处理 Git HTTP/SSH 协议细节、大文件上传，减少 Rails 负担。
  • Puma：Ruby Web 服务器，承载 Web 与 API 请求。
  • Sidekiq：后台任务处理器，负责邮件、Webhook、Pipeline 调度等异步工作。
  • PostgreSQL：主数据库，存放元数据、用户、权限、CI 记录。
  • Redis：缓存与 Sidekiq 队列存储。
  • Gitaly：Git RPC 服务，所有 Git 操作最终由它读写裸仓库，支持多节点水平扩展。

[!tip] 记忆口诀
对外看 Nginx，业务看 Puma，异步看 Sidekiq，数据看 PostgreSQL，仓库看 Gitaly。

4. 版本选型

维度 GitLab CE GitLab EE（Trial/付费）
价格 免费 按用户订阅
MR 审批规则 基础 高级规则、合规框架
安全扫描 无（依赖第三方） SAST/DAST/依赖扫描内建
审计 基础 全面审计事件
高可用 需自行搭建 官方支持 Geo、HA 参考

[!warning] 版本提示
自 2023 年起 GitLab 调整策略，部分原 CE 能力并入 EE 免费层（Free tier）。选型时以官方版本功能矩阵为准，商业决策前先试用 EE Trial。

5. 适用场景判断

  • 团队内网开发：私有化部署首选，代码不出内网，安全可控。
  • 已有 GitHub 但缺 CI 一体化：可用 GitLab 承接流水线，或直接迁移。
  • 中小团队全栈 DevOps：一个 GitLab 顶替 Git + Jenkins + Artifactory + 部分 Sonar 的组合。
