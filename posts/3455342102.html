工程实践与项目架构

ℹ️本页概览
本文讲解 Vue 中大型项目工程实践：目录分层、路由与权限架构、请求层封装、状态与错误处理、代码规范、多环境配置，建立可扩展的团队协作体系。

核心概念¶

  • 架构目标：职责分层、易扩展、可维护、团队一致。
  • 分层：视图层（views）→ 组件层（components）→ 状态层（stores）→ 数据层（api）。
  • 请求层统一封装：拦截器、错误提示、token、取消。
  • 规范：目录、命名、ESLint、提交信息。

代码规范与协作¶

  • 组件命名 PascalCase 多词；目录 kebab-case。
  • 提交信息规范：feat: / fix: / refactor:。
  • pre-commit：husky + lint-staged 跑 lint/format。
  • Code Review：props 类型、错误处理、可测试性。

常见坑¶

  1. 模块间循环依赖：api → store → router 互相引用易循环；用延迟引用或解耦。
  2. 拦截器误吞错误：401 刷新 token 与跳转重入，防止死循环。
  3. 目录过度分层：小项目套大架构反成负担；按规模选型。
  4. 硬编码 baseURL：各环境 API 不同，统一走 .env。
  5. 全局组件污染：基础组件全局注册适度，避免命名冲突。
  6. 提交不规范：无约定导致回滚困难；用 commitlint。

最佳实践¶

  • 架构随业务演进：先功能分层，规模再上升领域分层（modules）。
  • 请求层统一出入口，禁止组件内裸 fetch（特殊场景除外）。
  • 状态只放”跨组件/全局”数据，页面数据组件内管理。
  • 文档即规范：README、架构决策记录（ADR）进仓库。
  • 定期重构：依赖升级、废弃代码清理、性能基线跟踪。
