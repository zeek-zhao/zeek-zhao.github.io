备份恢复

ℹ️本篇目标
掌握 GitLab Omnibus 备份策略：备份命令、密钥备份、恢复流程与容灾演练，确保数据可随时还原。

1. 备份的对象¶

GitLab 数据分两部分：

  1. 应用数据：PostgreSQL、仓库、上传文件、CI 数据（gitlab-backup create）
  2. 密钥与配置文件：/etc/gitlab/gitlab-secrets.json、/etc/gitlab/gitlab.rb、SSH 主机密钥
⚡密钥丢失 = 数据不可读
若丢失 gitlab-secrets.json，即使有备份也无法解密既有数据（CI 变量、Runner 令牌、2FA 相关加密）。密钥与配置必须单独备份。

4. 恢复流程¶

恢复必须在全新安装的同版本实例上进行（或同一版本降级环境）：

⚠️版本一致
备份 tar 只能恢复到 相同主版本（或升级路径允许的版本）。大版本升级后旧备份可能无法直接恢复，详见 11-升级迁移。

5. 部分恢复（Rails console / 单对象）¶

  • 单个仓库误删：从备份 tar 中提取对应仓库目录，或用 Git 端 git push --mirror 从远程镜像恢复。
  • 误删用户/组：Web UI 删除前可在 Admin 审计日志中追溯，重要对象建议启用”删除需二次确认”。

6. 容灾演练清单¶

⚡演练即检验
没有验证过的备份等于没有备份。恢复演练暴露的问题（密钥缺失、版本不匹配、磁盘不足）必须在真实灾难前解决。
