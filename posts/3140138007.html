根文件系统类型与构建方法

很多人把根文件系统当成一个笼统的词，但真正动手时你会发现，它既可以指根目录 / 下那一堆目录，也可以指内存里的 initramfs、Flash 上的 UBIFS，甚至远程的 NFS。我在做嵌入式开发时最常踩的坑，就是没先想清楚存储介质就去选文件系统类型。

这篇从基础概念讲起，把手动构建、Buildroot、Yocto、debootstrap 几条路子都过一遍，再深入到 initramfs、闪存文件系统和网络文件系统，最后给出裁剪、优化、备份恢复的具体做法。

1. 根文件系统基础：挂载点与核心目录的职责¶

1.1 什么是根文件系统¶

根文件系统是操作系统启动过程中挂载的第一个文件系统，包含系统引导和运行所需的基本目录和文件。在Linux系统中，根文件系统挂载在根目录（/）上，为整个系统提供基础环境。我一般会先按下面这张目录清单核对一遍，缺哪个目录，启动阶段大概率就会报错。

根文件系统通常包含以下关键部分：

  • /bin和/sbin: 存放基本命令和系统管理命令
  • /etc: 配置文件目录
  • /lib: 系统库文件目录
  • /dev: 设备文件目录
  • /proc和/sys: 虚拟文件系统挂载点
  • /var: 存放变量数据的目录
  • /tmp: 临时文件目录
  • /usr: 用户程序和数据存放目录
  • /home: 用户主目录

1.2 文件系统类型概览¶

在Linux系统中，根据存储介质和使用场景的不同，文件系统可以分为多种类型：

1.2.1 内核生成的文件系统

  • procfs: 进程文件系统，提供系统运行信息
  • sysfs: 设备文件系统，提供设备和驱动信息
  • devtmpfs: 设备文件系统，自动创建设备节点
  • debugfs: 调试文件系统，用于内核调试
  • configfs: 用户空间配置内核对象的文件系统

1.2.2 基于存储设备的文件系统

  1. 内存文件系统

    • tmpfs: 临时文件系统，使用RAM和swap空间
    • ramfs: RAM文件系统，只使用RAM，无大小限制
    • ramdisk: 将一部分RAM模拟为磁盘，需要格式化
    • initramfs: 初始化RAM文件系统，作为启动初期的临时根文件系统

  2. Flash文件系统

    • cramfs: 只读压缩文件系统，适合小型嵌入式系统
    • squashfs: 只读压缩文件系统，支持高压缩比和更大文件
    • jffs2: 日志闪存文件系统，适用于NOR Flash，支持写平衡
    • yaffs2: 日志闪存文件系统，适用于NAND Flash，支持坏块管理
    • ubifs: 大容量日志闪存文件系统，基于UBI层，适合大容量NAND Flash

  3. 磁盘文件系统

    • ext2/ext3/ext4: Linux标准文件系统系列，稳定可靠
    • btrfs: 新一代Linux文件系统，支持快照、校验和等高级功能
    • xfs: 高性能文件系统，适合大容量存储
    • f2fs: 闪存友好型文件系统，针对SSD和eMMC优化

  4. 可移动存储文件系统

    • FAT16/FAT32/exFAT: 兼容性好，适用于跨平台
    • NTFS: Windows文件系统，在Linux下需特殊支持

  5. 网络文件系统

    • NFS: 网络文件系统，Unix/Linux间共享
    • Samba/CIFS: Windows与Linux之间共享机制
    • SSHFS: 基于SSH协议的文件系统

1.3 根文件系统的启动流程¶

根文件系统在Linux启动过程中扮演关键角色：

  1. 引导加载阶段：

    • 引导加载器(如GRUB、U-Boot)加载内核和初始化RAM磁盘(initramfs/initrd)
    • 内核解压并初始化核心硬件

  2. 内核初始化阶段：

    • 内核挂载初始rootfs(通常是initramfs)
    • 执行初始化脚本(/init)

  3. 根文件系统切换：

    • 识别并挂载实际的根文件系统
    • 可能通过switch_root从initramfs切换到真正的根文件系统

  4. 系统初始化阶段：

    • 执行根文件系统中的初始化进程(如SysVinit、Systemd、OpenRC等)
    • 启动系统服务和用户空间程序

3.3.6 网络根文件系统调试和优化

3.3.6.1 常见问题及解决方案

  1. 网络连接问题

    • 现象：开发板无法连接到NFS服务器
    • 解决方案：
      1. 检查网线连接和网络设备
      2. 确认IP地址配置正确
      3. 使用ping命令测试连接
      4. 检查防火墙设置，必要时临时禁用：sudo ufw disable

  2. NFS挂载失败

    • 现象：内核启动时报NFS挂载错误
    • 解决方案：
      1. 检查NFS服务是否正常运行：sudo service nfs-kernel-server status
      2. 确认导出目录权限：cat /etc/exports
      3. 检查NFS版本匹配，尝试指定不同版本：vers=3或vers=4
      4. 查看服务器日志：sudo journalctl -u nfs-kernel-server

  3. 内核加载失败

    • 现象：无法通过TFTP加载内核或设备树
    • 解决方案：
      1. 检查TFTP服务是否正常运行：sudo service tftpd-hpa status
      2. 确认文件权限和所有者：ls -la /tftpboot/
      3. 测试TFTP服务：使用TFTP客户端从另一台机器下载测试

  4. 文件系统权限问题

    • 现象：挂载成功但无法创建文件或修改权限
    • 解决方案：
      1. 确认NFS导出选项包含no_root_squash
      2. 检查目录权限：ls -la /home/user/nfsroot/
      3. 修改共享目录的所有者：sudo chown -R nobody:nogroup /home/user/nfsroot/
3.3.6.2 性能优化

  1. NFS优化

    • 协议选择：

      • UDP通常比TCP更快，但可靠性低：nfsroot=...,udp
      • 对于不稳定网络，应使用TCP：nfsroot=...,tcp

    • 缓存优化：

      • 增加读写缓冲区大小：rsize=8192,wsize=8192
      • 例如：nfsroot=...,rsize=8192,wsize=8192,udp

    • 挂载选项：

      • 异步模式提高性能但降低数据安全性：async
      • 例如：nfsroot=...,async

  2. 网络优化

    • 使用交换机而非集线器
    • 使用千兆网而非百兆网
    • 调整网卡参数：
    • 减少网络拥塞：为NFS服务器和开发板配置专用网络

3.3.8 网络根文件系统的应用场景

3.3.8.1 开发和调试环境

网络根文件系统在开发和调试阶段特别有价值，可以：

  • 快速测试软件更改，无需重新烧录
  • 方便使用主机上的开发工具
  • 简化日志收集和分析过程
  • 允许多人同时在同一环境中开发
3.3.8.2 产品测试和质量控制

在测试环境中使用网络根文件系统可以：

  • 确保所有设备使用完全相同的文件系统
  • 方便在测试中快速更新软件
  • 集中收集测试日志和结果
  • 简化批量设备测试流程
3.3.8.3 生产环境中的考量

在生产环境中，通常不会使用网络根文件系统，因为：

  • 需要稳定独立运行
  • 网络依赖会增加故障点
  • 性能和安全考虑

生产系统通常会将开发阶段的网络根文件系统转换为本地存储的文件系统。

    • 实施适当的安全强化措施

  4. 验证和测试：

    • 全面测试本地存储的系统行为
    • 验证启动时间和性能参数
    • 测试系统恢复和容错能力

9.3 根文件系统规划策略¶

在设计嵌入式系统时，建议采用以下分区策略：

  1. 引导分区：包含引导加载器和内核
  2. 系统分区A：只读根文件系统
  3. 系统分区B：用于A/B系统更新
  4. 配置分区：存储系统配置
  5. 数据分区：用户数据和应用数据
  6. 恢复分区：用于系统恢复

我自己的做法是先把引导、系统 A/B、数据这三块划出来，够用就别再切更细；分区一多，后续 OTA 和镜像管理的复杂度会成倍上升。
