BareMetal ARM S3C2440 时钟体系结构

裸机把 S3C2440 跑起来，第一道坎往往不是代码，而是时钟。我一般先把数据手册里的寄存器地址抄下来核对一遍，别凭记忆写，地址错一位整个系统就没反应。

1. 芯片底子：ARM920T 内核加一整套片上外设¶

S3C2440 是三星（Samsung）推出的一款基于 ARM920T 核心的 32 位微控制器，广泛应用于嵌入式系统开发。作为一款 System-On-Chip（SOC），S3C2440 不仅集成了 ARM920T 处理器核心，还包含丰富的外设资源，如 LCD 控制器、存储控制器、DMA 控制器、USB 控制器、多个串口、中断控制器等。

S3C2440 的主要特性包括：

  • 使用 0.13μm CMOS 工艺制造
  • 基于 ARM920T 内核，16KB 指令缓存，16KB 数据缓存
  • MMU（内存管理单元）支持虚拟内存管理
  • 最高工作频率 400MHz
  • 功耗控制功能，支持正常模式、空闲模式和睡眠模式
  • 丰富的外设接口和控制器

2. 时钟基础：晶振经 PLL 倍频后分给各模块¶

时钟系统是嵌入式系统的核心部分之一，它为芯片中的各个模块提供时钟信号，控制整个系统的运行速度。了解芯片的时钟系统对于优化系统性能和功耗至关重要。我理解它的主线就一条：晶振给参考，PLL 倍频，再分频下发。

2.1 时钟信号的四个作用¶

时钟信号在数字系统中主要有以下几个作用：

  • 同步控制：为系统提供统一的时间基准，使各个部件能够协调工作
  • 速度控制：通过调整时钟频率，可以控制芯片的工作速度
  • 功耗管理：降低时钟频率或关闭不需要的时钟可以降低系统功耗
  • 时序控制：保证各种操作在正确的时序下进行

2.2 晶振与时钟源：压电效应产生稳定振荡¶

芯片的时钟通常来源于外部晶振。晶振利用石英晶体的压电效应，在通电后会产生稳定的振荡信号。这种信号经过芯片内部的时钟电路处理后，形成系统所需的各种时钟。

2.3 锁相环：把参考时钟倍频上去¶

锁相环（Phase-Locked Loop, PLL）是一种能够从输入参考时钟信号产生高频输出时钟信号的电路。PLL 可以对输入时钟进行倍频，产生比输入时钟频率更高的时钟信号，使芯片能够工作在更高的频率。

3. 时钟体系：FCLK、HCLK、PCLK 三层分频¶

S3C2440 的时钟系统相对复杂，它支持多种时钟源，并通过 PLL 和分频器生成不同频率的时钟信号供芯片内部各个模块使用。踩过的坑是把 HCLK 和 PCLK 的顺序记反，结果外设全不工作。

3.1 整体架构：三个层次的硬件模块¶

S3C2440 芯片的时钟系统可以从参考手册的 Block Diagram 中看出：

从功能上可以将 S3C2440 的硬件模块分为三个层次：

  • 上层：与 CPU 密切相关的模块，工作于 FCLK（Fast Clock）
  • 中层：对性能要求较高的模块，如 LCD 控制器、相机接口等，工作于 HCLK（AHB Bus Clock，High-speed Clock）
  • 下层：对性能要求不高的外设模块，工作于 PCLK（APB Bus Clock，Peripheral Clock）

3.2 时钟源与 PLL：OM[3:2] 选择后送 MPLL/UPLL¶

S3C2440 有两个主要的时钟源：

  1. **外部晶振(EXTCLK)**：通常为 12MHz 的晶振，作为输入时钟源
  2. **外部时钟(EXTCLK)**：从外部提供的时钟信号

这些输入时钟通过选择器（由 OM[3:2] 控制）选择一个作为系统时钟源，然后送入两个 PLL：

  • **MPLL(Main PLL)**：主 PLL，为系统的主要时钟源，提供 FCLK
  • **UPLL(USB PLL)**：USB PLL，为 USB 控制器提供时钟

3.3 三个时钟域：FCLK ≥ HCLK ≥ PCLK¶

S3C2440 内部有三个主要的时钟域：

  1. **FCLK(Fast Clock)**：

    • 处理器核心时钟
    • 由 MPLL 直接产生
    • 最高可达 400MHz
    • 用于 CPU 核心和与 CPU 紧密耦合的模块

  2. **HCLK(AHB Bus Clock)**：

    • 高速总线时钟
    • 由 FCLK 分频产生
    • 最高可达 136MHz
    • 用于 AHB 总线上的高速外设，如 LCD 控制器、DMA 等

  3. **PCLK(APB Bus Clock)**：

    • 外设时钟
    • 由 HCLK 分频产生
    • 最高可达 68MHz
    • 用于 APB 总线上的低速外设，如 UART、I2C、SPI 等

4. 控制寄存器：LOCKTIME、MPLLCON、CLKDIVN 是核心¶

S3C2440 提供了一系列寄存器用于配置和控制时钟系统。以下是主要的时钟控制寄存器。实测下来 LOCKTIME 直接用 0xFFFFFFFF 最省事，别去抠手册的推荐值。

4.1 LOCKTIME(0x4C000000)：设 PLL 锁定时间¶

LOCKTIME 寄存器用于设置 PLL 锁定时间。当 PLL 设置发生变化时，需要一定的时间来稳定输出频率，这个时间就由 LOCKTIME 寄存器控制。

4.2 MPLLCON(0x4C000004)：MDIV/PDIV/SDIV 决定 FCLK¶

MPLLCON 寄存器用于配置 MPLL 的参数，决定 FCLK 的频率。它包含三个主要字段：

  • **MDIV[19:12]**：M 值，用于设置 PLL 倍频系数
  • **PDIV[9:4]**：P 值，用于设置 PLL 预分频系数
  • **SDIV[1:0]**：S 值，用于设置 PLL 后分频系数

4.3 UPLLCON(0x4C000008)：USB 专用 PLL¶

UPLLCON 寄存器用于配置 UPLL 的参数，与 MPLLCON 结构类似，但专门用于 USB 控制器。

4.4 CLKDIVN(0x4C000014)：分频比与异步模式¶

CLKDIVN 寄存器用于设置 FCLK、HCLK 和 PCLK 之间的分频比例，包含以下字段：

  • **HDIVN[2:1]**：设置 HCLK 与 FCLK 的分频比
  • **PDIVN[0]**：设置 PCLK 与 HCLK 的分频比

当 HDIVN 不为 0 时，需要同时设置 CPU 为异步模式，否则系统会不稳定。

4.5 CAMDIVN(0x4C000018)：相机等模块的额外分频¶

CAMDIVN 寄存器用于设置相机接口和其他一些特殊模块的时钟分频。对于 HDIVN 的设置，有时也需要配合 CAMDIVN[9] 使用。

5. 配置实例：12MHz 晶振倍到 400MHz 的完整算例¶

下面通过一个典型的例子来说明如何配置 S3C2440 的时钟系统。假设我们使用 12MHz 的晶振，希望设置：

  • FCLK = 400MHz
  • HCLK = 100MHz
  • PCLK = 50MHz

我一般按手册的 PLL 值选择表挑参数，再拿公式验算一遍，比自己硬算快。

5.1 计算 PLL 参数：MDIV=92、PDIV=1、SDIV=1¶

首先，我们需要根据目标频率计算 MPLL 参数：

目标：FCLK = 400MHz = (2 * m * 12MHz) / (p * 2^s)

参考 PLL 值选择表，当输入为 12MHz，输出为 400MHz 时，建议设置：

  • MDIV = 92 (m = 92 + 8 = 100)
  • PDIV = 1 (p = 1 + 2 = 3)
  • SDIV = 1 (s = 1)

验算：(2 * 100 * 12) / (3 * 2^1) = 2400 / 6 = 400MHz ✓

5.2 设置分频比：HDIVN=2、PDIVN=1¶

接下来设置 HCLK 和 PCLK 的分频比：

  • HCLK = FCLK / 4 = 100MHz，需要设置 HDIVN = 2（二进制10）
  • PCLK = HCLK / 2 = 50MHz，需要设置 PDIVN = 1

6. 异步模式：HCLK 低于 FCLK 时必须打开¶

当 HDIVN 不为 0，即 HCLK 频率低于 FCLK 时，ARM 核心与 AHB 总线工作在不同的频率下。此时，为了确保系统稳定运行，需要设置 CPU 为异步模式。

6.1 为什么需要：不同步会出时序错误¶

在默认的同步模式下，ARM 核心期望总线时钟与核心时钟同步。当 HCLK 与 FCLK 不同步时，如果仍然使用同步模式，会导致时序错误，引起系统不稳定或崩溃。

  • iA 位(bit30)：设置为 1，使能异步总线模式

6.3 影响：多一层同步逻辑换稳定¶

启用异步模式后，ARM 核心与总线之间会增加同步逻辑，确保在不同时钟频率下的正确通信。这可能会增加一些延迟，但相比系统不稳定，这种延迟是可以接受的。

7. 性能影响：频率、总线、外设与功耗的权衡¶

时钟系统配置直接影响系统的性能和功耗。我一般先定 FCLK，再看 HCLK、PCLK 能压到多少，功耗是最后权衡的。

7.1 处理性能：FCLK 定指令速度¶

FCLK 频率决定了 CPU 的指令执行速度。较高的 FCLK 可以提高 CPU 处理速度，但也会增加功耗和发热。

7.2 总线性能：HCLK 定 AHB 带宽¶

HCLK 频率决定了 AHB 总线和连接在其上的外设的数据传输速率。较高的 HCLK 可以提高数据传输效率，特别是对于 LCD、DMA 等高带宽外设。

7.4 功耗与发热：频率越高越费电¶

时钟频率与芯片功耗和发热成正比。提高时钟频率会增加功耗，产生更多热量。在电池供电的设备中，平衡性能和功耗尤为重要。

10. 故障定位：不启动、串口乱码、计时不准与功耗高¶

在配置 S3C2440 时钟系统时，可能遇到的一些常见问题及其解决方案。踩过的坑是改了 MPLL 却忘了重算 UBRDIV，串口直接乱码。

10.1 不启动或不稳定：先查异步模式与 PLL¶

问题：配置时钟后系统不稳定或完全无法启动
可能原因：

  • 未设置异步模式
  • PLL 参数计算错误
  • LOCKTIME 设置不足

解决方案：

  • 确保在设置 HDIVN>0 时启用异步模式
  • 仔细检查 MPLL 参数计算
  • 设置 LOCKTIME 为最大值(0xFFFFFFFF)
  • 尝试使用已知稳定的保守配置

10.2 串口乱码：按新 PCLK 重算 UBRDIV¶

问题：配置时钟后串口通信异常（乱码或无输出）
可能原因：

  • PCLK 变化导致波特率改变
  • 串口初始化没有考虑新的 PCLK

解决方案：

  • 根据新的 PCLK 重新计算并设置 UBRDIV 值

10.3 计时不准：定时器时钟源随 PCLK 变¶

问题：定时器的计时不符合预期
可能原因：

  • 定时器使用 PCLK 作为时钟源
  • PCLK 改变导致计时改变

解决方案：

  • 根据新的 PCLK 重新计算定时器参数
  • 使用基于 HCLK 的定时器（如果可用）

10.4 功耗过高：降频并关掉不用模块的时钟¶

问题：系统功耗高于预期
可能原因：

  • 时钟频率设置过高
  • 未使用的模块时钟未关闭

解决方案：

  • 根据实际需求降低时钟频率
  • 关闭未使用模块的时钟

11. 收尾：先跑通保守配置，再逐项调频验证¶

S3C2440 的时钟系统复杂但可控，架构、寄存器、配置方法和常见故障都已经摊开在上面。我的做法是留一版已验证的保守配置，调不动就回退，别在起不来的板子上死磕。

通过合理配置 S3C2440 的时钟系统，可以实现以下目标：

  • 最大化系统性能，满足应用需求
  • 优化功耗，延长电池寿命
  • 保证系统稳定性，避免时序相关的问题
  • 为各种外设提供合适的时钟频率

下一步建议：先固定 FCLK 跑通串口和定时器，再逐项调 HCLK、PCLK，每改一次就用第 9 节的软件验证法测一遍 time_diff 比例。
