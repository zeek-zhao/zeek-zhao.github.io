12-时钟与定时器

发表于2026-10-24|Zephyr
|浏览量:

[!info] 本节目标
掌握 Zephyr 时钟与定时器机制。

1. 系统时钟

系统时钟由硬件定时器驱动，提供节拍与时间基准。节拍频率配置影响分辨率与开销。Zephyr 使用硬件时钟抽象，支持多种定时器驱动。

2. 内核定时器

k_timer 提供软件定时器，支持单次与周期模式。定时器回调在线程上下文执行，可绑定线程。创建、启动、停止与状态查询接口完整。

3. tickless 模式

tickless 在空闲时停止节拍，降低功耗。唤醒后补偿时间，保持调度正确。tickless 配置与时钟驱动配合，功耗优化关键。

4. 时间 API

k_uptime_get 获取运行时间，k_sleep 与 k_usleep 提供延时。时间单位换算统一，绝对与相对延时区分。时间 API 满足业务计时需求。

5. 定时器精度

定时器精度受硬件与节拍粒度影响，高精度需求使用硬件定时器。周期任务使用绝对定时减少漂移。精度评估按应用需求。

6. 低功耗与时钟

低功耗模式暂停系统时钟，唤醒补偿时间漂移。时钟驱动支持 tickless 暂停与恢复。功耗与时间精度平衡设计。

7. 实践建议

延时使用内核 API 而非忙等，周期任务稳定节奏。tickless 配置验证时间正确性，监控定时器负载。时间计算统一单位，避免误差累积。

8. 常见问题

定时器相关故障多与时间基准理解偏差有关。k_sleep 与 k_timer 基于内核节拍，精度受 CONFIG_SYS_CLOCK_HW_CYCLES_PER_SEC 与 tickless 影响；需要高精度延时用 k_busy_wait。周期任务直接用周期定时器而不要在回调里再次 sleep，避免漂移累积。tickless 模式下系统在空闲时停摆节拍，唤醒后需要补偿时间，若时钟驱动实现有缺陷会导致时间偏慢。多线程共享时间基准时，避免依赖相对延时的叠加，尽量使用绝对时刻安排任务。
