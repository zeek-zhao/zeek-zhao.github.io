28-Cyber异步调用机制

解析 Cyber RT 异步调用：Async/Yield 协程原语、TaskManager 有界任务队列与 SysMo 运行时监控。
📅 2026-10-25· 更新于 2026-10-25 ✍ zeek.zhao #系统#apollo
ℹ️本节目标
掌握 Cyber RT 的异步编程层：Async/Yield/SleepFor 原语、TaskManager 的协程池与有界队列实现、实模式/仿真模式双路径设计，以及 SysMo 对异步任务的监控手段。

本篇是第四阶段 Cyber RT 深度剖析的第四篇。组件的”消息驱动”路径由 29-Cyber数据系统详解 负责，本篇讲”代码主动并发”路径——cyber::Async 一行调用背后的完整基础设施，它同样构建在 26-Cyber调度系统详解 的协程之上。

1. 设计定位¶

自动驾驶软件反复出现这类需求：点云预处理耗时但不挡主流程、MPC 求解可能超时、路径要并行生成多方案。Cyber 的异步机制围绕五个目标设计：

  1. 高性能：实模式下走协程，上下文切换开销近于零
  2. 易用：API 形态对齐 std::async，返回 std::future
  3. 灵活：协程/线程双模型，按运行模式自动切换
  4. 资源可控：有界队列 + 池化协程，防任务风暴
  5. 可观测：SysMo 持续输出协程执行快照

源码目录：cyber/task/（task.h、task_manager.h/cc）。

2. Task 接口一览¶

cyber/task/task.h 暴露四个原语：

接口 行为
Async(f, args...) 提交异步任务，返回 std::future
Yield() 让出执行权（协程让出 / 线程 yield）
SleepFor(dur) 异步休眠指定 Duration
USleep(us) 微秒级异步休眠
🔥双模式设计的用意
IsRealityMode() 为 false 时（仿真/单测，cyber::Init 前设 CYBER_AGENT 或 flag 控制），Async 退化为 std::async 起线程。这保证单测环境无需拉起整套调度器即可验证业务逻辑——工程上非常实用的逃生门。

3. TaskManager：异步调用的引擎¶

3.1 结构与初始化¶

TaskManager 是进程级单例：一个有界队列 + 一组消费协程。

4. 与调度器的关系¶

异步任务池不是独立的执行体系，而是调度器上的一组”命名协程”：

  • 优先级可控：在调度配置文件中给 task_xxx 前缀任务配置 prio，可让异步任务整体让位于控制任务
  • 亲和性可控：Choreography 策略下可绑定处理器
  • 与消息驱动任务竞争同一批 Processor：因此 TaskPoolSize 配置要量入为出，过大反而加剧队列锁与上下文切换竞争

场景 适合度

5.3 注意事项¶

⚠️异步调用五大坑
  1. 协程里阻塞：回调中调用阻塞系统调用（read/cudaMemcpy 同步版）会钉死整个 Processor 线程，所有共驻协程遭殃
  2. future.get 死锁：在消费协程内 get 另一个永不完成的任务
  3. 队列积压：生产速率持续高于 TaskPoolSize 消化能力，1000 深的队列会掩盖问题直到爆发
  4. 数据竞争：future 返回前共享状态的写操作需同步，lambda 捕获引用要小心生命周期
  5. 小任务风暴：每个任务有队列 + future 开销，微任务应合并批处理

特性 cyber::Async std::async ROS 回调队列
底层模型 协程（实）/线程（仿真） 线程 回调 + 线程池

8. 小结¶

cyber::Async = 一行 API 背后的四件套：packaged_task/future 桥接 + 有界队列背压 + 池化消费协程 + 调度器统一编排；Yield/SleepFor 则是协程感知的通用原语，在线程环境自动退化。它让”组件主流程短平快、重活异步化”成为 Cyber 应用的标准写法。任务从何而来（消息驱动）见 29-Cyber数据系统详解，任务跑在什么环境（协程与优先级）见 26-Cyber调度系统详解。
