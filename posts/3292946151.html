主流工具族谱

语言 工具 风格基准 特点
C/C++ clang-format LLVM / Google / Chromium 配置项丰富，基于 clang 库
Python black PEP8 子集（严格） “不可配置”哲学，幂等
Python ruff format black 兼容 Rust 实现，超快

Java Google Java Format Google Style 单一风格，Spotless 封装

Swift swift-format Swift 官方 官方工具
SQL sqlfluff / pg_format 可配置 数据库脚本格式化

格式化 vs Lint

选型原则

常见坑

  1. 格式化与 linter 冲突：black 与 flake8 个别规则（如 E203）冲突，需在配置中忽略。
  2. 忽略文件：生成代码（protobuf、OpenAPI 生成）应加入格式化忽略列表。
  3. 全量格式化造成巨型 diff：历史代码先”格式化提交”与”逻辑提交”分离。
  4. 保存时格式化与团队工具不一致：IDE 用团队统一配置，禁止个人偏好。
  5. prettier 与 ESLint 规则重叠：prettier 负责格式，ESLint 规则关闭格式类。

最佳实践

  • 每个仓库提交 .editorconfig + 各工具配置文件，强制统一。
  • CI 中加 format check 步骤，不通过则拦截合并。
  • 新代码即时格式化；存量代码分批平滑过渡（见 14-批量与增量格式化）。
  • 后续各篇深入工具：02-clang-format-C与C++、03-black-Python格式化、04-gofmt与goimports。
