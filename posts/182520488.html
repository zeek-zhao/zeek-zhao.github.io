SSO/LDAP 集成

接着上一篇 08-权限管理，权限在 GitLab 里定义好了，身份来源最好交给企业目录统一管。这篇讲 LDAP/AD 和 SAML/OIDC 怎么接，把账号、建组和权限映射一次理顺。

集成 SSO/LDAP 是为了账号统一和审计¶

  • 账号统一：员工用企业账号登录，无需各自注册 GitLab 密码。
  • 自动同步：LDAP 组自动映射 GitLab 组权限，成员增减一处生效。
  • 审计合规：登录行为纳入企业统一审计。
  • 减少弱口令：密码策略由企业目录统一管控。

LDAP 配置核心是 host、base 和加密方式¶

编辑 /etc/gitlab/gitlab.rb：

⚠️连接加密
生产必须使用 TLS（simple_tls/start_tls）。明文 389 会暴露账号密码；证书自签名时需配置 ca_file 或系统信任库。

我一般先把 LDAP 配成底层认证，跑通 gitlab:ldap:check 再往上叠单点登录；TLS 一定开，明文 389 绝不碰。

组同步让权限跟着 LDAP 成员自动增删¶

在 GitLab 组设置中绑定 LDAP 组：

组 Settings -> LDAP Synchronization

  • LDAP group CN=gitlab-devs
  • GitLab 角色 Maintainer
    => 该 LDAP 组成员自动获得组 Maintainer 权限，LDAP 移除后自动失效
🔥外部成员标识
LDAP 用户标记为 “external”，可将其可见性限制为仅外部可见项目，实现外包与内部隔离。

外包人员我一般标成 external 再映射到外部项目，跟内部研发隔离开， LDAP 一移除权限自动失效，省得手动清理。

留好本地 root 这条逃生通道¶

  • 保留本地 root 管理员：SSO 故障时仍有逃生通道（可在服务器上用 gitlab-rails console 重置）。
  • 登录失败排查：先 gitlab-rake gitlab:ldap:check，再看 /var/log/gitlab/rails/ 日志。
  • 双重认证策略：SSO 之外建议为管理员开 2FA，见 12-安全加固。
  • 禁用本地注册：开启 OmniAuth 后关闭注册与密码重置入口，避免绕过企业身份体系。
⚡锁定风险
若所有账号都依赖外部 IdP，IdP 故障将导致全员无法登录。务必保留 LDAP 与本地管理员双通道，并在维护窗口演练 IdP 故障恢复。

我基本都留着本地 root 当逃生通道，开着 OmniAuth 就顺手把本地注册和密码重置入口关掉。集成做完后记得在维护窗口演练一次 IdP 故障，确认双通道能顶上再收工。
