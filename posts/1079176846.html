USB总线协议与驱动开发基础

搞嵌入式迟早要和 USB 打交道：插上就能用时觉得它简单，枚举失败、描述符对不上时才知道里面门道有多深。这篇把总线拓扑、四种传输、数据包结构、描述符和枚举流程串起来，再顺着看到主机/设备/OTG 角色、驱动开发和调试优化。

我在实际调 USB 时习惯按分层调试的顺序走——先确认物理连接和供电，再看枚举过没过，最后才查端点和描述符。顺序反过来排查，往往会在一个写错的设备描述符上耗掉半天。

1. USB概述：一个接口统一所有外设¶

我一般先看设备属于哪一类、跑在哪一版规范上，1.5Mbps 和 40Gbps 的选型差别太大，先把代际分清再谈接口形态。

USB（Universal Serial Bus，通用串行总线）是一种连接计算机与外部设备的总线标准，旨在取代以往各种各样的连接器和总线，为外部设备提供统一的接口标准。自1996年首次推出以来，USB已经发展成为全球最为普及的计算机外设接口标准之一。

1.1 发展历史：从 1.0 到 USB4 的速率跃迁¶

  • 1994年：USB概念由一组公司（包括Intel、Microsoft、IBM等）联合提出
  • 1996年：USB 1.0规范正式发布，传输速率为1.5Mbps（低速）和12Mbps（全速）
  • 1998年：USB 1.1规范发布，主要是对1.0的改进和修复
  • 2000年：USB 2.0规范发布，最大传输速率提升至480Mbps（高速）
  • 2008年：USB 3.0规范发布，传输速率提升至5Gbps（超高速）
  • 2013年：USB 3.1发布，传输速率提升至10Gbps（超高速+）
  • 2014年：USB Type-C连接器规范发布，提供更小的连接器和可逆插入功能
  • 2015年：USB 3.2发布，多通道聚合达到20Gbps
  • 2019年：USB4规范基于Thunderbolt 3发布，速率可达40Gbps，支持DisplayPort和PCIe协议

1.2 基本特点：即插即用、热插拔与统一供电¶

USB通过一系列创新特性解决了以往外设连接的诸多问题：

  1. 即插即用：设备连接后可自动识别和配置，无需手动安装驱动
  2. 热插拔：设备可在系统运行时连接或断开，无需重启
  3. 标准化连接器：统一的连接器类型简化了设备连接
  4. 供电能力：USB可为连接的设备供电，减少外部电源需求
  5. 大量端口扩展：通过集线器可轻松扩展端口数量
  6. 高速数据传输：从最初的12Mbps到现在的40Gbps不断发展
  7. 广泛兼容性：向后兼容确保旧设备在新系统上可用
  8. 多平台支持：几乎所有操作系统都原生支持USB

1.3 应用范围：从存储到医疗的八类外设¶

USB已经成为连接各种外部设备的首选接口，其应用涵盖了：

  • 存储设备：优盘、移动硬盘、SSD等
  • 输入设备：键盘、鼠标、游戏控制器、触摸板等
  • 输出设备：打印机、显示器、扬声器等
  • 通信设备：网络适配器、调制解调器、蓝牙适配器等
  • 多媒体设备：摄像头、麦克风、数码相机、扫描仪等
  • 医疗设备：医疗监测设备、诊断设备等
  • 工业设备：数据采集系统、测量仪器等
  • 移动设备：智能手机、平板电脑、可穿戴设备等

1.4 嵌入式地位：扩展、调试与数据交换的入口¶

在嵌入式系统中，USB扮演着连接外部世界的关键角色：

  • 系统扩展：通过USB可轻松扩展嵌入式系统功能
  • 维护接口：提供系统编程、调试和固件更新的接口
  • 数据交换：与PC或其他嵌入式系统交换数据
  • 外设连接：连接各种传感器、执行器和人机界面设备
  • 供电选项：为嵌入式系统提供标准化的供电方案

随着USB技术的发展，越来越多的嵌入式系统不仅可以作为USB设备，还可以作为USB主机连接其他设备，极大地增强了系统灵活性和功能扩展能力。

2. 协议基础：分层星型拓扑加四种传输类型¶

踩过的坑是把端点和管道混着说：端点是设备上真实的缓冲区，管道只是主机到端点的逻辑连接，调试日志里认端点号才有用。

2.1 总线拓扑：最多七层、127 个设备的分层星型¶

USB系统采用分层星型拓扑结构，具有明确的主从关系：

  • **主机(Host)**：系统中只有一个主机（如计算机），控制总线上的所有活动
  • **设备(Device)**：连接到主机的外部设备，只能响应主机请求
  • **集线器(Hub)**：扩展USB端口数量，允许将多个设备连接到单个主机端口

USB总线拓扑具有以下特征：

  • 分层结构最多支持7层（包括根集线器）
  • 最多可连接127个设备（包括集线器）
  • 主机与设备之间的通信必须经过集线器
  • 每个设备都有唯一的地址（1-127，地址0保留用于配置新设备）

2.2 传输模型：主机轮询加逻辑管道¶

USB采用基于令牌的通信模型，有以下特点：

  1. 主机控制：所有通信都由主机发起和控制
  2. 轮询机制：主机通过轮询确定设备是否需要传输数据
  3. 管道概念：通信通过逻辑管道进行，连接主机端点和设备端点
  4. 数据包传输：所有数据都以数据包形式传输
  5. **端点(Endpoint)**：设备上的数据源或接收点，具有方向性和传输特性

2.2.1 管道和端点

  • 管道：是主机与设备端点之间的逻辑连接，分为流管道和消息管道
  • 端点：是设备上的数据缓冲区，具有唯一的端点号和方向
    • 端点0：每个USB设备必须实现的双向控制端点
    • 其他端点：可根据设备功能实现，最多可有15个IN端点和15个OUT端点

2.2.2 基本传输过程

  1. 主机发送令牌包(Token Packet)，指定地址和端点号
  2. 目标设备响应，根据令牌类型发送或接收数据包
  3. 主机或设备发送数据包(Data Packet)
  4. 接收方发送握手包(Handshake Packet)确认接收状态

2.3 数据包结构：令牌、数据与握手三类包¶

USB通信通过各种类型的数据包进行，每种包类型具有特定的结构和功能：

2.3.1 基本包结构

所有USB数据包都包含至少以下字段：

  • SYNC：同步字段，用于位同步
  • PID：包标识符，指示包类型
  • EOP：包结束标记

2.3.2 主要数据包类型

  1. **令牌包(Token Packet)**：

    • OUT：指示主机向设备发送数据
    • IN：指示主机请求设备发送数据
    • SETUP：用于控制传输的初始化

  2. **数据包(Data Packet)**：

    • DATA0/DATA1：用于数据切换同步
    • DATA2/MDATA：仅用于高速模式

  3. **握手包(Handshake Packet)**：

    • ACK：确认成功接收
    • NAK：指示暂时无法接收数据
    • STALL：指示端点状态错误
    • NYET：仅用于高速模式，表示现在不准备好

  4. **特殊包(Special Packet)**：

    • PRE：用于低速设备前导
    • ERR：用于指示分离事务中的错误
    • SPLIT：用于分离事务
    • PING：测试设备是否准备好接收

2.4 四种传输类型：控制、批量、中断与等时¶

USB支持四种不同的传输类型，适用于不同的应用需求：

2.4.1 控制传输(Control Transfer)

  • 用途：用于设备配置、获取状态和设备命令
  • 特点：
    • 所有设备必须支持
    • 使用端点0
    • 具有内置错误检测和重试机制
    • 传输格式包含设置、数据和状态三个阶段
  • 应用：设备枚举、配置和控制

2.4.2 批量传输(Bulk Transfer)

  • 用途：用于大量非时间关键数据的传输
  • 特点：
    • 高带宽利用率
    • 错误检测和重试机制
    • 不保证带宽和延迟
    • 只适用于全速和高速设备
  • 应用：打印机、扫描仪和存储设备

2.4.3 中断传输(Interrupt Transfer)

  • 用途：用于及时但小数据量的传输
  • 特点：
    • 保证在指定时间间隔内轮询
    • 有限的数据量
    • 适用于所有速度模式
    • 错误检测和有限重试
  • 应用：键盘、鼠标和其他输入设备

2.4.4 等时传输(Isochronous Transfer)

  • 用途：用于时间关键但可容忍一定错误的数据流
  • 特点：
    • 保证带宽
    • 低延迟
    • 无错误重试机制
    • 只适用于全速和高速设备
  • 应用：音频和视频流

2.5 状态机：从 Attached 到 Configured 的六级跳转¶

USB通信过程中，设备可以处于以下几种状态：

  1. **附接(Attached)**：设备物理连接到USB总线
  2. **供电(Powered)**：设备获得电源但尚未初始化
  3. **默认(Default)**：设备已接收复位信号并分配默认地址0
  4. **地址(Address)**：设备已分配唯一地址
  5. **配置(Configured)**：设备已完全配置，可以进行正常功能操作
  6. **挂起(Suspended)**：总线无活动超过3ms，设备进入低功耗状态

3. 物理层与电气特性：线缆、电平和供电决定稳定性¶

实测下来最容易被忽略的是线缆：标称 5Gbps 的线，超过 3 米就容易掉速，问题往往不在 PHY 配置上。

3.1 物理连接：连接器与线缆的演进¶

3.1.1 连接器类型

USB规范定义了多种不同的连接器类型，适用于不同的设备和应用场景：

  1. Standard-A：常见的矩形扁平连接器，用于主机端
  2. Standard-B：方形连接器，用于大型设备端（如打印机）
  3. Mini-A/B：比标准连接器小，用于早期便携设备（已弃用）
  4. Micro-A/B：比Mini更小，成为手机等设备的标准（直到Type-C出现）
  5. Type-C：最新的可逆连接器标准，适用于所有设备类型

随着USB版本的发展，连接器在保持向后兼容的同时，不断变得更小、更强大。

3.1.2 线缆规格

USB线缆内包含多根导线，其功能因USB版本和连接器类型而异：

  1. USB 2.0线缆：

    • VBUS（红色）：+5V电源
    • D-（白色）：数据线（负）
    • D+（绿色）：数据线（正）
    • GND（黑色）：接地线

  2. USB 3.0/3.1线缆（增加了五根导线）：

    • 原有的USB 2.0信号线
    • SSTX+/SSTX-：超高速发送差分对
    • SSRX+/SSRX-：超高速接收差分对
    • GND_DRAIN：额外接地屏蔽

  3. USB Type-C线缆：

    • 支持24针双向设计
    • 可支持高达100W的电力传输
    • 包含多组差分对，支持模式切换
    • 增加了配置通道(CC)用于电源和角色协商

3.2 电气特性：电压、电流与速度识别¶

3.2.1 电压和电流规格

  1. 供电电压：

    • 标准USB端口：5V±5%
    • USB-PD：可协商5V、9V、15V、20V等多档电压

  2. 电流规格：

    • USB 1.x/2.0：最大500mA
    • USB 3.0：最大900mA
    • USB-BC（电池充电规范）：最大1.5A
    • USB-PD：最高5A（100W@20V）
    • Type-C电流广告：默认0.5A、1.5A、3.0A等级

3.2.2 速度识别和信号电平

各种USB速度模式通过不同的连接方式进行识别：

  1. **低速(Low-Speed, 1.5Mbps)**：

    • D-上拉到3.3V
    • 信号摆幅：3.0V±0.3V
    • 最大线缆长度：3米

  2. **全速(Full-Speed, 12Mbps)**：

    • D+上拉到3.3V
    • 信号摆幅：3.0V±0.3V
    • 最大线缆长度：5米

  3. **高速(High-Speed, 480Mbps)**：

    • 首先以全速连接，然后通过协商切换到高速
    • 差分信号：400mV±10%
    • 最大线缆长度：5米

  4. **超高速(SuperSpeed, 5Gbps及以上)**：

    • 使用专用的高速差分对
    • 差分信号：1V峰峰值
    • 推荐线缆长度：3米以内

3.2.3 电源管理

USB电源管理机制包括：

  1. 总线供电与自供电设备：

    • 总线供电：设备完全通过USB获取电源
    • 自供电：设备通过外部电源运行，只使用USB进行通信

  2. 电源状态：

    • 活动状态：设备正常工作
    • 挂起状态：总线无活动时进入低功耗模式，总线供电设备需限制电流至2.5mA
    • 唤醒：设备可通过恢复信号恢复到活动状态

  3. 电源协商：

    • USB-PD：通过专用协议协商更高电压/电流
    • Type-C：通过CC（配置通道）引脚进行电流能力广告

3.3 信号完整性：阻抗、线材与距离限制¶

影响USB信号完整性的因素：

  1. 阻抗匹配：

    • 差分阻抗：90Ω±15%
    • 不匹配会导致反射和信号失真

  2. 线缆质量：

    • 导体尺寸影响电压降
    • 屏蔽对抗外部干扰能力
    • 双绞线设计减少电磁干扰

  3. 传输距离限制：

    • 直接连接下的最大理论距离：
      • USB 2.0：5米
      • USB 3.0/3.1：3米
      • USB 3.2/4：0.8米
    • 使用主动延长器可增加传输距离

  4. EMI/RFI考虑：

    • USB 3.0+需要更好的屏蔽以防止射频干扰
    • 差分信号设计有助于抵消共模噪声

5. 枚举过程：从检测到加载驱动的七个步骤¶

枚举失败时我习惯先抓前 8 字节描述符请求那一段——主机连最大包大小都没读到，说明硬件或供电还有问题。

当USB设备连接到主机时，必须经过枚举过程才能被识别和使用。这一过程包括多个步骤，主机收集设备信息并为设备分配资源。

5.1 枚举七步：检测、复位、取描述符、分配地址到加载驱动¶

枚举是主机与设备之间的交互过程，包括以下主要步骤：

  1. 检测连接：

    • 主机检测到D+或D-线上的上拉电阻，确认设备连接
    • 集线器通知主机有新设备连接

  2. 复位设备：

    • 主机发送总线复位信号（D+和D-都保持在低电平超过10ms）
    • 设备进入默认状态，使用默认地址（0）

  3. 确定速度：

    • 主机通过检测哪条线上有上拉电阻，确定设备速度（低速、全速）
    • 如果检测到全速设备，可能通过高速协商确定是否支持高速模式

  4. 获取描述符：主机按以下顺序请求设备描述符：

    • 请求前8个字节的设备描述符以确定最大包大小
    • 请求完整的设备描述符
    • 请求配置描述符（包括所有相关的接口和端点描述符）
    • 可选地请求字符串描述符

  5. 分配地址：

    • 主机向设备发送SetAddress请求，分配唯一地址（1-127）
    • 设备确认并使用新地址进行后续通信

  6. 选择配置：

    • 主机向设备发送SetConfiguration请求
    • 设备进入配置状态，激活指定配置中定义的所有接口

  7. 加载驱动程序：

    • 主机基于设备的VID（厂商ID）、PID（产品ID）和类信息选择合适的驱动程序
    • 驱动初始化并开始与设备通信

6.2.1 人机接口设备类(HID)

  • 通过报告描述符定义数据结构

CDC类用于各种通信设备，包括调制解调器、网络适配器和虚拟串行端口：

主要特点：

  • 支持多种通信模型
  • 通常使用控制传输发送命令
  • 使用批量传输进行数据收发
  • 可创建虚拟COM端口(CDC-ACM)

CDC类设备通常包含两个接口：

  1. 通信类接口：用于接收命令和通知
  2. 数据类接口：用于实际数据传输

CDC-ACM子类是最流行的CDC子类，提供虚拟串行端口功能，广泛用于嵌入式设备与PC通信。

7. 主机与设备角色：控制器、OTG 和双角色切换¶

USB通信有明确的主机和设备角色，但随着技术发展，这些角色变得更加灵活。

7.1 主机控制器：UHCI/OHCI 到 xHCI¶

USB主机控制器是系统中负责管理USB总线的硬件组件：

7.1.1 主机控制器类型

  1. UHCI (Universal Host Controller Interface)

    • 由Intel开发
    • 支持USB 1.1（低速和全速）
    • 依赖CPU进行大量处理

  2. OHCI (Open Host Controller Interface)

    • 由Compaq、Microsoft和National Semiconductor开发
    • 支持USB 1.1
    • 控制器执行更多任务，减轻CPU负担

  3. EHCI (Enhanced Host Controller Interface)

    • 支持USB 2.0高速模式
    • 通常与UHCI/OHCI配对使用，处理低速/全速设备

  4. xHCI (Extensible Host Controller Interface)

    • 支持USB 3.0及更高版本
    • 向后兼容USB 2.0和1.1设备
    • 集成了所有速度模式的支持
    • 先进的电源管理功能

7.1.2 主机控制器职责

USB主机控制器负责：

  • 总线时序和帧同步
  • 数据包生成和解析
  • 错误检测和处理
  • 数据缓冲管理
  • 与系统内存的数据传输
  • 支持设备的热插拔

7.2 设备控制器：收发器、SIE 与端点缓冲¶

USB设备控制器是设备端的硬件组件，负责实现USB设备功能：

7.2.1 设备控制器架构

典型的USB设备控制器包括：

  • USB收发器（模拟前端）
  • SIE（串行接口引擎）
  • 端点缓冲区和控制逻辑
  • CPU接口和寄存器组
  • DMA控制器（在某些高性能设计中）

7.2.2 设备控制器工作模式

设备控制器通常支持两种工作模式：

  1. 轮询模式：CPU定期检查事件标志
  2. 中断模式：特定事件触发处理程序

7.3 OTG：HNP 与 SRP 实现角色切换¶

USB On-The-Go (OTG)功能允许设备在主机和设备角色之间切换：

7.3.1 OTG功能概述

OTG功能包括：

  • 角色协商（通过ID引脚或软件）
  • 主机协商协议(HNP)：允许设备成为临时主机
  • 会话请求协议(SRP)：允许设备启动主机会话
  • 对于小型设备的简化主机功能

7.3.2 角色切换过程

典型的角色切换过程：

  1. 通过ID引脚或软件命令初始确定角色
  2. 设备可通过HNP请求切换为主机
  3. 主机进入挂起状态允许角色切换
  4. 完成角色切换后，原设备开始执行主机功能

11.3 性能优化：速度、功耗与内存三头兼顾¶

11.3.1 传输速度优化

提高USB数据传输性能的技术：

  • 缓冲区管理：

    • 使用多重缓冲（双缓冲/三缓冲）减少等待
    • 优化缓冲区大小与最大包大小匹配
    • 使用DMA减少CPU开销
    • 采用零拷贝技术减少数据移动

  • 端点配置：

    • 根据实际需求选择端点数量和类型
    • 优化中断端点的轮询间隔
    • 对批量传输使用最大允许的包大小
    • 利用高速模式下的多端点并行

  • 传输策略：

    • 减少小包传输，批量处理数据
    • 使用HIGH_BANDWIDTH端点增加带宽（USB 2.0）
    • 优化等时传输的缓冲方案
    • 使用流式传输减少延迟

11.3.2 功耗优化

最小化USB设备功耗的技术：

  • 选择性端点使能：

    • 仅初始化必要的端点
    • 未使用的端点保持关闭
    • 根据需要动态配置端点

  • 电源状态管理：

    • 积极使用USB挂起模式
    • 实现细粒度的设备端电源状态
    • 优化唤醒延迟和唤醒源
    • 使用低功耗模式间的平滑过渡

  • 时钟管理：

    • 根据当前速度模式调整时钟
    • 未使用的模块时钟门控
    • 优化PLL配置减少功耗
    • 使用异步电路减少时钟分布

  • 数据处理策略：

    • 批量处理数据减少唤醒次数
    • 使用DMA减少CPU干预
    • 使用硬件加速器卸载CPU

11.3.3 内存优化

在资源受限的嵌入式系统中优化USB内存使用：

  • 静态内存分配：

    • 预先分配固定大小的缓冲区
    • 避免动态内存分配
    • 定义最大支持的配置参数

  • 数据结构优化：

    • 使用位字段减少控制结构大小
    • 优化数据对齐减少填充浪费
    • 共享公共配置数据
    • 使用ROM存储常量数据

  • 缓冲区策略：

    • 实现缓冲区共享和重用
    • 优化缓冲区大小符合实际需求
    • 使用单个大缓冲区在多个小缓冲区之间切换

12. 设计要点与参考资料¶

回头看，合规性和向后兼容是 USB 能铺开的关键；新项目先把规范版本和认证要求定死，后面少很多麻烦。

12.1 技术演进的五个关键词¶

把前面十几节串起来看，USB 的价值集中在五点：统一连接、持续提速、功能复合、开放规范和成熟生态。

  • 统一连接：从最初不同设备使用不同接口到单一通用标准
  • 持续演进：从最初的12Mbps到现在的40Gbps，速度提升超过3000倍
  • 多功能性：从简单的数据传输扩展到充电、显示、外设扩展等多种功能
  • 开放标准：由USB-IF维护的开放规范确保了广泛兼容性和创新
  • 生态系统：丰富的设备类定义和协议使设备即插即用成为可能

12.2 落地时要盯住的四类问题¶

在设计USB设备或系统时，应重点考虑以下因素：

  1. 合规性：

    • 严格遵循USB规范
    • 通过USB-IF合规性测试（如适用）
    • 解决互操作性问题

  2. 用户体验：

    • 可靠的即插即用功能
    • 一致的性能表现
    • 电源管理和热设计

  3. 安全性：

    • 数据保护和加密
    • 设备认证机制
    • 防篡改功能

  4. 未来兼容性：

    • 向后兼容旧标准
    • 设计预留升级空间
    • 遵循最佳实践指南

12.3 接下来值得关注的方向¶

USB技术仍在快速演进，未来几年可能的发展方向：

  • 更高传输速率：超过现有USB4的40Gbps
  • 更强电力传输：支持更多设备类型的快速充电
  • 更广泛集成：与其他标准的深度融合
  • 更智能的连接：上下文感知和自适应功能
  • 改进的安全标准：增强防护针对新型威胁
  • 更高能效：满足绿色环保和移动设备需求
