18-sesearch与seinfo查询

发表于2026-10-24|selinux
|浏览量:

[!info] 本节目标
使用 sesearch 与 seinfo 检索策略规则，理解策略结构。

1. sesearch 功能

sesearch 检索策略中的 allow/type_transition/dontaudit 等规则。典型用法：sesearch -A -s httpd_t 查询某域全部允许规则，-t 按目标类型过滤，-c 按类别过滤。

2. seinfo 功能

seinfo 查询策略对象信息：seinfo -t 列出全部类型，-b 列出布尔值，-r 列出角色，-u 列出用户。与 sesearch 配合可快速建立策略全貌。

3. 查询场景示例

判断某域能否读写某文件类型：sesearch -A -s 域 -t 文件类型 -c file。查询域转换：sesearch -T -s 域。查询端口访问：sesearch -A -s 域 -t 端口类型 -c tcp_socket。

4. 输出解读

规则行包含 source/target/class/permission，与 audit 日志字段对应。理解规则表达可推断拒绝原因与补规则方向，是策略分析的核心技能。

5. 组合分析

先 seinfo 定位类型与属性，再 sesearch 检索相关规则，最后结合日志验证。三步骤构成标准策略分析流程，适用绝大多数排障场景。

6. 注意事项

查询结果依赖加载策略版本，自定义模块需重新加载后查询。策略库庞大时使用过滤参数缩小范围，避免输出爆炸。

7. 常见查询模板

判断文件访问：sesearch -A -s 域 -t 类型 -c file；判断网络连接：sesearch -A -s 域 -t 端口类型 -c tcp_socket；判断域转换：sesearch -T -s 域；列出全部类型：seinfo -t。将这些模板沉淀为脚本或备忘，可大幅提升日常策略分析效率。查询结果与审计日志字段对照，能快速定位缺失规则。

8. 策略版本一致性

查询结果基于当前加载策略，加载前后结果可能不同。排障时确保查询与问题场景使用同一策略版本。自定义模块未加载时规则不可见，先 semodule -l 确认。版本一致性是避免误判的基础。

9. 查询能力进阶

结合管道与过滤参数构建复杂查询，一次定位多条件场景。学习正则过滤提升检索精度。将常用查询封装为脚本工具，方便团队共享。查询能力提升显著加速策略分析与排障。
