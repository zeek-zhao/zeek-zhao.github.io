网络协议与通信原理

学网络绕不开协议，可我一开始死记各层字段总记不住，后来改成盯住「一个包从我的机器出发，经过哪些环节才到对方」这条主线，反而全串起来了。协议本质上就是通信双方约定好的规则，跟不同方言的人要靠普通话沟通是一个道理——ARPANET 当年能推广开，靠的就是把 TCP/IP 做成了互联网里的通用语言。下面按分层模型、地址解析、传输控制、应用协议、安全这条线往下捋。

一图看懂：OSI 七层、TCP/IP 四层、五层模型逐层封装与解封装。

1. 网络层次划分：OSI 七层、TCP/IP 四层与五层的对应¶

为了使不同计算机厂家生产的计算机能够相互通信，以便在更大的范围内建立计算机网络，国际标准化组织（ISO）在1978年提出了”开放系统互联参考模型”，即著名的OSI/RM模型（Open System Interconnection/Reference Model）。它将计算机网络体系结构的通信协议划分为七层，自下而上依次为：物理层（Physics Layer）、数据链路层（Data Link Layer）、网络层（Network Layer）、传输层（Transport Layer）、会话层（Session Layer）、表示层（Presentation Layer）、应用层（Application Layer）。其中第四层完成数据传送服务，上面三层面向用户。

除了标准的OSI七层模型以外，常见的网络层次划分还有TCP/IP四层协议以及TCP/IP五层协议，它们之间的对应关系如下：

我记这张表时只抓两头：OSI 是理论上的七层，实际互联网跑的是 TCP/IP 四层，五层只是把四层的网络接口拆成数据链路和物理两层方便教学。

2. OSI 七层模型：从物理信号逐层封装到应用数据¶

TCP/IP协议是互联网的基础协议，没有它就无法上网，任何与互联网相关的操作都离不开TCP/IP协议。不管是OSI七层模型还是TCP/IP的四层、五层模型，每一层都有自己的专属协议，完成相应的工作并与上下层级沟通。以下是OSI七层模型的详细介绍：

2.1 物理层：把比特流送上物理媒体¶

物理层负责激活、维持、关闭通信端点之间的机械特性、电气特性、功能特性以及过程特性。该层为上层协议提供了一个传输数据的可靠物理媒体。简单来说，物理层确保原始数据可在各种物理媒体上传输。物理层的重要设备包括中继器（Repeater，也叫放大器）和集线器。

2.1.1 基本概念和功能

物理层解决如何在连接各种计算机的传输媒体上传输数据比特流，而不是指具体的传输媒体，尽可能地屏蔽掉传输媒体和通信手段的差异。物理层的主要任务包括：

  • 确定机械特性：接口形状，引线数目
  • 电气特性：规定电压的范围（如-5V到+5V）
  • 功能特性：如规定-5V表示0，+5V表示1
  • 过程特性：各个相关部件的工作步骤

2.1.2 数据通信相关术语

  • 数据：运送消息的实体
  • 信号：数据电气或电磁的表现
    • 模拟信号：代表消息的参数取值是连续的
    • 数字信号：代表消息的参数取值是离散的
  • 码元：代表不同离散数值的基本波形

2.1.3 信道的基本概念

信道一般表示向一个方向上传递信息的媒体：

  • 单工通道：只有一个方向的通信，没有反方向的交互
  • 半双工通信：通信双方都可发送信息，但不能同时发送（如对讲机）
  • 全双工通信：通信双方可以同时发送和接收信息（如手机）

2.1.4 编码与调制

  • 基带信号：来自信源的信号
  • 带通信号：通过将基带信号进行载波调制后，把信号频率搬到较高的频段

常见编码方式：

  • 曼切斯特编码：位中间有信号跳变，跳变方向决定比特值（低到高为1，高到低为0）
  • 差分曼切斯特编码：位中间有信号跳变，位与位之间是否有跳变决定比特值

2.1.5 信道极限容量

  • 奈氏准则：在任何信道中，码元的传输速率是有上限的，否则会出现码间串扰
  • 香农定理：信道的极限信息传输速度 C = W log₂(1 + S/N) bit/s
    • W：信道的带宽（Hz）
    • S：信号平均功率
    • N：噪声功率

2.1.6 传输媒体

  • 导向传输媒体：电磁波沿着固体媒体传播
    • 双绞线（屏蔽STP和非屏蔽UTP）
    • 同轴电缆
    • 光纤
  • 非导向传输媒体：无线传输

2.1.7 信道复用技术

  • 频分复用（FDM）：用户在不同频带同时占用信道
  • 时分复用（TDM）：用户在不同的时间片使用信道
  • 波分复用（WDM）：光的频分复用，在光纤中传输多种不同波长的光信号
  • 码分复用（CDM）：每个用户使用不同的码型进行编码

2.2 数据链路层：成帧、透明传输与差错控制¶

数据链路层在物理层提供的服务基础上向网络层提供服务，其最基本的服务是将源自网络层的数据可靠地传输到相邻节点的目标机网络层。

2.2.1 基本概念和功能

  • 链路：一条点到点的物理线路段，中间没有其它交换节点
  • 数据链路：除物理链路外，还包括控制数据传输的通信协议

数据链路层的主要功能包括：

  • 封装成帧：将网络层数据添加首部和尾部，构成帧
  • 透明传输：确保数据中的任何比特组合都能够正确传输
  • 差错控制：检测并尽可能纠正传输中的差错

2.2.2 封装成帧与透明传输

封装成帧是通过在一段数据前后添加特殊字符（如SOH-开始标记和EOT-结束标记）来定界一个帧。当数据部分出现控制字符时，采用字符填充（或字节填充）技术解决：在控制字符前插入转义字符ESC。

2.2.3 差错控制

传输中可能会产生比特差错（1变成0，或0变成1）。误码率（BER）是指在一段时间内传输错误的比特占总传输比特的比率。

CRC循环冗余校验：

  • 发送方和接收方约定一个生成多项式G(x)
  • 发送方对要发送的数据M进行模2除法运算，得到余数R
  • 发送方将余数R添加到数据M后面，构成待传输的帧
  • 接收方对接收到的帧执行同样的除法运算
  • 如果余数为0，则认为帧无差错；否则认为有差错，丢弃该帧

2.2.4 局域网的拓扑结构

局域网的主要拓扑结构包括：

  • 星形拓扑：所有节点连接到中央节点
  • 总线拓扑：所有节点连接到一条公共传输介质
  • 环形拓扑：节点形成一个闭环
  • 网状拓扑：节点之间有多条连接路径

2.2.5 CSMA/CD协议

CSMA/CD（载波监听多址接入/碰撞检测）是以太网使用的一种介质访问控制方法：

  • 多点接入：多台计算机连接到同一总线
  • 载波监听：发送前检测总线上是否有其它信号
  • 碰撞检测：发送时检测是否发生碰撞，如发生碰撞则立即停止发送

当碰撞发生时，站点会发送阻塞信号，然后等待一个随机时间（退避时间）再尝试重发。

2.2.6 以太网与流量控制

以太网是目前最流行的局域网技术，遵循CSMA/CD原则。以太网提供的是不可靠的交付服务。

流量控制协议主要有：

  • 单工停等协议：发送方每发送一帧就等待接收方的确认
  • 连续ARQ协议：发送方可以连续发送多个帧，不必等待确认
  • 滑动窗口协议：发送方和接收方各维护一个窗口，只允许在窗口内的帧发送或接收

我在理解 CSMA/CD 时抓住「先听后发、边发边听、冲突停发、随机重发」这四句就够了，以太网不可靠这点也在这层就定了。

2.3 网络层：路径选择、路由与逻辑寻址¶

网络层的目的是实现两个端系统之间的数据透明传送，功能包括寻址和路由选择、连接的建立、保持和终止等。它提供的服务使传输层不需要了解网络中的数据传输和交换技术。网络层可以简单概括为”路径选择、路由及逻辑寻址”。

网络层中涉及众多的协议，其中最重要的是TCP/IP的核心协议——IP协议。IP协议提供不可靠、无连接的传送服务，主要功能有：无连接数据报传输、数据报路由选择和差错控制。

重要知识点：

  • 网络层负责对子网间的数据包进行路由选择，并实现拥塞控制、网际互连等功能
  • 基本数据单位为IP数据报
  • 主要协议：
    • IP协议（Internet Protocol）
    • ICMP协议（Internet Control Message Protocol）
    • ARP协议（Address Resolution Protocol）
    • RARP协议（Reverse Address Resolution Protocol）
  • 重要设备：路由器

2.4 传输层：第一个端到端的层次¶

传输层是第一个端到端的层次，负责将上层数据分段并提供端到端的、可靠或不可靠的传输。此外，传输层还处理端到端的差错控制和流量控制问题。传输层根据通信子网特性，最佳利用网络资源，为会话层提供建立、维护和取消传输连接的功能。

重要知识点：

  • 传输层负责端到端的数据分段传输、差错控制和流量控制
  • 主要协议：TCP协议（传输控制协议）、UDP协议（用户数据报协议）
  • 重要设备：网关

2.4.1 流量控制：靠接收窗口限制发送速率

流量控制的概念

流量控制是指防止发送方发送数据过快，导致接收方来不及处理，从而导致数据丢失的一种机制。流量控制的依据是接收端缓冲区的大小，目标是确保接收端能够处理所有收到的数据。

滑动窗口机制

滑动窗口是实现流量控制的关键机制，它允许发送方在收到确认前发送多个数据包。主要特点包括：

  1. 接收端通过TCP首部中的”窗口大小”字段通知发送端自己可用的缓冲区大小
  2. 窗口大小字段越大，表示网络吞吐率越高
  3. 窗口大小是指无需等待确认应答而可以继续发送的数据量上限
  4. 发送方维护发送缓冲区，记录未收到确认的数据
  5. 当接收方缓冲区即将满时，会减小通知的窗口大小，从而降低发送速率
  6. 如果接收方缓冲区满，会将窗口大小设为0，发送方将暂停发送数据，但会定期发送窗口探测报文

滑动窗口的优势在于可以高效可靠地发送大量数据，提高网络的吞吐量。

2.4.2 拥塞控制：慢启动、拥塞避免、快重传、快恢复

拥塞控制的概念

拥塞控制是防止过多的数据注入网络中，避免网络负载过重而导致网络性能下降的机制。拥塞控制的主要表现为丢包和延时增加。

拥塞控制算法

TCP采用了多种拥塞控制算法：

  1. 慢启动（Slow Start）：连接初始阶段，拥塞窗口（cwnd）从1个MSS开始，每收到一个确认就将cwnd加1，呈指数增长
  2. 拥塞避免（Congestion Avoidance）：当cwnd达到慢启动阈值（ssthresh）后，每经过一个往返时间增加1个MSS，呈线性增长
  3. 快速重传（Fast Retransmit）：接收方收到失序报文段后立即发送重复确认，发送方收到3个重复确认后立即重传
  4. 快速恢复（Fast Recovery）：发生拥塞后，ssthresh设为当前cwnd的一半，cwnd=ssthresh+3，并线性增长直到收到新的确认

拥塞控制工作过程

拥塞控制经历以下阶段：

  • 初始化：cwnd=1，ssthresh=65535
  • 慢启动阶段：cwnd指数增长
  • 拥塞避免阶段：cwnd线性增长
  • 拥塞发生后调整：检测到丢包后，ssthresh=cwnd/2，cwnd=1，重新开始慢启动

2.4.3 流量控制与拥塞控制的区别

相同点：

  • 都会导致丢包现象
  • 都通过控制发送方的发送速率来解决问题

不同点：

  • 丢包位置不同：流量控制丢包在接收端，拥塞控制丢包在路由器
  • 作用对象不同：流量控制针对接收方，拥塞控制针对整个网络
  • 范围不同：流量控制是点对点的控制，拥塞控制是全局性的过程

这两个概念我一开始老混，后来记成「流量控制是收方撑不住，拥塞控制是网络堵了」，丢包位置一个在接收端、一个在路由器，区分起来就清楚了。

2.5 会话层、表示层和应用层：面向用户的三层¶

会话层：管理主机之间的会话进程，负责建立、管理、终止进程之间的会话，并通过在数据中插入校验点实现数据同步。

表示层：对上层数据或信息进行变换，确保一个主机应用层信息可以被另一个主机的应用程序理解。表示层的数据转换包括数据加密、压缩、格式转换等。

应用层：为操作系统或网络应用程序提供访问网络服务的接口。

重要知识点：

  • 数据传输基本单位为报文
  • 主要协议：
    • FTP（文件传送协议）
    • Telnet（远程登录协议）
    • DNS（域名解析协议）
    • SMTP（邮件传送协议）
    • POP3（邮局协议）
    • HTTP（超文本传输协议）

3. IP地址：网络号加主机号，五类地址各有用途¶

3.1 网络地址¶

IP地址由网络号（包括子网号）和主机号组成，网络地址的主机号为全0，代表着整个网络。

3.2 广播地址¶

广播地址通常称为直接广播地址，用于区分受限广播地址。广播地址的主机号为全1。当向某个网络的广播地址发送消息时，该网络内的所有主机都能收到该广播消息。

3.3 IP地址分类¶

  • A类地址：以0开头，第一个字节作为网络号，地址范围为：0.0.0.0~127.255.255.255
  • B类地址：以10开头，前两个字节作为网络号，地址范围是：128.0.0.0~191.255.255.255
  • C类地址：以110开头，前三个字节作为网络号，地址范围是：192.0.0.0~223.255.255.255
  • D类地址：以1110开头，地址范围是224.0.0.0~239.255.255.255，作为组播地址
  • E类地址：以1111开头，地址范围是240.0.0.0~255.255.255.255，为保留地址

注：只有A、B、C类地址划分网络号和主机号，D类和E类地址没有这种划分。

3.4 特殊IP地址¶

  • 255.255.255.255：受限广播地址，仅用于本地网络，路由器不会转发
  • 0.0.0.0：常用于寻找自己的IP地址，如在DHCP、BOOTP等协议中使用
  • 127.0.0.0/8：回环地址，用于本机测试，常用127.0.0.1
  • 私有地址：
    • A类：10.0.0.0/8（10.0.0.0~10.255.255.255）
    • B类：172.16.0.0/12（172.16.0.0~172.31.255.255）
    • C类：192.168.0.0/16（192.168.0.0~192.168.255.255）

五类地址里真正能分给主机用的只有 A/B/C，D 类是组播、E 类保留，这个边界记清楚就不会在划分子网时把组播地址算进去。

4. 子网掩码：按位与判断是否在同一个子网¶

子网掩码用于标识两个IP地址是否同属于一个子网。它是32位二进制地址，其中1表示网络位，0表示主机位。如果两个IP地址在子网掩码的按位与计算下所得结果相同，则表明它们属于同一子网。

在计算子网时，需要注意保留地址（全0地址和广播地址），这些地址通常不能用于主机分配。

子网掩码计算方法：

  1. 利用子网数计算：将所需子网数转换为二进制，确定位数N，然后在类地址子网掩码的主机地址部分前N位置1
  2. 利用主机数计算：将主机数转换为二进制，确定位数N，然后在全1子网掩码中从后向前N位置0

规划子网时，还需考虑每个网络的网关地址、网络地址和广播地址需求。

我算子网时习惯把掩码写成二进制对着看，全 1 是网络位、全 0 是主机位，再扣掉网络地址和广播地址两个保留值，能分配的主机数就不会算错。

5. ARP与RARP：IP 和 MAC 地址互相解析¶

5.1 ARP协议¶

地址解析协议（ARP）根据IP地址获取物理地址（MAC地址）。主机发送包含目标IP地址的ARP请求广播到网络，接收返回消息确定目标的物理地址，并将对应关系存入ARP缓存。

ARP工作流程：

  1. 主机A查询本地ARP缓存是否有主机B的MAC地址
  2. 如果没有，发送ARP请求广播到本地网络
  3. 与请求IP地址匹配的主机B将A的IP和MAC映射添加到自己的ARP缓存
  4. 主机B发送ARP回复给主机A
  5. 主机A更新ARP缓存，开始通信

5.2 RARP协议¶

逆地址解析协议（RARP）将物理地址转换为IP地址。当主机只知道自己的物理地址而不知道IP地址时，可通过RARP广播请求获取IP地址。

RARP工作流程：

  1. 主机发送RARP广播，声明自己的MAC地址并请求IP地址
  2. RARP服务器检查其RARP列表
  3. 如果存在对应关系，返回IP地址给请求主机
  4. 如果不存在，不做任何响应

ARP 和 RARP 是一对反过程：一个问「这个 IP 的 MAC 是谁」，一个问「这个 MAC 该配什么 IP」，无盘工作站当年就靠 RARP 拿到地址。

6. DNS协议和域名解析：把域名翻译成 IP 的分布式系统¶

6.1 DNS简介¶

DNS（Domain Name Service，域名服务）是互联网上最重要的应用层协议之一，使用TCP和UDP协议的53号端口。DNS将人类易于记忆的域名（如www.baidu.com）转换为机器可识别的IP地址。

DNS是一个C/S结构的协议，其中客户端发起查询请求，服务器负责解析域名并返回结果。

6.2 域名结构¶

域名系统采用层次树状结构，从右到左依次为：

  • 顶级域（TLD）：
    • 组织域：.com、.net、.org、.gov、.edu、.mil等
    • 国家域：.cn、.jp、.uk、.us等
  • 二级域：通常是组织名称，如baidu.com
  • 子域或主机名：如www.baidu.com中的www

完全限定域名（FQDN）是包含所有层级且在最后有一个点的域名，例如：www.baidu.com.

6.3 DNS查询类型¶

DNS支持两种主要的查询方式：

  • 递归查询：客户端要求DNS服务器返回最终结果，DNS服务器负责追踪整个解析过程
  • 迭代查询：DNS服务器返回它知道的最接近的下一个DNS服务器信息，由客户端继续向下一个服务器查询

6.4 DNS名称解析方式¶

  • 正向解析：名称 –> IP地址
  • 反向解析：IP地址 –> 名称

这两种解析方式使用不同的名称空间，并维护在不同的解析库中。

6.5 DNS服务器类型¶

DNS服务器分为以下几种类型：

  • 负责解析至少一个域的服务器：
    • 主名称服务器：域的权威服务器，负责维护域数据库，可进行读写操作
    • 辅助名称服务器：从主服务器复制数据库，只能进行读操作，为域提供冗余服务
  • 不负责解析域的服务器：
    • 缓存名称服务器：缓存解析结果但不负责特定域的解析

6.6 域数据同步¶

主DNS服务器与辅助DNS服务器之间的数据同步通过”区域传送”实现：

  • 序列号（Serial）：数据库版本号，主服务器数据变化时递增
  • 刷新时间间隔（Refresh）：辅助服务器检查主服务器序列号更新的时间间隔
  • 重试时间间隔（Retry）：同步失败后重试的时间间隔
  • 过期时常（Expire）：辅助服务器无法联系主服务器的最长时间，超过后停止服务
  • 否定答案的缓存时长（Negative Answer TTL）：不存在域名记录的缓存时间

区域传送类型：

  • 全量传送（AXFR）：传送整个数据库
  • 增量传送（IXFR）：仅传送变化的数据

6.7 DNS资源记录类型¶

DNS区域文件由资源记录（Resource Record，RR）组成：

  • SOA记录（Start Of Authority）：区域权威信息，每个区域只能有一个
  • NS记录（Name Service）：指定区域的名称服务器
  • A记录：域名到IPv4地址的映射
  • AAAA记录：域名到IPv6地址的映射
  • CNAME记录（Canonical Name）：域名别名
  • PTR记录（Pointer）：IP地址到域名的映射，用于反向解析
  • MX记录（Mail Exchanger）：邮件服务器记录，含优先级字段
  • TXT记录：文本信息记录
  • SRV记录：服务定位记录

资源记录格式：name [TTL] IN RR_TYPE value

6.8 BIND配置与实现¶

BIND（Berkeley Internet Name Domain）是DNS协议最常用的实现，由ISC.org维护。在BIND中：

  • dns是协议
  • bind是dns协议的一种实现
  • named是bind程序运行的进程名

BIND相关程序包包括：

  • bind-libs：被bind和bind-utils包中的程序共同用到的库文件
  • bind-utils：bind客户端程序集，例如dig、host、nslookup等
  • bind：提供dns server程序以及几个常用的测试程序
  • bind-chroot：让named运行于jail模式下的安全选项

BIND的主配置文件为/etc/named.conf，解析库文件通常存放在/var/named/目录下。

8. TCP/IP：三次握手建连、四次挥手断开的可靠传输¶

TCP/IP是互联网的基础协议，由网络层的IP协议和传输层的TCP协议组成。TCP负责发现传输问题并要求重传，确保数据正确传输；IP负责为每台联网设备规定地址。

TCP是面向连接的通信协议，通过三次握手建立连接，通信完成后通过四次挥手断开连接。TCP提供可靠的数据流服务，采用”带重传的肯定确认”技术确保可靠性，并使用”滑动窗口”进行流量控制。

8.1 TCP报文首部字段¶

TCP报文首部包含以下字段：

  • 源端口号（16位）
  • 目的端口号（16位）
  • 序号（32位）
  • 确认号（32位）
  • 首部长度（4位）
  • 保留（6位）
  • 控制位（6位）：URG、ACK、PSH、RST、SYN、FIN
  • 窗口大小（16位）
  • 校验和（16位）
  • 紧急指针（16位）
  • 选项（可变长度）

8.2 TCP三次握手：三步确认双方收发能力¶

三次握手是TCP建立连接的过程，通过三次通信确保双方都具备收发数据的能力。过程如下：

  1. 客户端发送SYN请求建立连接
  2. 服务器回复SYN+ACK
  3. 客户端发送ACK确认

8.4 TCP状态转换¶

TCP连接状态转换过程：

  • CLOSED：初始状态
  • LISTEN：服务器等待连接
  • SYN_SENT：客户端发送SYN后等待响应
  • SYN_RECV：服务器收到SYN后等待确认
  • ESTABLISHED：连接建立，双方可以通信
  • FIN_WAIT1：客户端发起关闭请求
  • CLOSE_WAIT：服务器收到关闭请求，等待应用程序关闭
  • FIN_WAIT2：客户端等待服务器关闭
  • LAST_ACK：服务器发送最后关闭确认
  • TIME_WAIT：客户端等待足够时间以确保服务器收到确认
  • CLOSED：连接完全关闭

8.5 TCP的特性¶

  1. 面向连接：通过三次握手建立连接
  2. 可靠传输：使用确认和重传机制
  3. 流量控制：滑动窗口机制
  4. 拥塞控制：慢启动、拥塞避免、快速重传、快速恢复
  5. 全双工通信：双方可同时收发数据
  6. 面向字节流：应用程序数据被看作一个字节序列

9. UDP：无连接、不可靠，但更快¶

UDP是面向无连接的通信协议，包含源端口和目的端口信息，可实现广播发送，但不进行连接确认，属于不可靠传输。

UDP报文由报头（源端口、目标端口、数据报长度、校验值）和数据区组成。UDP适用于对实时性要求较高而对可靠性要求较低的应用。

使用UDP的协议包括：TFTP、SNMP、DNS、NFS、BOOTP等。

TCP与UDP的区别：

特性 TCP UDP
连接 面向连接 无连接
可靠性 可靠 不可靠
传输顺序 保证顺序 不保证顺序
速度 慢 快
头部大小 20-60字节 8字节
流量控制 有 无
拥塞控制 有 无
应用场景 要求可靠传输的应用 实时性要求高的应用

选 TCP 还是 UDP 我通常就问一句：能不能接受丢包？视频、语音这类实时场景丢一两个包无伤大雅，用 UDP；文件、网页必须完整，那就 TCP。

10. HTTP与HTTPS：请求响应模型加一层 TLS 加密¶

10.1 HTTP协议基础：跑在 TCP 上的请求-响应协议¶

HTTP（HyperText Transfer Protocol，超文本传输协议）是互联网上应用最广泛的网络协议，所有WWW文件都必须遵守这个标准。HTTP是一个简单的请求-响应协议，运行在TCP之上，默认端口为80。

HTTP协议是无状态的，对事务处理没有记忆能力，每个请求都是独立的。HTTP协议具有以下特点：

  1. 简单快速：客户端向服务器请求服务时，只需传送请求方法和路径
  2. 灵活：允许传输任意类型的数据对象
  3. 无连接：无连接意味着限制每次连接只处理一个请求，处理完客户的请求后，即断开连接
  4. 无状态：协议对于事务处理没有记忆能力，服务器不知道客户端是什么状态

HTTP协议版本演变：

  • HTTP/0.9：只支持GET方法，无HTTP头部，只能传送HTML文件
  • HTTP/1.0：新增POST和HEAD方法，支持多种文件格式，引入状态码和头部
  • HTTP/1.1：默认持久连接，新增PUT、DELETE、OPTIONS等方法，支持Host头部
  • HTTP/2.0：使用二进制格式，支持多路复用、头部压缩、服务器推送

10.1.1 HTTP请求方法

  • GET：请求获取URL指定的资源
  • POST：向服务器提交数据，请求服务器进行处理
  • HEAD：类似GET请求，但只返回报文头部，不返回实体主体
  • PUT：上传文件到指定位置
  • DELETE：请求服务器删除指定资源
  • TRACE：追踪请求-响应的传输路径
  • OPTIONS：查询服务器支持的方法
  • CONNECT：用于代理服务器，将连接改为管道方式
  • PATCH：对资源进行部分修改

10.2 HTTP状态码：五类状态一眼定位问题¶

HTTP状态码负责表示客户端HTTP请求的返回结果、标记服务器端的处理是否正常、通知出现的错误等工作。

状态码分类：

类别 含义
1XX 信息性状态码，接收的请求正在处理
2XX 成功状态码，请求正常处理完毕
3XX 重定向状态码，需要进行附加操作以完成请求
4XX 客户端错误状态码，服务器无法处理请求
5XX 服务器错误状态码，服务器处理请求出错

10.2.1 2XX 成功状态码

200 OK
表示从客户端发来的请求在服务器端被正常处理。在响应报文内，随状态码一起返回的信息会因方法的不同而发生改变。比如，使用GET方法时，对应请求资源的实体会作为响应返回；而使用HEAD方法时，对应请求资源的实体主体不随报文首部作为响应返回（即在响应中只返回首部，不会返回实体的主体部分）。

204 No Content
该状态码代表服务器接收的请求已成功处理，但在返回的响应报文中不含实体的主体部分。另外，也不允许返回任何实体的主体。比如，当从浏览器发出请求处理后，返回204响应，那么浏览器显示的页面不发生更新。一般在只需要从客户端往服务器发送信息，而对客户端不需要发送新信息内容的情况下使用。

206 Partial Content
该状态码表示客户端进行了范围请求，而服务器成功执行了这部分的GET请求。响应报文中包含由Content-Range指定范围的实体内容。

10.2.2 3XX 重定向状态码

301 Moved Permanently
永久性重定向。该状态码表示请求的资源已被分配了新的URI，以后应使用资源现在所指的URI。也就是说，如果已经把资源对应的URI保存为书签了，这时应该按Location首部字段提示的URI重新保存。

302 Found
临时性重定向。该状态码表示请求的资源已被分配了新的URI，希望用户（本次）能使用新的URI访问。和301 Moved Permanently状态码相似，但302状态码代表的资源不是被永久移动，只是临时性质的。换句话说，已移动的资源对应的URI将来还有可能发生改变。

303 See Other
该状态码表示由于请求对应的资源存在着另一个URI，应使用GET方法定向获取请求的资源。303状态码和302 Found状态码有着相同的功能，但303状态码明确表示客户端应当采用GET方法获取资源，这点与302状态码有区别。

304 Not Modified
该状态码表示客户端发送附带条件的请求时，服务器端允许请求访问资源，但因发生请求未满足条件的情况后，直接返回304 Not Modified（服务器端资源未改变，可直接使用客户端未过期的缓存）。304状态码返回时，不包含任何响应的主体部分。304虽然被划分在3XX类别中，但是和重定向没有关系。

307 Temporary Redirect
临时重定向。该状态码与302 Found有着相同的含义。尽管302标准禁止POST变换成GET，但实际使用时大家并不遵守。307会遵照浏览器标准，不会从POST变成GET。但是，对于处理响应时的行为，每种浏览器有可能出现不同的情况。

10.2.3 4XX 客户端错误状态码

400 Bad Request
该状态码表示请求报文中存在语法错误。当错误发生时，需修改请求的内容后再次发送请求。另外，浏览器会像200 OK一样对待该状态码。

401 Unauthorized
该状态码表示发送的请求需要有通过HTTP认证（BASIC认证、DIGEST认证）的认证信息。另外若之前已进行过1次请求，则表示用户认证失败。返回含有401的响应必须包含一个适用于被请求资源的WWW-Authenticate首部用以质询（challenge）用户信息。当浏览器初次接收到401响应，会弹出认证用的对话窗口。

403 Forbidden
该状态码表明对请求资源的访问被服务器拒绝了。服务器端没有必要给出拒绝的详细理由，但如果想作说明的话，可以在实体的主体部分对原因进行描述，这样就能让用户看到了。未获得文件系统的访问授权，访问权限出现某些问题（从未授权的发送源IP地址试图访问）等列举的情况都可能是发生403的原因。

404 Not Found
该状态码表明服务器上无法找到请求的资源或是服务器无法回应且不知原因。除此之外，也可以在服务器端拒绝请求且不想说明理由时使用。

10.2.4 5XX 服务器错误状态码

500 Internal Server Error
该状态码表明服务器端在执行请求时发生了错误。也有可能是Web应用存在的bug或某些临时的故障。

503 Service Unavailable
该状态码表明服务器暂时处于超负载或正在进行停机维护，现在无法处理请求。如果事先得知解除以上状况需要的时间，最好写入Retry-After首部字段再返回给客户端。

看状态码我按首位数字分大类：2XX 是成了，4XX 找客户端自己的毛病，5XX 才是服务端要背锅，排查时先定大类再看具体码。

10.3 HTTP首部字段：四类字段各管一摊¶

HTTP首部字段用于传递重要信息，如请求/响应类型、资源特性、内容协商等。首部字段格式为字段名: 字段值。

首部字段分类：

  1. 通用首部字段：请求和响应报文都使用的首部

    • Cache-Control：缓存控制
    • Connection：连接管理
    • Date：创建报文日期和时间
    • Pragma：报文指令
    • Trailer：报文末端首部一览
    • Transfer-Encoding：指定报文主体的传输编码方式
    • Upgrade：升级为其他协议
    • Via：代理服务器相关信息
    • Warning：错误通知

  2. 请求首部字段：请求报文使用的首部

    • Accept：用户代理能处理的媒体类型
    • Accept-Charset：优先的字符集
    • Accept-Encoding：优先的内容编码
    • Accept-Language：优先的语言
    • Authorization：Web认证信息
    • Expect：期待服务器的特定行为
    • From：用户的电子邮箱地址
    • Host：请求资源所在服务器
    • If-Match：实体标记的比较
    • If-Modified-Since：比较资源的更新时间
    • If-None-Match：比较实体标记
    • If-Range：资源未更新时发送实体范围请求
    • If-Unmodified-Since：比较资源的更新时间
    • Max-Forwards：最大传输逐跳数
    • Proxy-Authorization：代理服务器要求客户端的认证信息
    • Range：实体的字节范围请求
    • Referer：对请求中URI的原始获取方
    • TE：传输编码的优先级
    • User-Agent：HTTP客户端程序的信息

  3. 响应首部字段：响应报文使用的首部

    • Accept-Ranges：是否接受字节范围请求
    • Age：推算资源创建经过时间
    • ETag：资源的匹配信息
    • Location：令客户端重定向至指定URI
    • Proxy-Authenticate：代理服务器对客户端的认证信息
    • Retry-After：对再次发起请求的时机要求
    • Server：HTTP服务器的安装信息
    • Vary：代理服务器缓存的管理信息
    • WWW-Authenticate：服务器对客户端的认证信息

  4. 实体首部字段：针对请求报文和响应报文的实体部分使用的首部

    • Allow：资源可支持的HTTP方法
    • Content-Encoding：实体主体使用的编码方式
    • Content-Language：实体主体的自然语言
    • Content-Length：实体主体的大小
    • Content-Location：替代对应资源的URI
    • Content-MD5：实体主体的报文摘要
    • Content-Range：实体主体的位置范围
    • Content-Type：实体主体的媒体类型
    • Expires：实体主体过期的日期时间
    • Last-Modified：资源的最后修改日期时间

10.4 HTTP工作原理：建连到记录日志的七步¶

HTTP工作在客户端-服务端（C/S）架构上。一次HTTP交互过程如下：

  1. 建立连接：客户端与Web服务器建立TCP连接
  2. 发送HTTP请求：客户端发送请求到服务器
  3. 服务器处理请求：服务器解析请求，访问资源
  4. 返回响应结果：服务器将响应结果发送给客户端
  5. 关闭连接：若Connection: close，则断开连接；若Connection: keep-alive，则保持连接

一次完整的HTTP请求处理过程：

  1. 建立或处理连接：接收请求或拒绝请求
  2. 接收请求：接收来自于网络上的主机请求报文
  3. 处理请求：解析请求报文，获取资源及请求方法等信息
  4. 访问资源：获取请求报文中请求的资源
  5. 构建响应报文：根据请求构建适当的响应
  6. 发送响应报文：将响应发送给客户端
  7. 记录日志：记录访问日志信息

10.5 HTTPS协议：HTTP 外面套一层 TLS¶

HTTPS（Hypertext Transfer Protocol Secure，超文本传输安全协议）是HTTP协议的安全版本，通过SSL/TLS加密HTTP通信内容。HTTPS默认端口为443。

HTTPS的特点：

  • 数据加密传输，提高了通信安全性
  • 提供服务器身份验证，防止中间人攻击
  • 保护数据完整性，防止数据被篡改

10.5.1 HTTP与HTTPS的区别

  1. 安全性：HTTP明文传输，安全性差；HTTPS加密传输，安全性高
  2. 证书：HTTPS需要CA证书，一般需要付费申请
  3. 性能：HTTP连接简单，响应速度更快；HTTPS需要额外的SSL握手，耗时更多
  4. 端口：HTTP使用80端口，HTTPS使用443端口
  5. 资源消耗：HTTPS会消耗更多服务器资源

10.5.2 HTTPS的工作原理

HTTPS通过SSL/TLS协议进行加密通信，主要工作流程如下：

  1. 客户端发起HTTPS请求：连接到服务器443端口
  2. 服务器配置证书：服务器需要配置公钥证书，可以是自签名的或由CA颁发的
  3. 服务器发送证书：包含公钥及其他相关信息
  4. 客户端验证证书：检查证书有效性、颁发机构、过期时间等
  5. 客户端生成随机值：生成会话密钥，并用服务器公钥加密
  6. 客户端发送加密信息：将加密后的随机值发送给服务器
  7. 服务器解密信息：使用私钥解密获取会话密钥
  8. 双方使用会话密钥加密通信：之后的所有通信都使用这个对称密钥加密

HTTPS握手流程：

HTTPS 握手本质是「非对称加密协商出会话密钥，之后用对称加密传数据」，前半段慢、后半段快，这样既安全又不拖累传输效率。

11. 网络安全与加密：对称、非对称、哈希三类算法¶

11.1 网络安全基本目标：保密性、完整性、可用性¶

网络安全主要包括三个方面：

  • 保密性（Confidentiality）：确保信息只能被授权用户访问
  • 完整性（Integrity）：防止数据被未授权修改
  • 可用性（Availability）：确保合法用户能够访问服务

11.2 常见攻击类型：分别冲击三个安全目标¶

  • 威胁保密性的攻击：窃听、通信量分析
  • 威胁完整性的攻击：数据更改、伪装、重放、否认
  • 威胁可用性的攻击：拒绝服务攻击（DoS/DDoS）

11.3 加密和解密技术：三类算法各有分工¶

加密技术是网络安全的核心，主要分为两类：

11.3.1 对称加密

对称加密使用同一密钥进行加密和解密。主要特点：

  • 加密解密速度快
  • 密钥管理复杂，密钥分发困难
  • 适合大量数据加密

主要对称加密算法：

  • DES（Data Encryption Standard）：56位密钥
  • 3DES（Triple DES）：使用三重DES加密
  • AES（Advanced Encryption Standard）：支持128、192、256位密钥
  • Blowfish、Twofish、IDEA、RC6、CAST5等

11.3.2 非对称加密（公钥加密）

非对称加密使用一对密钥：公钥和私钥。主要特点：

  • 公钥可公开分发，私钥保密保存
  • 用公钥加密的数据只能用对应的私钥解密，反之亦然
  • 加解密速度慢，不适合大量数据加密

主要用途：

  • 数字签名：发送方用私钥加密数据特征码，接收方用发送方公钥验证
  • 密钥交换：安全地交换对称加密的密钥
  • 数据加密：小量敏感数据的加密

主要非对称加密算法：

  • RSA：可用于加密和签名
  • DSA（Digital Signature Algorithm）：仅用于签名
  • ECC（椭圆曲线加密）：更高效的非对称加密
  • ElGamal：基于离散对数问题的加密算法

11.3.3 单向加密（哈希算法）

单向加密算法将任意长度的数据映射为固定长度的散列值，不可逆。主要特点：

  • 定长输出
  • 雪崩效应：输入微小变化导致输出显著不同
  • 不可逆：无法从散列值重建原始数据

主要用途：数据完整性验证、密码存储

主要哈希算法：

  • MD5：128位输出，现已不安全
  • SHA-1：160位输出，现已不安全
  • SHA-2系列：包括SHA-224、SHA-256、SHA-384、SHA-512
  • SHA-3：最新的哈希标准

这三类算法我会这么区分：对称加密用来快速加密大文件，非对称加密解决「密钥怎么安全送到对方手里」，哈希则用来验数据有没有被改动，三者经常组合着用。

11.4 PKI与数字证书：把公钥和身份绑起来¶

PKI（Public Key Infrastructure，公钥基础设施）是支持公钥加密的安全体系，主要组件包括：

  • CA（Certificate Authority）：证书颁发机构
  • RA（Registration Authority）：证书注册机构
  • CRL（Certificate Revocation List）：证书吊销列表
  • CB（Certificate Base）：证书存取库

数字证书（X.509 v3标准）包含以下信息：

  • 版本号
  • 序列号
  • 签名算法ID
  • 发行者名称
  • 有效期限
  • 主体名称
  • 主体公钥
  • 发行者的唯一标识
  • 主体的唯一标识
  • 扩展信息
  • 发行者签名

11.5 SSL/TLS协议：为通信加一道加密层¶

SSL（Secure Sockets Layer）和TLS（Transport Layer Security）是为网络通信提供安全及数据完整性的加密协议。

协议版本演进：

  • SSL：由Netscape开发，包括v1.0、v2.0、v3.0（已废弃）
  • TLS：由IETF标准化，包括v1.0、v1.1、v1.2、v1.3

协议分层设计：

  1. 最底层：基础算法原语的实现（AES、RSA、MD5等）
  2. 向上一层：各种算法的实现
  3. 再向上一层：组合算法实现的半成品
  4. 最上层：各种成品密码学协议软件

OpenSSL是SSL/TLS协议的开源实现，由三部分组成：

  • libencrypto库：加密算法库
  • libssl库：SSL/TLS协议实现
  • openssl命令行工具：提供各种加密、证书管理功能

12. NAT协议：私网地址换公网地址，缓解 IP 不足¶

网络地址转换(NAT)将私有地址转换为合法IP地址，解决IP地址不足问题，同时能有效避免外部攻击，保护内部网络计算机。

13. DHCP协议：基于 UDP 自动分配 IP¶

动态主机设置协议(DHCP)是一个使用UDP协议的局域网协议，主要用于自动分配IP地址和进行集中管理计算机。

14. 一次完整通信：从输入网址到页面渲染¶

在浏览器输入www.baidu.com后发生的过程：

  1. 浏览器通过DNS解析获取百度服务器IP地址

    • 检查浏览器DNS缓存
    • 检查操作系统DNS缓存
    • 检查本地hosts文件
    • 向本地DNS服务器发起查询请求
    • 如果本地DNS服务器没有记录，则进行递归或迭代查询

  2. 浏览器发起HTTP请求，TCP封装数据包并传输到网络层

    • 浏览器创建HTTP请求消息
    • 应用层将HTTP请求交给传输层

  3. 传输层将HTTP请求分段，添加源端口和目的端口

    • 客户端随机选择一个源端口
    • 目的端口为HTTP默认端口80或HTTPS默认端口443
    • 进行三次握手建立TCP连接

  4. 网络层查找路由表确定如何到达服务器

    • 添加源IP和目的IP
    • 确定下一跳路由

  5. 链路层通过ARP获取目的MAC地址并发送数据包

    • 如果目标在同一网段，直接ARP获取目标MAC
    • 如果不在同一网段，ARP获取默认网关MAC

  6. 数据包经过多个路由器最终到达服务器

    • 每个路由器检查目的IP并决定转发路径
    • 可能经过NAT转换等过程

  7. 服务器处理请求并返回响应

    • 服务器接收请求并解析
    • 服务器生成响应并发送回客户端
    • 响应经过与请求相反的路径返回

  8. 浏览器接收响应并渲染页面

    • 解析HTML、CSS、JavaScript
    • 加载其他资源（图片、样式表、脚本等）
    • 渲染网页内容

  9. 通信完成后断开TCP连接

    • 通过四次挥手关闭连接
    • 释放相关资源
