核心概念：笔记与链接

[!abstract] 一句话
笔记是原子，链接是化合键：吃透 Markdown 语法、双链 与 Callout，就掌握了 Obsidian 八成的日常操作。

为什么是 Markdown

Obsidian 的所有笔记都是标准 Markdown 文件，这意味着它们可以被任何编辑器打开、被任何工具处理、几十年后依然可读。Markdown 用极少的符号承担了排版职责，让你专注内容本身。常用语法一屏就能装下：

在实时预览模式下，这些符号会即刻渲染成排版效果，学习成本比纯文本 Markdown 编辑器低得多。

Wiki 链接：双链的语法基础

Obsidian 对标准 Markdown 最重要的扩展是 Wiki 链接（``）。输入两个左中括号，Obsidian 会弹出笔记名自动补全：

Wiki 链接最大的好处是不依赖路径：笔记改名或移动文件夹时，所有指向它的链接自动更新。这正是它比 [文字](相对路径) 形式更适合知识库的原因。

[!tip] 链接方式选择
内部链接统一用 ``，指向网络的资源用标准 Markdown 链接。两者混而不乱：库内靠双链编织，库外靠 URL 引用。

嵌入与块引用

在 `` 前加感叹号即变成嵌入（transclusion）：> [!warning] 未转换的 Obsidian 嵌入: 某笔记 会把整篇笔记内容内嵌展示；配合标题或块 ID 可以只嵌入一个片段，例如 > [!warning] 未转换的 Obsidian 嵌入: 读书笔记#第三章。块引用的块 ID 无需手写——把光标放在目标段落，打开命令面板执行”复制块引用”，或直接输入 [[笔记名#^ 时 Obsidian 会自动列出可选块。

[!tip] 嵌入要有节制
嵌入长文会让当前笔记变成”套娃”，阅读负担陡增。原则是：引用观点用块引用，整合内容（如周报汇总每日笔记）才用整篇嵌入。

Callout：结构化的提示块

Callout 是 Obsidian 内置的可视化提示块，语法建立在引用块之上：

常用类型包括 note（普通笔记）、abstract/summary/tldr（摘要）、info（信息）、tip/hint/important（提示）、success/check（成功）、question/help/faq（疑问）、warning/caution（警告）、danger（危险）、bug（缺陷）、example（示例）、quote/cite（引用）。每种类型有专属图标与颜色，信息优先级一目了然。

两个进阶用法值得掌握。折叠：在类型后加 - 默认折叠、加 + 默认展开，如 > [!note]- 默认折叠的补充说明，非常适合收纳长段附录；嵌套与富文本：Callout 内部可以继续使用列表、表格、代码块，甚至嵌套另一层 Callout，用它做”要点摘录 + 展开细节”的分层笔记非常顺手。

[!warning] Callout 兼容性
Callout 是 Obsidian 扩展语法。笔记仅在 Obsidian 生态内（含官方 Publish、多数发布插件）才能正确渲染；导出到其他平台时会被降级为普通引用块，重要文档对外分发前要考虑这一点。

反向链接与 Frontmatter 预告

每一条 `` 链接都会被自动记录：被链接的笔记右侧面板会出现”反向链接”，告诉你”谁引用了我”。这是 04-双向链接与图谱 的主角。此外，笔记开头可以写一段 YAML 头（Frontmatter），为笔记添加标签、日期、状态等结构化属性，它是标签、模板与数据库视图的共同地基，详见 05-属性元数据与标签。

常见坑

[!warning] 避坑清单

  1. 同名笔记：不同目录下的同名文件会让 `` 产生歧义，尽量保证全库标题唯一；
  2. YAML 语法错误：冒号后忘写空格、列表缩进不对，都会让 Frontmatter 整体失效；
  3. 全用绝对路径链接：文件夹一重构链接全断，内部链接坚持用 Wiki 链接；
  4. 把 Callout 当装饰：满屏彩色提示块等于没有重点，一块笔记留一到两处即可。
