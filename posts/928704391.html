Caddy 简介与适用场景

接着上一篇 00-索引 往下，先弄明白 Caddy 到底适合干什么。它是 Go 编写的开源 Web 服务器，主打”自动 HTTPS”，配置简单、运维省心；我判断一套系统值不值得换，通常就看它能不能替我把证书和配置这两件麻烦事扛下来。

Caddy 主打自动 HTTPS 和省心配置¶

Caddy 是使用 Go 编写的开源 Web 服务器，以”自动 HTTPS”为核心卖点：

核心特性：

  • 自动获取/续期 TLS 证书，无需人工干预
  • Caddyfile 配置极简，可读性强
  • 默认启用 HTTP/2、HTTP/3
  • 内建安全响应头与 OCSP stapling
  • 支持静态站点、反向代理、负载均衡
  • 单二进制部署，无运行时依赖
  • JSON API 管理接口（Caddy v2）

比 Nginx 省心，但生态更年轻¶

维度 Caddy Nginx
配置 Caddyfile 简洁 nginx.conf 复杂
HTTPS 全自动 需手动/脚本
扩展 模块化（xcaddy） 模块/Lua 丰富
性能 优秀（Go） 优秀（C）
生态 较年轻 成熟庞大
学习成本 低 中高

中小站点和内网暴露最合适¶

  1. 个人/中小站点：自动 HTTPS 的静态博客、文档站
  2. 内网服务暴露：把 NAS、GitLab、监控等反代到域名
  3. API 网关：简单路由、负载均衡、限流
  4. 容器环境：与 Docker Compose 组合自动发现服务
  5. 快速原型：几分钟完成 HTTPS 上线

复杂企业架构还得看 Nginx¶

  • 需要丰富第三方模块的复杂企业架构（Nginx/OpenResty 更合适）
  • 团队已有深厚的 Nginx 配置资产
  • 需要细粒度企业级 WAF 商业功能

新项目只认 v2¶

  • Caddy v2 为当前主线（本套教程基于 v2）
  • Caddy v1 已停止维护，勿用于新项目
  • 通过 xcaddy 可编译带自定义模块的二进制
