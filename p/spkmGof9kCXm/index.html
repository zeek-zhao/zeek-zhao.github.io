devops-gitlab-开发指南

1. GitLab 简介

GitLab 是一个基于 Git 的完整 DevOps 平台，提供从项目规划、源代码管理到 CI/CD、监控和安全的端到端解决方案。GitLab 提供了两个版本：社区版（CE）是开源的，而企业版（EE）提供更多商业功能。

2. 仓库管理

2.1 创建与管理仓库

在 GitLab 中创建仓库（在 GitLab 中称为项目）是开始工作的第一步。

2.1.1 创建新项目

  1. 登录到 GitLab
  2. 点击导航栏中的 “+” 按钮，选择 “New project”
  3. 选择创建方式：
    • 创建空项目
    • 从模板创建项目
    • 导入项目
    • 从外部仓库克隆
  4. 填写项目信息：
    • 项目名称
    • 项目描述
    • 可见性级别（Private, Internal, Public）
    • 初始化选项（README, .gitignore, license）

2.2 分支管理策略

有效的分支管理策略是团队协作的关键，GitLab 支持多种分支工作流。

2.2.1 GitLab Flow

graph LR
    A[主分支<br>main] --> B[环境分支<br>production]
    A --> C[环境分支<br>pre-production]
    D[特性分支<br>feature/x] --> A
    E[特性分支<br>feature/y] --> A
    F[修复分支<br>hotfix/z] --> A
    F -.-> B

    style A fill:#f96,stroke:#333,stroke-width:2px
    style B fill:#6c6,stroke:#333,stroke-width:1px
    style C fill:#69f,stroke:#333,stroke-width:1px

GitLab Flow 是一种简单而灵活的工作流，结合了功能分支和环境分支的优点：

  1. 主分支（main）：包含最新的开发代码
  2. 特性分支：从主分支创建，开发完成后通过合并请求合并回主分支
  3. 环境分支：表示部署环境，如 production、staging 等
  4. 发布分支：可选，用于特定版本的代码

2.2.2 保护分支配置

为确保代码质量和稳定性，应配置分支保护规则：

graph TD
    A[分支保护机制] --> B[推送权限保护]
    A --> C[合并权限保护]
    A --> D[强制推送保护]

    B --> B1[禁止推送]
    B --> B2[允许维护者推送]
    B --> B3[允许开发者推送]

    C --> C1[禁止合并]
    C --> C2[允许维护者合并]
    C --> C3[允许开发者合并]

    D --> D1[启用强制推送保护]
    D --> D2[禁用强制推送保护]

    style A fill:#bbf,stroke:#333,stroke-width:2px

在 GitLab 中配置分支保护：

  1. 进入项目 > Settings > Repository
  2. 展开 “Protected Branches” 部分
  3. 选择要保护的分支
  4. 设置谁可以推送和合并
  5. 启用额外保护选项，如代码所有者审批

2.3.2 语义化版本控制

采用语义化版本控制（Semantic Versioning）来命名标签：

  • MAJOR: 进行不兼容的 API 更改时增加
  • MINOR: 以向后兼容的方式添加功能时增加
  • PATCH: 进行向后兼容的错误修复时增加
  • PRERELEASE: 预发布版本标识，如 alpha、beta
  • BUILD: 构建元数据标识

3. Git 工作流

3.1 日常工作流程

sequenceDiagram
    participant D as 开发者
    participant F as 特性分支
    participant M as 主分支
    participant R as 远程仓库

    D->>R: 克隆仓库 (git clone)
    D->>M: 拉取最新代码 (git pull)
    D->>F: 创建特性分支 (git checkout -b feature/x)

    loop 开发循环
        D->>D: 编码与本地测试
        D->>F: 提交更改 (git commit)
        D->>R: 推送特性分支 (git push)
    end

    D->>R: 创建合并请求
    Note over R: 代码审查过程
    Note over R: CI/CD 流水线验证
    R->>M: 合并特性分支
    D->>M: 拉取更新 (git pull)
    D->>D: 删除本地特性分支 (git branch -d feature/x)

3.3 使用 GitLab Web IDE

GitLab 提供了内置的 Web IDE，可以直接在浏览器中编辑文件：

  1. 进入项目仓库页面
  2. 选择文件并点击 “Edit” 按钮，或点击 “WebIDE” 按钮
  3. 进行编辑并提交更改
  4. 可选择直接提交到分支或创建合并请求

Web IDE 优势：

  • 无需本地 Git 环境
  • 内置语法高亮
  • 实时预览 Markdown 文件
  • 集成的终端
  • 直接访问 CI/CD 流水线

4.2.1 审查清单

创建标准代码审查清单可提高审查质量和一致性：

  1. 功能性

    • 代码是否完成需求？
    • 是否处理了边缘情况？
    • 是否有适当的错误处理？

  2. 可读性和可维护性

    • 代码是否易于理解？
    • 命名是否清晰和一致？
    • 是否有适当的注释和文档？

  3. 性能

    • 是否有潜在的性能问题？
    • 是否有优化空间？
    • 大数据集测试？

  4. 安全性

    • 是否存在安全漏洞？
    • 用户输入是否被适当验证？
    • 敏感数据是否安全处理？

  5. 测试

    • 是否有足够的单元测试？
    • 测试是否覆盖关键路径？
    • 是否测试了错误情况？

6.3.1 里程碑最佳实践

  • 为每个迭代或发布版本创建单独的里程碑
  • 使用一致的命名约定（如 v1.0, v1.1 或 Sprint 1, Sprint 2）
  • 为里程碑设置明确的开始和结束日期
  • 使用描述字段说明里程碑的目标和范围
  • 定期检查里程碑进度

12.3 常见错误及解决方案

错误场景 可能原因 解决方案
推送被拒绝 分支保护规则 检查分支保护设置，使用合并请求
合并请求无法合并 合并冲突 本地解决冲突，更新分支
Runner 离线 网络或配置问题 检查 Runner 连接，重启服务
流水线作业超时 作业执行时间过长 优化脚本，增加超时时间
文件过大无法上传 仓库限制 使用 Git LFS，调整限制
权限被拒绝 权限不足 检查用户权限配置
容器构建失败 Docker 配置问题 检查 Dockerfile，使用 dind 服务
