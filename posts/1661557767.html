ROS2 与 Docker

[!info] 本节目标
掌握用 Docker 容器化 ROS2 开发与部署：镜像拉取、容器交互、GUI 与设备透传。

1. Docker 基础

Docker 提供轻量隔离环境，解决 ROS2 环境依赖与多版本共存问题。

概念 说明
镜像（Image） 只读模板
容器（Container） 镜像运行实例
Dockerfile 构建脚本
卷（Volume） 持久化数据

2. 拉取 ROS2 官方镜像

[!note] 镜像标签
ros-base（核心）、ros-core、desktop（桌面工具）；osrf/ros 系列含教程演示环境。

3. 带 GUI 的容器

Linux 下 X11 转发：

[!warning] 权限
xhost 需谨慎使用（局域网环境可能暴露显示）；Windows/macOS 桌面场景可用 VNC 方案。

4. 设备透传

[!tip] 权限组
容器内串口访问可能需 --group-add dialout 或容器内 usermod。

5. Dockerfile 构建

[!warning] 多阶段
大型工程建议多阶段构建（编译镜像 -> 运行镜像），显著减小体积。

6. compose 多容器

[!tip] 编排
机器人 + 中间件 + Web 服务用 compose 统一管理，便于生产部署。

7. 常见问题

问题 排查
容器内无 GUI DISPLAY 转发/Xvfb/VNC
设备不可见 –device 未传、权限组
时间不同步 -v /etc/localtime:/etc/localtime:ro
共享内存不足 /dev/shm 挂载

[!note] 延伸
容器化部署与产品化见 38-产品化与部署实践；嵌入式同样用 Docker 见 32-ROS2与嵌入式平台。

8. 镜像管理最佳实践

镜像管理遵循”小而精、标签化”原则：基于官方基础镜像构建，仅安装必要依赖；用语义化标签记录发行版、架构与构建时间，避免 latest 混乱。多机部署用 Docker Compose 或 Kubernetes 编排，统一网络与存储配置。镜像构建纳入 CI，每次代码更新自动构建并跑冒烟测试。运行容器建议挂载配置目录、限制资源与开启日志收集。升级依赖后回归测试，防止环境漂移引入隐性故障。

[!note] 建议
Docker 是 ROS2 交付与部署的利器，配合 CI/CD 可实现一键部署；生产部署完整方案见 38-产品化与部署实践。
