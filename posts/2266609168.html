06-内核与调度

发表于2026-10-24|Zephyr
|浏览量:

[!info] 本节目标
理解 Zephyr 内核模型与调度机制。

1. 内核概述

Zephyr 内核提供线程、调度、同步与内存管理等核心能力，支持可抢占与协作式调度模式。内核小巧高效，架构抽象统一多平台。应用通过内核 API 组织并发任务。

2. 线程模型

线程是执行单元，拥有独立栈与上下文。Zephyr 线程支持动态与静态创建，优先级数值小者优先。线程状态包括就绪、运行、等待与挂起，状态迁移由调度器管理。

3. 调度器

调度器选择最高优先级就绪线程运行，支持抢占式与时间片轮转。协作式调度依赖线程主动让出，可配置调度算法。调度行为影响实时性，配置按需求选择。

4. 同步原语

信号量、互斥量、条件变量与队列提供同步与通信。同步原语阻塞线程让出 CPU，避免忙等。原语选择按语义匹配，事件与数据传递场景区分。

5. 中断处理

中断服务程序快速处理硬件事件，中断安全 API 通知线程。中断嵌套与优先级配置，ISR 遵循规范约束。中断与线程协作高效处理异步事件。

6. 时间服务

系统节拍驱动延时与定时器，tickless 降低空闲功耗。软件定时器管理周期任务，时间 API 统一。时间精度与开销平衡，按应用需求配置。

7. 实践要点

线程划分与栈规划合理，优先级设计考虑反转。同步语义明确，中断路径最短化。调度与时间配置测试验证，监控系统状态。

8. 常见问题

调度相关问题的排查重点在于区分抢占点与协作点：Zephyr 默认抢占式调度，但在中断上下文、临界区与某些系统调用内部不会发生线程切换。优先级反转是经典难题，互斥量自带优先级继承可以缓解，使用信号量或自旋锁则没有该机制。栈溢出是最隐蔽的故障，建议开启栈溢出检测与线程分析器，在开发阶段把栈余量数据打印出来。多线程程序的时序问题难以复现，尽量把共享状态收敛到少数对象，并用信号量或事件替代轮询，减少不确定窗口。
