性能优化的关键指标¶

了解并监控关键性能指标是优化工作的基础：

📝Web前端性能核心指标

  1. 加载性能指标

    • First Contentful Paint (FCP): 首次内容绘制，首个文本或图像元素显示的时间
    • Largest Contentful Paint (LCP): 最大内容绘制，最大文本或图像元素显示的时间
    • Time to Interactive (TTI): 可交互时间，页面可以可靠响应用户交互的时间
    • Total Blocking Time (TBT): 总阻塞时间，主线程被阻塞时间总和
    • Cumulative Layout Shift (CLS): 累积布局偏移，衡量视觉稳定性

  2. Google Core Web Vitals

    • LCP: 应在2.5秒内完成
    • FID: 首次输入延迟，应小于100ms
    • CLS: 应小于0.1

  3. 网络性能指标

    • DNS解析时间
    • TCP连接时间
    • TLS握手时间
    • TTFB (Time To First Byte): 首字节时间
    • 页面加载总时间
    • 资源大小与数量

前端：加载、渲染与 JS¶

网站加载优化¶

网站加载速度是用户体验的第一关，优化加载性能需要综合考虑多个方面：

资源优化
资源优化策略

  1. 图像优化

    • 选择适当的图像格式（WebP、AVIF等现代格式）
    • 根据设备尺寸提供响应式图片
    • 使用图像压缩工具减小文件大小
    • 实现延迟加载（Lazy Loading）
    • 使用图像CDN服务提供优化

  2. JavaScript优化

    • 代码分割（Code Splitting）
    • 按需加载（懒加载）
    • 压缩和混淆
    • 移除未使用的代码
    • 减少第三方脚本使用

  3. CSS优化

    • Critical CSS（关键CSS）抽取
    • 移除未使用的CSS
    • 压缩CSS文件
    • 减少CSS框架大小

  4. HTML优化

    • 压缩HTML
    • 减少DOM节点数量
    • 避免内联大型资源

JavaScript性能优化¶

JavaScript性能直接影响页面的交互体验和响应速度：

🔥JavaScript性能优化关键点

  1. 代码级优化

    • 避免全局变量
    • 减少闭包使用
    • 优化循环（缓存长度、减少DOM访问）
    • 使用恰当的数据结构和算法
    • 字面量代替构造函数

  2. 内存管理

    • 及时清理不再使用的对象引用
    • 避免内存泄漏（特别是事件监听器）
    • 避免频繁创建短生命周期对象
    • 使用对象池模式处理频繁创建销毁

  3. 异步优化

    • Promise优化替代多层回调
    • 使用async/await提高可读性
    • 避免阻塞主线程
    • 恰当使用microtasks和macrotasks

  4. 框架优化

    • React: 使用React.memo、PureComponent、useMemo等
    • Vue: 恰当使用v-once、keep-alive、虚拟滚动
    • 减少组件重渲染
    • 状态管理优化

缓存模式与策略:

⚠️缓存更新策略比较

  1. Cache-Aside (旁路缓存)

    • 操作流程: 先查缓存，未命中则查DB并更新缓存
    • 优点: 简单实现，适应性强
    • 缺点: 写操作复杂度增加，可能造成数据不一致
    • 适用场景: 读多写少，对一致性要求不高

  2. Read-Through

    • 操作流程: 由缓存层负责加载数据，对应用透明
    • 优点: 简化应用逻辑，统一缓存管理
    • 缺点: 首次访问性能较差
    • 适用场景: 需要统一缓存管理的系统

  3. Write-Through

    • 操作流程: 写入时同步更新缓存和数据库
    • 优点: 数据一致性好
    • 缺点: 写性能受影响，可能缓存无效数据
    • 适用场景: 对一致性要求高的系统

  4. Write-Behind (写回)

    • 操作流程: 先写缓存，异步批量写数据库
    • 优点: 写性能高，可合并操作
    • 缺点: 复杂度高，可能数据丢失
    • 适用场景: 高写入负载，容忍短暂不一致

阿姆达尔定律分析:

$$S(n) = \frac{1}{(1-p) + \frac{p}{n}}$$

其中：

  • $S(n)$ 是使用n个处理单元的加速比
  • $p$ 是可并行化的程序比例
  • $n$ 是处理单元数量

这个公式告诉我们，程序中的串行部分会限制整体可能的加速比，无论我们添加多少处理单元。
