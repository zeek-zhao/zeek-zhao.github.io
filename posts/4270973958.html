性能与效率

[!info] 本页概览
本文讲解 Shell 脚本性能优化：减少子进程、内建替代外部命令、并行执行、避免重复管道、超大文件处理策略与锁防并发。

核心概念

Shell 每条外部命令都 fork 新进程，循环内频繁调用外部命令是性能头号杀手。优化方向：内建优先、批量处理、减少往返、并行化。

内建 vs 外部命令

场景 外部命令 内建替代
数值运算 expr (( )) / $(( ))
字符串替换 sed ${var//...}
字符串截取 cut ${var:0:5}
长度 wc -c ${#var}
大小写 tr ${var^^}
去空格 sed ${var%% }（部分场景）

常见坑

  1. 过度优化：先测量（time）再优化，脚本常受 I/O 而非 CPU 限制。
  2. 循环内外部命令：最常被忽略；先缓存值、合并命令。
  3. 并行写同一文件：数据竞争；每个任务写独立文件再合并。
  4. wait -n 兼容性：需 bash 4.3+；老系统用轮询 jobs。
  5. xargs -0 未配对 find -print0：文件名含换行/空格时出错。
  6. flock 文件描述符未关闭：exec 9> 保持打开，脚本退出自动释放。

最佳实践

  • 用 time script.sh 与 bash -x 定位耗时点。
  • 循环内只调内建与管道外命令；必要子进程先缓存结果。
  • 批量命令（gzip/cp/curl）用通配或 xargs 一次完成。
  • I/O 密集并行（P 核数），CPU 密集多进程小心资源耗尽。
  • 生产脚本统一 flock 防并发，避免定时任务重叠。
