仓库类型详解

接着上一篇 02-安装部署 把服务装起来，这篇讲仓库。Nexus 的仓库说到底就三种：proxy 缓存外部源、hosted 存私有制品、group 把它们聚成一个统一入口。记住这一句，后面配仓库心里就有底了。

1. proxy、hosted、group 各管一摊¶

类型 行为 用途
proxy 按需拉取外部源并缓存 中央仓库、Docker Hub、registry
hosted 只存本地，不可外联 公司私有组件、内部镜像
group 聚合多仓库，对外一个 URL 客户端唯一入口

2. proxy 重在缓存参数和能回源¶

Repository → Create → proxy
Name: maven-central
Remote storage: https://repo1.maven.org/maven2/
Maximum component age: 1440（分钟，缓存保留）
Negative cache TTL: 1440（404 缓存）
Authentication: 可选（外部源需要）

参数 建议
Auto blocking 开启，外部源故障自动标记
Maximum component age 一般不动（除非需要强制刷新）
Negative cache TTL 避免 404 频繁重试

要强制刷新缓存，勾选 “Expire cache” 或把 Maximum age 调小就会重新拉一遍。

3. hosted 重在版本策略和禁覆盖¶

参数 建议
Version policy Release / Snapshot（Maven）；其他格式无此项
Deployment policy 默认 Disable redeploy（防覆盖）
写入认证 必须登录，禁止匿名上传

4. group 就是客户端的唯一入口¶

  • 组内顺序 = 查找顺序（先本地后代理）；
  • 客户端只配 group URL，内部路由透明；
  • group 可嵌套（组套组，慎用）。

5. 命名先定好，格式建完改不了¶

我一般不做组套组，排查起来太绕；命名也按这个套路走，省得后面认不出哪个仓是哪个。

6. 权限和清理靠选择器与策略¶

  • Content Selector：按路径正则控制权限（09-权限与匿名访问）；
  • Cleanup Policy：按年龄/大小自动清理（10-Cleanup与任务调度）。

几个坑提前说：proxy 指向的外部源必须双向可达（不管是外网还是内网源）；往 group 里加新仓库前先确认成员仓库是健康的；仓库一旦创建格式就改不了，所以命名一定想清楚再点创建。
