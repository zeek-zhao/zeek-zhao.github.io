泛型

[!info] 本页概览
本文讲解 Java 泛型：泛型类/接口/方法、类型参数、通配符（? extends / ? super）、类型擦除、泛型与数组/异常的限制，配可运行示例与实战技巧。

核心概念

  • 泛型（Generic）：把”类型”作为参数，编译期保证类型安全，消除强制转换。
  • 类型参数：<T>、<K,V>，约定：T（Type）、E（Element）、K/V（Key/Value）、N（Number）。
  • 通配符：? 表示未知类型；? extends T 上界；? super T 下界（PECS）。
  • 类型擦除：编译后擦除类型参数，运行期无泛型信息。

[!note] PECS 原则
生产者（读取数据）用 ? extends T；消费者（写入数据）用 ? super T。List<? extends Number> 只能读不能写；List<? super Integer> 只能写不能安全读。

泛型的限制

常见坑

  1. 泛型不是协变的：List<String> 不是 List<Object> 子类；要协变用 List<? extends Object>。
  2. 不能创建泛型数组：new T[10] 编译错误；用 ArrayList 或 Array.newInstance。
  3. 静态上下文不能用类型参数：static 方法/字段无法使用类的 T。
  4. 异常类不能泛型：class MyException<T> extends Exception 编译错误。
  5. 基本类型不能作类型参数：List<int> 错误，用 List<Integer>。
  6. 擦除后 instanceof 检查受限：list instanceof List<String> 非法，只能用 list instanceof List。

最佳实践

  • API 返回泛型集合时声明不可变/只读类型，避免滥用通配符。
  • 集合泛型使用 List<String> 而非裸 List（raw type 编译警告）。
  • 复杂泛型签名拆成方法或类型别名（如 Map<String, List<Integer>> 用接口封装）。
  • 优先 Collections.unmodifiableList 防御性设计。
  • PECS 原则：extends 读、super 写。
