脚本调试

[!info] 本页概览
本文讲解 Shell 脚本调试方法：bash -x 跟踪执行、set -x/-v 动态开启、shellcheck 静态检查、日志与断言，以及常见错误的定位技巧。

核心概念

  • bash -x：逐条打印执行的命令（展开后），是调试利器。
  • set 选项：-x 跟踪、-v 打印原命令、-e 出错即停、-u 未定义变量报错。
  • shellcheck：静态分析工具，找出隐藏 bug（引号、误用）。
  • 调试核心：定位”哪一行、什么值、为什么”。

实战调试示例

调试步骤：bash -x script.sh a.log 观察每一行；发现 grep 无匹配导致 set -e 退出，加 || true。

常见坑

  1. set -e 陷阱：cmd || true、if cmd、grep 无匹配、函数返回值等场景不会退出，勿过度依赖。
  2. 调试信息泄漏：set -x 会打印变量值，含密码/密钥时慎用。
  3. 只查语法不查逻辑：bash -n 通过不代表正确，配合 -x 观察运行。
  4. 忘记 pipefail：管道失败被掩盖（cmd | grep 只看 grep 结果）。
  5. 错误行号定位：bash -x + PS4='${LINENO}: ' 显示行号。
  6. &&/|| 与 set -e 交互：理解优先级避免意外退出或继续。

最佳实践

  • 所有新脚本开头 set -euo pipefail（老旧脚本逐步迁移）。
  • CI 中跑 shellcheck 强制规范。
  • 调试顺序：bash -n（语法）→ shellcheck（静态）→ bash -x（运行跟踪）。
  • 关键路径打印结构化日志，失败时留证据。
  • 复杂脚本拆函数，单函数单测；用 trap（见 18-信号处理与trap）记录退出。
