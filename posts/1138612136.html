rosbridge 与 Web 端

[!info] 本节目标
掌握 rosbridge 桥接机制，能通过 WebSocket 在浏览器中收发 ROS2 话题与服务。

1. rosbridge 架构

rosbridge 把 ROS2 通信转换为 WebSocket JSON 协议，浏览器/移动端无需安装 ROS 即可交互。

组件 用途
rosbridge_server ROS2 侧 WebSocket 服务
roslibjs 前端 JS 库
ros2djs / ros2d 2D 地图可视化
rviz_web / foxglove 高级可视化

2. 安装与启动

[!note] 参数
可设置 port、address；跨机访问注意防火墙与回环地址。

3. 前端连接（roslibjs）

[!warning] 消息类型
前端 messageType 必须与 ROS2 侧完全一致（含包名前缀），否则订阅无数据。

4. 服务调用

[!tip] 服务超时
Web 服务调用是异步的；前端可加 loading 状态，服务端不可用时设置超时提示。

5. TF 与地图可视化

[!note] 地图可视化
ros2djs 通过订阅 /map（nav_msgs/OccupancyGrid）渲染二维栅格，配合机器人位姿显示。

6. 安全考虑

风险 对策
未授权访问 部署在可信网络、加认证代理
指令滥用 服务端做权限校验
明文传输 WebSocket 升级 TLS（wss）
端口暴露 不直接暴露公网

[!warning] 安全提示
rosbridge 本身无认证机制；远程控制机器人务必加访问控制层（见 34-安全与权限）。

7. 常见问题

问题 排查
连接失败 端口、地址、防火墙
订阅无数据 类型名、QoS 不匹配
中文乱码 统一 UTF-8 编码
高负载卡顿 消息频率、压缩

[!note] 延伸
跨网络通信见 29-多机器人协同；部署安全见 34-安全与权限；Web 可视化常与 17-rviz2可视化 对照。

8. Web 端工程实践

Web 端工程实践注意：rosbridge 转发时需控制消息带宽，高频话题在服务端降采样或只转发摘要，避免浏览器与网络过载；前端订阅话题需处理断线重连与 QoS 差异。安全方面 WebSocket 端口应加鉴权与 TLS（见 34-安全与权限）。常用模式是 Web 端下发目标、接收状态与可视化，复杂计算留在机器人端。调试用 rosbridge 自带测试页与 WebSocket 抓包工具。上线前做多浏览器与弱网测试。

[!note] 建议
rosbridge 是 ROS2 与互联网世界连接的桥梁，适合远程监控与云端调度；与多机器人、部署结合见 29-多机器人协同、38-产品化与部署实践。
