26-Jenkins声明式与脚本式

发表于2026-10-25|groovy
|浏览量:

[!info] 本节目标
理解两种 Pipeline 风格差异，按场景选择最合适的写法。

1. 声明式 Pipeline

声明式语法用结构化块表达流水线：pipeline、agent、stages、steps、post。它约束结构、内置安全检查，适合绝大多数标准 CI/CD。

声明式的优点是结构清晰、易读易维护，通过 DSL 保证流程符合预期。

2. 脚本式 Pipeline

脚本式语法就是 Groovy 脚本，由 node 块包裹执行步骤，完全使用 Groovy 控制流与逻辑。它灵活自由，适合复杂编排与动态逻辑。

脚本式提供最大自由度，但要求开发者具备 Groovy 能力，代码结构自由度大。

3. 语法对比

声明式用 stage 块显式声明阶段，脚本式用 stage 方法调用；声明式内置 post 条件执行，脚本式用 try-catch-finally；声明式步骤受限制，脚本式任意 Groovy。

相同流程两种写法都可行，选择取决于复杂度与团队习惯。

4. 选择建议

标准流水线（构建、测试、部署三步）用声明式；需要循环、动态分支、复杂逻辑时用脚本式；两者可以在声明式中嵌入 script 块混合使用。

团队统一风格，声明式优先，脚本式用于声明式无法表达的局部。

5. 共享库与封装

无论哪种风格，共享库都是复用流水线逻辑的正确方式。Groovy 库封装步骤与工具函数，Jenkinsfile 保持精简。

共享库配合声明式实现声明式流水线模板，兼顾灵活与规范。

6. 调试与维护

用片段生成器生成步骤语法；本地 lint 工具检查 Jenkinsfile；日志分级输出定位问题。

流水线逻辑复杂时拆分共享库并配单元测试，保证 CI 本身可靠。

7. 两种风格选型实践

新项目默认声明式，结构规范易上手；复杂条件与循环逻辑用 script 块局部脚本化，保持整体声明式骨架。

团队维护流水线模板库，统一构建、测试、部署步骤，项目只需声明参数与阶段，降低维护成本。

流水线本身也要测试：用 Jenkins 测试运行器验证语法与逻辑，避免把错误提交到 CI 环境。
