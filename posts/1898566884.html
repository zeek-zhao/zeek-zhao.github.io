Kubernetes 核心概念与架构

[!abstract] 一句话
Kubernetes（K8s）是容器编排平台：自动部署、扩缩、管理容器化应用，让”应用调度”变成声明式配置。

为什么需要 K8s

单机 Docker 只能管理一台机器。生产环境需要多机调度、故障自愈、滚动发布、服务发现——这些正是 K8s 的核心能力。声明式是灵魂：你描述”期望状态”，K8s 不断调和（Reconcile）到该状态。

集群架构

控制平面（Master 节点）

组件 职责
kube-apiserver 所有请求入口，REST API，认证鉴权
etcd 分布式键值存储，保存全部集群状态
kube-controller-manager 运行各类控制器，持续调和状态
kube-scheduler 为 Pod 选择合适节点

工作节点（Worker 节点）

组件 职责
kubelet 节点代理，负责启停容器、上报状态
kube-proxy 实现 Service 网络转发规则
容器运行时 containerd / CRI-O 等，真正运行容器

核心资源对象

对象 层级 作用
Pod 最小调度单元 一组共享网络的容器
Deployment 工作负载 无状态应用副本管理
Service 网络 稳定的访问入口与负载均衡
ConfigMap / Secret 配置 注入配置与密钥
PV / PVC 存储 持久化存储抽象

一次部署的旅程

  1. kubectl apply 提交 Deployment 到 apiserver；
  2. apiserver 写入 etcd，scheduler 调度到某节点；
  3. 该节点 kubelet 调用运行时启动 Pod；
  4. 控制器持续检查，Pod 异常时自动重建。

[!note] 与 Docker 的关系
Docker 负责”单容器运行”，K8s 负责”跨节点编排”。容器运行时已可用 containerd 替代 Docker。
