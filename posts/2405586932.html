30-中断安全编程

发表于2026-10-24|FreeRTOS
|浏览量:

[!info] 本节目标
掌握中断服务程序安全编程实践。

1. ISR 编程原则

中断服务程序应短小快速，只处理必要的硬件状态与数据传递。耗时逻辑移交任务执行。ISR 中调用 API 必须使用 FromISR 后缀版本，确保内核状态安全。

2. 安全 API 清单

队列、信号量、事件组、任务通知与缓冲提供 FromISR 版本。发送与通知接口可在 ISR 使用，接收接口部分支持。获取系统状态如 Tick 计数有中断安全版本。

3. 高优先级任务唤醒

ISR 通知后调用 portYIELD_FROM_ISR，若唤醒任务优先级高于当前任务立即切换。优化中断到任务响应延迟。条件切换减少无谓上下文切换。

4. ISR 与共享数据

ISR 与任务共享数据需保护，使用临界区或原子操作。ISR 中临界区使用中断安全宏。数据传递优先通过队列与缓冲，避免直接共享复杂结构。

5. 中断嵌套

嵌套中断中高优先级中断可打断低优先级中断，ISR 内仍需保持安全。嵌套深度影响栈使用与响应。FreeRTOS 配置限制可调用 API 的中断优先级，避免破坏临界区。

6. 外设中断实践

外设中断处理典型流程：读取状态与数据、存入缓冲、FromISR 通知任务、清除中断标志。任务随后处理数据。设计避免中断标志未清导致反复触发。

7. 验证与测试

测试覆盖中断高频触发、嵌套与临界区交互。使用跟踪工具观察中断延迟与唤醒开销。静态检查 ISR 调用合规，代码审查重点核查 API 使用。

8. 中断架构设计

中断架构设计从系统需求出发，划分中断优先级与处理策略。高频外设中断采用直接数据处理加批量通知，低频事件中断直接唤醒任务。多个中断汇聚共享队列或事件组，统一处理降低复杂度。中断响应指标分解到各阶段测量，定位延迟瓶颈。嵌套中断栈需求评估充分预留。中断与任务数据流清晰，避免在中断上下文做复杂业务，保障系统在极端负载下的稳定性与可预测性。
