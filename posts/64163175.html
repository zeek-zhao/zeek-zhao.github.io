中断处理子系统与上下半部

中断这块，光背概念很容易绕晕，我更习惯从「一个硬中断进来之后内核到底做了哪几步」入手去记。这篇就按这条主线，把中断架构、上下半部、软中断机制和调试观测点串起来。

我在排查网卡丢包、中断风暴这类问题时翻得最多的其实是 /proc/interrupts 和 /proc/softirqs，所以最后会把这两个观测点单独拎出来讲。

1. 中断基础：硬件中断、软件中断与异常三类¶

中断（Interrupt）是指计算机在执行程序过程中，出现需要特别处理的事件时，CPU暂停正在执行的程序，转而执行处理该事件的程序，处理完成后再返回原程序继续执行的过程。

我一般把异常单独记成一类，因为它不是外部设备「请求」 CPU，而是指令执行本身出了状况，这点跟硬中断、软中断的触发逻辑不一样。

中断的三种分类¶

Linux系统中的中断主要分为三类：

  1. 硬件中断（Hardware IRQ）：由硬件设备触发，如键盘输入、磁盘完成I/O操作等
  2. 软件中断（Software IRQ）：由软件请求触发的中断，如定时器、网络收包等
  3. 异常（Exception）：执行指令时遇到的异常情况，如页错误、除零错误等
flowchart TD A[中断类型] --> B[硬件中断] A --> C[软件中断] A --> D[异常] B --> B1[外设IRQ] B --> B2[时钟中断] B --> B3[处理器间中断IPI] C --> C1[软中断] C --> C2[Tasklet] C --> C3[工作队列] D --> D1[故障Fault] D --> D2[陷阱Trap] D --> D3[终止Abort]

2. 中断子系统架构：五层组件与上下半部流水线¶

Linux中断子系统由以下几个主要部分组成：

  1. 中断控制器硬件
  2. 中断控制器驱动
  3. 通用中断层（Generic IRQ Layer）
  4. 中断处理程序（Interrupt Handlers）
  5. 软中断和下半部（Softirq & Bottom Halves）

这条流水线里，硬件控制器负责把信号送到 CPU，通用中断层负责统一不同控制器的差异，上下半部则把「必须马上应答」和「可以慢慢做」的活分开。我读源码时就是照着这个顺序一层层往下看的。

graph TD HW[硬件设备] -->|产生中断| IC[中断控制器] IC -->|中断信号| CPU[CPU] CPU -->|1. 保存上下文| ISR[上半部处理] ISR -->|2. 快速响应| ACK[确认中断] ACK -->|3. 安排下半部| BH[下半部/软中断] BH -->|4. 完成处理| END[处理完成] END -->|5. 恢复上下文| RET[返回被中断程序]

3. 中断处理流程：从硬中断到软中断的完整链路¶

3.1 硬中断处理过程：设备到 handler 的时序¶

当硬件设备需要CPU服务时，会通过引脚向中断控制器发送信号，中断处理过程如下：

sequenceDiagram participant 设备 participant 中断控制器 participant CPU participant 中断处理程序 participant 软中断 设备->>中断控制器: 发送中断请求 中断控制器->>CPU: 中断信号（IRQ号） Note over CPU: 保存当前上下文 CPU->>中断处理程序: 调用对应IRQ handler 中断处理程序->>中断控制器: 确认中断 中断处理程序-->>软中断: 安排下半部处理 中断处理程序->>CPU: 返回 Note over CPU: 恢复上下文 CPU->>软中断: 在适当时机处理

3.2 上半部与下半部：快响应与延后处理的分工¶

Linux将中断处理分为两部分：上半部（Top Half）和下半部（Bottom Half）。

📝上半部特点
  • 在中断上下文中执行
  • 不可被中断
  • 执行时间必须短
  • 主要完成对硬件的快速响应
🔥下半部特点
  • 可以被中断
  • 可以推迟执行
  • 可以执行耗时操作
  • 通常在进程上下文中执行

下半部四种实现方式比较

实测下来，选哪种下半部主要看两点：要不要休眠、要不要在多 CPU 上并行。下面这张图把四种机制的定位摆得很清楚。

graph LR BH[下半部机制] --> S[软中断] BH --> T[tasklet] BH --> W[工作队列] BH --> TE[线程化IRQ] S -->|最高优先级<br>多CPU并行| SN[NET_RX/TX_SOFTIRQ等] T -->|基于软中断<br>单CPU串行| TN[网卡收发包等] W -->|进程上下文<br>可休眠| WN[块设备I/O等] TE -->|专用内核线程<br>可休眠| TEN[USB等复杂设备]

4. 中断控制器与IRQ域：管理多级控制器层次¶

现代计算机系统中通常包含多级中断控制器，Linux通过IRQ域（IRQ Domain）来管理这种复杂的中断控制器层次结构。

7. 中断亲和性与负载均衡：SMP IRQ Affinity¶

多处理器系统中，中断负载均衡对系统性能至关重要。Linux提供了SMP IRQ Affinity机制来控制中断在不同CPU之间的分配。

踩过的坑是：只改了 /proc/irq/N/smp_affinity 却发现中断还是集中在 CPU0——因为 irqbalance 服务在后台又给改回去了，调之前得先确认它有没有运行。

11. 定位中断问题的切入点¶

中断子系统的主线其实就一句话：上半部快速应答硬件，下半部把耗时活推迟出去。我查中断性能问题时一般按这个顺序走——先看 /proc/interrupts 判断中断有没有堆在单个 CPU 上，再用 /proc/softirqs 看软中断分布，最后用 ftrace 抓 irq_* 确认具体 handler 的耗时。下一步可以把 kernel/irq 目录里对应控制器的实现对照着读一遍。
