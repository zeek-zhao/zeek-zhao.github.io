devops-gitness-开发指南

1. Gitness 简介

Gitness 是由 Harness 公司于 2023 年推出的一个开源 Git 仓库管理和 CI/CD 平台，由 Drone CI 的创建者构建。它旨在提供一个现代化、性能优越的 Git 托管解决方案，具有内置的 CI/CD 功能，可以看作是 GitHub 和 GitLab 的替代品。

1.1 核心功能与特性

mindmap
  root((Gitness核心功能))
    Git仓库管理
      多仓库支持
      分支管理
      标签管理
      Pull Requests
      代码审查
    CI/CD系统
      管道配置
      多步骤构建
      并行执行
      矩阵构建
      构建缓存
    权限管理
      用户认证
      仓库权限
      细粒度访问控制
      服务账户
    集成能力
      REST API
      Webhooks
      通知系统
      第三方集成
    高性能设计
      Go语言实现
      高效资源利用
      水平扩展
      缓存机制

sequenceDiagram

3.4 Pull Request 流程

sequenceDiagram
    participant D as 开发者
    participant R as 代码仓库
    participant PR as Pull Request
    participant CI as CI管道
    participant Rev as 审阅者

    D->>D: 在特性分支开发
    D->>R: 推送特性分支
    D->>PR: 创建Pull Request
    PR->>CI: 触发CI检查

    alt CI检查失败
        CI->>PR: 更新状态为失败
        PR->>D: 通知失败
        D->>D: 修复问题
        D->>R: 推送更新
        R->>CI: 重新触发CI检查
    else CI检查成功
        CI->>PR: 更新状态为成功
        PR->>Rev: 通知审阅者
        Rev->>PR: 审阅代码

        alt 需要修改
            Rev->>PR: 添加评论
            PR->>D: 通知修改请求
            D->>D: 进行修改
            D->>R: 推送更新
            R->>CI: 重新触发CI检查
            CI->>PR: 更新状态
            PR->>Rev: 通知可再次审阅
            Rev->>PR: 审阅更新
        end

        Rev->>PR: 批准Pull Request
        PR->>R: 合并到目标分支
        R->>CI: 触发部署管道
        CI->>D: 通知部署完成
    end

8.3 常见错误码和解决方案

错误码 描述 解决方案
401 未授权 检查认证信息，重新登录或生成新的访问令牌
403 访问禁止 检查用户权限，确认是否有足够的访问权限
404 资源未找到 验证路径和资源名称是否正确
422 验证错误 检查请求数据格式，修正无效字段
500 服务器错误 检查服务器日志，联系系统管理员
503 服务不可用 检查系统资源，可能需要扩容或重启服务
