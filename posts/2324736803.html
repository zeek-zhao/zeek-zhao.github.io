工程实践与代码规范

[!info] 本页概览
本文讲解 Java 工程实践：代码规范（命名/格式）、设计原则（SOLID）、分层架构、日志规范、异常与空值处理、代码评审、版本控制与 CI/CD 基础，配示例与检查清单。

核心概念

  • 代码规范：可读性 > 炫技；命名即文档。
  • SOLID：SRP（单一职责）、OCP（开闭）、LSP（里氏替换）、ISP（接口隔离）、DIP（依赖倒置）。
  • 分层架构：Controller → Service → Repository（DAO），依赖方向自上而下。
  • 日志：SLF4J + Logback/Log4j2；级别 error/warn/info/debug。
  • CI/CD：持续集成（构建+测试）与持续部署（自动发布）。

代码评审清单

  • 命名清晰、注释解释”为什么”而非”是什么”
  • 方法短小（< 40 行），职责单一
  • 无魔法数字，常量/枚举化
  • 异常处理正确：不吞异常、不 catch Exception 过宽
  • 资源用 try-with-resources 关闭
  • SQL 参数化，无注入风险
  • 并发安全：共享可变状态有锁/原子类/不可变
  • 测试覆盖正常/边界/异常路径

CI/CD 基础

常见坑

  1. 过度设计：为”未来需求”写抽象，违背 YAGNI；按需演进。
  2. 贫血模型/上帝类：实体只有 getter/setter 或一个类做所有事；职责拆分。
  3. 日志打印对象直接 toString：可能泄露敏感字段；用 DTO 或脱敏。
  4. 复制粘贴代码：提取工具方法/模板方法。
  5. 提交信息随意：用 Conventional Commits（feat/fix/refactor）。
  6. 缺少 code review：双人把关，防止坏味道蔓延。
  7. 依赖方向混乱：web 依赖 service 依赖 repository，禁止反向。

最佳实践

  • 团队统一代码风格 + 格式化工具 + 静态检查（SpotBugs/PMD）。
  • 关键路径加可观测性：日志 + 指标 + 追踪（见 18-性能调优）。
  • 提交小步、频繁集成，CI 全绿再合并。
  • 写代码前先想清楚接口契约与异常语义。
  • 持续重构：红绿重构（测试驱动）保持代码健康。
