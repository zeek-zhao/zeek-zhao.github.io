11-中断处理

发表于2026-10-24|Zephyr
|浏览量:

[!info] 本节目标
掌握中断机制与 ISR 安全编程规范。

1. 中断机制

Zephyr 通过 IRQ 抽象管理中断，ISR 注册与硬件向量绑定。中断处理快速响应硬件事件，中断上下文独立于线程。中断配置在设备树与驱动完成。

2. ISR 注册

IRQ_CONNECT 与 IRQ_DIRECT_CONNECT 注册中断处理，指定优先级与参数。设备树生成中断信息，驱动注册处理函数。注册时机与使能管理规范。

3. ISR 安全 API

ISR 中可使用信号量 give、队列入队与事件发送等安全 API，不可阻塞与分配。耗时处理延迟到线程，中断保持短小。API 文档标注中断可用性。

4. 中断优先级

中断优先级按硬件特性配置，高优先级快速响应。嵌套中断增加栈需求，合理规划。优先级分配影响实时性，关键事件优先保障。

5. 临界区

关中断与调度器锁保护共享数据，临界区极短化。保存中断状态恢复，嵌套保护正确。临界区不阻塞，适合短操作。

6. 中断与线程协作

中断记录事件通知线程，线程处理耗时业务。数据缓冲与一致性保护，避免竞争。协作模式高效处理异步事件，设计清晰。

7. 实践建议

ISR 最小化处理，耗时工作派发线程。中断安全 API 严格遵守，嵌套与栈规划验证。测试覆盖高频中断与嵌套场景，测量中断延迟。

8. 常见问题

中断编程的典型错误是在 ISR 中调用阻塞或耗时 API，导致系统响应劣化甚至死锁。ISR 中只能使用文档明确标注安全的内核 API，如信号量 give、队列入队与事件发送。共享变量在 ISR 与线程之间访问时，必须使用关中断或调度器锁保护临界区。嵌套中断会增加栈需求，配置高优先级中断时要复核栈大小。中断优先级分配要符合实时性需求，不是所有中断都需要最高优先级。验证阶段通过高频中断压力测试与延迟测量确认设计余量。
