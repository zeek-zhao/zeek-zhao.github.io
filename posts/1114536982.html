内存管理基础

我第一次啃内存管理这块时，被「虚拟地址」「页表」「伙伴系统」这些词绕得晕头转向，后来干脆抓住一个问题反复问：我 malloc 出来的这块内存，到底经过了哪些环节才落到真实的物理内存上？顺着这条线把分配、地址转换、回收三种机制串起来，整篇就不再是零散的名词了。下面从最基础的层次结构讲起，一路走到 Linux 的具体实现和调优工具。

1. 内存管理的核心是分配映射与回收¶

1.1 六项职责撑起内存管理¶

内存管理是操作系统负责的核心功能，涉及对计算机物理内存资源的分配、组织和控制。它的主要职责包括：

  • 内存分配：为进程分配所需的内存空间
  • 地址转换：维护虚拟地址与物理地址之间的映射关系
  • 内存保护：确保进程只能访问其被授权的内存区域
  • 内存共享：允许多个进程共享同一物理内存区域
  • 内存扩展：通过虚拟内存技术扩展可用内存容量
  • 内存回收：回收不再使用的内存资源

内存管理的重要性体现在：

  • 进程隔离：提供进程间内存隔离，增强系统安全性和稳定性
  • 资源利用：优化物理内存使用，提高系统资源利用率
  • 性能影响：内存管理效率直接影响系统整体性能
  • 编程简化：为应用程序提供一致、简单的内存视图
  • 多任务支持：使多个进程能够并发执行而不干扰彼此

我刚接触这块时最容易忽略的其实是地址转换，总觉得分配和回收才是主角，后来才发现进程隔离、共享这些好处全靠虚拟地址到物理地址那层映射撑着。

1.2 从直接寻址走到内存分层¶

内存管理技术随计算机硬件和操作系统的发展而不断演进：

  • 1950年代初：早期计算机使用物理地址直接寻址，无内存保护
  • 1960年代初：出现基地址/界限寄存器保护机制
  • 1960年代中期：分段内存管理模型在Multics系统中实现
  • 1969年：UNIX采用简单内存管理，无虚拟内存
  • 1970年代初：分页内存管理模型开始广泛应用
  • 1970年代中期：虚拟内存技术成熟，实现了按需分页
  • 1980年代初：Berkeley UNIX引入虚拟内存和内存映射文件
  • 1980年代中期：分段分页混合模型在x86架构上实现
  • 1990年代初：Linux采用了先进的内存管理架构
  • 1990年代末：大页支持和NUMA架构开始出现
  • 2000年代初：64位系统普及，虚拟地址空间极大扩展
  • 2000年代中期：透明大页和内存压缩技术实现
  • 2010年代：非易失性内存和持久内存技术兴起
  • 现在：内存分层技术、远程内存访问等新技术不断发展

1.3 有限资源要在碎片开销功耗间取舍¶

内存管理面临多方面的基本挑战：

  • 有限资源管理：物理内存是有限资源，需要高效分配和利用
  • 碎片问题：内存分配和释放过程中产生的碎片降低利用率
  • 地址转换开销：虚拟地址到物理地址的转换引入额外开销
  • 多级内存层次：需要协调缓存、主存和辅存之间的数据移动
  • 并发控制：在多处理器系统中需处理并发内存访问
  • 可扩展性：内存管理算法需适应从小型嵌入式系统到大型服务器
  • 功耗考量：内存管理策略直接影响系统能耗
  • 安全隐患：内存管理缺陷可能导致严重安全问题

1.4 寄存器缓存主存外存逐级变慢¶

现代计算机系统的内存组织为多级层次结构：

1.4.1 寄存器

  • 速度：亚纳秒级访问时间
  • 容量：数百字节至数KB
  • 特点：CPU内部，由编译器分配，速度最快

1.4.2 缓存

  • **一级缓存(L1)**：

    • 速度：几个CPU周期（1-3纳秒）
    • 容量：数十KB至数百KB
    • 特点：通常分为指令缓存和数据缓存

  • **二级缓存(L2)**：

    • 速度：10纳秒左右
    • 容量：数百KB至数MB
    • 特点：通常每核独立或小核组共享

  • **三级缓存(L3)**：

    • 速度：20-40纳秒
    • 容量：数MB至数十MB
    • 特点：通常在多核处理器中所有核心共享

1.4.3 主内存(RAM)

  • 速度：50-100纳秒
  • 容量：数GB至数TB
  • 特点：易失性存储，重启后数据丢失
  • 类型：
    • DRAM（动态随机访问内存）：需要周期性刷新，主要用作系统主内存
    • SRAM（静态随机访问内存）：无需刷新，更快但成本高，用于缓存

1.4.4 非易失性内存

  • 速度：主内存级别到持久存储级别（取决于技术）
  • 容量：数GB至数TB
  • 特点：断电后数据保持
  • 类型：
    • NVDIMM（非易失性双列直插式内存模块）
    • Intel Optane（3D XPoint）
    • MRAM（磁阻式随机访问内存）

1.4.5 外部存储

  • **固态硬盘(SSD)**：

    • 速度：微秒级到毫秒级
    • 容量：数百GB至数TB
    • 特点：无机械部件，随机读写性能好

  • **硬盘驱动器(HDD)**：

    • 速度：毫秒级
    • 容量：数TB
    • 特点：机械设备，顺序读写性能好

  • 网络存储：

    • 速度：毫秒到秒级（取决于网络）
    • 容量：理论上无限
    • 特点：通过网络访问，延迟较高但可扩展性强

2. 虚拟内存靠地址转换和分页撑起进程隔离¶

2.1 物理内存是硬件虚拟内存是抽象¶

2.1.1 物理内存

物理内存是实际的硬件RAM，有以下特性：

  • 有限容量：由系统中安装的内存模块决定
  • 连续地址空间：从0开始的连续物理地址
  • 多方共享：被所有进程和操作系统内核共享
  • 直接与处理器相连：处理器最终访问的是物理内存

物理内存的组织：

  • 页帧：物理内存被分割成固定大小的页帧（通常4KB）
  • 内存区域：根据硬件特性划分为不同区域（例如DMA区、普通区等）
  • NUMA节点：在NUMA架构中，物理内存分布在不同CPU节点上

2.1.2 虚拟内存

虚拟内存是一种抽象，为程序提供独立的地址空间：

  • 独立地址空间：每个进程拥有自己的完整地址空间
  • 超越物理限制：虚拟地址空间可大于实际物理内存
  • 按需分配：只有实际使用的虚拟内存才映射到物理内存
  • 地址隔离：进程间虚拟地址相互隔离，提高安全性

虚拟内存的工作原理：

  • 地址转换：通过MMU将虚拟地址转换为物理地址
  • 页表：记录虚拟页到物理页帧的映射关系
  • 页面调度：在物理内存和辅助存储（如swap分区）之间移动页面
  • 页面共享：多个虚拟地址可映射到同一物理地址（如共享库）

我第一次读页表时把它当成一张静态表，后来才反应过来它是随缺页动态改的，TLB 命中率高不高直接决定地址转换快不快。

2.1.3 虚拟内存的优势

  • 简化编程模型：程序员无需考虑物理内存管理和碎片
  • 提高内存利用率：按需分配物理内存，非活跃页面可以被置换出去
  • 提供内存保护：进程无法直接访问其他进程的内存
  • 支持内存超载：允许运行所需内存总和超过物理内存的程序
  • 简化共享：方便实现进程间内存共享
  • 简化加载：可以将程序代码和数据映射到地址空间而非复制

2.2 分段按逻辑分页按固定粒度¶

2.2.1 分段内存管理

分段是基于程序逻辑单元（如代码段、数据段、堆栈段）组织内存：

  • 基于语义：段代表程序的逻辑部分
  • 可变大小：段的大小根据需要确定，没有固定大小
  • 程序员可见：程序员直接感知段的存在
  • 地址格式：通常由<段选择器:偏移量>表示

分段优缺点：

  • 优点：

    • 符合程序的逻辑结构
    • 便于代码和数据的共享
    • 便于分别设置不同段的保护属性

  • 缺点：

    • 段大小可变导致外部碎片问题
    • 分配复杂，需要查找适合大小的空闲空间
    • 难以有效支持虚拟内存机制

2.2.2 分页内存管理

分页将内存划分为固定大小的页面：

  • 固定大小：页面大小固定（如4KB、8KB、2MB等）
  • 物理划分：按物理单位划分，而非逻辑单位
  • 程序员透明：程序员通常不感知页面存在
  • 地址转换：虚拟页号映射到物理页帧号

分页优缺点：

  • 优点：

    • 无外部碎片问题
    • 分配管理简单
    • 支持高效虚拟内存实现
    • 统一管理粒度便于硬件实现

  • 缺点：

    • 可能产生内部碎片（进程不使用整个页面）
    • 页表管理开销
    • 不直接反映程序逻辑结构

2.2.3 分段分页结合

某些架构（如早期x86）结合两种技术：

  • 先分段后分页：地址先经过段转换，再经过页转换
  • 程序逻辑与物理优化结合：兼顾程序逻辑结构和内存管理效率
  • 复杂度增加：实现和管理更为复杂
  • 当代趋势：现代系统（如Linux在x86-64上）倾向于只使用分页，将段基址设为0

2.3 地址转换走TLB加多级页表¶

2.3.1 地址空间类型

计算机系统中存在多种地址空间概念：

  • 逻辑地址空间：程序生成的地址，由段选择器和偏移量组成
  • 线性地址空间：也称虚拟地址空间，分段单元将逻辑地址转换后的结果
  • 物理地址空间：实际的硬件内存地址
  • I/O地址空间：用于访问I/O设备的地址（可能映射到内存地址空间）

2.3.2 地址转换过程

在启用分页的系统中，地址转换通常包括：

  1. 生成虚拟地址：CPU执行指令生成虚拟地址
  2. 查询TLB：先检查转换后备缓冲区(TLB)是否有映射项
  3. 页表遍历：如果TLB未命中，遍历多级页表
  4. 获取物理地址：找到对应的物理页帧号，与页内偏移组合成物理地址
  5. 更新TLB：将新查找的映射存入TLB以加速后续访问
  6. 访问物理内存：使用物理地址访问内存

2.3.3 多级页表

为解决页表占用空间问题，现代系统使用多级页表：

多级页表的优势：

  • 稀疏地址空间高效表示：只为使用的地址空间部分创建页表
  • 更小的内存占用：相比单级页表节省大量内存
  • 利用局部性：对于局部引用的程序，有效减少内存访问

2.4 缺页时按算法挑页面换出¶

当物理内存不足时，系统需要决定哪些页面被换出到辅存：

2.4.1 最优置换算法(OPT)

  • 原理：置换未来最长时间不会被访问的页面
  • 特点：理论上最佳，但需要预知未来，实际不可实现
  • 用途：作为其他算法的理论比较基准

2.4.2 先进先出置换(FIFO)

  • 原理：置换最早进入内存的页面
  • 特点：实现简单，但性能较差，不考虑页面访问频率
  • 缺点：可能出现Belady异常（增加物理页帧反而增加缺页率）

2.4.3 最近最少使用(LRU)

  • 原理：置换最长时间未被访问的页面
  • 特点：性能较好，符合程序局部性原理
  • 实现：
    • 计数器法：记录上次访问时间
    • 栈法：将访问的页面移到栈顶
  • 缺点：需要硬件支持跟踪所有内存访问，实现开销大

2.4.4 时钟置换算法(Clock)

  • 原理：LRU的近似实现，使用引用位
  • 特点：低开销，性能接近LRU
  • 实现：
    • 页表项增加访问位（由硬件设置）
    • 算法扫描页面环形链表
    • 跳过访问位为1的页（同时清零）
    • 选择访问位为0的页置换出去

2.4.5 改进的时钟算法

  • 原理：同时考虑访问位和修改位
  • 特点：进一步优化置换决策
  • 优先级：
    (0,0) → (0,1) → (1,0) → (1,1)
    （访问位,修改位），优先选择未访问未修改的页面

2.4.6 最不常用算法(LFU)

  • 原理：置换访问频率最低的页面
  • 特点：考虑长期访问模式，但不一定反映未来访问
  • 缺点：历史负担重，新页面可能频率低但很重要，实现复杂

2.5 首次适应最快伙伴系统碎片最少¶

操作系统需要管理内存分配，常见的策略包括：

2.5.1 首次适应(First-Fit)

  • 原理：分配第一个足够大的空闲块
  • 特点：搜索快速，但可能导致前端碎片
  • 实现：维护按地址排序的空闲块链表

2.5.2 最佳适应(Best-Fit)

  • 原理：分配最小的足够大的空闲块
  • 特点：理论上减少浪费，但实际产生难以利用的小碎片
  • 实现：维护按大小排序的空闲块链表

2.5.3 最差适应(Worst-Fit)

  • 原理：分配最大的空闲块
  • 特点：试图保留足够大的剩余空间以便未来使用
  • 实现：维护按大小降序排列的空闲块链表

2.5.4 下次适应(Next-Fit)

  • 原理：从上次分配位置开始搜索
  • 特点：分散内存分配，减轻对前端块的压力
  • 实现：维护指向上次分配位置的指针

2.5.5 伙伴系统(Buddy System)

  • 原理：基于二分的内存分配方式
  • 特点：高效合并空闲块，减少外部碎片
  • 工作流程：
    1. 将内存划分为2^n大小的块
    2. 对于大小为s的请求，分配大小为2^n≥s的最小块
    3. 如果需要的块不存在，将更大的块二分
    4. 释放时，检查”伙伴”是否也空闲，如果是则合并

2.5.6 Slab分配器

  • 原理：基于对象缓存的内存分配器
  • 特点：专为频繁分配/释放固定大小对象优化
  • 优势：
    • 减少碎片
    • 重用已初始化对象
    • 缓存硬件缓存行对齐
  • 结构：
    • 缓存：特定类型对象的容器
    • Slab：一组连续页面，被划分为对象大小的块
    • 对象：Slab中的单个内存块

6. 分配器设计就是在速度空间扩展性间权衡¶

6.1 速度空间局部性扩展性要权衡¶

内存分配器设计需要权衡多个目标：

  • 速度: 分配和释放操作应尽可能快
  • 空间效率: 最小化内部和外部碎片
  • 局部性: 相关分配应具有良好的缓存局部性
  • 扩展性: 在多线程环境中表现良好
  • 稳定性: 表现可预测，无性能”悬崖”

我看这些分配器源码时抓的主线就一条：锁到底加在哪一层。全局锁最省心但线程一多就堵，无锁最快可调试起来最痛苦。

6.1.1 常见权衡和挑战

  1. 速度与空间效率:

    • 更复杂的分配算法可减少碎片但增加CPU开销
    • 保持低碎片率可能需要周期性重组内存

  2. 通用性与特殊优化:

    • 针对特定应用优化会牺牲通用性
    • 通用分配器难以针对所有应用场景优化

  3. 多线程扩展性:

    • 单一全局锁: 简单但扩展性差
    • 细粒度锁: 扩展性好但复杂且有开销
    • 无锁算法: 最佳扩展性但实现复杂

  • 《现代操作系统》：Andrew S. Tanenbaum著，全面介绍操作系统内存管理
  • 《Linux内核设计与实现》：Robert Love著，详解Linux内存管理子系统
  • 《Advanced Programming in the UNIX Environment》：W. Richard Stevens著，详细介绍用户空间内存管理
  • 《系统性能调优》：Brendan Gregg著，包含内存性能分析方法

这几份材料里我翻得最多的是《深入理解计算机系统》的存储器层次那章，把缓存和主存的关系讲透之后，再看 Linux 的实现会顺很多。

9.3 开发优化排查三类建议¶

  1. 应用开发最佳实践：

    • 避免频繁小块内存分配/释放
    • 考虑内存池和对象缓存
    • 适当预分配内存避免运行时分配
    • 谨慎使用内存优化技术，平衡可读性和性能

  2. 系统优化建议：

    • 根据工作负载调整swappiness参数
    • 考虑使用透明大页提高性能
    • 监控并控制内存压力
    • NUMA系统上合理放置内存和进程

  3. 内存问题排查流程：

    • 识别内存问题类型（泄漏、碎片、性能等）
    • 收集内存使用数据（/proc、工具）
    • 使用专业工具深入分析
    • 验证修复效果
