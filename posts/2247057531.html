动态库与静态库

[!info] 本页概览
库是可复用的二进制代码集合。静态库（.a/.lib）在链接期打包进可执行文件；动态库（.so/.dll）在运行期加载。本文讲解生成、链接与使用两种库的完整流程。

核心概念

特性 静态库 动态库
后缀 Linux .a，Windows .lib Linux .so，Windows .dll
链接时机 编译链接期 加载/运行期
可执行文件 体积大，包含库代码 体积小，运行时依赖库
更新 需重新编译可执行文件 替换库文件即可（接口不变时）
启动速度 快 稍慢（加载/重定位）

常见坑

  1. -l 顺序问题：链接命令中库应放在引用它的目标文件之后：gcc main.o -L. -lmath，main.o 在前否则报 undefined reference（某些链接器允许乱序，但不要依赖）。
  2. 运行时找不到 .so：编译成功但运行报 error while loading shared libraries，需设置 LD_LIBRARY_PATH 或用 rpath（-Wl,-rpath,.）。
  3. Windows DLL 的 PATH：DLL 需在可执行文件同目录或系统 PATH 中。
  4. 静态库顺序依赖：A 依赖 B 时须 -lA -lB 顺序，否则符号未解析。
  5. C++ 库 ABI 不兼容：不同编译器/标准库版本编译的库混用会崩溃，动态库需保持 ABI 稳定。

最佳实践

  • 对外库接口保持稳定，头文件即契约；接口变化遵循语义化版本。
  • 第三方分发用动态库减少体积，公司内部小工具用静态库简化部署。
  • 构建时用 nm / objdump -T 检查导出符号是否符合预期。
  • 优先把库作为 CMake 目标（add_library(... STATIC/SHARED)）管理，自动处理链接与传递依赖。
