安全加固

接上一篇 13-备份与恢复，备份管的是数据丢了能回来，安全加固管的是别让人进来。我一般按管理面暴露面、认证、权限、Docker 环境这个顺序往下收，一步都跳不过去。

先把五条安全原则立住¶

Portainer 安全原则：

  1. 管理面最小暴露
  2. HTTPS 强制
  3. 认证强密码 / SSO
  4. 权限最小化
  5. Docker 环境自身加固

典型威胁：

  • 弱密码被爆破
  • 未授权访问管理 UI
  • 容器逃逸/提权
  • Edge Key 泄露

管理端口别直接暴露到公网¶

HTTPS 走原生端口或反代都行¶

方案1：Portainer 原生 HTTPS（默认 9443）
方案2：反向代理 TLS（Nginx/Traefik）

反代示例（见 02）：

  • 域名 + 证书
  • 强制跳转 https
  • 隐藏内部端口

注意：

  • 不要同时开放 9000 与 9443 造成绕过
  • 证书定期轮换

认证要把默认口令和弱口令都掐掉¶

强化措施：

  • 管理员强密码（12+ 位混合）
  • 启用 LDAP/OAuth（企业）
  • 禁用默认/弱口令
  • 定期密码轮换

账号管理：

  • 最小管理员数量
  • 禁用离职账号
  • 审计登录日志

权限按环境和团队分开授¶

RBAC 实践（见 09）：

  • 管理员仅运维核心
  • 环境按团队授权
  • 只读角色覆盖查看场景
  • 关闭公开环境访问

ACL 实践：

  • 敏感容器指定团队
  • 生产资源严格管控

Docker 侧要限制 socket 和容器能力¶

加固项：

  1. docker.sock 访问受限
  2. 镜像来源可信（私有仓库）
  3. 容器非 root 运行（USER）
  4. 资源限制（防失控）
  5. 只读根文件系统（read_only）

示例：
services:
app:
image: myapp
user: “1000:1000”
read_only: true
mem_limit: 512m
pids_limit: 100

注意：

  • Portainer 需要 docker.sock 管理 Docker
  • 但应限制宿主机上可访问 docker.sock 的用户
  • Edge Agent 挂载 / 与 privileged 慎用

密钥不外泄，网络只开必要端口¶

密钥管理：

  • Edge Key 轮换
  • 环境变量中的密码不硬编码
  • 使用 Secret/外部 Vault

网络安全：

  • Portainer Server 在内网
  • 8000 端口仅对 Edge Agent 开放
  • Agent 通信用 TLS
  • 定期漏洞扫描

五个坑基本都和暴露面与默认配置有关¶

  1. HTTP 公网暴露：9000 端口直接公网，被爆破。
  2. 默认密码未改：默认管理员口令危险。
  3. docker.sock 滥用：挂载 socket 的容器可控制宿主机。
  4. 权限全开：人人管理员，无法追溯。
  5. 证书过期：HTTPS 失效，客户端无法访问。

落地建议：内网隔离加 HTTPS，再做最小权限¶

  • 管理面内网隔离 + HTTPS。
  • 强认证（LDAP/SSO）+ 最小权限。
  • Docker 环境镜像可信、容器受限。
  • 定期安全审计与更新。
  • 配合 13-备份与恢复、15-升级与故障排查。
