rclcpp 编程（C++）

[!info] 本节目标
掌握 rclcpp C++ 客户端库的节点编写、发布订阅、服务、参数、定时器与生命周期基础用法。

1. rclcpp 概览

rclcpp 是 ROS2 的 C++ 客户端库，构建于 rcl（ROS Client Library）之上，封装 DDS 细节。适合对性能、实时性要求高的节点。

[!note] 包结构
ament_cmake 包包含 CMakeLists.txt、package.xml、src/、include/；创建命令见 04-工作空间与colcon构建。

2. 基础节点

关键 API 说明
rclcpp::init 初始化
rclcpp::spin 阻塞式运行回调
rclcpp::spin_some 非阻塞处理当前回调
rclcpp::shutdown 关闭

3. 发布订阅

[!tip] 回调风格
可使用类成员函数或 lambda；成员函数需 std::bind，lambda 更简洁。

4. 服务客户端

[!warning] 异步请求
使用 async_send_request 配合回调；不要在回调内同步等待。

colcon build --packages-select cpp_demo && source install/setup.bash 后 ros2 run cpp_demo pubsub_node。

7. 常见错误

错误 排查
链接找不到符号 ament_target_dependencies 未写全依赖
头文件找不到 include 目录未配置
段错误 未初始化 shared_ptr / 生命周期错误
回调不触发 未 spin 或 Executor 未启动

[!note] 延伸
生命周期节点见 12-生命周期节点；执行器与多线程见 14-执行器与回调组；C++ 与 Python 对比见 11-rclpy编程。

8. rclcpp 工程实践要点

从入门到精通，工程化习惯往往比语法更重要。

C++ 节点工程应注意生命周期管理：成员变量初始化、回调资源释放、节点销毁顺序都要明确。头文件依赖最小化可缩短编译时间，消息类型头文件在用到时才包含。回调内避免阻塞操作与长时间计算，必要时使用回调组与多线程执行器（见 14-执行器与回调组）。日志使用 RCLCPP_INFO 系列统一输出，便于过滤。发布订阅的 QoS 与节点参数保持一致，避免运行时异常。生产代码应补充单元测试与 lint 检查。

[!note] 建议
C++ 适合性能敏感的算法与驱动节点，Python 适合业务逻辑与原型；两者对比见 11-rclpy编程。
