Hexo简介与核心概念

📑一句话
Hexo 是一个基于 Node.js 的快速静态博客框架，用 Markdown 写作、秒级生成静态网页，是中文圈最流行的静态站点生成器之一。

为什么选择 Hexo¶

在众多建站方案中，Hexo 的定位非常清晰：用最轻量的方式，把 Markdown 文章变成一个可以部署到任何静态托管平台的博客网站。你不需要数据库、不需要后端服务器，写作时只关注内容本身，生成与部署交给命令行一条龙完成。

Hexo 的核心优势可以归纳为四点：

  1. 极速生成：依托 Node.js 的事件驱动模型，几百篇文章也能在数秒内完成全站构建，写作时配合本地预览服务器，保存即可看到效果。
  2. 纯 Markdown 写作：文章以 Markdown 文件形式存放在本地，天然兼容 Git 版本管理和 Obsidian 等笔记工具。
  3. 插件生态丰富：官方插件市场上超过 400 个插件，覆盖 SEO、RSS、搜索、图床、加密、部署等方方面面，几乎你能想到的功能都有现成方案。
  4. 主题生态成熟：社区主题数量庞大且持续维护，中文主题尤其出色，主题选择篇会详细展开。
📝2026 更新
Hexo 在 GitHub 上已积累 39,000+ stars，插件数量超过 400 个，至今仍是中文圈最流行的静态站点生成器（SSG）。它支持 EJS、Pug、Nunjucks 等模板引擎，并可集成 Babel、PostCSS、Less、Sass 等现代前端工具链，老树常青。

核心概念：两大配置文件¶

Hexo 的配置体系由两层 YAML 文件组成，务必分清：

  • **站点配置 _config.yml**：位于根目录，控制网站标题、URL、永久链接格式、分页、部署方式等全局行为，配置详解篇会逐项拆解。
  • **主题配置 _config.butterfly.yml**：每个主题自带一份配置文件，控制外观、菜单、侧边栏、评论等。推荐复制一份改名放在根目录，覆盖主题默认值，这样主题更新时自定义内容不会丢失。
🔥配置优先级
根目录下的 主题名.yml（如 _config.butterfly.yml）优先级高于主题目录内的 _config.yml。这是官方推荐的自定义方式，可以做到”升级主题不丢配置”。
