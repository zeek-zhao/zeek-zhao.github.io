调试与运维脚本集（scripts/）

本目录收录工程调试与运维用脚本。约定：全部可在 WSL（Ubuntu-24.04-Zeek）里直接执行；涉及 Docker 的脚本与云端 Actions 环境保持一致。运行环境与仓库约定见 08-repo，发布流程见 04-发布工作手册。

脚本清单

脚本 用途 典型场景
build-local.sh 本地 Docker 构建验证（挂真实 Vault 为内容源），不部署 push 前预检、排查构建失败
deploy-local.sh 本地构建并强推 gh-pages（孤儿提交） 云端 Actions 不可用时的兜底发布
verify-site.sh 线上关键页面 HTTP 状态批量检查 + 主页要素核验 每次部署后的核对步骤
poll-deploy.sh 轮询 gh-pages 新提交，等待云端部署完成 push 后等待流水线
check-tags.py 全库标签（≤3、≥2）与元数据审计 体检指令、发布前质检
inject-metadata.py 批量补齐目录元数据（title/tags/categories/description/放行字段，代码块 raw 包裹，标题查重） 新知识目录批量入库

用法示例

注意事项

  • build-local.sh / deploy-local.sh 默认读 ~/repos/hexo-engine，可用环境变量 HEXO_DIR、CONTENT_DIR 覆盖。
  • deploy-local.sh 是兜底通道：正常情况下 push 到 ob-content 即触发云端自动部署，不需要手动跑。
  • inject-metadata.py 会改写文件，执行前建议先 git status 确认工作区干净，跑完用 git diff 抽查。
  • 正文若需展示模板类字面语法（双花括号、Jinja 风格标签），必须放在代码块内（脚本会自动 raw 包裹）或用 raw 标签手动包裹，否则 nunjucks 渲染会让整站构建失败。
