信号处理与 trap

[!info] 本页概览
本文讲解 Shell 信号与 trap：常见信号、trap 捕获、退出清理、超时控制、优雅退出与 SIGINT/SIGTERM 处理，编写健壮的后台/服务脚本。

核心概念

  • 信号：操作系统通知进程的事件；kill -l 查看列表。
  • trap：在 Shell 内捕获信号或 EXIT/ERR 执行指定动作。
  • 常用：trap '动作' 信号；信号用名字（INT/TERM/EXIT）避免编号歧义。
  • 关键用途：退出清理临时文件、优雅停止子进程。

常见信号

信号 编号 含义
INT 2 中断（Ctrl+C）
HUP 1 挂起/重载配置
TERM 15 终止（默认 kill）
KILL 9 强制终止（不可捕获）
EXIT - 脚本退出（trap 专用）
ERR - 命令失败（set -e 配合）

常见坑

  1. trap 引号时机：单引号在信号触发时执行（变量用当时值）；双引号定义时展开，可能拿到旧值。
  2. EXIT 与显式 exit 顺序：trap EXIT 先执行再退出；别在里面再次 exit 造成递归。
  3. KILL 不可捕获：trap '...' KILL 无效。
  4. 子进程信号隔离：trap 不自动转发给子进程，需要手动 kill 或 exec 替换。
  5. sleep 中断：trap 触发后 sleep 可能继续，循环用 wait 或检查标志。
  6. trap ERR 与 set -e 冲突：ERR trap 与 set -e 组合时命令失败都会触发，注意幂等。

最佳实践

  • 所有写临时文件的脚本加 trap 'rm -f ...' EXIT。
  • 服务型脚本处理 TERM/INT 做优雅停机（刷缓冲、停子进程、清理锁）。
  • trap 函数化（写函数名而非内联），便于复用与测试。
  • 信号名使用可读名字：trap cleanup TERM INT。
  • 生产环境进程管理优先 systemd（自动信号处理与重启），trap 用于脚本级清理。
