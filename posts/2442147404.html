30-Cyber网络IO详解

发表于2026-10-25|apollo
|浏览量:

[!info] 本节目标
理解消息”跨出进程”之后的传输世界：Cyber RT 的三路传输选路逻辑、Receiver/Transmitter 抽象、基于 epoll 的异步 IO、服务发现机制与零拷贝优化手段。

本篇是第四阶段 Cyber RT 深度剖析的第六篇。29-Cyber数据系统详解 讲到消息抵达本进程 Receiver 后的旅程；本篇补全前半程——消息如何在进程间乃至跨机传输。它与调度优化共同支撑了 Cyber 的性能底盘。

1. 网络 IO 的定位

Cyber 的通信设计哲学是”按距离选传输“：

通信范围 传输方式 开销
同进程 shared_ptr 引用传递 零拷贝零系统调用
同主机跨进程 共享内存 + 通知 零数据拷贝，一次系统调用级通知
跨主机 UDP（RTPS/DDS 风格） 网络协议栈

[!note] 2026 年更新
支持零拷贝消息通信是 Cyber RT（Apollo 3.5，2019 年引入）的核心卖点之一；官方称 10.0 代际传输性能提升约 10 倍。Apollo 10.0 起还打通了 ROS 软件生态，便于复用外部工具链。GitHub 主分支已演进至 10.0/11.0（公开 tag 止于 v9.0.0）。10.0 整体资源使用降低 50%、单 NVIDIA Orin 支撑 L4，传输层优化是重要贡献者。

2. 传输层架构

2.1 Transport 三件套

源码目录：cyber/transport/。

  • Transmitter：发送端抽象，负责按通道序列化/分发
  • Receiver：接收端抽象，持有用户回调 msg_callback_，收到消息后触发——回调的下一站就是 29-Cyber数据系统详解 的 DataDispatcher
  • Hybrid 收发器：同时管理进程内/共享内存/RTPS 三条子通道，按对端注册情况动态选路

3. Socket 与异步 IO

3.1 Socket 选型

类型 特点 用途
UDP Socket 无连接、低开销 传感器数据等高频消息跨机传输
TCP Socket 可靠、面向连接 服务发现、控制类关键消息
Unix Domain Socket 本机高效 本地辅助通信

传感器数据选择 UDP 的理由：频率高、容忍单帧丢失（有更重要的下一帧）、避免 TCP 队头阻塞——典型的自动驾驶 QoS 权衡。

4. 服务发现

4.1 TopologyManager

跨进程通信的前提是互相知道对方存在。Cyber 用拓扑管理器实现无中心服务发现：

组件：

  • Participant/Role：每个进程是一个 Participant，携带自身全部 Writer/Reader/Server 信息
  • Topology Change 通报：新 Writer/Reader 创建时广播消息，全网维护一致的拓扑视图
  • 定时心跳：处理进程崩溃，超时即从拓扑中摘除

每个 Transmitter/Receiver 收到拓扑变更后刷新自己的”对端表”——这就是第 2.2 节选路判断的数据来源。

6. 零拷贝与传输优化

6.1 进程内：引用即零拷贝

同进程通信根本不过序列化——Writer::Write 的 shared_ptr 直接进入 29-Cyber数据系统详解 的数据链路。这是把高频组件（感知管线）放进同一进程的架构动机。

6.2 进程间：共享内存

大消息（点云、图像）跨进程走共享内存：

  1. 发送方将序列化数据写入共享内存块
  2. 通过 UDS 通知接收方（仅传”有新数据”信号，几十字节）
  3. 接收方 mmap 直接读取，构造对象

对比传统 socket 方案：省去两次内核态拷贝，大消息吞吐提升显著。代价是需要共享内存清理机制（进程崩溃残留段的回收）。

6.3 传输优化清单

手段 场景 收益
共享内存 同主机大消息 免内核拷贝
消息合并/批处理 高频小消息 摊薄每包开销
合理 history_depth/QoS 乱序容忍场景 丢旧保新降延迟
序列化复用 buffer 序列化热点 减少 malloc
核隔离 + 中断亲和 网卡软中断 降低抖动

7. 可靠性与错误处理

实践要点：

  • 跨机链路默认 UDP + best-effort；需要可靠性的消息（如控制指令）应在业务层做确认或走 TCP/服务
  • 监控丢包计数（cyber_monitor 可见），异常增长说明带宽或订阅端处理能力不足
  • 共享内存目录（/dev/shm/apollo 或 CYBER 环境变量指定）异常时删除残留段再启动

8. 调试与观测

[!tip] 跨进程不通的排查顺序

  1. 两端是否都完成了 cyber::Init（拓扑注册依赖它）
  2. cyber_node info 看对端 Writer/Reader 是否出现在拓扑里——不在则是发现层问题（组播/防火墙）
  3. 在拓扑里但无数据 → 检查共享内存权限与残留段
  4. 跨机不通 → 检查 UDP 组播配置与网卡多播路由

9. 小结

Cyber 网络层 = 按距离选传输（进程内引用 / 同机共享内存 / 跨机 UDP）+ epoll 事件驱动 + 拓扑式服务发现 + 异步 RPC。它把”在哪传、怎么传”完全下沉到框架，用户只见通道名；而零拷贝的三层实现（进程内引用传递、共享内存、序列化复用）配合 29-Cyber数据系统详解 的无锁数据链路与 26-Cyber调度系统详解 的编排调度，共同构成 Cyber 性能叙事的完整闭环。坐标变换类数据如何被消费，见下一篇 31-Cyber Transform与坐标变换。
