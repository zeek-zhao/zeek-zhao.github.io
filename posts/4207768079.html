图片与资源管理

[!abstract] 一句话：图片管理的三道题——放哪里（存储策略）、怎么引（路径规则）、如何快（压缩与分发），一次想清楚终身受益。

存储策略三选一

方案一：本地资源文件夹。开启 _config.yml 中的 post_asset_folder: true 后，每篇文章自动获得同名资源目录：

写作时 hexo new post 文章名 会在 source/_posts/ 下同时生成 文章名.md 与 文章名/ 目录，图片放进后者，Markdown 里直接 ![](图片名.png) 引用。优点是与文章同生共死、完全离线；缺点是图片散落在各目录，不便跨文章复用。

方案二：统一图床（GitHub 仓库）。创建专用图片仓库或源码仓库的独立分支存放图片，配合 CDN 域名引用。优点是集中管理、URL 稳定；缺点是引入外部依赖，需要上传工作流支撑。

方案三：对象存储 + CDN。图片上传到 COS/OSS 等对象存储并绑定 CDN，速度最优、带宽成本与用量挂钩，适合图片量大或追求极致加载体验的站点。

[!tip] 决策原则
个人博客文章量不大时，方案一最省心；图片多且常被多篇引用时上 GitHub 图床；追求国内访问速度则对象存储 + CDN。混用也可以——截图类随文章走，封面图与常用素材进图床。

压缩与格式优化

图片通常占据页面体积的大头，发布前统一压缩是必须养成的习惯。推荐工具链：

更工程化的做法是把压缩挂进 Gulp 发布链（见 13-性能优化与构建加速），用 gulp-imagemin 在每次构建时自动处理，人不再手工干预。格式选择上：截图、插画优先 WebP，需要透明通道的图标用 PNG 或 SVG（矢量图标永远首选 SVG），照片用 JPEG/WebP。

隐私与版权保护

发布图片前顺手检查三件事。EXIF 清理：手机照片的 EXIF 里藏着拍摄时间、GPS 坐标，jpegoptim --strip-all 或 -exif 参数可以一键清除。水印：需要版权声明的原创图可加半透明水印，图片处理脚本或在线工具皆可批量完成。引用授权：使用网络图片确认许可协议（CC0/CC-BY 等），并按协议要求署名，这是内容创作者的基本素养。

前端展示体验

存储和体积之外，展示层还有几个开关值得打开：

  • 懒加载：首屏只加载可视区域图片，LCP 显著改善。
  • 灯箱 Lightbox：点击图片全屏预览，支持缩放与左右切换。
  • 画廊：多图场景用 {% gallery %} 标签组织成网格画廊，比逐张罗列优雅得多。
  • 响应式图片：用 srcset 提供多种尺寸，小屏设备不下载大图。

[!warning] 图床的风险预案
第三方图床（包括 GitHub raw 域名的直链）随时可能限流或变更政策，导致全站图片失效。两条保险：图片副本永远保留在本地仓库中；引用外部图床时在自己的 CDN/Worker 前面加一层代理域名，未来迁移只需改一处配置。

一套可落地的默认方案

综合以上，给出一套开箱即用的组合：文章截图用本地资源文件夹 + 懒加载；封面图与素材库用 GitHub 图床分支 + 构建期 Gulp 压缩；EXIF 清理写入发布脚本；全站图片走 CDN 域名。配置一次，之后写作时只需专注于”截图 → 拖进目录 → 写 alt 文字”这个动作本身。
