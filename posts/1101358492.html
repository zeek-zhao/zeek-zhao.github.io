Nginx 限流与安全

讲清 Nginx 的 limit_req 与 limit_conn 限流、访问控制、防攻击配置，以及限流策略怎么按业务设计。

Nginx 限流与安全

缓存这篇接 10-缓存 往后，光快还不够，得先保证别被打垮。限流的目的一言以蔽之：保护后端，控制速率和并发，顺手挡住 CC 和爬虫。我一般先上 limit_req 控速率，再叠 limit_conn 控连接，两层一起才踏实，只配一层容易被绕过。

限流就是别让后端被打垮¶

限流目的：

  • 保护后端不被打垮
  • 控制请求速率/并发
  • 抵御 CC 攻击、爬虫

Nginx 限流：

  • 请求速率：limit_req（漏桶）
  • 连接数：limit_conn
  • 结合键：IP/URI/UA

速率限流用 limit_req 漏桶¶

参数：

  • rate=10r/s：每秒 10 请求
  • burst=20：突发缓冲队列
  • nodelay：突发立即处理（不排队）
  • 无 nodelay：排队处理，可能超时

返回：超出返回 503

并发连接用 limit_conn 兜底¶

说明：

  • 限制同一 IP 并发连接数
  • 防连接耗尽（慢速攻击）
  • 可配合 limit_req 双层防护

白名单先看 allow/deny¶

防攻击先卡超时和请求体¶

明显爬虫直接按 UA 拦掉¶

封禁靠日志加 WAF 纵深¶

简单方案：

  • 静态 deny 列表
  • 基于日志分析封禁（fail2ban）
  • 配合限流自动降级

进阶：

  • WAF（ModSecurity）
  • CDN 层防护
  • 云盾/高防

策略要按业务区分速率¶

我的习惯是登录接口往死里限，普通浏览松一点，阈值得照着真实流量调，别拍脑袋定个数：

设计要点：

  • 按业务区分速率（登录严、浏览松）
  • 键粒度：IP/账号/设备
  • 突发阈值合理（避免误伤）
  • 返回 429（Too Many Requests）更语义化

示例：
limit_req_zone $binary_remote_addr zone=login:10m rate=1r/s;
location /login {
limit_req zone=login burst=3 nodelay;
limit_req_status 429;
proxy_pass http://backend;
}

这几个坑我踩过¶

  1. 限流误伤正常用户：burst 过小。
  2. 键粒度错误：全部限同一键导致整体阻塞。
  3. proxy 层 IP 不准确：需 realip 模块取真实 IP。
  4. if 滥用：if 块有坑，慎用。
  5. 安全头缺失：基础安全基线未配。

登录和 API 必配限流¶

我基本都把限流返回码改成 429 并记进日志，排查误伤时全靠这条记录定位。

  • 登录/API 必配限流。
  • 管理后台 IP 白名单。
  • 基础安全头 + 隐藏版本。
  • 限流返回 429 并记录日志。
  • 配合 WAF/CDN 纵深防御。
  • 下一步：12-日志管理。
