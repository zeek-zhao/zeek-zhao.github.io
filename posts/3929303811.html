与SSO单点登录集成

[!info] 本节目标
理解 LDAP 在统一身份认证中的位置，掌握与 Keycloak、CAS、SAML/OIDC 体系对接的完整路径。

LDAP 与 SSO 的关系

LDAP 负责”身份数据存储与认证”（你是谁、密码对不对），SSO 负责”会话与票据”（登录一次到处可用）。两者通常组合为：

典型链路：业务系统重定向到 IdP -> IdP 校验用户 -> IdP 通过 LDAP bind 验证凭据 -> 颁发票据 -> 业务系统放行。

方案一：Keycloak + LDAP

配置 Keycloak 的 User Federation：

验证方式选择 simple bind，Keycloak 会以用户输入的密码对 LDAP 执行 bind，密码不落库，安全性更高。

方案二：CAS 服务端对接 LDAP

在 CAS 配置中指定认证源：

用户访问任一接入 CAS 的应用，都会被重定向到 CAS 登录页，由 CAS 通过 LDAP 完成认证。

方案三：直接 LDAP 认证的应用

Nginx、Jenkins、Jira、GitLab 等自带 LDAP 认证：

  • GitLab：管理区 -> LDAP -> 填入 host/base/uid/filter
  • Jenkins：全局安全 -> LDAP 插件 -> server/bind/search
  • Jira：用户目录 -> 添加 LDAP 目录

统一原则：所有应用共享同一 base DN 与 (uid={0}) 过滤器，保证用户唯一。

密码策略联动

SSO 场景下密码策略由 LDAP 统一承载：

  • 修改密码入口收敛到自助服务（如 Apache Directory Studio 或自研改密页）
  • 通过 ppolicy overlay 实施复杂度、有效期、失败锁定
  • 密码同步：将 LDAP 密码通过 webhook 同步到 Keycloak/AD（可选）

排错清单

现象 排查
登录提示密码错误 确认 bind DN 与搜索过滤器，先 ldapsearch 验证
用户导入失败 检查 objectClass 是否含 inetOrgPerson
认证慢 检查索引：为 uid 建 equality 索引
证书报错 LDAPS 需要导入 CA 到 IdP 信任库

[!tip] 最佳实践
先建一个测试组，小范围接入 1-2 个低风险系统验证，再逐步全量推广；保留本地超级账号作为应急入口。
