函数库与模块化

ℹ️本页概览
本文讲解 Shell 脚本的模块化：函数库组织、source 复用、命名空间约定、参数校验封装、错误处理统一，构建可维护的多文件脚本项目。

核心概念¶

  • 函数库：一组通用函数集合，供多个脚本 source 复用。
  • 模块化：主脚本 + 模块（配置、工具、业务）分层。
  • source 在当前 shell 执行，库内可设置变量供调用方使用。
  • 库文件不直接执行（无副作用），只定义函数与常量。

常见坑¶

  1. BASH_SOURCE 与 $0 区别：被 source 的库中 $0 仍是主脚本名；库文件自身路径用 ${BASH_SOURCE[0]}。
  2. 库文件被直接执行：顶层加守卫 if [[ "${BASH_SOURCE[0]}" == "$0" ]]; then echo "请勿直接运行"; fi。
  3. 命名冲突：不同库同名函数互相覆盖；用模块前缀（backend_）。
  4. source 路径相对性：source ./common.sh 依赖 CWD；用绝对路径计算 SCRIPT_DIR。
  5. 循环 source：A source B、B source A 死循环；保持依赖单向。
  6. 全局变量污染：库内变量尽量 readonly 或 local；核心配置放单独 config.sh。

最佳实践¶

  • 公共函数库独立成文件，主脚本只留业务流程。
  • 入口脚本统一：set -euo pipefail → 定位目录 → source 库 → 参数校验 → 执行业务。
  • 库函数带前缀命名，文档注释说明用法。
  • 错误处理统一走 die/error，调用方少重复 try-catch 逻辑。
  • 配置集中：环境差异用 config.sh 或环境变量，避免散落魔法值。
