管道与重定向

[!info] 本页概览
本文讲解 Shell 的数据流机制：stdin/stdout/stderr 重定向、管道组合、tee、进程替换与文件描述符，是”组合小工具成强大命令”的基石。

核心概念

  • 三个标准流：0 stdin、1 stdout、2 stderr。
  • 重定向：> 覆盖、>> 追加、2> 错误流、&> 全部。
  • 管道 |：把前一个命令 stdout 接到后一个命令 stdin。
  • 管道中每条命令在子 shell 执行，变量不回流父 shell。

常见坑

  1. cat file | grep 多余：grep file 直接处理即可（UUOC：Useless Use of Cat）。
  2. 管道内变量修改不生效：echo hi | read v; echo $v 为空；用进程替换 < <(...) 或命令替换。
  3. > 误覆盖：> 直接清空目标；需要保留时用 >> 或先备份。
  4. 2>&1 顺序：cmd 2>&1 >file 与 cmd >file 2>&1 顺序不同，后者才把 stderr 也进文件。
  5. echo $var | grep 中 var 含换行：管道传输按行，多行值用 <<< "$var"（here-string）。
  6. 重定向位置：echo text >file 重定向在命令末尾；管道符与重定向可组合但注意语义。

最佳实践

  • 理解”一个流”心智模型：写命令时画数据流方向。
  • 管道链控制在合理长度，过长用脚本或 awk 一步处理。
  • 需要中间结果用 tee 或 /tmp 暂存文件。
  • 读取命令输出并需保留变量 → 进程替换 while read ... < <(cmd)。
  • 错误与成功分别处理：cmd 2>/tmp/err.log 后检查文件非空。
