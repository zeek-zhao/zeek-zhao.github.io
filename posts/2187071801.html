常见坑

  1. 未设置 Content-Type：返回 JSON 需显式设置，否则浏览器按文本渲染。
  2. 忽略 Body 关闭：服务端 r.Body 由框架关闭，但客户端响应 body 必须 defer resp.Body.Close()。
  3. 并发写 ResponseWriter：多个 goroutine 同时写 w 会 panic，需同步。
  4. 生产用默认 ServeMux 未配置超时：生产环境设置 http.Server 的 ReadTimeout/WriteTimeout。
  5. ListenAndServe 错误被忽略：端口占用等错误直接 panic 或 log.Fatal。
  6. 没有优雅停机：server.Shutdown(ctx) 在收到信号时平滑退出，避免正在处理的请求被中断。

最佳实践

  • Go 1.22+ 用方法路由模式（"GET /path/{id}"）替代手写 if 判断。
  • 业务逻辑与 HTTP 层分离：handler 只做参数解析与响应，逻辑放 service 层。
  • 统一错误响应格式（{"error": "..."}），用 http.Error 或自封装。
  • 中间件洋葱模型：日志→鉴权→业务，顺序清晰。
  • 生产框架可选：标准库足够时优先标准库；复杂项目用 Gin/Echo（见 90-资料索引指南）。
