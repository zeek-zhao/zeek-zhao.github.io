部署

[!info] 本页概览
Go 编译为单一静态可执行文件，部署极其简单。本文讲解交叉编译、Docker 多阶段构建、容器化发布与 CI/CD 流水线。

核心概念

Go 的优势：静态编译、无运行时依赖、跨平台交叉编译。产物就是一个二进制文件，拷贝到目标机即可运行，非常适合容器化与云原生部署。

Docker 多阶段构建

[!tip] CGO_ENABLED=0
关闭 CGO 得到纯静态二进制，可在任意 Linux 运行（无需 glibc），但使用依赖 CGO 的库（如 sqlite、部分网络库）时需谨慎。

常见坑

  1. CGO_ENABLED 未关闭导致依赖 glibc：部署到精简/不同发行版报 no such file or directory（找不到动态链接器）。检查 file myapp 是否 statically linked。
  2. 配置硬编码：配置放环境变量或配置文件，容器里用 -e 注入。
  3. 监听 127.0.0.1：容器内只能本机访问，监听 0.0.0.0 或 :8080。
  4. 忘记健康检查：容器编排（K8s）依赖 livenessProbe/readinessProbe，加 /healthz 接口。
  5. 二进制提交进镜像臃肿：多阶段构建（builder → 精简镜像）可大幅减小体积。
  6. 环境差异：本地/测试/生产配置分离，用 config 包统一加载并校验。

最佳实践

  • 默认 CGO_ENABLED=0 静态编译，镜像用 scratch/alpine。
  • 配置注入用环境变量 + .env 文件，敏感信息走 secrets 管理。
  • 优雅停机：监听 SIGTERM 调用 server.Shutdown(ctx)。
  • 日志输出到 stdout，由日志平台统一采集；请求 ID 贯穿链路。
  • 发布走 CI/CD 流水线，镜像打版本 tag，支持秒级回滚。
