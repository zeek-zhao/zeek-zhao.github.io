代码仓库处理办法（WSL Ubuntu 24.04）

原则：Windows 侧不用 CMD/PowerShell 做仓库操作；所有 git / 构建调试统一走 WSL Ubuntu 24.04。

环境

项 约定
发行版 Ubuntu-24.04-Zeek（wsl -d Ubuntu-24.04-Zeek 进入；注意不是 Ubuntu-24.04）
内容仓库 ob-content 本 Vault：WSL 路径 /mnt/d/zeek/WorkBuddy/obsidian（就地操作）
其他仓库 hexo-engine、username.github.io clone 到 WSL 侧 ~/repos/（Linux 文件系统，git/构建快）
远端认证 SSH key（git@github.com:zeek-zhao/ai-obsidian.git，已验证）；不用 HTTPS token
部署凭据 决策（2026-10-24 更新）：**hexo-engine 仓库内提交 .github/deploy_key**（WSL ~/.ssh/id_rsa 副本），云端 Actions 直接使用、零 secrets。风险约束：该仓库必须永远私有，泄露即撤销账户 SSH key
凭据 git 身份 Zeek Zhao / zeek.zhao@foxmail.com；token/私钥不写进任何 md

调用方式（Windows 侧发起时）

AI 在 WSL 内执行则直接用 bash，无需 wsl 前缀。

Docker 验证陷阱（已踩，勿重蹈）

  1. WSL 内 $PWD / $(pwd) 可能不随 cd 刷新——docker -v 挂载一律写绝对路径（如 /home/zeek.zhao/repos/hexo-engine）。
  2. Windows 侧经 Git Bash 调 docker 时，命令前加 MSYS_NO_PATHCONV=1，否则 /app 等路径被 MSYS 改写。
  3. package.json 必须含 hexo: {"version": "x.y.z"} 字段，否则 hexo-cli 不认站点目录、只显示 help/init/version。

允许 / 禁止

允许：git status/diff/log、add、commit、push、pull、分支查看；在 ~/repos/hexo-engine 内 npm ci && npx hexo generate && npx hexo server 本地调试预览。

禁止：

  • git push --force、改写已推送历史
  • 手动向 username.github.io 推任何东西（仅流水线写入）
  • 在 Windows 侧对仓库做换行符改写（.gitattributes 统一 LF，避免 CRLF 污染）
  • 把 token/密钥写入仓库内任何文件

提交规范

  • message 格式：type: 摘要（feat / fix / docs / chore），如 docs: 新增插件管理规则。
  • 内容类提交由 Obsidian Git 自动完成（vault backup）；AI 手动提交仅用于规则/模板/配置变更。
  • 每次仓库操作在 90-OB工程管理/log/ 留一行（时间 · 操作 · 仓库 · 结果）。
