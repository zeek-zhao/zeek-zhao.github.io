博客加密与内容保护

接着上一篇 09-插件生态总览 提到的加密插件往下说。hexo-blog-encrypt 能给单篇文章加密码，实现”输入密码才能阅读”的效果，但要把话说明白：它是前端加密，不等于绝对安全，用之前先认清边界。

先认清这是一道”防君子”的锁¶

博客写作中常有这类需求：私密日记只给家人看、会议记录只给团队看、付费教程只给已购读者看。Hexo 是纯静态站点，没有服务端鉴权，文章加密由 hexo-blog-encrypt 插件在浏览器端完成：文章正文以 AES 算法加密后仍会随页面下载到访客浏览器，只有输入正确密码才解密显示。

这里的安全边界必须认清：这是前端加密，密文可以被技术能力强的人拿到并尝试破解，解密逻辑也运行在浏览器中。它适合”防止随意浏览与搜索引擎索引”、保护非关键信息，不适合存放真正机密的内容。高安全需求应使用服务端鉴权方案。我的取舍是：重要东西干脆不进仓库，而不是指望这把锁。

参数 说明

主题基本兼容，排错按症状对号入座¶

插件兼容大多数主题，Butterfly 下通常无需额外处理，仅需注意封面图仍会正常显示、自定义 CSS 适配明暗模式即可。常见故障：

  • 加密后文章不显示：升级插件 npm update hexo-blog-encrypt；检查主题是否自带加密功能造成双重处理；临时禁用修改 HTML 结构的插件（如某些压缩类插件）二分排查。
  • 密码正确但无响应：打开浏览器控制台看 JS 报错，多为其他插件脚本冲突；清除缓存或换隐私窗口重试；避免在密码中使用特殊字符。
  • 移动端异常：低端设备解密可能较慢，可减小加密内容体积；老浏览器可能不支持所需加密 API。

插件冲突高发名单：hexo-asset-image、hexo-math、hexo-filter-cleanup 这几类与加密插件冲突概率较高，遇到问题优先怀疑它们。

把发布前检查固化成清单¶

  • 安装插件并通过 hexo clean && hexo g 重建验证
  • 逐篇设置独立密码，不使用全局默认密码
  • 测试移动端解锁体验
  • 在摘要中说明如何获取密码（如”联系我获取”）
  • 备份密码清单，忘记密码后密文无法恢复

还有个更彻底的思路：内容根本不进仓库——私密内容留在 Obsidian 本地库中，发布时只同步公开文章。这与 19-Obsidian与Hexo发布工作流 的分层发布设计可以结合，做到公开区与私藏区彻底隔离，比任何前端加密都更安全。真要放敏感内容，我基本都走这条路。
