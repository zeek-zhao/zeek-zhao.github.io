Redis 持久化与集群

[!info] 本页概览
本文讲解 Redis 持久化（RDB/AOF）与高可用方案：主从复制、哨兵（Sentinel）、Cluster 集群、混合持久化与容灾实践，配可运行配置与命令。

核心概念

  • RDB：全量快照文件（dump.rdb），恢复快、可能丢数据。
  • AOF：追加写命令日志（appendonly.aof），数据更安全、文件大。
  • 主从复制：主节点写、从节点读，数据冗余 + 读写分离。
  • 哨兵 Sentinel：监控主从、自动故障转移，提供高可用。
  • Cluster：分片集群，数据分布在多个主节点，支持水平扩展。

RDB 持久化

[!warning] RDB 丢失窗口
RDB 按触发条件快照，两次快照间宕机会丢失数据；对数据安全要求高时搭配 AOF。

AOF 持久化

[!note] 混合持久化
Redis 4.0+ 支持 aof-use-rdb-preamble yes：AOF 头部为 RDB 快照，之后追加增量，重启恢复快且丢数据少。

主从复制

[!note] 复制注意
主从复制全量同步首次会生成 RDB 传输；主节点最好开启持久化，否则主重启后从会丢数据。

容灾实践

常见坑

  1. 主从不一致：主库未持久化、网络闪断导致部分重同步失败。
  2. 哨兵脑裂：网络分区多主短暂出现；配合 min-replicas-to-write 防丢写。
  3. Cluster 跨槽报错：CROSSSLOT Keys in request don’t hash to the same slot。
  4. 全量同步风暴：多从同时全量同步压垮主库，错峰挂从。
  5. AOF 文件损坏：redis-check-aof 修复后重启。
  6. 持久化目录权限：无法写 RDB 导致后台保存失败。

最佳实践

  • 数据敏感用 AOF everysec + RDB 混合。
  • 从节点配置 replica-read-only yes，只读分流。
  • 监控复制延迟（master_repl_offset - slave_repl_offset）。
  • 结合 14-Redis 高级特性 处理缓存一致性等业务问题。
