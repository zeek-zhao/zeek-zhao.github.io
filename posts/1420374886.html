06-策略语言与语法基础

发表于2026-10-24|selinux
|浏览量:

[!info] 本节目标
掌握策略语言的核心语法，能读懂与编写基本规则。

1. 策略文件组成

SELinux 策略由多个模块组成，每个模块文件包含类型声明、属性、规则与辅助语句。模块编译为二进制策略模块，通过 semodule 安装到系统策略库。

2. 类型与属性声明

类型声明使用 type 关键字，属性声明使用 attribute 关键字。可声明别名与角色关联。类型与属性的合理设计决定策略可维护性。

3. allow 规则

allow 规则是策略主体：allow httpd_t httpd_sys_content_t:file read; 声明 httpd 域可读 Web 内容文件。规则可写多源多目标，操作集以类别+权限组合。

4. 权限类别

权限类别（class）对应内核对象类型：file、dir、process、tcp_socket、unix_stream_socket 等。每类有权限集合，规则按需组合，权限粒度细化到具体操作。

5. 辅助语句

策略语言提供 bool、ifelse、optional、require 等辅助语句。bool 定义运行时布尔，ifelse 按布尔值条件加载规则，optional 处理依赖缺失，require 声明外部引用。

6. 宏与模板

参考策略（refpolicy）提供大量宏与接口，如 gen_require、files_type 等，封装常见规则模式。使用宏可显著简化自定义模块，减少重复代码与错误。

7. 编译与验证

策略源通过 checkmodule 编译为模块，semodule_package 打包，semodule 安装。安装前可用 semodule -l 查看已安装模块，验证规则冲突与依赖完整。

7. 策略文件组织

策略源文件通常按模块组织：te 文件存放规则，if 文件定义接口，fc 文件描述文件上下文。编译时通过 Makefile 统一处理，生成可加载模块。合理的文件组织便于团队协作与版本管理，也是大型策略项目可维护性的关键。掌握组织规范后再编写规则，能显著减少混乱与重复。

8. 规则匹配与优先级

策略规则按最具体优先原则匹配，属性与通配符规则优先级较低。理解匹配顺序有助于预测实际授权结果，避免规则冲突。编写规则时尽量使用具体类型，减少对属性的依赖。使用 sesearch 验证生效规则，是确认策略行为的可靠手段。
