性能优化

[!info] 本节目标
掌握 ROS1 系统性能分析工具与优化手段：消息调度、降频压缩、计算负载与多机部署优化。

1. 性能瓶颈定位

[!tip] 先测后优
优化前先记录基线（hz、CPU、内存），每步优化后对比，避免无效改动。

2. 消息调度优化

手段 说明
queue_size 调小 丢弃旧消息，避免积压
降频发布 传感器数据降频
异步回调 重计算放线程/池
合并话题 数据打包减少消息数
减少拷贝 用指针/const ref

[!warning] 降频权衡
降频降低负载但也降低响应实时性；控制回路（如 PID）不能随意降频，传感器/可视化层可降。

3. 图像/点云压缩

数据类型 优化
图像 compressed / 降分辨率 / JPEG
点云 体素滤波/区域裁剪
激光 按需降频
大消息 分离高频关键字段

[!tip] 按需订阅
只订阅真正需要的消息，用 remap 隔离不需要的高频话题，避免全量接收。

4. 计算负载优化

  • 用 C++ 替代 Python 热点模块（如消息转换、滤波）。
  • 避免回调内做耗时计算，放入 worker 线程。
  • 用 ros::AsyncSpinner 多线程处理多话题回调。

[!note] 线程模型
roscpp 默认单线程 spinner，多话题高负载时回调排队；AsyncSpinner 并行处理回调，注意线程安全。

5. 多机负载均衡

[!tip] 数据流向
跨机只传必要话题（压缩图像、低频状态），避免原始点云/图像全量跨网络。

6. 参数化调优实践

场景 推荐配置
树莓派跑导航 降频激光+关闭 rviz
Jetson 视觉 GPU 加速+压缩输出
远程监控 压缩图像+低频状态

[!warning] 一次一参数
性能优化同样遵循”一次只改一个参数”，记录对比数据，避免多个改动互相掩盖。

7. 监控与自动化

[!tip] 日志告警
长时间运行时记录 CPU/话题频率，异常时告警；配合 34-常见问题排查 快速定位。

8. 常见优化误区

误区 正确做法
无脑降频所有话题 只降非实时/可视化层
压缩所有图像 关键识别任务保留原始分辨率
加节点并行 先分析瓶颈在计算还是 IO
只看 CPU 也要看带宽、延迟、内存

[!note] 延伸
嵌入式平台资源受限场景见 31-ROS与嵌入式平台；排查基础见 34-常见问题排查。
