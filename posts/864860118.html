云计算基础概念

云计算的概念不复杂，复杂的是各种术语叠在一起。我一般先按服务模型和部署模型把坐标定下来。

云计算到底是什么，先把定义对齐¶

1.1 云计算的定义¶

云计算是一种按需提供计算资源的模型，这些资源（包括网络、服务器、存储、应用程序和服务）可以通过网络快速获取和释放，且管理成本低。根据美国国家标准与技术研究院(NIST)的定义，云计算具有五个核心特征、三种服务模型和四种部署模型。

mindmap root((云计算定义)) 按需自助服务 自动化资源分配 无人工干预 广泛的网络访问 多种设备接入 标准化机制 资源池化 多租户模型 位置独立性 快速弹性 自动扩缩容 快速资源调整 服务可计量 透明的计费模式 资源利用监控

1.2 云计算的演进历史¶

云计算的发展经历了从大型机时代到虚拟化技术，再到现代云服务的漫长过程：

timeline title 云计算技术发展历程 1950s : 大型主机时代 1960s : 分时计算与电脑实用程序 1990s : 网格计算概念出现 1999 : Salesforce开创SaaS模式 2002 : Amazon开始开发AWS 2006 : Amazon EC2面世，IaaS概念兴起 2008 : Google App Engine引入PaaS模式 2010 : 微软Azure商业化 2013 : Docker容器技术革新 2014 : Kubernetes开源 2016 : 无服务器计算普及 2020+ : 混合云与多云战略成主流

1.3 云计算的核心特性详解¶

1.3.1 按需自助服务

云计算用户可以单方面地自动获取计算能力，如服务器时间和网络存储，无需与每个服务提供商进行人工交互。这一特性实现了资源的自动化配置和管理。

1.3.2 广泛的网络访问

云计算能力可通过网络使用标准机制获取，这些机制支持各种客户端平台（如移动电话、平板电脑、笔记本电脑和工作站）的使用。

1.3.3 资源池化

云提供商的计算资源被池化以服务多个消费者，不同的物理和虚拟资源根据消费者需求动态分配和重新分配。客户通常不知道也不能控制提供的资源的确切位置，但可能能够在更高抽象级别（如国家、州或数据中心）指定位置。

1.3.4 快速弹性

云计算能力可以弹性地提供和释放，在某些情况下可以自动进行，以快速适应需求变化。对消费者来说，可用的能力通常看起来是无限的，可以在任何时候以任何数量购买。

1.3.5 服务可计量

云系统会自动控制和优化资源使用，通过在适合服务类型的某种抽象级别（如存储、处理、带宽和活跃用户账户）上进行计量来实现。资源使用可以被监控、控制和报告，为服务提供商和消费者双方提供使用透明度。

虚拟化是云计算的地基¶

虚拟化是云计算的关键支持技术，它允许在单一物理硬件上运行多个虚拟系统。

2.1 虚拟化的定义与类型¶

虚拟化是一种资源抽象技术，通过在物理硬件之上添加一层软件层，将底层硬件资源转换为虚拟资源，实现资源的灵活分配和管理。

flowchart TD A[虚拟化类型] --> B[计算虚拟化] A --> C[存储虚拟化] A --> D[网络虚拟化] A --> E[桌面虚拟化] B --> B1[全虚拟化] B --> B2[半虚拟化] B --> B3[容器虚拟化] C --> C1[块存储虚拟化] C --> C2[文件存储虚拟化] D --> D1[SDN软件定义网络] D --> D2[NFV网络功能虚拟化] E --> E1[VDI虚拟桌面基础架构] E --> E2[DaaS桌面即服务]

2.2 虚拟机监控器（Hypervisor）¶

Hypervisor是虚拟化的核心组件，负责创建、运行和管理虚拟机，分配物理资源给各个虚拟机使用。

graph TB subgraph "Type 1: 裸金属Hypervisor" A[物理硬件] --- B[Hypervisor] B --- C[虚拟机1] B --- D[虚拟机2] B --- E[虚拟机3] end subgraph "Type 2: 宿主Hypervisor" F[物理硬件] --- G[宿主操作系统] G --- H[Hypervisor] H --- I[虚拟机1] H --- J[虚拟机2] end style A fill:#f9f,stroke:#333,stroke-width:2px style F fill:#f9f,stroke:#333,stroke-width:2px style B fill:#bbf,stroke:#333,stroke-width:2px style H fill:#bbf,stroke:#333,stroke-width:2px

常见的Hypervisor实现包括：

  • Type 1（裸金属）：直接运行在硬件上，如VMware ESXi、Microsoft Hyper-V、KVM
  • Type 2（宿主）：运行在操作系统上，如Oracle VirtualBox、VMware Workstation

2.3 容器技术与虚拟机的比较¶

容器技术是一种轻量级的虚拟化解决方案，与传统虚拟机相比具有更高的效率。

graph TD subgraph "虚拟机架构" A[硬件基础设施] --> B[Hypervisor] B --> C[Guest OS 1] B --> D[Guest OS 2] C --> E[Bins/Libs] D --> F[Bins/Libs] E --> G[App 1] F --> H[App 2] end subgraph "容器架构" I[硬件基础设施] --> J[Host OS] J --> K[容器引擎] K --> L[Bins/Libs] K --> M[Bins/Libs] L --> N[App 1] M --> O[App 2] end

虚拟机vs容器的主要差异：

启动时间 分钟级 秒级
资源占用 较高 较低
系统依赖 独立OS 共享Host OS
安全性 较高 相对较低
可移植性 依赖Hypervisor 高可移植性

IaaS、PaaS、SaaS 分界在哪¶

云计算根据服务抽象程度的不同，主要分为IaaS、PaaS和SaaS三种服务模型。

graph TD A[云计算服务模型] --> B[IaaS] A --> C[PaaS] A --> D[SaaS] E[管理责任分配] --> F[传统IT] E --> B E --> C E --> D E --> G[托管服务] F -.-> H["用户管理:应用、数据、运行时、中间件、OS、虚拟化、服务器、存储、网络"] B -.-> I["用户管理:应用、数据、运行时、中间件、OS | 云管理:虚拟化、服务器、存储、网络"] C -.-> J["用户管理:应用、数据 | 云管理:运行时、中间件、OS、虚拟化、服务器、存储、网络"] D -.-> K["用户管理:无 | 云管理:应用、数据、运行时、中间件、OS、虚拟化、服务器、存储、网络"] G -.-> L["云管理:应用、数据、运行时、中间件、OS、虚拟化、服务器、存储、网络"] style A fill:#f9f,stroke:#333,stroke-width:2px style B fill:#bbf,stroke:#333,stroke-width:2px style C fill:#bfb,stroke:#333,stroke-width:2px style D fill:#fbb,stroke:#333,stroke-width:2px

3.1 IaaS（基础设施即服务）¶

IaaS提供最基本的云计算资源，包括虚拟化的计算、存储和网络资源。用户无需管理或控制底层云基础设施，但可以控制操作系统、存储和已部署的应用程序。

3.1.1 IaaS的核心组件

flowchart LR A[IaaS核心组件] --> B[计算资源] A --> C[存储资源] A --> D[网络资源] A --> E[安全组件] B --> B1[虚拟机] B --> B2[裸金属服务器] B --> B3[GPU实例] C --> C1[块存储] C --> C2[对象存储] C --> C3[文件存储] D --> D1[VPC] D --> D2[负载均衡器] D --> D3[弹性IP] D --> D4[NAT网关] E --> E1[安全组] E --> E2[网络ACL] E --> E3[IAM]

3.1.2 IaaS的优势与适用场景

优势：

  • 按需资源获取，降低资本支出
  • 快速扩展能力，应对业务增长
  • 减少硬件维护成本和工作
  • 提高灾难恢复能力

适用场景：

  • 开发和测试环境
  • 业务负载变化大的应用
  • 存储、备份和恢复解决方案
  • 高性能计算需求
  • 小型企业需要快速部署的IT基础设施

3.1.3 主要IaaS提供商及服务

  • AWS：EC2（计算）、S3（存储）、VPC（网络）
  • 微软Azure：虚拟机、存储账户、虚拟网络
  • Google Cloud：Compute Engine、Cloud Storage、VPC
  • 阿里云：ECS、OSS、专有网络
  • 腾讯云：CVM、对象存储、私有网络

3.2 PaaS（平台即服务）¶

PaaS在IaaS的基础上提供了开发、测试和部署应用程序的平台，使开发者能够专注于应用程序开发而无需关心底层基础设施。

3.2.1 PaaS的核心功能

graph TD A[PaaS平台功能] --> B[开发环境] A --> C[中间件服务] A --> D[数据库服务] A --> E[部署服务] A --> F[管理工具] A --> G[分析服务] B --> B1[IDE集成] B --> B2[多语言支持] B --> B3[API管理] C --> C1[消息队列] C --> C2[API网关] C --> C3[服务网格] D --> D1[关系型数据库] D --> D2[NoSQL数据库] D --> D3[内存数据库] E --> E1[CI/CD管道] E --> E2[容器编排] E --> E3[无服务器计算] F --> F1[监控工具] F --> F2[日志管理] F --> F3[配置管理] G --> G1[实时分析] G --> G2[预测分析] G --> G3[报告工具]

3.2.2 PaaS的优势与适用场景

优势：

  • 加速应用开发周期
  • 减少环境配置工作
  • 简化多云和混合云部署
  • 自动化部署和扩展
  • 内置开发工具和API

适用场景：

  • 敏捷应用开发团队
  • 微服务架构实现
  • API开发和管理
  • 物联网应用开发
  • 需要快速迭代的项目

3.2.3 主要PaaS提供商及服务

  • Heroku：应用容器（Dynos）
  • AWS：Elastic Beanstalk、Lambda、App Runner
  • Google Cloud：App Engine、Cloud Functions、Cloud Run
  • 微软Azure：App Service、Functions、Logic Apps
  • 阿里云：SAE、函数计算、容器服务

3.3 SaaS（软件即服务）¶

SaaS提供完整的应用程序解决方案，通过Internet按订阅方式提供。用户无需关心应用程序的安装、维护和基础设施管理。

3.3.1 SaaS的特点

mindmap root((SaaS特点)) 多租户架构 单实例多客户 资源共享 数据隔离 订阅定价模型 按用户计费 按功能计费 按使用量计费 零客户端安装 浏览器访问 移动应用访问 自动更新维护 后台升级 无需用户干预 始终最新版本 快速部署 即开即用 无需安装 灵活扩展 用户快速增减 功能模块选择

3.3.2 SaaS的优势与适用场景

优势：

  • 减少软件获取和维护成本
  • 无需硬件投资
  • 随时随地可访问
  • 快速部署和实施
  • 自动更新和升级

适用场景：

  • 企业通信与协作
  • 客户关系管理
  • 人力资源管理
  • 财务管理和ERP
  • 项目管理与生产力工具

3.3.3 主要SaaS应用类别与示例

  • 协作工具：Microsoft 365、Google Workspace
  • CRM系统：Salesforce、HubSpot
  • ERP系统：SAP、Oracle NetSuite
  • HR软件：Workday、BambooHR
  • 项目管理：Asana、Jira、Trello
  • 电子商务：Shopify、WooCommerce

公有、私有、混合怎么选¶

云部署模型定义了云服务的所有权、规模和访问权限，主要包括公有云、私有云、混合云和多云。

4.1 公有云¶

由第三方云服务提供商拥有和运营的云服务，通过公共互联网向多个组织提供资源。

graph TD A[公有云架构] --> B[云服务提供商] B --> C[共享基础设施] C --> D[虚拟隔离] D --> E[客户1] D --> F[客户2] D --> G[客户3] H[公有云优势] --> I[低成本] H --> J[零维护] H --> K[无限扩展] H --> L[高可靠性] H --> M[按需付费] N[公有云挑战] --> O[数据安全与隐私] N --> P[合规性问题] N --> Q[控制力有限] N --> R[长期成本管理]

4.2 私有云¶

为单个组织专用的云基础设施，可以由该组织或第三方管理，可部署在本地数据中心或外部托管设施。

graph TD A[私有云类型] --> B[本地私有云] A --> C[托管私有云] B --> D[组织自有数据中心] B --> E[组织自行管理] C --> F[第三方设施] C --> G[可能由第三方管理] H[私有云优势] --> I[控制力强] H --> J[安全性高] H --> K[合规适应性] H --> L[网络性能优] M[私有云挑战] --> N[高前期成本] M --> O[资源利用效率] M --> P[扩展性有限] M --> Q[管理复杂性]

4.3 混合云¶

结合公有云和私有云的云计算环境，允许数据和应用程序在两者之间共享。

graph LR A[混合云架构] --> B[私有云/本地数据中心] A --> C[公有云服务] B <-- 安全连接 --> C D[数据分类] --> E[敏感数据] D --> F[非敏感数据] E --> B F --> C G[混合云优势] --> H[灵活性] G --> I[成本优化] G --> J[风险管理] G --> K[遗留系统整合]

4.4 多云策略¶

组织使用来自多个云提供商的服务的策略，以避免供应商锁定并优化性能和成本。
