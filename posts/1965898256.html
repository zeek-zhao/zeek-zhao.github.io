15-表格与数据管理

Advanced Tables、Notion-like Tables、DB Folder、Metadata Menu、Metatable、Sortable 六插件融合：从编辑表格到管理结构化数据的完整工具箱。
📅 2026-10-25· 更新于 2026-10-25 ✍ zeek.zhao #工具#obsidian

表格与数据管理

📑一句话
表格痛点分四层：写表格难（Advanced Tables）、要数据库视图（Notion-like Tables / DB Folder）、属性管理乱（Metadata Menu / Metatable）、文件散乱无序（Sortable）——本篇六件工具各解一层，并与官方 Bases 明确分工。

Advanced Tables：把 Markdown 表格写爽¶

Markdown 表格的痛点是管道符对齐烦人、改一格全行乱。Advanced Tables 用三招解决：

  1. 自动格式化：首行输入 | 姓名 | 年龄 | 按回车，自动补全分隔行；编辑中实时对齐列宽，也可 Shift+Alt+F 手动触发
  2. 键盘导航：Tab/Shift+Tab 在单元格间跳转，Enter 换行，Alt+Enter 插入行、Alt+Shift+方向键移动行/列——双手不用碰鼠标
  3. 实用附加：按列排序、简单公式（=B2*C2）、CSV 粘贴导入与导出、单元格内支持 链接 和 Markdown 格式

Notion-like Tables 与 DB Folder：数据库式视图¶

当表格需要”每行一篇笔记、可筛选可切换视图”时，就轮到数据库类插件出场。

Notion-like Tables 用 ```notion-table 代码块创建内嵌数据库，属性类型覆盖文本、数字、单选/多选、日期、复选框、文件、公式，并支持同一数据的表格/看板/日历/画廊四种视图切换，筛选与多级排序一应俱全，最接近 Notion 数据库体验。

DB Folder 的思路相反：把一个文件夹变成数据库——文件夹里每篇笔记是一行，frontmatter 属性是列。右键文件夹选择”将文件夹设置为数据库”即生成视图，直接在表格里改单元格会写回笔记的 YAML；同样支持看板、画廊、日历视图和公式字段（如用 moment 计算截止日期剩余天数）。它的优势是数据完全以”文件+属性”形态存在，与 09-Dataview数据查询 天然互通。

📝2026 更新
官方 Bases（Obsidian 1.9+ 内置，见 06-Bases数据库视图）上线后，DB Folder、Notion-like Tables 这类”数据库表”插件的使用场景明显收窄：Bases 以属性驱动、零代码、官方维护，支持表格/卡片等视图与筛选排序，已成为结构化数据的首选。数据库类插件仍可作为补充保留（如内嵌在单篇笔记里的表格视图、更丰富的公式能力），但新用户建议先学 Bases。另外，Obsidian 官方 Importer 在 1.10-1.12 已原生支持 Notion、Airtable 式数据与 CSV 导入，迁移外部数据不再需要曲线救国。

Metadata Menu：给属性立规矩¶

数据库视图好用与否，取决于 frontmatter 属性是否规范。Metadata Menu 是属性层的治理工具：

  • 字段定义：为每个字段声明类型（文本/数字/日期/单选/文件/公式等），录入时出现对应的选择器——日期字段弹日历、单选字段给下拉列表，从源头杜绝手误
  • 文件类（Fileclass）：按文件夹或标签给笔记分组，每组定义统一属性结构。例如 #project 类笔记必备 status/priority/due 三个字段
  • 批量操作：在文件管理器多选笔记右键批量设置属性；支持条件字段（type=project 时才显示 due_date）与级联字段（选了国家，城市只列出该国的）

配合 Dataview 的效果立竿见影：查询语句 TABLE status, priority, due FROM #project SORT due ASC 之所以不会查空，正因为 Metadata Menu 保证了每篇笔记的属性都规规矩矩。

Metatable：让 frontmatter 可读¶

Metatable 很轻量：在阅读视图中把 YAML frontmatter 渲染成整洁的表格，链接可点击、日期格式化、嵌套结构可折叠。适合元数据较多的笔记（文献卡、书籍卡）提升阅读体验。它还支持按字段设置别名（due 显示为”截止日期”）、排除字段、用 CSS 片段定制样式。

与 05-属性元数据与标签 的关系：官方 Properties 面板已提供基本的属性展示，Metatable 的差异化在于”阅读态表格呈现 + 精细显示控制”，元数据重度用户值得保留，轻用户可省。

Sortable：文件层面的自动整理¶

前面都是”笔记内的数据”，Sortable 管”库里的文件”：按规则自动排序、重命名、移动文件。

  • 规则要素：目标文件夹、文件筛选器、基于 YAML 属性的排序（如按 priority 降序）、触发时机（创建时/修改时/定时/启动时）
  • 动态路径：目标文件夹支持变量，如 Archives/{{date:YYYY}}/{{date:MM}} 自动按年月归档；{{yaml:category}} 按属性分类
  • 典型用法：带 #archived 标签的笔记每周自动移入归档库；按 status 字段把项目笔记分流到”进行中/已完成/已归档”三个文件夹
⚠️
自动移动文件有风险：先在测试文件夹验证规则，为重要文件加 sortable: false 排除标记，规则列表的顺序会影响执行结果。它只移动和重命名文件，不改内容，但误移仍会打乱链接结构，建议配合”更新内部链接”选项。

数据管理的进阶路径很清晰：先用 Advanced Tables 把”写表格”的摩擦降到零；属性多起来后用 Metadata Menu 立规范；需要视图时优先 Bases、特殊场景补数据库插件；最后用 Sortable 兜底文件卫生。每一步都建立在属性规范的基础上——这也是为什么 05-属性元数据与标签 值得先读。
