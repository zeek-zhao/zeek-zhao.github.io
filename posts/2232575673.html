核心概念与架构

[!abstract] Gerrit 是什么
基于 Git 的代码评审系统：代码先到 Gerrit 生成 Change，评审通过后才合入主干，配合 CI（Jenkins）形成质量闸门。

核心模型

关键术语

术语 含义
Change 一次评审单元（对应一个提交的评审过程）
PatchSet 同一 Change 的新版本（每 push 一次 +1）
refs/for/branch 评审引用，推送到这里进入评审
refs/changes/xx 评审中的引用存储位置
Verified CI 验证标签（+1 通过 / -1 失败）
Code-Review 人工评审标签（+2 通过才可合入）
submit 评审通过后合入目标分支

架构组件

组件 作用
Gerrit Web（HTTP/SSH） 评审 UI、git 协议、REST API
H2/PostgreSQL/MySQL 元数据存储（账号、Change、权限）
文件系统（gerrit.site） 所有 Git 仓库、索引、配置
Lucene 索引 代码/Change 全文搜索
复制插件（replication） 推送镜像到远程 Git（10-复制与二级服务器）
Hook 事件回调脚本（08-Hook与事件）

数据目录结构

评审为什么用 refs/for

[!note] 关键区别
refs/for/ 不是真实分支，是评审入口；Gerrit 据此创建 refs/changes/NN/xxxx/1 补丁集引用。

三种合并方式

方式 说明 适用
Merge if Necessary 三方合并 默认推荐
Fast Forward Only 线性提交 严格要求线性历史
Cherry Pick 自动拣选提交 目标分支被保护/冲突
