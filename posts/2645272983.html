测试

[!info] 本页概览
Go 内置测试框架 testing，无需第三方即可写单元测试、表驱动测试与基准测试。本文讲解 test 文件组织、断言写法、覆盖率、基准测试与 httptest。

核心概念

  • 测试文件命名 xxx_test.go，与被测代码同包（可访问私有符号）。
  • 测试函数签名 func TestXxx(t *testing.T)；基准 func BenchmarkXxx(b *testing.B)。
  • 常用命令：go test、go test -v、go test -cover、go test -bench . -run ^$。

测试覆盖率

常见坑

  1. 测试与被测代码同包 vs 外部包：同包可测私有函数；外部包（package main_test）只测公开接口，更能模拟用户视角。
  2. **t.Error 与 t.Fatal**：Error 继续执行，Fatal 终止当前 goroutine。子测试中 t.Fatal 只终止子测试。
  3. **基准测试用 b.N**：不要硬编码循环次数，框架自动调整。
  4. 测试间共享状态：并行测试（t.Parallel）共享包级变量会互相污染，尽量隔离。
  5. 跳过真实网络：依赖网络的测试用 httptest 或 mock 接口，保证可重复。
  6. **测试只断言”应该成功”**：也要测失败路径（错误返回、边界值、空输入）。

最佳实践

  • 表驱动测试是 Go 社区标准，新增用例只需加一行。
  • 命名清晰：TestXxxYyy，失败信息含输入与期望。
  • CI 中跑 go test -race ./...，检测并发 bug。
  • 覆盖率高不等于质量高，关键路径（错误处理、并发、边界）优先覆盖。
  • 用 testify/require 或标准库均可，团队统一风格即可。
