Docker Compose

[!abstract] 是什么
Compose 用 YAML 文件定义并运行多容器应用，一条命令启停整套服务。

[!note] 说明
默认读取当前目录 compose.yaml / docker-compose.yml，可用 -f 文件 指定其他文件。

常用配置项

字段 作用
build: 用 Dockerfile 构建而非拉取镜像
depends_on: 声明启动依赖顺序
environment: 环境变量
restart: 重启策略（always 等）
networks: 指定自定义网络

[!tip] 实战建议
个人项目（如 nginx + MySQL + Redis）用 Compose 一键启动，环境可复现、迁移方便。

[!warning] 版本注意
Compose V2 已内置到 Docker 引擎，命令统一为 docker compose（无空格）。

01-什么是Docker与核心概念
什么是 Docker 与核心概念 [!abstract] 一句话Docker 是容器化平台，将应用及其依赖打包成标准化单元，实现”一次构建，处处运行”。 为什么需要 Docker传统部署依赖环境一致，应用换个机器就报错。容器把代码 + 运行时 + 依赖打包成镜像，彻底消除环境差异，秒级启动、资源占用远小于虚拟机。 三大核心概念 概念 说明 类比 镜像 Image 只读模板，包含应用与依赖 安装光盘 容器 Container 镜像的运行实例，可启动/停止 光盘运行出的进程 仓库 Registry 存放与分发镜像的服务 应用商店 镜像 vs 容器 镜像是静态文件，容器是动态进程； 一个镜像可启动多个容器； 容器内修改不会影响镜像，除非提交为新镜像。 Docker 与虚拟机 维度 容器 虚拟机 启动速度 秒级 分钟级 资源占用 共享内核，极小 独占系统，较大 隔离级别 进程级 系统级 [!note] 核心命令预览下一篇 02-安装与初体验 将带你装好 Docker 并运行第一个容器。 返回索引 · 下一篇：02-安装与初体...
