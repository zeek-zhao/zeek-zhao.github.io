性能优化

[!info] 本页概览
Python 性能优化要”先测量、后优化”。本文讲解 cProfile 剖析、常见性能瓶颈（循环、字符串、I/O、算法）与优化手段，以及何时考虑 C 扩展/并发/异步。

核心概念

Python 是解释型动态语言，性能优化目标通常是：减少解释器开销、减少内存分配、把重活交给 C 实现（标准库/第三方 C 扩展）。铁律：用剖析数据定位热点。

剖析：cProfile

命令行：python -m cProfile -s cumulative app.py。

常见坑

  1. 过早优化：正确性优先，性能问题用剖析证明再改。
  2. 误判瓶颈：只优化猜测热点，实际热点在别处（网络、I/O）。
  3. 盲目多线程：CPU 密集用线程因 GIL 反而更慢，用进程。
  4. += 字符串在循环内：O(n²) 拷贝，改用列表 + join。
  5. 全局查找 vs 局部：循环内频繁访问全局变量慢，先缓存为局部变量。
  6. 微优化忽略 I/O：数据库/网络往往是大头，先看调用次数与延迟。

最佳实践

  • 剖析流程：cProfile → 定位 top 函数 → 优化 → 复测。
  • 热路径用 C 实现：标准库 > numpy > Cython/Numba > C 扩展。
  • 用 timeit 比较小段代码：python -m timeit "sum(range(100))"。
  • 性能基线放 CI（pytest-benchmark），防回归。
  • 大 JSON 解析用 orjson，大数值运算用 numpy。
