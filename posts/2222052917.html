环境与工程结构

[!info] 本页概览
本文讲解 Go 的安装、环境变量、模块（module）工程结构与第一个 Hello World 程序。理解 GOPATH 到 Go Modules 的演进是掌握 Go 工程化的第一步。

核心概念

Go 从 1.11 起引入 Go Modules 作为官方依赖管理方案，替代早期的 GOPATH 模式。现代 Go 项目都基于模块组织：一个模块由 go.mod 描述，包含模块路径、Go 版本与依赖。

    • GOPROXY：模块代理，国内建议 https://goproxy.cn,direct
    • GOBIN：go install 安装可执行文件的目录

常见坑

  1. 模块路径与仓库不一致：go mod init 常用仓库地址（如 github.com/user/myapp），模块路径需唯一且稳定。
  2. 包名与目录名混淆：导入路径用目录名，包声明用 package xxx，两者最好一致，否则阅读混乱。
  3. GOPATH 时代残留教程误导：src 目录强制要求已经过时，新项目直接 go mod init。
  4. go run 与 go build 输出位置：go build 在当前目录生成可执行文件；go install 装到 GOBIN。
  5. 代理未配置导致依赖下载慢/失败：国内务必设置 GOPROXY。

最佳实践

  • 可执行程序放 cmd/<name>，库代码放 pkg 或 internal，internal 包禁止外部导入。
  • go fmt 格式化所有代码，保持官方风格。
  • 用 go vet 静态检查，用 golangci-lint 做更全面的 lint。
  • 每完成一个小功能就 go build 验证，避免错误堆积。
