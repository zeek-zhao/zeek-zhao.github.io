搜索语法

接着上一篇 03-代码索引基础 往下，索引建好之后就得靠搜索把它用起来。OpenGrok 顶部那个搜索框看着普通，默认走全文分词匹配，真正的功夫全藏在字段前缀、正则和布尔组合里。我一般是先想清楚要找的是定义还是引用，再决定加哪个前缀，上来就全文搜噪音太多。这篇把常用语法和对应示例过一遍。

搜索框默认全文，字段前缀才是精确入口¶

OpenGrok 顶部搜索框：

  • 默认全文搜索
  • 支持字段前缀
  • 支持正则与布尔

搜索设置：

  • 项目选择（搜索范围）
  • 历史（搜索提交记录）
  • 类型过滤

URL 参数：
/source/search?q=&project=
/source/search?full=keyword

多词默认 AND，短语记得加引号¶

基本示例：

  • 关键词：main
  • 多词：parse request
  • 短语：使用引号 “http request”

说明：

  • 默认分词匹配
  • 多词默认 AND？取决于配置（默认 AND）
  • 大小写不敏感（默认）

找定义用 def:，找引用用 refs:¶

常用字段前缀：

  • full: 全文
  • def: 定义（函数/类定义）
  • sym: 符号（定义+引用）
  • refs: 引用
  • path: 路径/文件名
  • hist: 历史提交信息
  • type: 文件类型

示例：

  • def:main 查找 main 函数定义
  • sym:parseConfig 查找符号
  • refs:HttpClient 查找引用
  • path:*.java 按路径过滤
  • type:java 只搜 Java 文件
  • hist:fix bug 在提交记录中搜

正则用 re: 显式指定，但别拿它做常规搜索¶

正则示例：

  • \bparse\w* parse 开头的词
  • (error|exception).*timeout 错误与超时
  • ^public.*void main 以 public 开头包含 void main

说明：

  • 正则用 re: 前缀可显式指定
  • 支持标准 Java 正则
  • 正则查询性能较低，谨慎大量使用

正则能应急，但我基本只在字段搜索解决不了时才用它，开销摆在那儿。

布尔关键字要大写，括号控制优先级¶

布尔操作符：

  • AND（默认，可省略）
  • OR
  • NOT / -

示例：

  • main OR run
  • def:main AND path:utils
  • parse NOT test
  • (def:connect OR refs:connect) AND type:java

说明：

  • 大写关键字生效
  • 括号控制优先级
  • 字段可与布尔组合

搜索建议靠 -G 生成的符号索引¶

搜索建议：

  • 输入时实时提示符号/路径
  • 基于索引中符号
  • 快速补全查询

启用：索引 -G 参数生成 suggester
使用：输入关键词，下拉选择符号/文件

价值：

  • 减少拼写错误
  • 快速定位符号
  • 探索性浏览

结果能按相关性排，链接可以直接分享¶

结果元素：

  • 文件名 + 路径
  • 匹配行 + 上下文
  • 符号链接（点击跳转）
  • 类型/语言标签
  • 项目标识

排序：

  • 相关性默认排序
  • 可按文件/路径/时间调整

导出：

  • 结果 URL 可分享
  • 支持 RSS（部分版本）

六个高频套路直接套用¶

实战技巧：

  1. 找定义：def:函数名
  2. 找所有引用：refs:符号名
  3. 找配置文件：path:*.xml AND full:port
  4. 找改动：hist:关键词
  5. 找测试：path:test AND type:java
  6. 交叉引用：点击符号 → 定义/引用列表

搜不到先查范围和索引新鲜度¶

  1. 忘记字段前缀：全文搜索噪音多，用 def:/sym: 精确。
  2. 正则语法错误：转义不当无结果。
  3. 大小写问题：默认不敏感，需精确用 re:。
  4. 范围未选：未选项目只搜默认项目。
  5. 索引陈旧：搜不到新代码，先增量索引。

常用符号搜索固定用 sym:/def:¶

  • 常用符号搜索用 sym:/def:。
  • 保存常用查询（浏览器书签）。
  • 结合交叉引用深度分析代码，这是把搜索结果变成代码理解的关键一步。
  • 下一步：05-浏览与导航。
