DMA工作原理与内核API

我一般把 DMA 理解成给数据搬运单开的一条旁路：CPU 只负责配置好源地址、目的地址和长度，真正的数据搬运交给控制器，搬完再发一次中断通知。把这个心智模型立住，后面看 Linux 那套 dma API 就顺了——本质上都是围绕「怎么配置、怎么映射、怎么同步」这三件事。

一图看懂：DMA 绕过 CPU 直访内存，三段流程完成一次传输。

graph LR CPU[CPU 初始化] --> BUF[分配 DMA 缓冲区] BUF --> MAP[映射 一致性或流式] MAP --> DEV[设备直访内存传输] DEV --> IRQ[完成中断] IRQ --> SYNC[同步缓存 释放]

1. DMA概述：用绕过CPU的直访内存换I/O吞吐¶

直接内存访问(DMA)是一种允许输入/输出(I/O)设备直接读写系统内存而无需CPU干预的硬件机制，可以显著减轻CPU负担并提高数据传输效率。

我判断一个设备值不值得上 DMA，主要看数据路径里 CPU 是不是还在逐字节搬运——只要还在搬，DMA 就有用武之地。

1.1 什么是DMA：设备直读写内存的硬件旁路¶

DMA的主要特点：

  • 绕过CPU：数据传输不需要CPU执行指令
  • 并行处理：CPU可以同时执行其他任务
  • 高速传输：减少中断处理开销，提高吞吐量
  • 降低延迟：减少数据从源到目的地的路径长度

1.2 为什么需要DMA：把CPU从逐字节搬运里解放出来¶

在没有DMA的系统中，所有I/O操作都需要CPU参与，这导致以下问题：

  1. CPU效率低下：大量时间花在简单的数据搬运上
  2. 中断频繁：每次传输少量数据就产生中断
  3. 延迟增加：数据必须经过CPU，增加了传输路径
  4. 带宽受限：处理器成为数据传输的瓶颈

以网卡为例，不使用DMA接收数据流程：

  1. 网卡接收数据包
  2. 触发中断
  3. CPU执行中断处理程序
  4. CPU逐字节从网卡读取数据
  5. CPU逐字节写入内存
  6. 返回用户程序

而使用DMA的流程：

  1. 网卡接收数据包
  2. DMA控制器将数据写入预定义的内存区域
  3. 数据传输完成后触发一次中断
  4. CPU处理完整数据包，无需参与传输过程
  5. 返回用户程序

1.3 发展历史：从8237到IOMMU的演进¶

DMA技术随着计算机硬件的演进不断发展：

  • 1960年代：早期大型计算机引入基本DMA通道
  • 1970年代：个人计算机采用简单的DMA控制器(Intel 8237)
  • 1980年代：引入总线主控DMA(Bus-mastering DMA)
  • 1990年代：PCI总线标准化DMA传输
  • 2000年代：引入分散-聚集(Scatter-Gather)DMA
  • 2010年代：RDMA(远程直接内存访问)技术成熟
  • 现在：支持虚拟化的DMA技术，IOMMU广泛应用

2. DMA工作原理：初始化、传输、完成中断三段流程¶

我实测下来，传输模式选错的代价往往比驱动代码写得糙更大——音频流用块传输会因为延迟被投诉，网络包用按需传输又会被中断压垮。

2.1 基本工作流程：分配缓冲区、拿总线、发完成中断¶

DMA传输通常遵循以下步骤：

  1. 初始化：

    • 驱动程序分配DMA缓冲区
    • 设置数据源、目标地址
    • 配置传输参数(数据量、方向等)
    • 向DMA控制器发出启动命令

  2. 传输过程：

    • DMA控制器请求总线控制权
    • 总线仲裁器授予控制权
    • DMA控制器直接在内存和设备间传输数据
    • 传输过程中CPU可执行其他任务

  3. 完成通知：

    • 传输完成后，DMA控制器发出中断
    • CPU处理完成中断，执行后续操作
    • 释放或重用DMA缓冲区

2.2 四种传输模式：按数据形态选而不是按习惯选¶

2.2.1 块传输模式

  • 特点：一次性传输大块连续数据
  • 应用：硬盘读写、大文件传输
  • 优点：效率高，适合大量数据
  • 缺点：延迟较高，内存占用大

2.2.2 按需传输模式

  • 特点：根据设备请求传输小块数据
  • 应用：音频流、实时数据采集
  • 优点：低延迟，实时性好
  • 缺点：中断频繁，效率较低

2.2.3 循环缓冲模式

  • 特点：使用环形缓冲区，连续不断地传输
  • 应用：数字信号处理、音频录制
  • 优点：持续传输不中断，效率高
  • 缺点：管理复杂，需处理溢出

2.2.4 分散-聚集模式(Scatter-Gather)

  • 特点：允许在一个DMA操作中使用多个非连续内存区域
  • 应用：网络数据包处理，大型数据库I/O
  • 优点：减少内存拷贝，支持复杂数据结构
  • 缺点：需要硬件支持，设置复杂

2.3 控制器架构：寄存器组加仲裁逻辑¶

DMA控制器是实现DMA功能的核心硬件，典型架构包括：

  • 通道寄存器：存储源地址、目标地址、传输长度等
  • 状态寄存器：指示传输状态、错误条件等
  • 控制寄存器：配置传输模式、方向、中断等
  • 传输计数器：跟踪剩余传输字节数
  • 仲裁逻辑：处理总线访问请求
  • 缓冲区：临时存储传输数据

现代DMA控制器类型：

  1. 中央DMA控制器：独立芯片，服务多个设备
  2. 集成DMA控制器：集成在外设内部
  3. 系统芯片组DMA：集成在芯片组中的DMA功能
  4. 外设特定DMA：为特定设备优化的DMA引擎

3. Linux DMA子系统：一致性映射与流式映射两套API¶

Linux内核通过DMA子系统为驱动程序提供统一的API，简化DMA操作并处理硬件差异。

我一般按数据存活时间选映射方式：长期共享的结构用一致性 DMA，单次传输用流式 DMA 并在完成后立刻 unmap，别混着用。

3.1 子系统概览：统一API屏蔽硬件差异¶

3.1.1 DMA区域划分

Linux将物理内存分为不同DMA区域：

  • ZONE_DMA：用于传统ISA设备的低16MB空间
  • ZONE_DMA32：32位设备可寻址的4GB空间
  • ZONE_NORMAL：常规内存区域

3.1.2 一致性DMA和流式DMA

Linux DMA API区分两种主要的DMA映射：

  1. **一致性DMA(Coherent DMA)**：

    • 内存在整个生命周期内保持一致映射
    • CPU和设备同时可见的一致视图
    • 适用于长期存在的共享数据结构
    • 通常性能较低但更安全

  2. **流式DMA(Streaming DMA)**：

    • 为特定传输临时映射
    • 完成后立即解除映射
    • 通过显式同步保持一致性
    • 性能更高，资源消耗少

实测下来，把一堆小块传输改成 scatter-gather 一次提交，往往比调各种寄存器更立竿见影。

5.1 影响性能的关键因素¶

影响DMA传输性能的关键因素：

  1. 总线带宽：系统总线(如PCIe)的最大数据吞吐量
  2. 内存访问延迟：内存控制器响应时间
  3. 缓存一致性开销：保持CPU缓存与DMA操作一致性的成本
  4. 中断处理延迟：从DMA完成到CPU响应的时间
  5. DMA描述符设置：描述符链结构的效率
  6. 页面边界处理：跨页面传输的额外开销
  7. DMA控制器能力：硬件特性如最大突发长度

5.3 瓶颈分析：先用工具定位再谈优化¶

5.3.1 性能分析工具

  • perf：Linux性能分析工具

  • ftrace：追踪内核DMA事件

  • BCC工具集：eBPF基础的分析工具

5.3.2 常见瓶颈及解决方法

  1. PCIe带宽饱和

    • 症状：设备无法达到理论性能
    • 解决：升级PCIe链接、优化驱动多队列支持

  2. 过多中断

    • 症状：系统CPU使用率高，大部分在中断处理上
    • 解决：配置中断合并、使用NAPI模型

  3. 缓存抖动

    • 症状：性能波动大，延迟不稳定
    • 解决：正确使用缓存同步API、调整内存访问模式

  4. 内存带宽瓶颈

    • 症状：多个DMA设备同时活动时性能下降
    • 解决：负载均衡到不同内存通道、NUMA优化

6. 现代DMA：PCIe、IOMMU与RDMA把能力推向虚拟化¶

踩过的坑是，IOMMU 没先把 domain attach 和 map 跑通就去测性能，得到的数字全是错的。

6.1 PCIe DMA：MSI-X、ATS与SR-IOV¶

PCIe协议提供了高效的DMA实现机制：

  • MSI/MSI-X中断：支持多向量中断，减少中断处理开销
  • **地址转换服务(ATS)**：简化PCIe设备地址转换
  • I/O虚拟化：支持SR-IOV等技术
  • 原子操作：支持CAS等原子操作
  • TLP处理提示：优化数据包处理

PCIe 3.0/4.0/5.0带宽比较：

PCIe版本 单通道带宽 x16槽带宽
PCIe 3.0 985 MB/s 15.76 GB/s
PCIe 4.0 1969 MB/s 31.5 GB/s
PCIe 5.0 3938 MB/s 63 GB/s

6.2 IOMMU：设备用虚拟地址并做隔离¶

IOMMU(I/O内存管理单元)提供设备DMA的地址转换和保护：

  • 虚拟地址转换：设备DMA使用虚拟地址而非物理地址
  • DMA隔离：防止恶意设备访问未授权内存区域
  • 虚拟化支持：为虚拟机提供直接设备访问能力
  • 简化大内存管理：支持超过设备寻址能力的内存

6.3 RDMA：零拷贝与内核旁路¶

RDMA允许网络设备直接访问远程系统的内存而无需目标CPU干预：

  • 零拷贝：数据直接从源内存移动到目标内存
  • 内核旁路：绕过操作系统内核
  • 低延迟：减少CPU处理和协议栈开销
  • 高带宽：支持高速网络传输

主要RDMA协议：

  • InfiniBand：完整的网络协议栈和传输层
  • **RoCE(RDMA over Converged Ethernet)**：在以太网上运行RDMA
  • **iWARP(Internet Wide Area RDMA Protocol)**：在TCP之上实现RDMA

7. DMA安全与调试：IOMMU做隔离，dmatest做定位¶

我一般先开 CONFIG_DMA_API_DEBUG 和 dmatest 跑一遍，再去怀疑硬件——大部分「内存损坏」最后是映射方向写反了。

7.1 安全面：DMA攻击与四类缓解措施¶

7.1.1 DMA攻击

恶意设备可能通过DMA访问未授权内存：

  • 直接内存读取：窃取敏感数据、加密密钥
  • 代码注入：修改内核或应用代码
  • 权限提升：修改权限相关数据结构

7.1.2 缓解措施

  • 启用IOMMU：限制设备访问内存区域
  • 驱动隔离：使用驱动域分离
  • 完整性检查：验证DMA缓冲区内容
  • 固件安全：确保设备固件安全可信

7.2.2 常见DMA问题及调试

    • 症状：随机崩溃、数据损坏
    • 调试：启用DMA调试标志，使用内存屏障

8. DMA的下一步：计算存储融合与新互连标准¶

我倾向于认为 CXL 这类统一内存模型会改变 DMA 的边界，但眼下驱动里该做的同步一步都不能省。

8.1 计算存储融合(CSF)¶

存储设备集成计算能力，通过DMA直接处理数据：

  • 数据库过滤
  • 压缩/解压缩
  • 加密/解密
  • 媒体转码

8.2 DMA技术方向¶

  • 智能DMA引擎：支持复杂数据转换和处理
  • 安全增强DMA：加密DMA传输、内置完整性检查
  • 软件定义DMA：可编程DMA控制器
  • 跨设备DMA：设备间直接DMA传输
  • 存储类内存DMA：针对SCM优化的DMA路径

8.3 新型互连技术¶

  • **CXL(Compute Express Link)**：统一内存模型
  • Gen-Z：内存语义通信架构
  • **CCIX(Cache Coherent Interconnect for Accelerators)**：加速器缓存一致性

10. 落地建议：先定映射方式，再谈优化¶

我实际落地 DMA 的顺序是：先确认设备能力，把一致性映射还是流式映射定下来；再决定要不要上 scatter-gather 和中断合并；最后才用 perf、ftrace 去抠那几个百分点。真到了 IOMMU 场景，先把 domain attach 和地址映射跑通，再谈性能数字——反过来做基本都会返工。
