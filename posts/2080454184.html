42-实战：搭建Demo自动驾驶演示

从零跑通 Apollo 本地 Demo：环境怎么备、源码怎么编、模块怎么起，再到 DreamView 里看全链路。附一份验证清单和排查方向。
📅 2026-10-09· 更新于 2026-10-09 · 4177 字 · 约 11 分钟 ✍ zeek.zhao #配置#apollo

前面几篇都在讲模块怎么设计，这篇动手把它们串起来跑一遍。照着做一次很有必要——从拉代码、编译，到在 DreamView 里看着车自己沿轨迹走完，整套流程下来，前面那些抽象概念会一下子具体。本篇接着 41-性能优化与车规级部署 往下。

1. 这个 Demo 到底跑通什么¶

用 Apollo 自带的演示地图和仿真、回放数据，把各模块依次拉起来，在 DreamView 里盯住一条完整链路：感知框出现，规划轨迹生成，车辆沿轨迹行驶。前面讲的 33-车道级导航与决策、36-高速场景 那些机制，在这里能看到它们真正跑起来的样子。这是上手这套系统最直观的一个实验。

2. 先把环境备齐¶

2.1 硬件与软件底线¶

配置按下面这张表来，最低档能跑，推荐档编译会快不少。

项目 最低配置 推荐配置
CPU i7 四核 Xeon/多核 8 核以上
内存 32GB 64GB
硬盘 500GB SSD 1TB SSD
GPU GTX 1080 RTX 2080 Ti / Tesla T4
系统 Ubuntu 18.04/20.04 同左
驱动 NVIDIA Driver 460+ 470+
Docker 19.03+ + NVIDIA Docker 2.0+ 同左

2.2 安装 Docker 与驱动¶

2.3 拉代码、起容器¶

dev_start.sh 第一次跑会去拉镜像，慢是正常的，耐心等。国内网络提前配好 Docker 镜像加速器，能省不少时间。进了容器之后，编译和运行都在容器里做，宿主机只负责把 Docker 跑起来。

3. 编译，然后启动¶

可以全量编译，也可以只编演示需要的那几个模块——后者快得多。

4. 在 DreamView 里跑一遍¶

  1. 打开 DreamView：浏览器访问 http://localhost:8888
  2. 选择地图与车辆：左侧下拉选择演示地图（如 San Jose / 国内演示地图）与开发车辆配置
  3. 启动数据回放/仿真：播放预置 demo record，或使用 Sim Control 模式让车辆在仿真中行驶
  4. 设置目的地：在地图上右键选择目的地，触发 Routing
  5. 观察全链路：
观察对象 预期表现
感知框 障碍物（车辆/行人）被检测并跟踪
红绿灯 识别状态显示正确
规划轨迹 从车头延伸的平滑曲线，随环境实时更新
决策标签 跟车/变道/停车等决策文本
车辆位姿 沿轨迹平滑行驶，弯道减速

检查项 预期

感知框 障碍物检测稳定、ID 连续

DreamView 无报错弹窗，图层渲染正常

6. 卡住了先查这几处¶

现象 排查方向
容器启动失败 检查 Docker 与 NVIDIA Docker 安装、查看 docker logs
编译失败 磁盘空间不足 / 依赖缺失，重试 ./apollo.sh build
模块不启动 查看 launch 依赖顺序与模块日志
话题无数据 检查回放文件路径、驱动配置
规划无轨迹 检查地图与车辆配置是否匹配、Routing 是否下发
控制不执行 检查底盘/仿真模式配置

系统性排查方法论见 43-常见问题排查。

7. 跑通之后往哪走¶

演示跑通后，按下面几条往下深入：

  1. 修改规划参数：调整速度限制、车距参数，观察轨迹与行为变化，体会参数-行为映射
  2. 构造自定义仿真场景：设计行人横穿、前车急刹等场景，验证决策逻辑
  3. 替换感知模型：更换检测模型对比效果，实践模型部署流程
  4. 接入真实传感器数据：录制实车数据后回放调试，体验数据闭环
  5. 开发自己的组件：按 Cyber RT 组件规范写一个简单模块，理解 DAG/launch 机制

这五条里，我建议先做前两条：改参数和造场景成本最低，回报最快。

说到底，Demo 的价值是让你看懂系统怎么运转。工业界这两年的新东西——Apollo 10.0 的 ADFM 大模型和火焰图性能工具、11.0 的低速功能车场景——要吃更大的数据和算力，整套在 Demo 里跑不动。但外围工具链是共通的，性能分析和数据回放这套工作流和本篇一致，可以照着练。

注意事项与常见坑¶

  1. GPU 容器自检要在编译前做：nvidia-smi 在容器里跑不起来就别急着编译，先查驱动与镜像版本匹配。
  2. 宿主机驱动装完要重启：没重启时 nvidia-smi 都跑不起来，容器里自然没有 GPU。
  3. 预留足够磁盘空间：bazel 编译缓存 + record 数据很占空间，至少留 100GB 空闲，别和编译缓存同分区。
  4. 回放前停掉实时模块：真实传感器数据和回放数据同时进链路会让定位/感知错乱。
  5. 话题存在不等于有数据：用 cyber_monitor -c 看实际频率，别只看 cyber_channel list。
  6. 注意模块启动顺序：定位没起来规划就等不到位姿，先启依赖模块再启上层模块。
  7. DreamView 远程访问要配端口映射：访问宿主机 IP 前确认 -p 8888:8888，否则用 localhost。
  8. 全量录包很占空间：全话题录制几十秒上 GB，调试时只录关心的几个话题。
  9. proto 的 BUILD 依赖要配对：自定义组件编译时找不到 .pb.h，多半是 proto_library 依赖没声明。
  10. 验证要话题+日志双管齐下：有些错误只体现在话题停更上，光扫日志发现不了。
