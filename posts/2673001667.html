状态管理 Pinia

[!info] 本页概览
本文讲解 Pinia（Vue 3 官方状态管理）：store 定义（Setup 与 Options 风格）、state/getters/actions、组合式 store、持久化与模块化，替代 Vuex 的现代方案。

核心概念

  • Pinia：轻量、类型友好、支持组合式 API，官方推荐替代 Vuex。
  • Store：集中管理共享状态（用户、购物车、主题）。
  • 三个核心：state（数据）、getters（派生）、actions（方法，可异步）。
  • Setup 风格 store 更灵活（像写组合函数）。

常见坑

  1. 在 setup 外使用 store：需先创建 pinia 实例并传入（useStore(pinia)），如路由守卫中。
  2. 解构 store 失去响应性：const { name } = store 非响应式；用 storeToRefs(store) 解构 state/getters。
  3. actions 中 this：Options 风格用 this 访问；箭头函数会丢 this。
  4. 持久化覆盖更新：初始 state 与本地数据合并策略注意版本迁移。
  5. 多个 store 相互调用：在 action 内 useOtherStore() 直接使用。
  6. 忘记 pinia 实例：未 app.use(pinia) 报 “no active Pinia”。

最佳实践

  • 新项目直接用 Pinia，不必学 Vuex。
  • 全局性、跨组件共享状态才入 store；局部状态留组件内。
  • Setup 风格 + TypeScript 类型推导更佳（见 19-TypeScript集成）。
  • getters 保持纯函数，action 承担副作用与异步。
  • 敏感数据（token）持久化用安全存储并设过期。
