iot-安全完全指南

文章摘要

随着物联网(IoT)设备的爆炸性增长，安全问题已成为制约行业发展的关键因素。本文系统性地介绍了IoT安全架构、威胁模型、防护策略及最佳实践，从设备层、通信层、平台层到应用层全方位剖析安全挑战与解决方案。通过理解物联网特有的安全风险和防护机制，帮助开发者、架构师和安全专业人员构建更安全可靠的IoT生态系统。

1. IoT安全基础与挑战

1.1 物联网安全特性与挑战

物联网安全面临着传统网络安全所没有的独特挑战：

    部署环境

      多种设备类型
      多种通信协议

      标准不统一

IoT安全与传统IT安全的主要区别：

特性 传统IT安全 IoT安全
计算资源 较充足 严重受限
更新机制 成熟、自动化 困难、不统一

{% note warning %}
IoT安全核心挑战：

  1. 资源受限设备难以实施复杂安全机制
  2. 大规模部署使传统安全管理方法难以适用
  3. 设备长生命周期与安全算法的有效期不匹配
  4. 物理接触可能性增加了硬件级攻击风险
  5. 协议多样性导致安全解决方案难以标准化
    {% endnote %}

安全架构设计原则：

  • 深度防御：在多个层次实施安全控制
  • 最小权限：每个组件仅具备完成其功能所需的最小权限
  • 安全默认设置：默认配置应是最安全的选项

  • 开放设计：不依赖于保密的设计细节
  • 全面保护：识别并保护所有攻击面

硬件安全机制

安全机制 描述 作用 适用场景
安全启动 验证固件完整性和真实性的过程 防止恶意固件加载 所有IoT设备
硬件安全模块(HSM) 专用安全硬件，管理密码学操作和密钥 保护加密密钥，执行密码学运算 对安全要求高的系统
可信平台模块(TPM) 存储加密密钥和执行加密操作的硬件 安全启动，密钥存储，远程认证 工业IoT和关键基础设施
可信执行环境(TEE) 隔离的执行环境，独立于主操作系统 安全处理敏感操作和数据 高安全性要求的设备
eFuses/OTP 一次性可编程存储元件 存储不可更改信息，如唯一ID 设备身份认证
SRAM PUF 基于SRAM物理特性的指纹 生成设备唯一密钥，无需存储 低成本安全设备识别
防篡改技术 物理防护措施，防止未授权访问 检测并响应物理入侵尝试 部署在不安全环境的设备

{% note warning %}
常见硬件安全风险：

  1. 旁路通信接口：未禁用的调试端口(UART, JTAG, SWD)可能被用于获取固件或绕过安全机制
  2. 测试点暴露：电路板上的测试点可能提供对内部总线的访问
  3. 非易失性存储未加密：存储的敏感数据或固件如未加密，可被直接读取
  4. 冷启动攻击：RAM中的数据在断电后短时间内仍可读取
  5. 侧信道攻击：通过功耗分析、电磁分析或时序分析泄露密钥信息
    {% endnote %}

固件安全最佳实践：

{% tabs 固件安全最佳实践 %}

  1. 安全开发生命周期

    • 实施威胁建模和风险评估
    • 遵循安全编码标准（CERT C, MISRA C）
    • 定期安全代码审查

  2. 内存安全

    • 使用安全操作系统或安全内核
    • 实施内存保护（栈保护、ASLR）
    • 防止缓冲区溢出和格式化字符串漏洞

  3. 编译安全

    • 启用编译器保护（-fstack-protector, FORTIFY_SOURCE）
    • 静态代码分析
    • 审查依赖和第三方库

  1. 固件加密与签名

    • 使用强加密算法保护固件
    • 实施代码签名，确保只加载经授权的固件
    • 妥善管理签名密钥

  2. 安全启动

    • 实施不可破坏的信任根
    • 验证每个启动阶段的完整性和真实性
    • 配置硬件防篡改机制

  3. 接口安全

    • 禁用生产环境中的调试接口
    • 安全配置UART、JTAG和其他测试接口
    • 限制JTAG/SWD访问，使用密码保护

  1. 运行时保护

    • 实施安全审计和日志记录
    • 运行时完整性检查
    • 异常行为监测

  2. 隔离与沙箱

    • 进程隔离和权限分离
    • 容器化敏感操作
    • 可信执行环境的使用

  3. 安全存储

    • 敏感数据加密存储
    • 安全地存储加密密钥（优先使用硬件安全存储）
    • 实现安全擦除功能

  1. 安全更新机制

    • 加密和签名更新包
    • 验证更新前后的完整性
    • 更新过程中断电保护

  2. OTA更新安全

    • 安全通道传输固件
    • 更新前的设备认证
    • 增量更新降低带宽和失败风险

  3. 回滚保护与恢复

    • 防止降级攻击
    • 版本控制和管理
    • 提供故障安全恢复机制

{% note info %}
设备身份最佳实践:

  1. 基于硬件的唯一身份：利用硬件安全模块或不可复制的物理特性(PUF)
  2. 设备证书管理：实施完整的证书生命周期管理，包括轮换和吊销
  3. 强设备认证：使用多因素认证，将物理特性与逻辑认证相结合
  4. 动态身份管理：定期更新凭证，避免静态身份
  5. 零信任方法：持续验证设备身份，不假定网络内部安全
  6. 兼顾效率与安全：为不同类型设备选择适当的认证方案
  7. 优雅降级：为认证失败场景设计安全的降级策略
    {% endnote %}

深度防御原则是构建多层防御机制，确保单一防御层被突破不会导致整个系统被攻陷。

实施策略:

  • 在物理、网络、应用和数据层同时实施安全控制
  • 结合预防性、检测性和响应性控制
  • 不同安全层使用不同技术，避免共性缺陷
  • 确保安全控制相互补充而非重复

IoT场景应用:

  • 物理层：设备物理防护、防篡改设计
  • 硬件层：安全启动、可信执行环境
  • 通信层：加密、认证、完整性检查
  • 网络层：分段、过滤、监控
  • 应用层：输入验证、会话管理、授权控制
  • 数据层：加密存储、访问控制、数据完整性

最小权限原则要求每个组件、流程或用户只被授予完成其功能所必需的最小权限。

实施策略:

  • 详细定义每个组件所需的最小权限集
  • 定期审查和调整权限，移除不再需要的权限
  • 使用特权访问管理(PAM)系统控制特权操作
  • 实施精细的访问控制策略

IoT场景应用:

  • 为设备创建功能专用账户而非管理员账户
  • 微隔离设备间通信，只允许必要流量
  • 限制云服务API仅访问所需功能
  • 使用专用证书/令牌限制访问特定资源
  • 按设备类型和功能分配不同权限级别

零信任架构原则摒弃了传统的”网络内部可信”思想，要求验证每个访问请求，无论来源何处。

核心概念:

  • “永不信任，始终验证”
  • 微分段网络
  • 持续的认证和授权
  • 最小权限访问
  • 全面可见性和监控

IoT实施方法:

  • 持续验证每个设备的身份和健康状态
  • 为每个设备和服务建立强身份认证
  • 实施基于上下文的访问控制(设备状态、位置、行为)
  • 加密所有通信，无论内部还是外部
  • 持续监控所有设备和通信的异常行为
  • 实施自适应响应机制，自动隔离可疑设备

安全默认配置原则确保系统在默认状态下具备最高安全性，无需用户额外操作。

实施策略:

  • 安全功能默认启用(如加密通信)
  • 高风险功能默认禁用(如远程管理接口)
  • 默认禁止所有不必要服务和端口
  • 出厂默认凭证唯一且强健
  • 默认安装最小功能集合

IoT场景应用:

  • 设备出厂时通信加密默认开启
  • 初始状态下仅启用必要服务和端口
  • 每台设备出厂预置唯一强密码
  • 默认启用防火墙和访问控制
  • 安全更新默认自动检查和应用
  • 敏感服务(如SSH)默认禁用，需显式开启

安全引导实施的关键要素：

  1. 硬件信任锚：

  2. 密钥管理：

    • 安全密钥层次结构
    • 使用非对称加密(如ECDSA)进行代码签名
    • 安全的密钥存储和保护

  3. 固件签名与验证：

    • 对每个组件使用强密码签名
    • 链式信任模型
    • 完整性校验(如安全哈希)

  4. 故障处理机制：

    • 定义验证失败时的策略(拒绝启动、恢复模式等)
    • 防回滚保护
    • 安全日志记录

  • 大规模补丁部署困难且风险高

  • 使用设备组管理方法
  • 建立多个响应团队处理大规模事件

挑战：

  • 许多设备缺乏远程更新能力
  • 更新失败可能导致设备无法使用
  • 带宽限制使大规模更新缓慢

欧盟《通用数据保护条例》对IoT系统的核心要求：

关键原则：

  • 数据最小化：只收集必要数据
  • 目的限制：明确数据使用目的
  • 存储限制：限定数据保留期限

  • 知情权：了解收集的个人数据
  • 访问权：获取已收集的个人数据
  • 删除权：请求删除个人数据
  • 选择退出权：拒绝个人数据销售/共享
  • 非歧视权：行使权利不受歧视

IoT应用特点：

  • 需要提供隐私政策
  • 支持消费者数据权利请求
  • 提供不出售/不共享数据选项
  • 对敏感数据提供额外保护
  • 确保服务提供商合规

  • 更注重消费者控制权
  • 关注数据销售行为
  • 有经济阈值适用条件

中国《个人信息保护法》与《数据安全法》：

核心要求：

  • 合法收集：明确告知并获得同意
  • 目的明确：特定、明确、合理的使用目的
  • 最少必要：最小范围内收集使用
  • 安全保障：采取必要措施保护信息
  • 跨境限制：个人信息出境需评估和同意

  • 禁止过度收集行为

  2. 深度防御策略

    • 多层次安全控制，避免单点防御
    • 不同层次使用不同安全机制
    • 物理、网络、应用多层面保护
    • 即使外围防御被突破也能保持核心安全

  3. 最小权限原则

    • 组件只被授予完成任务所需的最低权限
    • 功能分离与边界定义明确
    • 基于角色的细粒度访问控制
    • 定期权限审查与优化

  4. 失效安全设计

    • 系统故障时默认至安全状态
    • 错误处理不暴露敏感信息
    • 异常检测与响应机制
    • 优雅降级策略保持核心安全功能

  5. 隐私设计原则

    • 默认隐私保护配置
    • 数据最小化和去标识化
    • 用户可控的隐私选项
    • 透明的数据收集和使用政策
      {% endnote %}
