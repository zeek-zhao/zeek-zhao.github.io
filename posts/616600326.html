06-Layer机制与自定义层

层（Layer）的组织方式、优先级与自定义层创建
📅 2026-10-24· 更新于 2026-10-24 ✍ zeek.zhao #技能#yocto
ℹ️本节目标
理解层机制的原理，学会创建与使用自定义 Layer。

1. Layer 是什么¶

Layer 是一组相关配方、配置与类的集合，用于组织元数据。Yocto 构建由多个 Layer 叠加而成，每个 Layer 负责特定领域，如 BSP、发行版、应用功能等。

2. 常用官方层¶

层 用途
meta OpenEmbedded Core 基础层
meta-poky 参考发行版配置
meta-yocto-bsp 参考板级支持
meta-openembedded 社区扩展软件集
meta-raspberrypi Raspberry Pi 支持

5. 优先级机制¶

层优先级决定同名配方的选用顺序，优先级高的层覆盖优先级低的层。合理设置优先级可避免配方冲突。

7. 最佳实践¶

每个产品应创建独立应用层，遵循 OpenEmbedded 命名规范，保持层职责单一，减少层间耦合。

8. 层测试与发布¶

创建层后可通过 bitbake-layers 工具验证层配置正确，使用 oe-selftest 测试层内配方行为。发布层时遵循 OpenEmbedded 规范：包含 README、COPYING、层配置与配方目录，必要时提交到 Layer Index 供社区使用。良好的层结构便于团队协作与版本管理，是 Yocto 工程化的基石。

9. 常见层问题¶

常见问题包括：层未加入 bblayers.conf 导致配方找不到；优先级设置不当导致配方覆盖异常；BBFILES 模式错误导致配方未被解析。排查时使用 bitbake-layers show-recipes 与 bitbake -e 确认层与配方状态。保持层职责单一与命名规范，可显著减少此类问题。

10. 层结构模板¶

标准层结构包含：conf/layer.conf 定义层配置与优先级；recipes-* 目录按类别存放配方；文件目录存放补丁与数据；README 与 COPYING 说明用途与许可。创建层使用 bitbake-layers create-layer 自动生成骨架。遵循标准结构便于工具识别与团队协作，也便于发布到社区 Layer Index 供他人使用。

11. 本节小结¶

Layer 机制支撑 Yocto 的分层协作。掌握层结构与覆盖规则后，可参考后续篇目实现产品级定制与维护。
