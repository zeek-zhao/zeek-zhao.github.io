19-JSON与XML处理

发表于2026-10-25|groovy
|浏览量:

[!info] 本节目标
Groovy 内置 JSON 与 XML 处理模块，学习数据交换格式处理。

1. JSON 解析

JsonSlurper 解析 JSON 字符串或流为 Groovy 数据结构，Map 与 List 直接使用点号访问。JsonOutput 序列化对象为 JSON 文本。

解析配置、接口响应、日志数据是日常高频场景，slurper 的惰性流模式适合大 JSON。

2. JSON 生成与美化

JsonOutput.toJson 序列化任意对象，prettyPrint 美化输出。自定义序列化通过 JsonGenerator 或注解控制字段。

日期、枚举等特殊类型的序列化规则要提前验证，避免格式不符。

3. XML 解析

XmlSlurper 提供惰性解析，适合大文档与流式处理；XmlParser 构建完整对象模型，方便随机访问。二者 API 相似。

GPath 表达式按路径访问 XML 节点，类似 XPath 的 Groovy 风格访问。

4. XML 生成

MarkupBuilder 以代码方式构建 XML，嵌套与属性语法直观。StreamingMarkupBuilder 用于流式输出。

XML 生成适合配置导出、接口报文构造等场景。

5. 数据转换应用

JSON 与 XML 互转：解析后再序列化；对象与数据结构互转：map 转对象、对象转 map。数据管道中常用。

从 API 拉取 JSON、转换为领域对象、再序列化返回是典型服务端流程。

6. 性能与安全

大 JSON 用流式解析避免内存峰值；XML 解析注意 XXE 注入，禁用外部实体；字段缺失用安全访问与默认值兜底。

数据结构复杂时先小样本验证解析结果，再接入生产数据。

7. 数据交换实战

对接第三方 API 时，用 JsonSlurper 解析响应、提取业务字段、转换为领域对象，字段缺失用安全导航与默认值兜底。

XML 配置导出用 MarkupBuilder 生成结构化文档，节点与属性表达直观，生成的报文可直接与旧系统交互。

数据量大时优先流式解析，边读边处理避免内存峰值；复杂转换流程先在小样本上验证再接入生产。

延伸阅读与实践

JSON 与 XML 的选择取决于业务生态：前端与 API 场景 JSON 更简洁，文档交换与遗留系统 XML 更严谨，按场景灵活切换。

数据模型复杂时先定义领域对象再序列化，避免散落的 Map 与 List 让数据结构失控。
