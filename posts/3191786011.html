rclpy 编程（Python）

[!info] 本节目标
掌握 rclpy Python 客户端库的节点编写、发布订阅、服务、动作、参数与定时器用法。

1. rclpy 概览

rclpy 是 ROS2 的 Python 客户端库，适合快速原型、逻辑型节点、胶水代码与工具脚本。

[!note] 包结构
ament_python 包：setup.py 声明入口点，包目录放 .py 源码；详见 04-工作空间与colcon构建。

2. 入口点配置

[!tip] 入口点
ros2 run py_demo talker 依赖 console_scripts 声明；修改入口点后需重新 colcon build 才生效。

3. 发布者与定时器

[!warning] 入口规范
main() 必须调用 rclpy.init(args=args)，结尾 rclpy.shutdown()；控制台脚本入口为 main。

4. 订阅者与回调

[!tip] 回调注意
回调在 Executor 线程执行；默认 MutuallyExclusive 回调组会串行，耗时任务会阻塞其他回调（见 14-执行器与回调组）。

5. 服务与动作

[!note] 完整示例
服务与动作的完整代码见 07-服务通信 与 08-动作通信。

6. 参数与 QoS

[!tip] QoS 快速写法
传感器订阅常用 qos_profile_sensor_data 预置常量；详见 33-实时性与QoS策略。

7. 多线程执行

[!warning] 线程安全
MultiThreadedExecutor 下同一回调组的回调仍串行；不同回调组可并行，注意共享状态加锁。

8. 常见问题

问题 排查
ros2 run 找不到命令 入口点未声明/未重新 build
Python 改代码不生效 未用 --symlink-install 构建
回调不触发 未 spin、QoS 不匹配
内存增长 发布队列/日志过多，检查 rate

[!note] 延伸
生命周期节点见 12-生命周期节点；launch Python 见 19-launch系统；日志与调试见 20-日志与调试工具。

8. rclpy 工程实践要点

Python 节点开发效率高，适合原型验证与业务编排，但要注意 GIL 与回调阻塞问题：耗时计算会阻塞同一执行器内的其他回调，应使用多线程执行器或把重计算放到独立线程。Python 消息与 C++ 消息完全兼容，接口定义见 13-自定义消息接口。脚本入口统一使用 main 函数并在 setup.py 声明入口点，包结构保持清晰。日志与参数 API 与 C++ 对应，切换语言成本低。性能敏感时可将核心算法下沉为 C++ 扩展。

[!note] 建议
同一工程可混合使用 C++ 与 Python 节点，按模块性能需求选择；性能优化细节见 35-性能优化与Benchmark。
