项目创建与 manifest

[!abstract] 组织代码仓库
Gerrit 用项目管理 Git 仓库；项目间通过 All-Projects 继承权限（05-权限与组）；多仓库可用 manifest 项目统一编排。

1. 创建项目

[!note] 命名规范
建议 team/project 层级：platform/web-frontend、ops/deploy-scripts。命名即命名空间，权限可按前缀匹配。

2. 项目基本配置

常用项目参数：

参数 说明
submit-type 合并方式（三种合并）
use-contributor-agreements 是否要求贡献者协议
require-change-id 是否强制 Change-Id
require-signed-off-by 是否强制 Signed-off-by

[!tip] manifest 收益
一个 repo sync 拉齐整套代码；版本管理集中在 manifest 分支（tag 发布基线）。manifest 自身也放 Gerrit 走评审。

4. 初始化本地仓库

[!warning] 注意

  • 项目创建即确定权限基线：Owner 组给最小集，后续在 05-权限与组 细化；
  • require-change-id 建议开启：Change-Id 缺失会导致每次 push 都生成新 Change；
  • 目录级仓库规划提前做，后期移动项目会影响克隆地址。
