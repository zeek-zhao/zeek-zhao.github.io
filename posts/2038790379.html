14-元编程MOP

发表于2026-10-25|groovy
|浏览量:

[!info] 本节目标
MOP 是 Groovy 动态能力的核心，学习元类与动态方法的运行机制。

1. 元对象协议

Groovy 的对象模型基于 MetaClass 扩展：每个对象关联元类，方法调用先经过元类解析。MOP 是运行时元编程的基础设施。

元类可以动态添加方法、拦截调用、修改属性行为，实现运行时能力扩展。

2. metaClass 与 ExpandoMetaClass

对象的 metaClass 属性可以添加方法、属性与静态方法。ExpandoMetaClass 提供最常用的动态扩展 API，直接在元类上定义闭包方法。

例如为第三方类添加领域方法，不改动原始类即可扩展行为。

3. 方法解析链

Groovy 方法调用解析顺序：具体方法、属性访问、methodMissing、GroovyObject 钩子、异常。理解解析链能定位动态调用问题。

propertyMissing 处理不存在的属性访问，methodMissing 处理不存在的方法调用，是动态拦截的两大入口。

4. 动态代理与拦截

Groovy 可以通过元编程实现 AOP 风格拦截：方法调用前后注入日志、权限、缓存等横切逻辑，无需修改业务代码。

Proxy 与 InvocationHandler 结合实现动态代理，与 Java 动态代理无缝衔接。

5. MOP 与 DSL

DSL 设计中，methodMissing 常被用于接收未定义的方法调用并转换为领域操作，实现声明式配置与流式 API。

委托策略与 MOP 结合，可以构建表达力极强的领域语言。

6. 元编程最佳实践

元编程强大但需克制：优先具体方法，动态扩展用于边界场景；动态方法要配测试覆盖；避免在热路径过度使用反射式调用。

团队内明确元编程使用规范，防止代码难以追踪与维护。

7. MOP 实战场景

为第三方库对象动态添加统计与监控方法，不改动原始类即可接入公司监控体系，这是运行时扩展的典型落地。

动态代理结合方法拦截可以实现权限校验、参数校验与日志记录，横切逻辑从业务代码中剥离，业务方法保持纯粹。

使用 ExpandoMetaClass 扩展全局对象时要限定作用域，避免跨模块污染，团队约定扩展方法与命名前缀。
