测试

[!info] 本页概览
测试是代码质量的保障。本文讲解 pytest 的用法：断言、fixture、参数化、mock，以及测试组织与覆盖率，建立可靠的测试习惯。

核心概念

  • 单元测试：验证单一函数/类行为。
  • fixture：测试前置准备与清理。
  • mock：替换外部依赖（网络、时间、数据库）。
  • pytest：主流框架，断言简洁（assert），自动发现 test_*.py。

测试组织

常见坑

  1. 测试依赖执行顺序/共享状态：测试必须可独立运行，fixture 提供隔离。
  2. mock 打错路径：应 patch 使用处的模块路径（requests.get 在调用模块里是 "requests.get"，但若 from requests import get 则打 "myapp.xxx.get"）。
  3. 断言太弱：assert result is not None 不如断言具体值。
  4. 只测 happy path：边界（0、空、None、超大）与异常路径都该测。
  5. 测试读写真实网络/数据库：慢且不稳定，用 mock 或本地容器。
  6. 忘记 conftest 作用域：顶层 conftest 对整个 tests 生效，避免污染。

最佳实践

  • 每修一个 bug 先写失败测试（TDD 习惯）。
  • 用覆盖率工具找盲区，但不要为 100% 而测（关键逻辑优先）。
  • CI 中跑 pytest -q 并启用 --strict-markers。
  • fixture 返回工厂函数以按需构造数据。
  • 集成测试用真实依赖（测试数据库），单测用 mock 隔离。
