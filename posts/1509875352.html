权限与认证

[!info] 本节目标
掌握 OpenGrok 的认证接入与项目级访问控制，实现”谁能搜什么”的精细化管控。

认证方式概览

OpenGrok 自身不实现用户体系，通过容器/网关认证组件集成：

方案 特点 适用
反向代理 Basic Auth 简单，网关统一认证 小团队
LDAP / SSO（Keycloak） 集中账号，OIDC/SAML 企业
容器认证插件 与 Jenkins/CI 体系一致 开发平台

反向代理认证示例（Nginx + Basic Auth）

项目级访问控制

OpenGrok 支持按项目授权（allow/deny 规则），依赖认证头注入的用户：

或通过配置文件维护 ACL 映射，将 LDAP 组映射到项目可见性。

与 Keycloak 集成（OIDC）

OpenGrok 部署在 Keycloak 之后：

用户在 Keycloak 完成登录后，由 OpenGrok 读取用户组做项目授权。

安全建议

  • 生产环境强制 HTTPS（TLS 终止在反向代理）
  • 关闭匿名访问：OPENGROK_ALLOW_ANON=false 或代理层强制认证
  • 最小化暴露：仅内网或 VPN 可达
  • 管理接口（/api）单独限制 IP

配置清单

项 配置 说明
认证开关 OPENGROK_AUTH none/basic/oidc
匿名访问 OPENGROK_ALLOW_ANON false 关闭
用户头 X-Forwarded-User 代理注入
组映射 管理界面 项目可见性
TLS 反向代理 加密传输

[!warning] 提醒
认证只控制”访问 OpenGrok 界面”，不改变索引本身；敏感代码建议同时启用仓库级权限（如 GitLab 权限）双重收敛。
