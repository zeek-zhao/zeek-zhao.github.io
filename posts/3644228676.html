测试

[!info] 本页概览
本文讲解 Vue 前端测试体系：Vitest 单元测试、组件挂载测试（@vue/test-utils）、Mock 与异步测试、E2E 测试概览，构建可靠代码防线。

核心概念

  • Vitest：Vite 原生测试框架，快、TS 友好。
  • @vue/test-utils：挂载组件、断言 DOM 与交互。
  • 单元测试：测试纯逻辑/函数/组件渲染；E2E：Playwright 端到端。
  • 测试金字塔：大量单元 → 适量组件 → 少量 E2E。

常见坑

  1. 挂载组件报 window 未定义：测试环境用 jsdom（vite.config test.environment）。
  2. 异步更新未 flush：trigger 后需 await（或 flushPromises）再断言。
  3. Mock 路径写错：vi.mock 路径与 import 路径一致（相对模块）。
  4. 定时器测试：用 vi.useFakeTimers() + advanceTimersByTime，测完恢复。
  5. E2E 选择器脆弱：用 data-test 属性而非文本/类名。
  6. 全局组件/插件未注册：mount 时需 global.plugins/global.stubs 配置。

最佳实践

  • 核心业务逻辑（composable、store、工具函数）优先单元测试。
  • 组件测试聚焦”用户可见行为”（渲染、点击、输入）。
  • CI 中跑 vitest run 与 lint，E2E 可放部署前冒烟。
  • 用 data-test 标记关键交互节点。
  • 测试覆盖”关键路径”，不追求 100% 行覆盖（成本收益权衡）。
