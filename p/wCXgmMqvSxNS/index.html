1. Nexus Repository Manager 简介

Nexus Repository Manager 是由 Sonatype 开发的一款功能强大的仓库管理器。它是一个多格式制品仓库，支持管理各种类型的软件构建制品，包括 Maven、npm、Docker、NuGet、PyPI 等。Nexus 3 是其完全重写的版本，基于 Eclipse 的 OSGi 框架和 OrientDB 图数据库构建，提供了更好的性能和扩展性。

2.2 初始设置

2.2.1 首次登录与管理员设置

  1. 访问 http://localhost:8081 (默认端口)

  2. 首次登录需要使用初始管理员密码

2.2.2 系统配置

初始安装后，需要进行一些基本的系统配置：

  1. 设置 Blob Store：Blob Store 是 Nexus 存储制品的物理位置

    • 导航：管理 > Blob Stores > Create Blob Store
    • 选择类型：File、S3 等
    • 配置名称和路径

  2. 配置邮件服务器（可选）

    • 导航：管理 > System > Email Server
    • 设置 SMTP 服务器、端口、身份验证信息等

  3. 配置 HTTPS（推荐）

    • 导航：管理 > Security > SSL Certificates
    • 导入证书或配置自签名证书

  1. 导航：管理 > Security > Users > Create user
  2. 填写用户信息：
    • ID: username
    • First name, Last name
    • Email
    • Password
    • 选择角色：例如 nx-admin 或自定义角色

3.1.2 创建角色

自定义角色可以根据具体需求分配特定的权限：

  1. 导航：管理 > Security > Roles > Create role
  2. 选择 “Nexus role”
  3. 填写角色信息：
    • Role ID: custom-developer
    • Role Name: Developer Role
    • Role Description: Role for developers
  4. 分配所需权限，例如：
    • nx-repository-view-maven2-maven-releases-read
    • nx-repository-view-maven2-maven-releases-browse
    • nx-repository-view-maven2-maven-public-*

3.2.1 LDAP 集成配置

配置 LDAP 身份验证：

  1. 导航：管理 > Security > LDAP
  2. 点击 “Create LDAP connection”
  3. 填写 LDAP 服务器信息：
    • Name: Company LDAP
    • Protocol: ldap 或 ldaps
    • Hostname: ldap.company.com
    • Port: 389 (默认) 或 636 (LDAPS)
  4. 配置连接凭证和用户映射
    • LDAP 服务器的管理员账号
    • 用户和组的基本 DN
    • 用户 ID 字段 (通常是 uid 或 sAMAccountName)
  5. 测试连接并保存

Nexus 3 安全加固关键点：

  1. 启用 HTTPS：

    • 使用有效的 SSL 证书
    • 配置安全的 TLS 版本和加密套件
    • 考虑禁用 HTTP，仅使用 HTTPS

  2. 实施最小权限原则：

    • 限制匿名访问
    • 为用户分配具体所需权限而非管理员权限
    • 为不同团队/项目创建专用角色

  3. 加强身份验证：

    • 强制使用强密码
    • 实现双因素认证
    • 使用企业身份提供商进行集中认证

  4. 网络安全：

    • 使用反向代理限制直接访问
    • 配置 IP 白名单
    • 部署在私有网络中

6.1.1 清理策略

Nexus 可以通过清理策略自动清理旧的和未使用的组件：

  1. 导航：管理 > Repository > Cleanup Policies

  2. 点击 “Create Cleanup Policy”

  3. 设置清理条件：

    • Format: Maven, npm, Docker 等
    • Name: policy-name
    • Notes: 描述信息
    • Criteria:
      • Last downloaded: 比如 “older than 60 days”
      • Last updated: 比如 “older than 30 days”
      • Release type: Release, Snapshot, Mixed
      • Asset name pattern: 比如 .*-SNAPSHOT\.jar

  4. 将策略应用到仓库：

    • 导航：管理 > Repositories
    • 编辑目标仓库
    • 在 “Storage” 部分设置清理策略

6.1.2 任务调度

通过任务调度，可以自动执行仓库维护操作：

  1. 导航：管理 > System > Tasks

  2. 点击 “Create task”

  3. 选择任务类型：

    • Admin - Compact blob store: 优化 blob 存储空间
    • Admin - Remove unused components: 移除未使用的组件
    • Repository - Delete unused snapshots: 删除过期的快照版本
    • Repository - Rebuild Maven metadata: 重建 Maven 元数据
    • Repository - Purge unused: 清理未使用的缓存
    • Repository - Execute cleanup policy: 执行清理策略

  4. 配置任务调度：

    • Manual: 手动触发
    • Once: 一次性执行
    • Daily: 每天执行
    • Weekly: 每周执行
    • Monthly: 每月执行
    • Advanced (Cron): 自定义 Cron 表达式

  • 将高访问频率的仓库放在性能更好的存储上
  • 考虑存储成本和性能的平衡

7.3.1 常见性能问题诊断

  1. JVM 内存问题：

    • 症状：垃圾收集频繁、OutOfMemoryError
    • 分析：使用 jstat, jmap, VisualVM 分析内存使用
    • 解决：调整 JVM 参数，增加堆内存

  2. 高 CPU 使用率：

    • 症状：CPU 使用率高，响应缓慢
    • 分析：使用 top, VisualVM 查看线程使用情况
    • 解决：优化查询，调整并发设置

  3. 磁盘 I/O 瓶颈：

    • 症状：响应缓慢，特别是上传/下载大文件时
    • 分析：使用 iostat 监控磁盘活动
    • 解决：使用 SSD，优化存储配置
