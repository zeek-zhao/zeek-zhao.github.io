工作空间与 colcon 构建

[!info] 本节目标
掌握 ROS2 工作空间结构、colcon 构建流程、依赖安装与常见构建命令。

1. 工作空间结构

ROS2 工作空间（Workspace）是存放多个功能包（Package）的目录，典型结构如下：

[!warning] 工作目录
手动创建的顶层目录名建议用 src；build、install、log 由 colcon 自动生成，不要手动编辑。

2. colcon 简介

colcon 是 ROS2 官方构建工具（替代 ROS1 的 catkin）。它支持并行构建、增量编译、独立安装，并能处理包之间的依赖顺序。

命令 作用
colcon build 全量构建
colcon build --packages-select my_pkg 只构建指定包
colcon build --symlink-install Python 节点符号链接，免重复编译
colcon build --cmake-args -DCMAKE_BUILD_TYPE=Release 传 CMake 参数
colcon test 运行测试
colcon list 列出工作空间所有包

3. 创建并构建第一个包

[!tip] symlink-install
Python 包建议加 --symlink-install，改代码无需重新构建；C++ 包修改源码后必须重新 colcon build --packages-select。

package.xml 关键字段

[!note] format 3
ROS2 使用 package.xml format 3，依赖统一用 <depend>，不再区分 build/exec 依赖。

5. 依赖管理

[!warning] rosdep 网络问题
国内网络可配置 rosdepc 镜像（pip install rosdepc && rosdepc init && rosdepc update）。

6. 环境叠加（Overlay）

ROS2 支持底层（underlay）+ 叠加层（overlay）：先 source 基础发行版，再 source 自己的工作空间。

[!tip] 多空间叠加
可按依赖分层：底层装稳定包，上层装自己开发的包；多个 overlay 依次 source 即可。

7. 构建常见问题

问题 排查
package not found 未 source install/setup.bash 或包未构建
依赖缺失 rosdep install 后再构建
Python 改代码不生效 未加 --symlink-install
CMake 错误 看 log/latest_build 日志
缓存冲突 rm -rf build install log && colcon build

[!note] 延伸
创建自定义消息/服务/动作接口见 13-自定义消息接口；launch 文件组织见 19-launch系统；调试构建问题见 36-常见问题排查。

8. 工作空间管理技巧

建议按项目隔离工作空间，一个项目一个 src 目录，避免多个项目共享同一空间导致构建与依赖混乱。--symlink-install 在开发期能免去重复编译，但发布时应改为常规安装保证可移植性。构建失败时优先检查依赖声明：Python 包检查 setup.py 与 package.xml，C++ 包检查 CMakeLists.txt 的 find_package，rosdep 安装依赖后再构建。colcon 的输出目录（build/install/log）可加入版本控制忽略清单，防止误提交。

[!note] 建议
构建前先 source 系统 ROS2 环境，否则 ament_package 等基础命令不可用；持续集成场景参考 38-产品化与部署实践。
