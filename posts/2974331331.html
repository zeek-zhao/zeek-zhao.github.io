09-传感器接入（相机激光雷达毫米波）

传感器是自动驾驶的"眼睛与耳朵"，车载计算平台是"大脑"。本篇融合硬件概述与计算平台内容，讲解相机、激光雷达、毫米波雷达、超声波与 GPS/IMU 的选型、接入流程、时间同步与数据验证。
📅 2026-10-25· 更新于 2026-10-25 ✍ zeek.zhao #系统#apollo
ℹ️本节目标
掌握 Apollo 传感器体系（相机/激光雷达/毫米波/超声波/GPS-IMU）的工作原理与选型要点、车载计算平台（工控机）的配置要求，以及传感器从硬件连接到数据上线的完整接入流程。

1. 硬件系统全景¶

自动驾驶硬件可类比生命体：传感器是感官，计算平台是大脑，线控底盘是四肢（线控部分见 10-CAN总线与车辆控制接口）。

传感器分两类：环境感知（障碍物、车道线、信号灯）与状态感知（位置、速度、姿态）。本篇讲前者与计算平台；定位传感器细节见 08-定位模块。

2. 主要传感器原理与选型¶

2.1 激光雷达（LiDAR）¶

TOF 原理测距，多线束旋转扫描生成三维点云，是高精地图构建与点云定位的核心传感器。

参数 说明 典型值
线数 激光束数量，决定分辨率 16-128 线
水平视场角 旋转式 360°；固态约 50-120° —
探测距离 标称距离随点密度衰减 100-300 m
反射率要求 低反射率目标可能漏检 ≥10%

选型考量：旋转式视场大但体积大、有机械故障点；固态可靠性高、成本低但视场受限。注意激光雷达在雾霾天表现较差（颗粒尺寸与波长相近）。

2.2 相机¶

光学成像，信息最丰富、成本最低，负责分类识别（车辆/行人/标志/信号灯）。按焦距分长焦（看远处红绿灯）与短焦（环视近距目标）。

参数 典型值
分辨率 1920×1080 及以上
帧率 30-60 fps
动态范围 60-120 dB（应对逆光隧道口）
水平视场角 50-120°

局限：光照敏感，单目无法直接测距（需双目视差或算法估计）。

2.3 毫米波雷达¶

电磁波测距 + 多普勒测速，全天候工作，是速度测量的权威来源。

类型 探测距离 视场角 用途
短距 SRR 0.2-30 m ±60° 盲区监测、泊车
长距 LRR 10-250 m ±10° 自适应巡航、前向预警

局限：角分辨率低（1-3°），难以精确分类目标；垂直探测能力有限。

2.4 超声波雷达¶

0.2-5 m 近距测距，精度 ±1-2 cm，成本低，用于泊车与低速防碰撞。

2.5 GPS/IMU 组合¶

GNSS 提供绝对位置（RTK 厘米级），IMU 提供高频姿态与加速度，互补融合构成定位硬件基座（详见 08-定位模块）。

🔥学习提示
没有万能传感器。选型的核心是”互补矩阵”：激光雷达给三维结构、相机给语义、毫米波给速度与全天候能力、超声波补近距盲区。多传感器融合正是第三阶段感知篇的主题。

3. 车载计算平台（工控机）¶

计算平台运行感知、预测、规划、控制全部软件，需同时满足算力、实时性、功耗散热与车规可靠性。

3.1 典型配置要求¶

部件 要求 说明
CPU 多核高性能 系统调度与规划控制实时任务
GPU 50-100 TOPS 级算力 感知深度学习推理
内存 16-32 GB 多模块并发
存储 256 GB-1 TB SSD 地图、模型与日志
接口 多路千兆网口 + USB + CAN 传感器接入与底盘通信
功耗 300-800 W，配风冷/水冷 车载散热约束严格

3.2 软件环境¶

Apollo 运行在 Docker 容器内，宿主机需正确配置 GPU 驱动、CUDA、内核与时间同步：

需要配置：实时内核或实时调度策略、GPU 驱动与 CUDA、PTP/NTP 时间同步（多传感器一致性的前提）、网口带宽隔离（避免点云流量挤占控制通道）。

📝2026 年更新
Apollo 官方支持范围已覆盖 Ubuntu 18.04/20.04/22.04、CUDA 11.8、AMD ROCm 5.1 与 ARM Orin 平台，开发者可在 x86 + NVIDIA、AMD GPU 与国产化 ARM 计算单元间灵活选择。

4. 传感器接入流程¶

传感器通过驱动软件接入 Apollo，转换为标准消息发布到 Cyber 总线，供感知与定位模块订阅。

4.1 标准接入步骤¶

  1. 硬件连接与供电：网口/CAN/触发线连接，确认供电稳定
  2. 安装驱动并配置网络：配置传感器 IP 与网段路由
  3. 启用或编写驱动：官方驱动覆盖主流型号，其他型号开发自定义驱动
  4. 配置话题与参数：帧率、分辨率、话题名、外参文件路径
  5. 验证数据可视化：DreamView 与 cyber 工具确认数据质量

4.2 标准话题与消息¶

传感器 消息类型 话题示例
相机 Image（sensor proto） /apollo/sensor/camera/front_6mm
激光雷达 PointCloud /apollo/sensor/velodyne64/compensator/PointCloud2
毫米波雷达 ContiRadar /apollo/sensor/conti_radar/front

4.3 时间同步¶

多传感器融合的前提是时间一致，两种方式：

  • 硬件触发：GNSS PPS 信号 + 触发线统一相机/雷达曝光时刻，精度最高
  • 软件同步（PTP）：全网络时钟对齐，部署简单

驱动收到数据后按传感器时间戳打标，感知模块按时间窗对齐多源数据。时间戳断续或漂移是融合感知异常的头号嫌疑。

5. 数据验证与驱动开发要点¶

5.1 数据质量验证¶

检查清单：频率达标且稳定、时间戳连续无跳变、图像无坏点过曝、点云形态完整无空洞。通过 14-调试与可视化工具（DreamView） 叠加显示点云与图像，可直观发现外参或同步问题。

5.2 自定义驱动开发要点¶

接入非官方支持的传感器需要开发驱动，关键点：

  • 解析厂商私有数据协议（UDP 包结构、点云解码）
  • 统一时间戳（优先用传感器自身 GPS 授时）
  • 输出 Apollo 标准 proto 消息格式
  • 处理异常：断线重连、丢包检测、checksum 校验

驱动代码放于 modules/drivers/，遵循 Cyber 组件规范开发（见 12-Cyber消息通信与组件开发），消息机制细节见 11-Apollo Cyber RT框架。

5.3 安装与标定¶

传感器安装位置直接决定感知效果：相机高度与视角决定可视范围，激光雷达位置影响点云覆盖与盲区，毫米波需避免金属遮挡。安装须满足车规振动与防护等级要求，并记录安装坐标供外参标定使用——标定是接入与算法之间的桥梁，标定错误会让所有下游模块”看歪”。
