gofmt 与 goimports：Go 代码格式化

ℹ️本页概览
本文讲解 Go 官方格式化工具 gofmt 与 goimports：命令用法、风格约定、import 排序、go fmt 与工具链集成、CI 检查，配真实示例。

核心概念¶

  • gofmt：Go 官方格式化工具，随 Go 工具链发布，是 Go 社区唯一标准。
  • goimports：gofmt 超集，额外管理 import（分组、排序、增删）。
  • 不可争议：Go 语言在格式上”没有风格争论”，gofmt 即标准。
  • 工具链：go fmt（对包格式化）、gofmt（对文件）。

📝Tab vs 空格

常见坑¶

  1. Tab 显示宽度：团队 IDE 统一显示宽度（常用 4），避免误解。
  2. goimports 误加本地包：同模块包用相对导入名即可，别写成完整路径。
  3. 生成代码不格式化：protoc 生成代码用 go generate 后统一 gofmt。
  4. gofmt 版本差异：新旧 Go 版本格式化差异极小，但仍固定 CI 版本。
  5. 别名 import 冲突：goimports 不会改别名，冲突需手动。

最佳实践¶

  • 默认 gofmt 输出即规范，禁止个性化配置（Go 哲学）。
  • 用 goimports 统一 import 顺序，配合 CI 强制。
  • 结合 Effective Go 规范代码风格。
