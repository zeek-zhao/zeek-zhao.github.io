组合式 API 进阶与 Hooks

[!info] 本页概览
本文深入组合式 API：自定义 Hooks（useFetch/useTable/useDebounce）、生命周期组合、依赖注入进阶、模板引用与组件的响应式细节，实现高效代码复用。

核心概念

  • Hooks（组合函数）：useXxx 封装有状态逻辑，返回响应式数据与方法。
  • 组合函数可调用其他组合函数（组合的递归）。
  • 生命周期钩子可在组合函数内注册，随宿主组件生效。
  • 好的 Hook：输入（参数）→ 输出（响应式状态 + 方法），无副作用泄漏。

常见坑

  1. 组合函数在条件/循环中调用：Hooks 必须顶层调用（类似 React Hooks 规则），否则生命周期绑定错乱。
  2. 返回值解构丢失响应性：返回 ref 时用户 const { data } = useFetch() 解构 ref 仍是响应式的；但若返回 reactive 对象解构会丢，统一返回 ref。
  3. 定时器/监听未清理：组合函数内创建的定时器、全局监听在 onUnmounted 清理。
  4. 参数响应性：接收 ref 参数时内部要 watch(() => url.value) 或入参设计为 getter 函数。
  5. 多次调用重复副作用：同一 Hook 在多个组件调用各自独立（符合预期）；全局单例状态放 Pinia。
  6. async 组合函数竞态：用序号或 AbortController（如 useFetch 示例）。

最佳实践

  • Hook 命名 useXxx，返回对象含 ref 数据 + 方法。
  • 入参支持”ref 或普通值”时封装 toValue（Vue 3.3+）统一处理。
  • 复杂 Hook 内部用更小 Hook 组合，每个职责单一。
  • 全局共享有状态逻辑放 Pinia，组件级复用放 Hook。
  • 团队沉淀常用 Hooks 库（useFetch/useTable/usePagination），统一质量。
