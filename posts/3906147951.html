Effective Go：Go 语言风格与惯例

ℹ️本页概览
本文讲解 Effective Go 的核心风格与惯例：命名、包设计、错误处理、接口、并发风格，配真实代码示例。

背景¶

Effective Go 是 Go 官方风格指南（go.dev/doc/effective_go），
配合 gofmt 与 go vet 形成”少争论、强约定”的 Go 文化。

核心哲学：

  • 简单、可读、直接
  • 错误显式处理
  • 接口小而明确
  • 并发原语明确表达

命名规范¶

包与文件组织¶

  • 包名要传达用途，避免 generic（util、common 慎用）
  • 每个包有明确职责；避免循环依赖
  • 文件按职责拆分：types.go / handler.go / service.go（习惯非强制）
  • 目录即包：src 下按领域组织
  • 避免 init() 滥用：显式初始化优先

错误处理风格¶

原则：

  • 每个可能失败的调用都要检查 err
  • 错误信息带上下文（哪个文件、哪个操作）
  • 不要吞错误：要么处理、要么向上传播

常见坑¶

  1. 包名与目录名不一致：Go 以包名为准，保持一致减少困惑。
  2. 错误信息无上下文：fmt.Errorf(“%w”) 包装而非裸 err。
  3. 接口过大：拆小，接受接口时只声明所需方法。
  4. 并发泄漏 goroutine：注意 channel 关闭与 ctx 取消。
  5. 忽略 go vet / race：CI 必跑 go vet 与 -race 测试。

最佳实践¶

  • gofmt + goimports 强制（见 04-gofmt与goimports）。
  • go vet、staticcheck 纳入 CI。
  • 团队约定见 11-团队风格指南制定。
