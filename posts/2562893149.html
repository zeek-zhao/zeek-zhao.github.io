1. 为什么数据集是地基¶

KITTI 创建者在论文 “Are we ready for Autonomous Driving? The KITTI Vision Benchmark Suite” 里点破了一件事：自动驾驶最大的挑战之一，是缺乏强有力的 benchmark。不少算法在实验室里表现很好，一到真实环境就露怯。数据集的作用主要有三个：

  1. 训练：深度学习模型的燃料，规模与多样性直接决定上限。
  2. 评估：统一基准下横向对比，排行榜推着领域往前走。
  3. 发现边界：暴露算法在罕见场景、边缘情况下的安全隐患。

KITTI、Waymo 之外，nuScenes（2020 年起扩展为 Million Scenes 级的 nuScenes-W）和 Argoverse 2 也成了 3D 感知基准的主流选择：前者提供全天候、多传感器、含毫米波雷达的数据与 NDS 评价指标，后者提供大规模高精地图与长时序情景。新算法验证我建议至少覆盖 KITTI/Waymo/nuScenes/Argoverse 2 里的两个——只盯一个榜，很容易过拟合。

2.2 专项数据集（交通标志）¶

  • GTSRB：5 万+ 图像，43 类德国交通标志。
  • 清华-腾讯 TT100K：10 万张图，3 万个中国交通标志实例。
  • LISA：美国标志，7855 条标注，适合实时检测研究。

4. 标注有四类¶

  1. 检测标注：2D/3D 边界框、类别、朝向、遮挡与截断状态。
  2. 分割标注：像素级语义、实例级掩码。
  3. 轨迹标注：历史轨迹、预测目标、交互关系（Waymo Motion、Argoverse）。
  4. 地图标注：车道中心线、道路标线、道路边界、停止标志、人行横道、减速带。

通用流程：注册账号 → 同意许可协议 → 下载（wget/gsutil）→ 校验完整性 → 组织目录结构 → 安装官方 devkit。

5.2 devkit 快速上手¶

评估工具链这边，KITTI devkit（C++/MATLAB）、Waymo 官方 metrics（waymo_open_dataset.metrics）、nuScenes-devkit，还有统一多数据集的 MMDetection3D / OpenPCDet 工具箱——后者内置多数据集的转换与训练流程，我会直接拿它当起点，省得自己拼数据转换那摊事。

6. 指标口径先对齐¶

不同任务的评估口径不一样，跨数据集对比之前必须先把指标定义对齐：

任务 核心指标 说明
2D/3D 检测 mAP 不同 IoU 阈值下精度-召回曲线下面积
跟踪 MOTA / MOTP / IDS 综合漏检误检、位置精度、ID 切换次数
轨迹预测 ADE / FDE / minADE / minFDE 多模态预测取最优模态的位移误差
语义分割 mIoU 各类别交并比均值
nuScenes 综合 NDS mAP 与平移/尺度/朝向/速度/属性五类真阳性误差的加权组合

这里有个坑：Waymo 的 APH 考虑朝向精度、KITTI 分 Easy/Moderate/Hard 三档、nuScenes 用 NDS，三者的数值不能直接比。写论文汇报时务必注明基准和难度档位。

7. 处理数据前先想清楚这几件事¶

  1. 预处理：点云体素化与地面分割；图像颜色/几何增强；类别均衡采样与难例挖掘。
  2. 存储规划：KITTI 全量约 250GB、Waymo 约 2.5TB、nuScenes 全量约 1.4TB——提前规划磁盘和下载策略（分批、断点续传）。
  3. 实验管理：固定训练/验证/测试划分，用 DVC 管理数据版本，用 W&B/MLflow 跟踪实验。
  4. 许可合规：KITTI 仅限非商业用途且需引用论文；Waymo 需申请许可；使用前务必核对各数据集许可条款。

8. 数据闭环正在改写玩法¶

开源数据集之外，各厂商自建数据闭环已经成了主流：量产车回传数据 → 自动挖掘 corner case → 大模型自动标注 → 回流训练。开源数据集的定位，从”训练主力”慢慢转向”基准评测与算法入门”。

沿着这个方向往下看，还有几条线在往前推：

  1. 更大规模：从几万帧到百万帧（nuScenes-W、ONCE）。
  2. 更多模态：4D 标注、毫米波雷达、事件相机。
  3. 合成数据结合：CARLA、NVIDIA DRIVE Sim 等模拟器生成边缘场景（见 50-仿真平台对比与Gazebo-LGSVL实战），弥补真实数据里罕见场景的稀缺。
  4. 自监督/半监督标注：利用多传感器一致性与时序信息自动生成标签，降低人工成本。

操作步骤 使用流程¶

一次完整的数据集选型与接入，建议按下面的流程走：

  1. 明确任务与指标：先定是做 2D 检测、3D 检测还是轨迹预测，再定对齐的指标口径（如 3D 检测用 AP、跟踪用 MOTA）。任务不同，数据集差别很大。
  2. 查许可条款：到官网核对是否允许商用、是否要求引用论文、是否需要申请。KITTI 非商用、Waymo 需申请，这一步跳过后面会出合规问题。
  3. 估算存储与算力：按上面的 estimate_storage 估出容量，预留 1.5 倍余量；确认 GPU 显存能跑得动对应分辨率的模型。
  4. 下载并校验：用官方脚本或 wget/gsutil 分批下载，下载完对照官网 checksum 校验完整性，避免坏档污染训练。
  5. 安装 devkit 并跑通 demo：先跑官方 mini 集（nuScenes v1.0-mini、KITTI 单帧），确认读取链路通了再上全量。
  6. 统一格式：用 Box3D/Frame 结构把标注归一化，类别做映射，坐标系统一（相机系还是自车系要写清楚）。
  7. 固化划分与版本：固定随机种子划分训练/验证/测试，用 DVC 给数据打版本，避免不同实验用不同数据切分。
  8. 接入训练框架：转成 MMDetection3D/OpenPCDet 支持的格式，先跑一个小规模 overfit 验证流程正确性，再放大训练。
  9. 回归评测：用官方 devkit 复现 baseline 指标，确认自家实现与官方口径一致后再汇报。

注意事项与常见坑¶

数据集接入阶段踩过的坑，按出现频率排：

  1. 许可合规踩线：KITTI 仅限非商业用途且必须引用论文，Waymo 需申请许可。商用前不核对条款，后期会被迫下架模型。
  2. 指标口径混用：Waymo APH、KITTI 三档 AP、nuScenes NDS 数值不可直接比。汇报时不注明基准和难度档位，等于没说。
  3. 坐标系搞混：KITTI 标注在相机系、点云也在相机系，而 nuScenes 用自车系。融合前不统一坐标系，框会飘到十万八千里外。
  4. 点云读数 dtype 错：KITTI 的 bin 必须是 float32，用 float64 读会尺寸错乱；reshape 的 -1 要配合 4 列，否则点全乱。
  5. 存储估算不足：Waymo 全量约 2.5TB、nuScenes 约 1.4TB，下载中途磁盘满，前面的进度全废。务必预留 1.5 倍余量并分批下载。
  6. 忘记校验完整性：网盘/对象存储下载偶发坏档，不校验 checksum 会导致训练中途报解析错误，排查成本极高。
  7. 划分泄漏：随机种子不固定或划分粒度错（按帧而非按场景切），同一段路同时出现在训练和测试集，指标虚高且不可信。
  8. 类别映射遗漏：没映射的类别被丢进 unknown，长尾类别直接消失，评测时才发现召回率为零。
  9. 只盯单一榜单：只在一个数据集上调参，过拟合到该数据集的天气/地理分布，换域就崩。至少覆盖两到三个主流基准。
  10. 忽略时序同步：多传感器数据的时间戳不对齐，融合时相机和雷达画面错位，标注看着对但模型学的是错的对应关系。
