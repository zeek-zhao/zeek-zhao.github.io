发表于2026-10-25|apollo

[!info] 本节目标
掌握 PyTorch 的核心机制（张量、自动微分、动态图）、标准训练流程与部署路径，并理解它在自动驾驶研发链路中的定位：训练侧首选框架，训练成果经 ONNX/TorchScript 转换后进入车载推理引擎。基础原理见 51-深度学习基础与CNN。

1. PyTorch 概览

1.1 发展与定位

PyTorch 由 Facebook AI 研究院（FAIR）于 2016 年发布，2018 年与专注部署的 Caffe2 合并（这段历史见 53-TensorFlow与Caffe2在自动驾驶中的应用）。核心优势：

  • 动态计算图：图在运行时即时构建，可随时用 print/断点调试，与 Python 生态无缝集成
  • 研究社区主流：新论文模型（UniAD、BEVFormer 等）几乎都以 PyTorch 实现
  • 部署工具日益完善：TorchScript、ONNX 导出、ExecuTorch

版本里程碑：1.0（2018，引入 JIT）；2.0（2023，引入 torch.compile 编译加速）；2.x 持续增强 FSDP 分布式训练与编译优化。

3.2 混合精度训练（AMP）

3.3 其他实用技巧

  • 梯度累积：loss = loss / accum_steps，多步后再 step()，模拟大 batch
  • 梯度裁剪：torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)，防梯度爆炸
  • 激活检查点：torch.utils.checkpoint 用计算换显存
  • 性能分析：torch.profiler.profile 定位瓶颈，可导出 Chrome trace

4. 从训练到部署：与 Apollo 的关系

[!important] PyTorch 在自动驾驶链路中的位置
**PyTorch 负责”训练侧”**：Apollo 生态及多数自动驾驶团队的感知模型（2D/3D 检测、BEV 骨干、红绿灯、车道线网络）都在 PyTorch 中设计与训练。
车端推理不走 PyTorch：Apollo 内置推理框架基于 PaddlePaddle（PaddleInference）、ONNX Runtime 与 TensorRT 等，追求确定性低延迟与硬件加速。训练完成后需要转换模型格式：

[!note] 2026 年更新
端到端范式（UniAD、VLA 模型）下，训练侧模型规模显著增大，PyTorch + FSDP/DeepSpeed 的多机训练成为常态；车端则把蒸馏/量化后的小模型经 ONNX → TensorRT（NVIDIA Orin）等路线部署。训练用大框架、推理用专门引擎的”训练-部署分离”格局更加固化。Apollo 10.0/11.0 的部分感知模型训练也依赖云端平台（见 56-自动驾驶云服务与基础设施）。

部署链路：PyTorch 训练 → 量化/剪枝/蒸馏 → ONNX 导出 → TensorRT/PaddleInference 优化 → 车载 Cyber RT 模块加载推理（运行时框架见 58-自动驾驶运行时框架对比）。

6. 最佳实践清单

  1. 用 num_workers + pin_memory 优化数据加载；避免频繁在 CPU/GPU 间搬运数据
  2. 评估/推理时始终 model.eval() + torch.no_grad()
  3. 保存 state_dict() 而非整个模型对象；训练脚本保存完整 checkpoint（模型+优化器+调度器状态）以便断点续训
  4. 大 batch 训练用 AMP + 梯度累积；显存不足用激活检查点
  5. 上车部署前先做量化验证（PTQ 校准或 QAT），对比精度损失

7. 小结

  • PyTorch = 张量 + 自动微分 + 动态图，是自动驾驶模型训练的事实标准
  • 标准训练五步：数据管道 → 模型定义 → 损失/优化器 → 训练循环 → 验证保存
  • 自动驾驶链路中 PyTorch 守训练侧，车端推理交给 ONNX/TensorRT/PaddleInference
  • 2026 年趋势：训练规模变大（端到端/VLA），部署链路更强调量化与确定性
