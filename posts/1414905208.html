代理节点（Agent）

[!abstract] 核心问题
Controller 单机跑构建容易排队、环境单一。代理节点把构建分发到多台机器，用标签按需调度。

节点连接方式

方式 场景
SSH Linux/Windows 远程节点
JNLP（Java Web Start） 跨网络、容器节点
Docker/K8s 插件 按构建动态拉起 Pod

添加 SSH 节点

Manage Jenkins → Nodes → New Node：

[!note] 连接数
Executors（执行器数量）= 该节点可并行构建数；普通节点 2-4 个即可。

标签（Label）与调度

Pipeline 用标签选择节点：

[!tip] 标签规划
按能力而非机器名设标签：linux、windows、docker、gpu、arm64。调度只认标签，机器挂了换一台同样标签即可。

Docker 动态代理

Kubernetes 动态代理

[!note] 动态代理优势
用完即销毁（Pod/容器删除），无空闲资源占用，环境干净可复现；配合 K8s 系列 的 HPA 思维一致。

节点监控与排障

常见问题：节点离线（SSH 不通/凭据失效）、执行器占满（队列积压）、JNLP 连接超时（端口 50000 未放通）。

[!warning] 注意

  • Controller 上跑构建会拖垮调度；生产核心构建全部放 Agent；
  • Agent 环境要与产物目标一致（如打 Windows 包必须在 Windows Agent）。
