Linux PWM 开发指南

我在调背光和电机的时候，sysfs、自己写驱动、直接调子系统 API 这三条路来回切过好几轮，干脆把 PWM 这套东西从头捋了一遍，省得下次又翻文档。

1. PWM 的三个核心参数：周期、占空比与频率¶

PWM（Pulse Width Modulation，脉宽调制）是一种将模拟信号值转换为脉冲的编码技术。我最先记住的就是下面三个参数，调任何一路 PWM 都绕不开：

  • 周期(period): 完成一个脉冲所需的时间
  • 占空比(duty cycle): 高电平时间占总周期的比例
  • 频率(frequency): 单位时间内的脉冲数量，等于1/周期

1.1 PWM 信号示意图¶

graph LR subgraph "PWM信号" A[高电平] --- B[低电平] B --- C[高电平] C --- D[低电平] end subgraph "参数说明" E[占空比 = 高电平时间 / 周期] F[频率 = 1 / 周期] end

1.2 典型应用场景¶

  • LED亮度控制
  • 电机速度控制
  • 音频信号生成
  • 伺服电机位置控制
  • 电源电压调节

2. PWM 子系统架构：从用户空间到硬件控制器的两层抽象¶

Linux内核提供了统一的PWM子系统，用于管理PWM控制器和通道。我看架构图时习惯把它拆成「用户空间入口」和「内核控制器驱动」两层，理解起来清楚很多。

2.1 子系统架构图¶

flowchart TD A[用户空间应用] --> B[sysfs接口] A --> C[设备文件接口] B --> D[PWM核心子系统] C --> D D --> E[PWM控制器驱动] E --> F[硬件PWM控制器]

2.2 三个容易混的概念¶

  • PWM芯片/控制器: 提供一个或多个PWM输出通道的硬件
  • PWM设备: 控制器中的一个PWM通道
  • Consumer: 使用PWM的设备（如LED、电机等）

3. 设备树配置：控制器与消费者两端都要写¶

在基于设备树的系统中，PWM控制器和消费者都需要在设备树中进行配置，缺一端都跑不起来。

    • 2: 表示需要指定通道号和周期
    • 3: 表示需要指定通道号、周期和极性

实测下来，PWM 没波形十有八九是设备树那一层没配好，而不是驱动逻辑写错。

8.1 PWM 输出不稳定或无输出¶

可能原因：

  • 时钟配置错误
  • 引脚复用配置不正确
  • 硬件占用冲突
  • 驱动未正确加载

解决方法：

  1. 检查设备树中的时钟配置
  2. 检查引脚复用设置
  3. 使用示波器测量实际输出
  4. 检查dmesg日志信息

8.2 PWM 性能问题¶

⚠️高频率PWM应用中可能遇到的问题
  • 定时器分辨率限制
  • 系统负载导致的抖动
  • 软件PWM和硬件PWM的性能差异

8.3 调试方法¶

  1. 使用示波器直接测量PWM输出波形
  2. 检查内核日志：dmesg | grep pwm
  3. 使用sysfs检查PWM配置：cat /sys/class/pwm/pwmchip0/pwm0/period
  4. 开启内核PWM调试：在内核配置中启用CONFIG_PWM_DEBUG

9. 选型与最佳实践：按场景挑方式、卸载时释放资源¶

9.1 三种使用方式怎么选¶

使用方式 适用场景 优点 缺点
sysfs接口 简单测试、原型开发 无需编写驱动、方便调试 效率低、不适合实时应用
PWM子系统API 内核驱动开发 功能完善、性能高 需要编写内核代码
自定义驱动 特殊需求场景 灵活性高、可定制 开发复杂度高

我一般做原型验证就直接 sysfs，进产品代码再换成子系统 API，自定义驱动只在需要 ioctl 这种特殊接口时才写。

9.2 开发最佳实践¶

ℹ️PWM开发最佳实践
  1. 尽量使用硬件PWM而非软件模拟
  2. 合理设置PWM频率和分辨率
  3. 注意PWM引脚的复用配置
  4. 利用设备树进行PWM配置
  5. 考虑时钟源的稳定性
  6. 在驱动卸载时正确释放资源

9.3 技术演进方向¶

graph TD A[传统PWM] --> B[智能PWM控制器] A --> C[多通道同步PWM] B --> D[可编程PWM序列] C --> E[高精度PWM] D --> F[自适应PWM算法] E --> F

最后落到一个具体建议：新驱动优先走 pwm_apply_state() 这套原子接口，别再拼 pwm_config + pwm_enable；卸载路径里一定先 pwm_disable 再 pwm_free，顺序反了容易留下仍在输出的通道。
