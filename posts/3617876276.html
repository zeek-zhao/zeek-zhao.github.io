模块管理

[!info] 本页概览
Go Modules 是官方依赖管理方案。本文讲解 go.mod/go.sum、依赖添加更新、常用命令（get/tidy/vendor）、语义化版本与私有仓库处理。

核心概念

模块（module）是 Go 依赖管理的最小单位，由 go.mod 描述；go.sum 记录依赖的哈希校验，保证可复现。依赖版本遵循语义化版本（MAJOR.MINOR.PATCH）。

go.mod 结构

  • // indirect：间接依赖（被直接依赖引用），go mod tidy 自动管理。
  • replace：本地替换依赖（调试或 fork）：
  • exclude：排除特定版本。

私有仓库与认证

常见坑

  1. go get 与 go mod tidy 混用：手工编辑 go.mod 后忘 tidy，构建报错或不一致。统一用命令管理。
  2. 大版本升级破坏 API：v2+ 模块路径带 /v2（github.com/foo/bar/v2），直接 require v2 会失败。
  3. indirect 依赖多余：go mod tidy 可自动清理；手工保留会导致 go.sum 不一致。
  4. 依赖代理不可达：国内配置 GOPROXY=https://goproxy.cn,direct（见 01-环境与工程结构）。
  5. vendor 后忘记同步：用 go mod vendor 提交后，新增依赖必须重新 vendor，CI 才一致。
  6. replace 提交到生产：replace 指向本地路径会让别人无法构建，只用于调试分支。

最佳实践

  • go.mod 交给工具管理，不手工编辑（replace 除外）。
  • 每次改依赖后 go mod tidy 并提交 go.mod + go.sum。
  • 锁定依赖版本（不要用 @latest 长期悬浮），升级需回归测试。
  • 使用 Dependabot/Renovate 自动升级 PR 并跑 CI。
  • 依赖安全扫描：govulncheck ./...（Go 官方漏洞检测）。
