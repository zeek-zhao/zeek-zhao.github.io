注解与反射

ℹ️本页概览
本文讲解 Java 注解（自定义注解、元注解、保留策略）与反射（Class 对象、字段/方法/构造器操作、动态代理），配可运行示例与框架实践（Spring 注解原理）。

核心概念¶

  • 注解（Annotation）：给代码加元数据，本身不改变行为，由处理器/框架解释。
  • 元注解：@Target（作用位置）、@Retention（保留策略）、@Documented、@Inherited、@Repeatable。
  • 保留策略：SOURCE（编译期丢弃）、CLASS（字节码中）、RUNTIME（运行期可见，反射可读）。
  • 反射（Reflection）：运行期动态获取类信息、调用方法、操作字段；框架基石。

动态代理¶

📝JDK 动态代理 vs CGLIB
JDK 动态代理要求目标实现接口；无接口用 CGLIB（Spring Boot 默认对无接口 Bean 用 CGLIB）生成子类代理。

常见坑¶

  1. 注解未标 RUNTIME 保留：反射 getAnnotation 返回 null。
  2. 反射性能开销：高频调用用缓存 Method 对象或改编译期处理（注解处理器）。
  3. setAccessible(true) 绕过私有：安全校验与模块化（JDK9+）可能抛 InaccessibleObjectException。
  4. Class.forName 触发静态初始化：仅获取类元数据用 ClassName.class。
  5. getDeclared vs get：getMethod 只拿 public（含继承），getDeclaredMethod 拿本类全部。
  6. 动态代理方法内 self-call 失效：代理调用内部 this.run() 不经过代理，事务/AOP 失效。

最佳实践¶

  • 自定义注解三件套：@Target + @Retention(RUNTIME) + 默认值。
  • 反射用于框架层（Spring/MyBatis/JUnit），业务代码少用。
  • 注解只存元数据，行为由解析器实现（注解 + 处理器分离）。
  • 动态代理做 AOP：日志、事务、权限、缓存横切。
  • 结合 Spring 注解驱动（@Component/@Autowired/@Transactional）理解框架原理。
