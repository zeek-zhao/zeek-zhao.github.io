08-与Java互操作

发表于2026-10-25|groovy
|浏览量:

[!info] 本节目标
Groovy 与 Java 的无缝互操作是它的核心价值，学习双向调用与类型桥接。

1. Groovy 调用 Java

Groovy 可以毫无障碍地使用所有 Java 类库，导入、实例化、调用方法与 Java 语法基本一致，无需额外配置。Java 集合、并发、IO 与网络库均可直接使用。

Groovy 的动态特性让 Java API 调用更简洁：省略类型声明、属性访问替代 getter、闭包适配函数式接口。

2. Java 调用 Groovy

Java 调用 Groovy 类就像调用普通 Java 类，只要 Groovy 类在 classpath 中。编译后的 Groovy 类生成标准字节码，Java 代码可直接 new 实例并调用方法。

动态方法的调用需要通过 Groovy 的 GroovyObject 接口或 Script 引擎，Java 侧也可使用 GroovyShell 动态执行脚本。

3. 属性与 getter/setter

Groovy 属性自动生成 getter 与 setter，Java 侧可以用标准 getXxx/setXxx 访问。反过来，Groovy 侧可以用点号直接访问 JavaBean 属性。

这种对称的属性访问让两个语言之间的模型传递非常自然，无需额外适配层。

4. 集合与类型桥接

Groovy 的集合字面量生成 Java 集合接口实例，与 Java 集合无缝共享。Map、List、Set 可直接传给 Java API。

Groovy 的闭包可自动转换为 Java 函数式接口，Java 8 的 lambda 也可在 Groovy 中作为参数传递，双向桥接顺畅。

5. 异常与泛型

Groovy 不强制检查型异常，Java 方法声明的 checked exception 在 Groovy 中可以不用显式捕获，简化调用代码。

泛型在运行时擦除，Groovy 动态调用不做编译期泛型校验，@CompileStatic 下才严格检查。

6. 互操作最佳实践

跨语言开发时保持公共 API 简单明确：优先使用标准 Java 类型作为边界，避免过度依赖 Groovy 专属特性；文档标注动态方法的行为。

在 Gradle 或 Maven 中同时管理 Java 与 Groovy 源码，Groovy 编译依赖 Java 编译输出，构建顺序要正确配置。

7. 互操作典型案例

在测试中，Java 的 Mockito 与 Groovy 的 Spock 可以共存，团队可以按测试风格选择框架，两个语言的测试类互相引用没有障碍。

使用 Java 库时注意其线程模型与回调接口，Groovy 闭包自动适配函数式接口后，代码比 Java 匿名内部类短一半以上，可读性显著提升。

项目迁移阶段可以逐文件将 Java 重写为 Groovy，保持接口与行为不变，再逐步引入动态特性，实现平滑演进。
