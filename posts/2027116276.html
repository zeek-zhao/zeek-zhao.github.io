14-中断管理

发表于2026-10-24|RT-Thread
|浏览量:

[!info] 本节目标
掌握中断机制与中断安全编程。

1. 中断机制

中断由硬件事件触发，处理器转入中断服务程序。RT-Thread 提供中断登记接口，绑定设备中断处理函数。中断上下文优先级高于所有线程，处理要求快速与安全。

2. 中断登记与触发

rt_hw_interrupt_install 登记中断处理，rt_hw_interrupt_trigger 软件触发中断。中断使能与禁用按向量控制。驱动初始化阶段登记处理函数，触发后进入内核管理的中断处理流程。

3. 中断处理原则

中断服务保持短小，仅完成必要处理与状态记录。耗时工作通过信号量或消息通知线程处理。避免在中断中调用阻塞接口与动态分配，保持确定性。中断处理时间直接影响实时性。

4. 中断安全 API

RT-Thread 提供 rt_sem_release、rt_mq_send、rt_mb_send、rt_event_send 等中断安全接口。中断上下文可唤醒线程，不能调用 take 等阻塞接口。接口文档标注中断可用性，严格遵守。

5. 临界区保护

关中断与调度器锁提供临界区保护。关中断屏蔽所有中断，调度器锁仅禁止调度。短临界区选择关中断，较长保护使用互斥量。临界区长度最小化，降低中断延迟与优先级影响。

6. 中断嵌套

RT-Thread 支持中断嵌套，高优先级中断可打断低优先级处理。嵌套增加栈需求与复杂度，按需配置。中断栈独立分配，容量规划需考虑嵌套深度，溢出导致系统崩溃。

7. 实践要点

中断处理函数注册避免重复与冲突，参数传递安全。验证中断安全 API 使用场景，禁用中断期间操作保持极短。使用工具测量中断延迟与处理时间，优化热点。测试覆盖高频中断与嵌套场景。
