视图、存储过程与触发器

[!info] 本页概览
本文讲解 MySQL 数据库编程对象：视图（VIEW）、存储过程（PROCEDURE）、函数（FUNCTION）、触发器（TRIGGER）与事件调度器，配可运行示例与使用建议。

核心概念

  • 视图：虚拟表，封装查询逻辑，不存储数据（普通视图）。
  • 存储过程：预编译的 SQL 集合，可传参、返回结果，减少网络往返。
  • 函数：返回单值，可在 SQL 中直接调用。
  • 触发器：表上 DML 事件（INSERT/UPDATE/DELETE）自动触发的程序。
  • 事件调度器：定时执行任务（类似 cron）。

视图

[!note] 视图价值
简化复杂查询、提供安全隔离（只暴露必要列）、屏蔽表结构变化。性能上不要指望视图优化，它只是封装。

触发器

[!warning] 触发器代价
触发器在事务内执行，会延长事务、增加锁持有时间；高并发核心表慎用，审计可放应用层。

事件调度器

常见坑

  1. 存储过程滥用：业务逻辑放应用层更易测试与扩展；存储过程难调试。
  2. 触发器嵌套：触发器内再改表触发其他触发器，链式副作用难排查。
  3. 视图嵌套过深：多级视图性能差、难维护。
  4. DELIMITER 忘记恢复：客户端解析出错。
  5. 权限：存储过程需要 EXECUTE 权限，触发器需要 TRIGGER 权限。

最佳实践

  • 视图用于报表/权限隔离；存储过程用于强数据一致性批处理。
  • 触发器只做轻量审计/校验，避免复杂业务逻辑。
  • 函数保持 DETERMINISTIC 声明，利于优化器。
  • 事件调度任务监控执行日志，防止静默失败。
  • 结合 07-SQL 优化 评估存储过程的查询效率。
