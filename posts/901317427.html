一、ADB是什么：连上设备和电脑的那座桥¶

ADB，即 Android Debug Bridge 是一种允许模拟器或已连接的Android设备进行通信的命令行工具。它可以让开发者在计算机上控制Android设备，实现应用安装、调试以及访问设备Shell等功能。

ADB 是 Android SDK 的一部分，主要功能包括：

我第一次用的时候最意外的是它连模拟器也一并管了，装应用和进 shell 走的是同一套命令。

  • 在设备上运行Shell命令
  • 将本地APK软件安装至设备
  • 管理设备上的端口转发
  • 在设备上进行文件传输和管理

ADB 是一个客户端-服务器程序，包括三个组件：

排查连接问题时，我习惯先把 adb server 重启一遍，很多「设备消失」其实卡在中间这层。

flowchart LR A[客户端] --> B[服务器] B --> C[设备守护进程] C --> B B --> A
  1. 客户端：运行在开发计算机上，通过发送adb命令调用
  2. 服务器：作为后台进程运行在开发计算机上，管理客户端和设备之间的通信
  3. **设备守护进程(adbd)**：在每个模拟器或设备上运行的后台进程

7.3 端口转发¶

端口转发是ADB的强大功能，可以将计算机上的端口与设备上的端口建立映射。

我调前端页面时全靠这条命令，本地起服务、设备访问 127.0.0.1 就能通，比反复打包装 APK 快。

7.3.1 端口转发原理

flowchart LR A[PC应用\n连接到本地端口] --> B[ADB服务\n转发数据] B -- 通过USB/TCP --> C[设备上ADBD] C --> D[设备上应用\n监听设备端口] D --> C C -- 通过USB/TCP --> B B --> A

端口转发的工作流程：

  1. 在设备上运行应用程序，监听特定端口(如22222)
  2. 使用adb forward tcp:11111 tcp:22222命令设置转发
  3. 在PC上连接到本地端口11111
  4. 数据通过ADB在PC和设备间传递

十一、故障排除：三类常见连不上与服务的启停¶

11.1 常见错误解决¶

设备显示 offline 时，先换线再重启服务，这两步能解决我遇到的大半情况。

  1. 设备未授权

    • 确认设备上的USB调试授权提示并授权

  2. adb devices显示”offline”

    • 重启ADB服务：adb kill-server 然后 adb start-server
    • 检查USB连接或尝试更换USB线

  3. 找不到设备

    • 检查驱动是否正确安装
    • 尝试使用其他USB端口
    • 在设备上重新启用USB调试

11.2 ADB服务管理¶

十二、收尾建议：先保连接稳定，再谈命令熟练度¶

ADB 用熟之后，真正卡住人的往往不是命令记不全，而是设备没授权、服务没起来或者 USB 线不稳。我一般先把 adb devices 跑通，确认状态是 device 而不是 offline，再去做安装、抓日志这些后续操作；连不上时按第 11 节的顺序倒查，比瞎试命令快得多。
