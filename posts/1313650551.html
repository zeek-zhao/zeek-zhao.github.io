类型注解与异步编程

[!info] 本页概览
本文讲两大进阶主题：类型注解（typing、mypy/pyright 静态检查）与异步编程（asyncio、async/await），让代码更可维护、高并发。

核心概念

  • 类型注解：运行时不强制，供 IDE 与静态检查工具使用。
  • async/await：基于事件循环的协作式并发，适合 I/O 密集任务。
  • 异步不是多线程：单线程内通过”挂起等待 I/O”复用执行权。

常见坑

  1. **忘记 await**：asyncio.sleep(1) 没 await 会警告并跳过，返回 coroutine 对象。
  2. 在异步代码中调用同步阻塞：time.sleep() 阻塞事件循环，用 asyncio.to_thread 或 run_in_executor。
  3. 事件循环管理：asyncio.run 每次创建新循环；Jupyter 里需 nest_asyncio 或在已运行循环内用 create_task。
  4. 类型注解过度：全部标注降低可读性，公共 API 与复杂数据结构必标，局部可从简。
  5. Optional vs 默认 None：Optional[str] 与 str = None 语义不同，注解与默认值要一致。
  6. mypy 报大量错误：先跑 --ignore-missing-imports 处理第三方，再逐步收紧。

最佳实践

  • 新代码默认加类型注解，配合 pyright（VS Code）即时反馈。
  • asyncio 用于 I/O 密集（HTTP、DB、文件网络混合）；CPU 密集用多进程。
  • asyncio.gather 加 return_exceptions=True 防止一个失败全崩。
  • 异步库调用链保持 async 贯穿，同步包装用 asyncio.to_thread。
  • 用 TaskGroup（3.11+）结构化管理并发任务。
