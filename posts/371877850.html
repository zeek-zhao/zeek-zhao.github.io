Nginx 动静分离

负载均衡铺开后，接着 06-负载均衡 做动静分离。这篇讲静态资源怎么由 Nginx 直接服务、按路径或扩展名怎么分、缓存头怎么设，还有和 CDN 的配合。我一般先把静态路径切出来，因为这一步收益最直接、改动也最小。

静态交给 Nginx，动态转后端¶

动静分离：

  • 静态资源（JS/CSS/图片/字体）由 Nginx 直接服务
  • 动态请求（API/页面）转发后端
  • 降低后端压力，提升响应

收益：

  • 静态文件高吞吐（sendfile）
  • 后端专注业务逻辑
  • 缓存/压缩更高效

按路径给静态资源设缓存头¶

按扩展名或目录分离都行¶

说明：

  • alias 与 root 区别：alias 替换前缀
  • 正则匹配优先级高于普通前缀
  • 静态文件可关闭 access_log 减少开销

SPA 加 API 是常见组合¶

gzip 加 sendfile 提升吞吐¶

说明：

  • gzip 压缩文本类资源
  • 图片/视频一般不压缩（本身已压缩）
  • sendfile 零拷贝提升静态吞吐

带 hash 的文件才配长缓存¶

缓存策略：

  • 带 hash 的文件：immutable 长缓存
  • 易变文件：短缓存 + 协商（ETag）
  • 动态响应：Cache-Control no-cache

示例：
location /assets/ {
expires 30d;
add_header Cache-Control “public, immutable”;
}
location / {
add_header Cache-Control “no-cache”;
}

生产再加一层 CDN 回源¶

root/alias 和缓存错乱最常见¶

  1. root/alias 混淆：路径拼接错误 404。
  2. 缓存错乱：文件更新后仍旧缓存，用版本号文件名。
  3. 正则匹配漏掉格式：新资源类型未匹配。
  4. 静态文件走后端：未正确分离，后端压力大。
  5. 权限不足：静态目录权限 403。

hash 命名加长缓存¶

  • 前端构建产物 hash 命名 + 长缓存。
  • 静态与动态路径明确分离。
  • 开启 gzip + sendfile。
  • 接入 CDN 提升全球访问。
