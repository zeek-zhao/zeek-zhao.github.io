设备树语法：从节点定义到属性引用

设备树语法这东西，看两眼 DTS 觉得就是大括号加属性，真写起来才发现分号、cell 数、引用方式到处是坑。我把平时翻得最多的语法点整理成这一篇，从节点定义一路写到调试。

1. 语法底座：DTS、DTSI、DTB、DTC 与树形结构¶

设备树（Device Tree）用特定语法描述硬件资源，尤其在 ARM 架构的 Linux 系统里，它已经是描述硬件的标准方式。我刚开始把 DTS 当普通配置文件看，后来才发现它更像一门有严格语法的小语言。

1.1 四种文件：DTS、DTSI、DTB、DTC¶

设备树相关的文件主要有以下几种类型：

  • DTS（Device Tree Source）：设备树源文件，人类可读的文本格式
  • DTSI（Device Tree Source Include）：可被 DTS 文件包含的设备树源文件
  • DTB（Device Tree Blob）：由 DTS 编译而成的二进制文件，供内核解析使用
  • DTC（Device Tree Compiler）：设备树编译器，用于将 DTS 编译成 DTB

DTS 和 DTSI 文件使用类似 C 语言的语法，通过编译生成二进制的 DTB 文件，然后由 bootloader 传递给内核。

1.2 树形结构：根节点、属性与子节点¶

设备树采用树形结构，由节点（node）和属性（property）组成。其基本结构如下：

  • / 表示根节点
  • 每个节点可以包含多个属性和子节点
  • 节点以分号 ; 结束
  • 属性以分号 ; 结束

4. 高频属性逐个看：根、内存、中断、时钟、pinctrl¶

下面这几个属性在实际设备树里出现频率最高。我查中断问题时一定先看 #interrupt-cells 和 interrupts 的 cell 数对不对得上——数量不匹配是最常见的坑。

4.1 根节点四件套：model、compatible、两个 cells¶

根节点是设备树的起点，通常包含以下属性：

  • model：指定板子的具体型号
  • compatible：指定兼容的平台，内核根据此属性选择 machine_desc
  • #address-cells：子节点 reg 属性中表示地址的单元格数量
  • #size-cells：子节点 reg 属性中表示大小的单元格数量

4.2 内存节点：device_type 固定为 memory¶

内存节点描述系统物理内存的布局：

  • device_type：必须为 “memory”
  • reg：指定内存的起始地址和大小

4.3 中断四属性：控制器、cells、parent、interrupts¶

中断是硬件与处理器通信的重要机制，设备树中通过以下属性描述中断：

  • interrupt-controller：表明该节点是一个中断控制器
  • #interrupt-cells：指定子节点的 interrupts 属性中用多少个单元格描述一个中断
  • interrupt-parent：指定设备连接到哪个中断控制器
  • interrupts：描述设备使用的中断信息

4.4 时钟三属性：cells、clocks、clock-names¶

设备树中通过以下属性描述时钟信息：

  • #clock-cells：指定子节点的 clocks 属性中用多少个单元格描述一个时钟
  • clocks：指定设备使用的时钟
  • clock-names：为时钟分配名称，便于驱动程序引用

4.5 pinctrl：状态名配引脚组¶

pinctrl 用于配置和管理引脚复用和特性：

  • pinctrl-names：定义 pinctrl 状态的名称
  • pinctrl-0：第一个状态（通常是 “default”）使用的 pinctrl 设置
  • samsung,pins：指定要配置的引脚
  • samsung,pin-function：指定引脚的功能模式
