数组切片与映射

[!info] 本页概览
数组（array）、切片（slice）、映射（map）是 Go 最常用的三种集合类型。切片是数组的视图，是 Go 数据处理的灵魂；map 是哈希表。本文讲解三者区别、操作与陷阱。

核心概念

  • 数组：固定长度，长度是类型的一部分（[5]int 与 [3]int 是不同类型）。
  • 切片：对底层数组的引用，包含指针、长度、容量三个字段；可动态增长。
  • map：键值对集合，map[K]V，无序、自动扩容。

常见坑

  1. append 扩容改变底层数组：append 超容量时分配新数组，旧切片仍指向旧数组，两者”分道扬镳”，容易产生隐式 bug。
  2. 切片共享底层数组：子切片修改会污染父数组，业务上要隔离时用 copy。
  3. map 并发读写：map 非线程安全，多 goroutine 并发读写直接 panic。用 sync.Mutex 或 sync.Map（见 20-并发模式与sync包）。
  4. 对 nil 切片/空 map 操作：nil 切片可 append；nil map 读返回零值，但写会 panic。声明 map 必须 make 或用字面量。
  5. 遍历 map 删除元素：range 过程中 delete 安全，但新增元素不确定是否被遍历到，逻辑别依赖。
  6. [3]int 与 []int 类型不同：函数参数类型必须匹配，数组按值传递（拷贝），切片按引用。

最佳实践

  • 切片是首选集合类型；数组多用于固定长度或作为底层存储。
  • 预分配容量：make([]T, 0, n) 避免多次扩容。
  • map 取值用 v, ok 形式判断存在性，避免把”零值”当”存在”。
  • 函数参数接收切片时注意可能修改调用方底层数据；只读加注释或用值拷贝。
