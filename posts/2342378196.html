Git Hooks：钩子实战

[!info] 本页概览
本文讲解 Git Hooks 原理与实战：客户端/服务端钩子、常用脚本、pre-commit 框架、husky，配真实脚本示例。

[!note] 为什么用框架
手写 .git/hooks 不随仓库共享（.git 目录不入库）；pre-commit 框架通过配置 + install 让团队一致，且自动升级。

前端 husky

commitlint 校验提交信息

常见坑

  1. 钩子不入库：.git/hooks 本地文件，团队需用框架（pre-commit/husky）。
  2. 钩子太重：pre-commit 跑全量测试会拖慢提交，分层（快检查本地、全量 CI）。
  3. –no-verify 绕过：钩子只是防线，CI 必须兜底。
  4. 脚本跨平台：Windows 无 bash 时用 nvm/ husky 或确保 sh 可用。
  5. commit-msg 与 PR 规范不一致：两端统一规则。

最佳实践

  • 用 pre-commit / husky 框架共享钩子。
  • 分层：pre-commit 快检查（format/lint），pre-push 中等（单测），CI 全量。
  • 配合 09-提交信息规范 与 05-PR与MR流程。
