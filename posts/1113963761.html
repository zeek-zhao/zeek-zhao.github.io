24-内存保护MPU

发表于2026-10-24|FreeRTOS
|浏览量:

[!info] 本节目标
了解 FreeRTOS MPU 支持与安全隔离设计。

1. MPU 概述

内存保护单元 MPU 为处理器提供内存访问控制，划分特权与非特权区域，防止任务越权访问。MPU 增强系统安全性与健壮性，适合安全敏感与可靠性要求高的应用。

2. FreeRTOS MPU 版本

FreeRTOS 提供 MPU 支持版本，内核 API 分为特权与非特权接口。任务分为特权任务与非特权任务，非特权任务受限访问内存与外设。MPU 配置在任务切换时更新。

3. 内存区域划分

系统内存划分为内核区、任务栈区与共享数据区，MPU 区域属性定义访问权限。非特权任务仅可访问自身栈与共享区域，防止非法访问破坏系统。

4. 任务隔离

MPU 任务运行于受限上下文，崩溃或非法操作被硬件拦截。系统级函数通过特权调用机制提供服务。任务间数据交换通过安全机制传递，避免直接指针访问。

5. 配置与移植

MPU 支持依赖芯片硬件，需在移植层配置区域与权限。FreeRTOSConfig 使能 MPU 相关选项。区域数量与内存布局受硬件限制，设计时评估覆盖范围。

6. 应用场景

MPU 用于多租户系统、安全认证场景与防故障扩散。非可信第三方任务隔离运行，核心服务受保护。医疗与工业控制受益于内存隔离的健壮性。

7. 实践要点

MPU 增加切换与内存开销，评估性能影响。区域配置精确匹配内存布局，避免误隔离。安全设计从威胁模型出发定义保护边界。测试覆盖越权访问场景验证防护有效。

8. MPU 设计与性能平衡

MPU 配置随任务切换更新，增加切换开销与代码复杂度。区域数量有限，按安全需求优先级分配，非关键内存不纳入保护。特权调用机制增加 API 调用路径长度，热路径评估性能影响。安全设计与性能冲突时按威胁模型确定保护范围，避免过度隔离。测试验证越权访问被正确拦截，同时确认合法访问不受影响，在安全性、性能与实现复杂度间取得平衡。
