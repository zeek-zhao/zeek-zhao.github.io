13-与Gerrit集成

用 Gerrit Trigger 在 PatchSet 推送时跑验证构建，并把 Verified 结果回写 Gerrit。
📅 2026-11-07· 更新于 2026-11-07 · 641 字 · 约 2 分钟 ✍ zeek.zhao #指南#jenkins

与 Gerrit 集成

上一篇 12-与Git集成 讲的是推送即构建，这一篇接代码评审。Gerrit 是代码评审系统（见 Gerrit 系列），Jenkins 在它上面跑验证构建：每次 PatchSet 推送自动验证，再把 Verified 标签写回去。

先装 gerrit-trigger 插件¶

**Manage Jenkins → Plugins → 安装 gerrit-trigger**。

连接配置靠 SSH 私钥¶

Manage Jenkins → Gerrit Trigger → Add new server：

📝前置条件
Gerrit 侧创建 jenkins 账号并加入可访问项目的组；SSH 公钥配置见 Gerrit SSH 配置。

验证任务按项目名模式触发¶

Job 配置 → Build Triggers → Gerrit event：

Pipeline 方式（脚本化触发参数）：

构建结束自动回写 Verified¶

构建结束后 Jenkins 会把 Verified +1 / -1 写到 Gerrit Change：

🔥可用环境变量
GERRIT_CHANGE_NUMBER、GERRIT_PATCHSET_NUMBER、GERRIT_BRANCH、GERRIT_REFSPEC（形如 refs/changes/xx/yy/zz，用于精确 checkout 该 PatchSet）。

用 GERRIT_REFSPEC 精确检出¶

我一般直接用 GERRIT_REFSPEC 检出，这样每个 PatchSet 都是精确的，不会串到别的提交上。

一句话走完评审到主干 CI 的流程¶

验证任务我基本写成幂等的，同一 PatchSet 重跑结果得一致；并发多的时候加队列限制，别让验证洪峰把 Agent 打满。

⚠️注意
  • SSH 私钥需与 Gerrit 公钥匹配；权限不足会报 not permitted；
  • 验证任务要幂等：同一 PatchSet 重跑结果一致；
  • 大量并发 PatchSet 时给触发任务加队列限制，防验证洪峰。
