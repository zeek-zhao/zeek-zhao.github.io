29-性能优化

发表于2026-10-25|groovy
|浏览量:

[!info] 本节目标
动态语言性能需要针对性优化，学习分析与提速手段。

1. 性能特点

Groovy 动态调用有运行时开销，性能低于 Java 静态编译代码。但大部分应用瓶颈不在语言本身，而在算法、IO 与架构，先分析再优化。

Groovy 3+ 提供静态编译选项，可以显著缩小与 Java 的性能差距。

2. 分析与基准

用 JFR、VisualVM、JMH 基准测试定位热点。分析 CPU、内存与 IO 指标，找出真实瓶颈。

基准测试注意 JVM 预热与测试隔离，避免结果失真。

3. @CompileStatic 提速

@CompileStatic 在编译期绑定类型与方法，避免动态分发开销，性能接近 Java。适合热点类与核心逻辑。

@TypeChecked 提供静态检查但保留动态分发，作为渐进过渡。

4. 内存与集合优化

避免在循环中创建大对象与字符串拼接；使用合适集合结构与初始容量；大量数据处理用流式与惰性求值。

GString 与正则表达式注意复用；大文件流式处理避免内存峰值。

5. 并发与缓存

利用并发库并行化 CPU 密集任务；缓存高频计算结果（memoize 或显式缓存）；异步化 IO 等待。

缓存注意一致性与淘汰策略，避免内存泄漏。

6. 优化实践流程

先建立基准，再优化热点，每次改动后重新测量；优先算法与 IO 优化，再考虑语言级技巧；动态灵活性优先的代码不必过度优化。

性能优化是系统工程：合理目标、可复现测量、持续监控。

7. 性能优化实战

字符串拼接在热路径用 StringBuilder 或 GString 预编译，避免循环内反复创建对象。

集合按业务量设定初始容量，减少扩容拷贝；大对象池化复用，降低 GC 压力。

优化效果以基准为准：记录优化前后指标，确认收益真实且可复现，避免凭感觉优化。
