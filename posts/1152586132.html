Jira MCP 接入过程记录

ℹ️文档用途
本文档按时间线汇总本次在本机添加并连接 Jira MCP 的完整过程，记录失败尝试、关键解决步骤与经验沉淀，供后续参考复用。

1. 需求背景¶

  • 用户要求：添加 Jira MCP 并完成连接；
  • 目标站点：https://issues.rollingwireless.com/（自托管 Jira，非 Cloud）；
  • 客户端：Marvis（本机 MCP 管理器）。

2. 时间线¶

2.1 失败尝试 1：官方 Rovo 端点（Cloud-only）¶

  • 操作：尝试通过官方 Atlassian Rovo MCP 端点 https://mcp.atlassian.com/v2/mcp 安装；
  • 结果：失败；
  • 结论：官方 Rovo MCP 仅支持 Jira Cloud（OAuth 2.1 认证），不适用于自托管站点。自托管 Jira 必须改用社区版 mcp-atlassian。

2.2 失败尝试 2：社区版 config 使用 ${...} 占位符¶

  • 操作：改用社区版 mcp-atlassian，但在 config 的 env 中使用 ${...} 占位符写法；
  • 结果：安装校验失败；
  • 结论：私有（private）config 不接受占位符，必须填入真实凭据才能通过校验。

2.3 失败尝试 3：确认卡片在手机端多次超时¶

  • 操作：在手机端操作 Marvis，安装流程弹出 mcp_install 确认卡片，等待用户点击「连接」；
  • 结果：确认卡片多次超时，安装流程反复中断；
  • 结论：确认类弹窗在手机端容易因等待超时而失败，需要显式提醒用户及时点击「连接」。

2.4 失败尝试 4：config 缺少 "type": "stdio" 字段¶

  • 操作：config 中未声明 "type": "stdio" 即提交安装；
  • 结果：服务状态卡在 initializing / streamablehttp，工具数为 0；
  • 结论：stdio 类 MCP 服务**必须显式声明 "type": "stdio"**，否则客户端无法正确识别启动方式。

  • 操作：派发 browser-agent 在浏览器中登录 Jira 个人设置，创建 Personal Access Token（PAT），令牌名 mcp-jira；
  • 结果：成功取得真实 PAT，用于 config 的 JIRA_PERSONAL_TOKEN 字段。

3.3 补充 "type": "stdio" 后安装成功¶

5. 经验沉淀¶

  1. **自托管 Jira 必须使用社区版 mcp-atlassian**：官方 Rovo MCP 仅限 Jira Cloud，自托管 Server / DC 无官方端点可选；
  2. 确认卡片手机端易超时：mcp_install 弹窗需要用户点击「连接」，在手机端操作时应显式提醒用户及时响应，避免多次超时；
  3. 私有 config 必须使用真实凭据：${...} 占位符无法通过安装校验；
  4. **stdio 服务必须声明 "type": "stdio"**：缺失该字段会导致服务卡在 initializing / streamablehttp、工具数为 0；
  5. **启动入口优先使用 python -c**：本机缺少 uvx 时，python -c "from mcp_atlassian import main; main()" 是稳定可靠的 stdio 入口；
  6. PAT 生成可借助 browser-agent：浏览器自动化可快速完成登录、建令牌、取凭据全流程。
