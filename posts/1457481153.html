11-部署方式总览

对比 GitHub Pages、Vercel、Netlify、Cloudflare Pages 与自有服务器等 Hexo 部署方案，帮你选对发布路径。
📅 2026-10-25· 更新于 2026-10-25 ✍ zeek.zhao #工具#hexo

部署方式总览

📑一句话：Hexo 构建出来的是纯静态文件，部署的本质就是”把 public 目录送上网”，选对托管平台决定了后续的访问速度、自动化程度和维护成本。

部署的本质¶

执行 hexo generate 后，Hexo 会在项目根目录生成一个 public/ 文件夹，里面是构建完成的 HTML、CSS、JavaScript 与图片资源。所谓”部署”，就是把这份静态产物放到一台能被公网访问的服务器上。理解了这一点，所有的部署方案都只是”传输方式 + 托管位置”的不同组合，没有神秘感可言。

托管位置大致有三类：静态托管平台（GitHub Pages、Vercel、Netlify、Cloudflare Pages）、自有服务器（VPS + Nginx，通过 SSH 推送）、对象存储 + CDN（如 COS/OSS 配合 CDN 加速）。传输方式则包括 hexo-deployer-git 推送 Git 分支、SFTP/SCP 上传、rsync 同步，以及本文重点推荐的 GitHub Actions 全自动流水线。

主流托管平台对比¶

平台 免费额度 国内访问 特色
GitHub Pages 完全免费 一般 与源码仓库深度集成，生态最成熟
Vercel 个人免费 一般 构建快，预览环境丰富，边缘节点多
Netlify 个人免费 一般 表单、重定向等附加功能丰富
Cloudflare Pages 免费且宽松 较好 全球 CDN，绑定自定义域名后国内可达性提升
自有 VPS 服务器成本 取决于机房 完全可控，可部署动态服务
📝2026 更新
GitHub Pages、Vercel、Netlify、Cloudflare Pages 均为主流托管选择；GitHub Actions 全自动部署已是当前标准实践。若受众主要在国内，可考虑 Cloudflare Pages + 自定义域名的组合，实测可达性明显优于默认的 github.io 域名。

方案三：GitHub Actions 全自动部署¶

这是本套件强烈推荐的现代化方案：把 Hexo 源码放在一个私有仓库，推送到 main 分支时 GitHub Actions 自动完成”安装依赖 → 构建 → 发布”的全流程，本地只需要 git push。它同时解决了环境一致性、构建可追溯、多平台发布等问题，具体配置将在 12-GitHub Actions自动部署 中逐步拆解。

🔥源码与产物分离
无论选哪种方案，都建议把”源码仓库”和”产物仓库”分开管理（例如 blog-source 与 username.github.io）。源码仓库记录 Markdown 与配置变更历史，产物仓库只存放构建结果，回滚和迁移都更轻松。

如何选择¶

给一个简单的决策路径：纯新手选 GitHub Pages + Actions 自动部署，零成本且免维护；国内读者为主选 Cloudflare Pages 并绑定自定义域名；已有 VPS 或需要动态能力选 SSH 自托管；企业内或多人协作则把 Actions 流水线扩展出预发布环境。选型不必一步到位，静态站点的迁移成本极低，随时可以换平台。
