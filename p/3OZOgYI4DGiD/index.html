1. Gerrit 简介

Gerrit 是一个基于网页的代码审查和项目管理工具，专为 Git 版本控制系统设计。它促进软件开发者在提交代码到代码库之前互相检查修改。Gerrit 使用 Git 作为底层版本控制系统，并在其之上提供额外的功能。

1.1 Gerrit 的核心功能

mindmap
  root((Gerrit核心功能))
    代码审查
      多人评审机制
      行内评论
      评分系统
      交互式讨论
      版本比较
    访问控制
      细粒度权限控制
      基于分支的ACL
      用户组管理
      项目级权限
      标签级权限
    CI集成
      验证触发器
      构建状态反馈
      自动检查
      预提交测试
    工作流程强制
      提交前代码审查
      多级审批流程
      提交验证
      自动合并
    分支管理
      多仓库支持
      分支保护
      提交历史管理
      标签管理

1.3 Gerrit 历史与演进

timeline
    title Gerrit发展史
    section 早期阶段
        2008 : Shawn Pearce (Git贡献者) 开发了Gerrit
        2009 : Gerrit 2.0发布，完全重写为Java应用
    section 成熟期
        2010-2013 : Google采纳Gerrit作为内部代码审查系统
        2013-2015 : 添加了插件架构，代替脚本注入点
        2016 : Gerrit 2.13引入了PolyGerrit UI
    section 现代阶段
        2018 : Gerrit 2.15引入了NoteDb，取代关系型数据库
        2019 : Gerrit 3.0发布，完全使用NoteDb存储
        2020至今 : 改进用户体验和性能，支持现代开发流程

4. Gerrit 工作流

4.1 基本代码审查流程

sequenceDiagram
    participant D as 开发者
    participant G as Gerrit服务器
    participant R as 审查者
    participant I as CI系统

    D->>D: 克隆仓库
    D->>D: 创建分支
    D->>D: 修改代码
    D->>D: 提交变更
    D->>G: 推送变更进行审查
    G->>G: 创建更改请求(Change)
    G->>I: 触发CI构建
    I->>G: 返回构建结果
    G->>R: 通知审查者
    R->>G: 审查代码并评论
    G->>D: 转发评论和建议
    D->>D: 进行必要修改
    D->>G: 上传新的补丁集(Patch Set)
    R->>G: 批准变更(+2)
    G->>G: 验证所有条件已满足
    G->>G: 合并变更到目标分支
    G->>D: 通知合并完成

4.3.2 审查操作

  1. 行内评论：点击代码行左侧的行号，添加特定行的评论
  2. 回复评论：点击已有评论下方的”Reply”按钮
  3. 添加评分：在更改页面右上角的”Code-Review”和”Verified”选择框中选择适当的分数
  4. 提交评论：点击”Reply”按钮，添加总体评论并提交所有反馈
  5. 批准更改：如有权限，可以选择”+2”评分并点击”Submit”按钮提交更改
