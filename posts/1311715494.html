应用性能监控 APM

[!abstract] 是什么
APM（应用性能监控）解决”某个接口为什么慢“：采集请求耗时、调用链、错误堆栈，定位到具体方法与服务。

Kibana APM 界面用法

  1. 服务地图（Service Map）：服务间调用拓扑；
  2. Transactions：按接口看吞吐与耗时（P50/P95/P99）；
  3. Traces：单请求调用链（哪个下游慢、DB 慢还是外部 API 慢）；
  4. Errors：按异常类型聚合与堆栈查看；
  5. 设置告警：高延迟、错误率上升（见 16-告警与Watcher）。

[!tip] 典型排查故事
用户投诉接口慢 → APM 看到 P95 涨到 3s → Trace 显示 80% 时间在 SELECT ... → 定位慢 SQL 并优化索引 → P95 回落到 200ms。

[!warning] 注意

  • Agent 采样率与吞吐量平衡（默认 10% 采样可满足大多数场景）；
  • APM 数据会持续占用存储，结合 ILM 设置保留期；
  • 与日志关联：Trace ID 写入应用日志，Kibana 中 Logs ↔ APM 联动定位。
