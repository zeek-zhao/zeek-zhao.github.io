生产实践

[!info] 本节目标
将 dnsmasq 落地到生产环境的完整实践：高可用、监控、变更管理与规范。

部署架构

生产内网建议采用双节点主备：

  • 两节点配置文件通过 git 或 rsync 同步
  • keepalived 检测 dnsmasq 进程与端口，异常自动切换
  • 客户端 DHCP 下发 VIP 作为 DNS

配置管理规范

使用 conf-dir 拆分模块：

变更流程：编辑 -> dnsmasq --test -> 灰度重载（SIGHUP）-> 验证 -> 提交配置库。

监控指标

接入 Prometheus + node_exporter 或自定义脚本：

指标 采集方式 告警
进程存活 进程/端口探测 宕机 P1
解析成功率 定期 dig 探测 < 99.9% 告警
查询量 日志统计 突增告警
缓存命中率 日志统计 cached/query 持续偏低检查
DHCP 租约数 leases 文件行数 接近池上限告警

日志规范

  • 统一走 syslog + logrotate 轮转（按天或按大小）
  • 保留 90 天，满足审计
  • 关键变更记录到变更台账

灰度与回滚

容量规划

  • 单实例：缓存 1 万条可支撑 2-5 千终端日常解析
  • 大规模（万级终端）：多实例 + 一致性分流（按网段/策略）
  • 内存预算：cache-size 每条约 200-500 字节

[!tip] 长期建议
内网规模变大后，dnsmasq 定位应聚焦”边缘 DNS 网关”（缓存+条件转发+DHCP），权威解析交给 BIND，递归交给 Unbound，职责分离更稳。
