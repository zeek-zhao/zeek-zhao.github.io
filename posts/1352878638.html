51-深度学习基础与CNN

深度学习是机器学习的一个子领域，用多层神经网络模拟人脑的信息处理和模式识别，靠大量数据自动提特征、做决策。自动驾驶的环境感知、轨迹预测这些模块，算法基石就在这里。
📅 2026-09-30· 更新于 2026-09-30 · 4108 字 · 约 11 分钟 ✍ zeek.zhao #apollo#教程

感知这块绕不开深度学习，这篇把基础概念和 CNN 串一遍，再落到检测、分割这些实际任务上。上一篇讲仿真，见 50-仿真平台对比与Gazebo-LGSVL实战；训练框架怎么选，放在 52-PyTorch与自动驾驶实践 和 53-TensorFlow与Caffe2在自动驾驶中的应用。

1. 深度学习到底在做什么¶

1.1 什么是深度学习¶

深度学习是机器学习的一个子领域，用多层神经网络模拟人脑的信息处理和模式识别，靠大量数据自动提特征、做决策。自动驾驶的环境感知、轨迹预测这些模块，算法基石就在这里。

1.2 发展简史¶

  • 1943 年 McCulloch-Pitts 神经元模型；1958 年感知器
  • 1986 年反向传播算法普及；1989 年早期 CNN；1997 年 LSTM
  • 2012 年 AlexNet 在 ImageNet 突破，引爆深度学习革命
  • 2017 年 Transformer 提出；2018 年后大规模预训练模型兴起
  • 2020 年代：BEV 感知、Occupancy Network、端到端自动驾驶（详见第 7 节）

1.3 神经网络基本原理¶

一个神经元完成”加权求和 + 偏置 + 激活函数”三步：

常用激活函数：

激活函数 公式 特点
Sigmoid 1/(1+e⁻ˣ) 输出 (0,1)，有梯度消失问题
ReLU max(0, x) CNN 默认选择，缓解梯度消失
Leaky ReLU max(0.01x, x) 解决 Dead ReLU
GELU x·Φ(x) Transformer 常用
Softmax eˣⁱ/Σeˣʲ 多分类输出层

损失函数与优化：回归用 MSE，分类用交叉熵；优化器从 SGD（+Momentum）到 Adam/AdamW。训练循环就是”前向传播 → 计算损失 → 反向传播 → 参数更新”。

入门的话，吴恩达《深度学习》课程和《动手学深度学习》（李沐）都值得过一遍，配合 59-自动驾驶学习资源与链接 里的资源表系统学。

2. CNN 靠什么处理图像¶

CNN 靠”局部连接 + 权重共享”高效处理图像这类网格结构数据，是自动驾驶感知的基石。

组件 功能 要点
卷积层 特征提取 卷积核尺寸/步长/填充决定输出尺寸；参数共享带来平移不变性
池化层 降维抗噪 最大池化/平均池化，增大感受野、减少过拟合
激活函数 引入非线性 ReLU 系列
全连接层 分类/回归 现代 CNN 趋向用全局平均池化替代，减少参数

PyTorch 里一个卷积层：

输出尺寸公式：out = (in + 2*padding - kernel) / stride + 1。

还有个绕不开的组件是批归一化（BatchNorm）：对每个 mini-batch 的激活值做归一化再缩放平移，能明显加速训练、允许更大学习率。小批量场景可以换 GroupNorm/LayerNorm。

3. 架构怎么一步步变深变轻¶

3.1 从 LeNet 到 ResNet¶

架构 年份 关键创新
LeNet-5 1998 首次系统使用卷积+池化组合，手写数字识别
AlexNet 2012 8 层深网、ReLU、Dropout、GPU 训练
VGG 2014 堆叠 3×3 小卷积核替代大核，结构简洁
GoogLeNet 2014 Inception 多尺度并行模块，参数量仅为 AlexNet 1/12
ResNet 2015 残差连接 H(x)=F(x)+x，突破百层深度
MobileNet 2017+ 深度可分离卷积，面向移动/车载端

3.2 残差连接的意义¶

传统网络直接学 H(x)；ResNet 让网络学残差 F(x) = H(x) − x。当最优映射接近恒等映射时，”把权重推向 0”比”学一个恒等映射”容易得多，深层网络的退化问题就这么绕过去了。ResNet-50/101 至今仍是自动驾驶感知骨干的常用选择。

3.3 轻量化：面向车载部署¶

  • 深度可分离卷积：逐通道卷积 + 1×1 逐点卷积，参数量约为标准卷积的 1/8~1/9
  • EfficientNet 复合缩放：按 α·β²·γ²≈2 同时缩放深度、宽度、分辨率
  • 模型压缩三板斧：量化（FP32→INT8，体积减 75%）、剪枝、知识蒸馏（大模型教小模型）

车载端偏爱 CNN 是有道理的：它有平移不变性这类归纳偏置，数据效率高、推理延迟确定，在算力受限的车载平台上依然比纯 Transformer 好部署。我倾向于 CNN 加 Transformer 的混合路线，像 Swin、ConvNeXt 这种，算是个务实的折中。

4. 感知任务里的 CNN¶

4.1 目标检测¶

  • 两阶段（Faster R-CNN、Mask R-CNN）：RPN 生成候选框再分类回归，精度高、速度慢
  • 单阶段（YOLO 系列、SSD、FCOS、CenterNet）：直接预测类别与位置，速度快，是车载感知主流
  • 3D 检测：SECOND、CenterPoint 等面向激光雷达点云

4.2 语义分割¶

  • FCN：全卷积化，端到端像素级分类
  • U-Net：编码器-解码器 + 跳跃连接，保留空间细节
  • DeepLab 系列：空洞卷积 + ASPP，多尺度上下文建模

分割结果用于可行驶区域判断、车道线提取等。

4.3 深度估计与多任务网络¶

  • 单目深度估计：MonoDepth/MonoDepth2；立体匹配：PSMNet
  • 多任务共享骨干：一个编码器接检测头、分割头、深度头、车道线头，共享特征大幅降低车载计算量

4.4 与 Apollo 感知的衔接¶

Apollo 感知模块中的 2D 检测器（如 YOLO 系）、车道线网络、红绿灯识别网络都基于 CNN。训练产出模型后经 ONNX/TensorRT 转换部署到车载推理框架，流程见 52-PyTorch与自动驾驶实践；感知数据从哪来、怎么标注，见 55-标注工具与数据闭环；模型上车后如何验证，见 54-自动驾驶测试方法。

5. 训练时几个常用招¶

  1. 迁移学习：冻结骨干只训新头，或分层设置学习率（底层 1e-5，新头 1e-2）
  2. 数据增强：随机裁剪/翻转/色彩抖动；自动驾驶场景避免垂直翻转
  3. 类别不平衡：Focal Loss（检测）、Dice Loss（分割）
  4. 学习率调度：余弦退火、OneCycle、ReduceLROnPlateau
  5. 调试利器：TensorBoard 监控曲线，Grad-CAM 可视化模型关注区域

6. 四个绕不开的难题¶

挑战 说明 缓解手段
泛化/域偏移 训练域到测试域性能下降 域适应、更大更多样的数据集
可解释性 黑盒决策难以满足安全监管 Grad-CAM、注意力可视化
算力与能耗 车载平台资源受限 量化、剪枝、蒸馏、轻量架构
长尾场景 罕见场景样本稀缺 数据合成、场景挖掘（见 55-标注工具与数据闭环）

7. BEV 和端到端正在改写感知¶

感知模型的主流范式已经从”2D 检测 + 后融合”演进为 BEV（鸟瞰图）+ Transformer + Occupancy Network：多摄像头特征统一投影到 BEV 空间，直接输出 3D 障碍物与占用栅格，天然适配端到端下游。同时，端到端自动驾驶（UniAD 为代表，以及 VLA——视觉-语言-动作模型）在 2024-2026 年成了研究热点，感知、预测、规划由一个网络联合完成。Apollo 这类工业界系统则普遍走”BEV 主干 + 分层模块”的折中路线，兼顾性能和可解释性。

CNN 没被淘汰，它只是换了个位置——继续当 BEV 骨干和车端轻量模型的核心组件。

操作步骤 使用流程¶

从原理走到能部署的感知模型，建议按这条流程：

  1. 明确任务与指标：先定是分类、检测还是分割，指标用 mAP、mIoU 还是延迟；任务不同网络结构差别很大。
  2. 搭基线网络：先用经典的 ResNet-50 或 TinyCNN 跑通前向，用 conv_out_size 核对每层尺寸。
  3. 核对卷积与池化形状：手写网络最容易在 flatten 处形状对不上，先用随机张量跑一遍 forward。
  4. 接数据与损失：检测用 Focal Loss、分割用 Dice/CE+Dice，回归用 SmoothL1；按任务选对损失。
  5. 训练与监控：用 TensorBoard 看损失和精度曲线；迁移学习冻结骨干、分层设学习率。
  6. 可解释性排查：效果异常时用 grad_cam 看模型关注区域，确认它看的是物体而不是背景。
  7. 轻量化：车载部署前做深度可分离卷积替换、INT8 量化、剪枝、蒸馏，对比精度损失。
  8. 延迟基准：用 benchmark_latency 量实际帧耗时，确认满足车载实时性要求（通常 < 30ms）。
  9. 上车验证：转 ONNX/TensorRT 后在目标硬件复测（流程见 52-PyTorch与自动驾驶实践），再做整车验证（见 54-自动驾驶测试方法）。

注意事项与常见坑¶

CNN 实现与训练里最容易翻车的点：

  1. 卷积输出尺寸算错：padding/stride/dilation 任一设错，flatten 时形状对不上；先用 conv_out_size 和随机张量验证每层的 shape。
  2. BatchNorm 与小 batch：batch 太小时 BN 统计量不稳，效果反而变差；改用 GroupNorm 或冻结 BN。
  3. **漏写 model.eval()**：验证/推理时忘了切 eval，BN 和 Dropout 还在工作，每次结果不一样。
  4. 验证阶段没关梯度：推理时忘了 torch.no_grad()，白白构建计算图，显存暴涨、速度变慢。
  5. 垂直翻转数据增强：自动驾驶场景上下翻转会破坏物理含义（天变地、车倒过来），只能用水平翻转。
  6. 类别不平衡未处理：检测/分割里前景极少，不加权或用 Focal/Dice 的话，模型全预测背景也能拿高分。
  7. 残差块支路 stride 错：下采样时 shortcut 也要用 1×1 卷积匹配通道和尺寸，否则 out + shortcut 形状不符报错。
  8. 深度可分离卷积 groups 写错：groups 必须等于输入通道数，否则不是逐通道卷积，参数量和效果都不对。
  9. 量化后精度掉太多没测：FP32→INT8 必须做校准（PTQ/QAT）并对比精度损失，别等上车才发现漏检。
  10. 延迟只看 FPS 不看 p99：车载要的是确定性低延迟，平均帧率够不代表 p99 达标；用 benchmark_latency 多跑几轮看分布。
  11. BEV 投影坐标搞混：多摄像头投影到 BEV 时内外参和坐标系错一个，特征就错位，检测全飘（见 38-端到端自动驾驶与大模型）。
