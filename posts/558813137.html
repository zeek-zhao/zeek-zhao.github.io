插件生态总览

Hexo 的能力边界基本是插件划定的。我的习惯是先把插件分成生成器、渲染器、部署器、功能增强四类，脑子里有这张地图，再决定装什么，比零散看推荐靠谱得多。

从装插件到写插件，其实是同一套思维¶

Hexo 的模块化做得很彻底：连首页、归档、标签页这些”基础功能”本身也是由官方插件（generator）实现的。hexo init 安装的就是一组默认插件包，理解了这一点，你就明白装插件、写插件、换插件是同一种思维——用小的独立单元拼装出需要的站点能力。

插件生态现在已超过 400 个，GitHub 主仓库 39,000+ stars，仍是 Node.js SSG 中中文资料最丰富的。我装插件前一定会先去 GitHub 看最近提交时间，避免引入已经停止维护的包。

功能增强插件按需选装¶

这一类数量最多，列举高频成员：

  • hexo-wordcount：统计文章字数与阅读时长，配合主题的”本文字数/X 分钟”展示；
  • hexo-filter-mathjax：服务端 MathJax 公式支持，写作时在文章 front-matter 加 mathjax: true；
  • hexo-tag-aplayer：在文章中嵌入音乐播放器：
  • hexo-related-popular-posts：文章底部相关文章推荐；
  • hexo-all-minifier：构建期压缩 HTML/CSS/JS/图片，是 13-性能优化与构建加速 的基础手段；
  • hexo-blog-encrypt：文章密码保护，原理与用法详见 10-博客加密与内容保护；
  • hexo-helper-live2d：看板娘，配置模型、位置与透明度，为博客增加个性。

管好 package.json，插件多了也不乱¶

插件多了以后，package.json 就是博客的”依赖清单”，三条原则让它保持健康：

  1. 用 --save 安装，确保依赖写入 package.json，换机重建时 npm install 一步还原；
  2. 定期清理：不再使用的插件及时 npm uninstall，减少构建时间与冲突面；
  3. 警惕冲突：同时修改 HTML 结构或 Markdown 渲染的插件容易互相干扰（如加密插件与 HTML 压缩类插件），出问题时先二分排查。

写自己的插件也不难。Hexo 插件本质是一个导出注册函数的 npm 包：hexo.extend.filter/register、hexo.extend.generator/register、hexo.extend.tag.register 三个 API 覆盖了绝大多数场景，scripts/ 目录下的 JS 文件无需打包即可生效——07-Butterfly自定义侧边栏 中的图谱数据脚本就是一个”微型插件”。我一般先把小功能塞进 scripts/ 验证，跑顺了再考虑抽成独立包。
