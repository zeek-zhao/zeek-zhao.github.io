Caddy 简介与适用场景

[!info] 本节目标
了解 Caddy 的定位、核心特性与适用场景，判断是否适合替代 Nginx/其他反代。

什么是 Caddy

Caddy 是使用 Go 编写的开源 Web 服务器，以”自动 HTTPS”为核心卖点：

与 Nginx 对比

维度 Caddy Nginx
配置 Caddyfile 简洁 nginx.conf 复杂
HTTPS 全自动 需手动/脚本
扩展 模块化（xcaddy） 模块/Lua 丰富
性能 优秀（Go） 优秀（C）
生态 较年轻 成熟庞大
学习成本 低 中高

适用场景

  1. 个人/中小站点：自动 HTTPS 的静态博客、文档站
  2. 内网服务暴露：把 NAS、GitLab、监控等反代到域名
  3. API 网关：简单路由、负载均衡、限流
  4. 容器环境：与 Docker Compose 组合自动发现服务
  5. 快速原型：几分钟完成 HTTPS 上线

不适合的场景

  • 需要丰富第三方模块的复杂企业架构（Nginx/OpenResty 更合适）
  • 团队已有深厚的 Nginx 配置资产
  • 需要细粒度企业级 WAF 商业功能

快速体验

启动后访问 http://localhost:8080。

版本说明

  • Caddy v2 为当前主线（本套教程基于 v2）
  • Caddy v1 已停止维护，勿用于新项目
  • 通过 xcaddy 可编译带自定义模块的二进制

[!tip] 结论
追求”配置简单 + HTTPS 自动 + 运维省心”时 Caddy 优势明显；复杂企业场景则按现有资产权衡。
