Cleanup 与任务调度

[!abstract] 制品生命周期
Cleanup Policy 按规则删除组件，定时任务执行清理/修复/迁移，Compact Blob 真正回收磁盘。

1. 创建清理策略

条件 说明
Last downloaded 按最后拉取时间（缓存代理）
Last blobs updated 按 Blob 更新时间
is prerelease 预发布版本
正则表达式（资产名/路径） 精确匹配

2. 策略绑定仓库

[!note] 清理代理缓存
proxy 仓库清理只删缓存组件，不影响外部源（重新拉取自动回来）。

3. 定时任务（Tasks）

常用任务：

任务 用途
Cleanup - Remove unused components 执行清理策略
Compact blob store 回收已删组件的磁盘空间
Repair - Rebuild repository browse 重建浏览索引
Rebuild Maven metadata 修复 maven-metadata.xml
Admin - Blob store migration Blob 迁移
Health check 健康检查

调度：

4. 完整运维节奏

5. 磁盘空间告警

  • 配额预警（08-Blob Store与存储）；
  • 监控 Blob 目录使用率；
  • Cleanup 后观察实际释放量（du -sh /opt/nexus-blobs/*）。

[!warning] 注意

  • Compact Blob 是物理删除，执行前确认清理策略准确；
  • 清理不区分”仍在用的老组件”：被 CI 引用会拉不到（404）重新缓存；
  • 大库首次 Compact 耗时长，安排在低峰。

6. 查看任务日志

[!tip] 建议

  • 代理缓存保留 60-90 天足够；
  • snapshot 库：保留 30-60 天 + 只清 snapshot；
  • 私有 release 库不建议按时间清理（历史版本有合规/回滚价值）。
