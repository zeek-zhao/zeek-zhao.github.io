11-SDK与交叉编译

发表于2026-10-24|yocto
|浏览量:

[!info] 本节目标
生成并使用 Yocto SDK，掌握交叉编译环境搭建与应用开发。

1. 交叉编译概念

交叉编译指在宿主机架构上编译目标机架构可执行文件。Yocto 提供完整的交叉工具链，包括编译器、链接器、库与 sysroot。

2. 生成 SDK

SDK 脚本位于 tmp/deploy/sdk/，在目标开发机上运行安装即可。

3. 使用 SDK

设置后可直接使用 gcc、make 等交叉编译工具。

4. 外部工具链配置

企业可在 TCMODE 与 EXTERNAL_TOOLCHAIN 配置中使用外部工具链，保证与量产工具链一致。

5. 开发集成

SDK 支持与 IDE、CMake、Makefile 集成，便于应用开发团队独立开发。SDK 还包含 QEMU 环境用于目标机验证。

6. 常见问题

交叉编译常见问题包括 sysroot 不匹配、库路径错误与架构不匹配。使用 SDK 自带脚本初始化环境可避免多数问题。

8. SDK 与 sysroot 详解

标准 SDK 与 eSDK 均包含 sysroot 目录，提供目标系统头文件与库。应用编译时通过环境变量引用 sysroot，链接器从 sysroot 解析依赖库。eSDK 还包含 devtool 与配方工作区，可在不依赖完整构建环境的情况下开发应用。理解 sysroot 结构，可帮助排查头文件版本不一致、库路径错误等常见问题。

9. 交叉编译问题排查

常见问题包括：使用了主机工具链导致编译错误；头文件或库缺失导致链接失败；路径硬编码导致部署异常。排查方法：确认环境脚本已生效，检查编译日志中的工具链路径，使用 file 命令验证产物架构，在目标机运行验证动态链接依赖。结合调试技巧与日志篇的方法可快速定位多数问题。

10. 交叉编译环境变量

交叉编译依赖环境变量：CC、CXX 指向目标工具链；CFLAGS/LDFLAGS 包含目标架构选项；PATH 优先目标工具链目录；PKG_CONFIG_PATH 指向目标 sysroot 的 pkgconfig。Yocto SDK 环境脚本已配置好这些变量，source 后直接使用。手动配置时注意避免主机工具干扰，验证编译产物架构与链接库正确性。
