Context 与超时控制

[!info] 本页概览
context 包是 Go 并发控制的基石：在 goroutine 间传递取消信号、超时与请求级元数据。本文讲解 context 的四种创建方式、传递规则与标准库中的使用范例。

核心概念

context.Context 是一个携带截止时间、取消信号与键值对的接口。核心思想：取消要层层传递——父 context 取消，所有派生的子 context 一并取消，下游 goroutine 收到通知后主动停止工作。

[!warning] WithValue 规范
key 必须是自定义类型（避免字符串 key 冲突）；value 应只放请求级只读元数据（trace id、用户 ID），不要放可变状态。

常见坑

  1. 忘记调用 cancel：context.WithCancel/WithTimeout 必须 defer cancel()，否则资源（定时器、goroutine）泄漏。超时版即使超时也会在到期后自动释放，但显式 cancel 更早。
  2. 把 context 存进结构体：context 应作为函数第一个参数传递，不存字段（官方约定）。
  3. 取消后仍继续工作：下游不监听 ctx.Done()，取消通知形同虚设。所有阻塞操作应 select ctx.Done()。
  4. 用 Background 替代业务 context：数据库/HTTP 调用应接收传入的 ctx 才能超时与取消，自行 Background 失去链路控制。
  5. context 不可比较/序列化：不能存 map、不能跨进程传输；跨服务用 trace header（W3C Trace Context）。

最佳实践

  • 每个可能阻塞的 goroutine/请求都接受 ctx context.Context 作为第一参数。
  • 超时值从配置注入（用户请求带超时，服务内部有兜底超时）。
  • HTTP handler 用 r.Context() 获取请求 context，请求取消自动传播。
  • 日志携带 trace ID：WithTraceID 注入，日志包统一提取。
  • 库代码绝不取消 parent context（只读或派生自己的子 context）。
