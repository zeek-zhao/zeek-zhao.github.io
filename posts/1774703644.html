性能优化

[!info] 本页概览
本文讲解 Vue 应用性能优化：构建体积、加载性能、运行时渲染优化、列表优化（虚拟滚动）、缓存策略、性能监控，系统提升用户体验。

核心概念

性能优化分两层：加载性能（首屏资源、分包、缓存）与运行性能（渲染、更新、交互响应）。先测量再优化，避免无依据的过度优化。

构建体积优化

  • 大库按需引入（echarts 按模块、lodash-es 按函数）。
  • 路由/组件懒加载（见 14-组件高级模式）。
  • 产物压缩（Vite 默认 esbuild/terser）。

加载性能

  • 静态资源 hash + 长缓存（见 17-部署）。
  • 图片懒加载 loading="lazy"、WebP、CDN 压缩。
  • 骨架屏 + 异步组件占位，提升感知速度。

运行时渲染优化

  • key 稳定唯一，避免整表重建。
  • 列表大：分页 / 虚拟滚动（vue-virtual-scroller）。
  • 避免大对象 deep watch；用 getter 精确侦听。
  • 事件委托：列表项共用父级事件。

性能监控

常见坑

  1. 过度优化：小项目先关注可维护性；性能优化按需、量化。
  2. deep watch 大对象：每帧 diff 开销大；拆 getter 或浅比较。
  3. unstable key（index）：列表复用错乱；用唯一 id。
  4. shallowRef 忘整体替换：push 进浅 ref 不触发更新；整体赋值新数组。
  5. v-memo 依赖数组不完整：漏依赖导致不更新；与 v-for 组合谨慎。
  6. SSR/SSG 场景：客户端水合与缓存策略不同，勿照搬 CSR 配置。

最佳实践

  • 建立性能基线（Lighthouse 分数、包体积），每次发布对比。
  • 首屏优先：关键路径资源预加载，非关键异步。
  • 大数据渲染走分页/虚拟滚动，避免 DOM 爆炸。
  • 缓存”读多写少”数据，注意失效策略。
  • 团队定性能预算（如 main bundle < 200KB gzip）。
