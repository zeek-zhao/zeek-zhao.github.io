JDBC与数据库访问

[!info] 本页概览
本文讲解 JDBC 核心：驱动加载、Connection/Statement/PreparedStatement/ResultSet、事务管理、连接池（HikariCP）、以及 MyBatis/Spring JDBC 简化实践，配可运行示例与常见坑。

核心概念

  • JDBC（Java Database Connectivity）：Java 访问数据库的标准接口。
  • 核心接口：DriverManager/DataSource、Connection、Statement、PreparedStatement、ResultSet。
  • PreparedStatement 预编译 + 参数化，防 SQL 注入。
  • 事务：ACID；默认自动提交，可关闭自动提交手动 commit/rollback。
  • 连接池：复用连接，避免每次新建（HikariCP、Druid）。

Spring JDBC 与 ORM 简介

[!note] 选型建议
简单项目用 Spring JDBC；复杂 SQL/动态 SQL 用 MyBatis；领域模型复杂、跨数据库用 JPA/Hibernate。生产必配连接池 + 慢查询日志。

常见坑

  1. SQL 注入：字符串拼接 SQL 是重灾区；一律参数化（PreparedStatement）。
  2. 资源泄漏：Connection/Statement/ResultSet 未关闭；用 try-with-resources。
  3. 事务边界混乱：事务要短而明确；锁资源及时释放。
  4. 连接未归还：连接池连接用完不 close（实际归还池中）导致池耗尽。
  5. 时区问题：连接 URL 配 serverTimezone=Asia/Shanghai。
  6. ResultSet 遍历：必须 rs.next() 判断后再 get；列索引从 1 开始。
  7. 批量操作慢：用 addBatch/executeBatch 或 rewriteBatchedStatements 参数。
  8. 驱动版本与数据库不匹配：MySQL 8 用 com.mysql.cj.jdbc.Driver。

最佳实践

  • 所有 SQL 参数化，禁止字符串拼接。
  • 连接获取/释放用 try-with-resources 或框架管理。
  • 事务只在需要的地方开启（@Transactional 粒度到方法）。
  • 连接池参数按负载调优：maximumPoolSize、connectionTimeout、validationTimeout。
  • 结合 16-Spring Boot 入门 使用 Spring Data/MyBatis 减少样板代码。
