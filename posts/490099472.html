接口与抽象类

[!info] 本页概览
本文讲解接口与抽象类的区别、用法、Java 8+ 默认方法/静态方法、函数式接口、接口的多继承能力，配可运行示例与选型建议。

核心概念

  • 抽象类：用 abstract 修饰，可含抽象方法与具体方法，不能实例化，用 extends 继承（单继承）。
  • 接口：用 interface 声明，定义契约；类用 implements 实现（可多实现）。
  • 抽象方法：只有声明没有实现体，子类/实现类必须实现（除非自身抽象）。
  • Java 8+：接口可含 default 方法、static 方法；Java 9+：private 方法。

[!note] 实践建议
优先接口定义能力契约；有公共状态/模板骨架时用抽象类（模板方法模式）。

常见坑

  1. 接口字段都是常量：int x = 1; 实际是 public static final int x = 1;，不能修改。
  2. 默认方法冲突：多接口同名 default 方法必须显式 override。
  3. 抽象类不能实例化：new Shape() 编译错误。
  4. 未实现抽象方法：具体类实现所有抽象方法，否则类必须声明 abstract。
  5. 函数式接口多抽象方法：lambda 无法匹配多个抽象方法（@FunctionalInterface 会编译报错）。
  6. 继承 + 实现顺序：先 extends 后 implements：class C extends A implements B {}。

最佳实践

  • 接口命名以能力词结尾：-able/-ible（Runnable、Comparable）。
  • 业务能力契约放接口，公共骨架放抽象类，实现细节放具体类。
  • 用 default 方法向后兼容扩展接口（如 Collection.stream）。
  • Lambda 替代只含一个抽象方法的匿名类，代码更简洁。
  • 接口保持小而专（接口隔离原则 ISP）。
