常见坑

  1. rm -rf 误删：高危险；先 ls 预览，用引号与绝对路径，或 rm -i。
  2. find -exec 分号转义：\; 与 + 的区别（逐个 vs 批量参数），注意转义。
  3. 通配符不匹配时字面残留：for f in *.txt 无匹配时 $f 是 *.txt，用 nullglob 或 [ -f ] 判断。
  4. cp 覆盖不提示：cp -i 交互；批量前确认目标目录。
  5. 符号链接与源混淆：rm soft 只删链接；rm -r soft/ 可能删目标内容（取决于实现），谨慎。
  6. 路径含空格：所有引用加引号，遍历用 while IFS= read -r。

最佳实践

  • 删除类操作三连：先 find -print 预览 → 确认 → 执行；高危用 -delete 或移入 /tmp 暂存。
  • 备份脚本统一 cp -a（保留属性）或 rsync -a。
  • find 组合 -not -path、-prune 排除敏感目录（.git、node_modules）。
  • 路径拼接用 "${dir}/${file}"，避免斜杠问题。
  • 写脚本时用 set -u（见 14-安全与健壮性）防未定义变量路径错误。
