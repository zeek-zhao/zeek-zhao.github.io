GPIO 子系统与引脚控制架构

做嵌入式开发绕不开 GPIO，点灯、读按键、跟外设通信，第一件事往往就是它。我入行时也是从 GPIO driver 开始的，当时以为就是读写寄存器，后来才发现背后是 Pin Control 和 GPIO 两套子系统在配合。

这篇不去背 API 清单，而是顺着「硬件差异怎么被抽象掉」这条线，把 Linux 里 GPIO 的架构、编号和驱动写法过一遍。

一图看懂：GPIO 与 Pin Control 两层分工，屏蔽硬件差异。

graph TD APP[应用] --> GPIO[GPIO 子系统] APP --> PC[Pin Control 子系统] GPIO --> CHIP[gpio_chip 编号与消费者] PC --> STATE[Pin State 与 Map] CHIP --> HW[引脚硬件] STATE --> HW

一、前言：GPIO 是嵌入式的入口，难点在软件抽象¶

GPIO（General Purpose Input/Output，通用输入/输出）看着只是几个引脚，真要把不同平台、不同扩展芯片统一到一套接口后面，需要的架构并不简单。下面先从硬件差异说起，再一层层看内核怎么把它收干净。

二、GPIO 硬件基础：差异决定了必须做抽象¶

2.1 什么是 GPIO：可配方向的引脚¶

GPIO（General Purpose Input/Output）是嵌入式系统中最基本的I/O资源，它可以通过软件配置为输入或输出模式，在输入模式下可以读取引脚电平状态，在输出模式下可以控制引脚输出高电平或低电平。

GPIO的主要特性包括：

  • 可配置为输入或输出
  • 可读取或设置电平状态
  • 可配置上拉/下拉电阻
  • 部分GPIO支持中断功能
  • 部分GPIO支持唤醒功能

2.2 硬件差异性：五类差异催生两套子系统¶

在不同的硬件平台上，GPIO的实现存在诸多差异。我拿到一块新板子时一般先确认 GPIO 是 SOC 内置还是 I2C 扩展出来的，这决定了后面走哪套驱动。

  1. 与CPU的连接方式不同：

    • ARM SOC内部GPIO：通过SOC的总线(如AMBA)连接到CPU
    • 外部扩展GPIO：通过I2C、SPI等总线连接的IO扩展芯片

  2. 访问方式不同：

    • 有些SOC通过一个寄存器控制输出电平(写1为高，写0为低)
    • 有些SOC通过两个寄存器控制(一个寄存器写1设高，另一个写1设低)

  3. 配置方式不同：

    • 同一款SOC在不同系统中可能配置不同
    • 一个系统中的引脚在一个产品中可能是输入，在另一个中可能是输出

  4. 特性不同：

    • 中断支持：不是所有GPIO都支持中断功能
    • 唤醒能力：只有部分GPIO能将CPU从休眠状态唤醒
    • 上拉/下拉：有些GPIO支持软件控制的上拉或下拉电阻配置
    • 去抖动(debounce)：部分GPIO支持输入去抖动功能

  5. 多功能复用：

    • 纯GPIO与复用GPIO：有些引脚只能作为GPIO使用，而有些可以复用为其他功能(如SPI、I2C等)

这种硬件差异性使得GPIO的抽象和管理变得复杂。Linux内核通过pin controller subsystem和GPIO subsystem两个子系统来解决这些差异问题。

三、GPIO 软件架构：三层分工与代码分布¶

3.1 整体架构：应用、GPIO、Pin Control 三层¶

Linux内核中GPIO相关的软件架构主要分为三层。我读源码一般从 /drivers/gpio 起步，顺着 consumer 接口往回找，很快就能摸清调用链。

  1. Pin Controller Subsystem：

    • 管理pin复用(multiplexing)
    • 配置pin的电气特性
    • 为上层提供pin管理接口

  2. GPIO Subsystem：

    • 管理GPIO资源
    • 控制GPIO的方向、电平
    • 处理GPIO中断
    • 向用户空间提供访问接口

  3. 应用层接口：

    • sysfs接口：/sys/class/gpio
    • 新一代libgpiod接口

3.2 代码结构：核心目录与关键头文件¶

GPIO子系统的核心代码位于：

  • /drivers/gpio - GPIO核心驱动和各种具体平台的驱动
  • /include/linux/gpio.h - GPIO子系统主要头文件
  • /include/linux/gpio/consumer.h - GPIO消费者接口
  • /include/linux/gpio/driver.h - GPIO驱动接口

Pin Controller子系统的核心代码位于：

  • /drivers/pinctrl - Pin控制器核心驱动
  • /include/linux/pinctrl/pinctrl.h - Pin控制器主要头文件

四、Pin Control 子系统：复用、电气配置与状态映射¶

4.1 基本概念：复用管理与电气配置¶

Pin Control子系统负责管理系统中所有可控制的引脚，主要功能包括：

  1. Pin Multiplexing：引脚功能复用管理

    • 配置引脚功能(如GPIO、SPI、UART等)
    • 管理功能之间的互斥

  2. Pin Configuration：引脚电气特性配置

    • 上拉/下拉电阻配置
    • 驱动强度(drive strength)配置
    • 输入/输出模式配置

4.2 软件抽象：Pin、Group、Function 与 Controller¶

Pin Control子系统围绕以下几个关键概念构建：

  1. Pin：物理引脚，每个引脚都有唯一编号

  2. Pin Group：一组相关的引脚，通常用于实现特定功能

  3. Function：引脚的功能定义，如GPIO、SPI、I2C等

  4. Pin Controller：物理上的pin控制器硬件，用软件抽象表示

5.1 基本概念：gpio_chip 是核心抽象¶

GPIO子系统管理所有的GPIO资源，提供统一的访问接口。核心抽象是gpio_chip：

每个gpio_chip代表一个GPIO控制器(如SOC内置的GPIO控制器或外部扩展芯片)，管理一组GPIO引脚。

5.2 编号机制：全局号、芯片内偏移与硬件号¶

Linux中GPIO有三种编号系统：

  1. 全局GPIO编号：系统范围内唯一的GPIO编号，从0开始
  2. 芯片内偏移：特定gpio_chip内部的偏移量
  3. 硬件GPIO编号：实际硬件文档中的GPIO编号

转换关系：全局GPIO编号 = gpio_chip->base + 芯片内偏移

踩过的坑是把硬件文档上的编号直接当全局号用，结果操作错了整组引脚——这两套编号一定要先换算清楚。

九、小结：理解 GPIO 子系统抓住三条主线¶

GPIO 操作本身很简单，真正值得记住的是内核怎么把平台差异藏起来。三条主线串起来看就通了：Pin Control 管引脚复用和电气配置，GPIO 子系统用 gpio_chip 把控制器统一成一套接口，中间的 GPIO Range 负责把两组编号对上。

从早期的 sysfs 到现在的 libgpiod，接口一直在换，但这三条主线没变。下次遇到 GPIO 相关的问题，先确认是复用没配对、编号没换算对，还是消费者接口用错了，基本就能定位到方向。
