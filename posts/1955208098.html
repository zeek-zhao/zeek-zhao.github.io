01-Hexo简介与核心概念

说清 Hexo 的定位、工作原理和几个核心概念，给后面的环境搭建和写作打底。
📅 2026-11-19· 更新于 2026-11-19 · 1115 字 · 约 3 分钟 ✍ zeek.zhao #工具#hexo

Hexo简介与核心概念

写博客这事，我不想跟服务器较劲，能专心写内容最好。Hexo 就是冲着这个来的：基于 Node.js 的静态博客框架，用 Markdown 写，几秒生成整站，也是中文圈用得最多的静态站点生成器之一。它在 GitHub 上攒了 39,000+ stars、400 多个插件，支持 EJS、Pug、Nunjucks 模板，还能接 Babel、PostCSS、Less、Sass 这套前端工具链，算是老树常青。这篇先把几个核心概念捋清楚。

选 Hexo，图的是轻和快¶

它的定位很明确：用最轻量的方式，把 Markdown 文章变成能扔到任何静态托管平台的博客。不用数据库、不用后端，写作时只管内容，生成和部署交给命令行一条龙。

我把它值得说的优势归纳成四点：

  1. 极速生成：依托 Node.js 的事件驱动模型，几百篇文章也能几秒构建完，配合本地预览保存即见效。
  2. 纯 Markdown 写作：文章以文件存在本地，天然兼容 Git 版本管理和 Obsidian 等笔记工具。
  3. 插件生态丰富：官方市场 400 多个插件，SEO、RSS、搜索、图床、加密、部署基本都有现成方案。
  4. 主题生态成熟：社区主题多且持续维护，中文主题尤其出色，主题选择篇会细说。

先认清站点目录的职责¶

执行 hexo init 后会得到标准项目目录，理解每个目录干什么，是入门第一步：

我最关心的是 source/：Markdown 文章、图片、自定义页面都塞在这儿。Hexo 只渲染 Markdown 和 HTML，其余文件（比如图片）原样复制到输出目录。_posts 里的才是正式发布的博文，这个目录也正是 Obsidian 集成写作的入口，详见 03-写作与内容管理。

配置文件分站点和主题两层¶

Hexo 的配置体系由两层 YAML 组成，别搞混：

  • **站点配置 _config.yml**：在根目录，控制网站标题、URL、永久链接格式、分页、部署方式这些全局行为，配置详解篇会逐项拆。
  • **主题配置 _config.butterfly.yml**：每个主题自带一份，控制外观、菜单、侧边栏、评论。推荐复制一份改名放根目录覆盖默认值，这样主题更新时自定义内容不会丢。

这里有个优先级要记牢：根目录下的 主题名.yml（如 _config.butterfly.yml）优先于主题目录内的 _config.yml。这是官方推荐的自定义方式，能做到”升级主题不丢配置”。

每篇文章开头用 --- 包起来的 YAML 块叫 Front-matter，是文章的元数据声明：

Hexo 从中提取标题、日期、标签、分类，用来生成归档页、标签页、分类页和 RSS。不同主题还会扩展自己的字段（比如封面图 cover、置顶 sticky），06-Butterfly主题全面指南 里给了完整清单。

Hexo 的护城河是中文社区¶

Hexo 不是唯一选择：Hugo 以构建速度见长，Astro 主打组件化现代栈，Jekyll 是 GitHub Pages 的老牌选手。Hexo 的看家本事在中文社区的深度——文档汉化完善、主题设计精美、遇到问题容易搜到中文解答。要我选，中文写作为主又想开箱即用还好看的场景，它到 2026 年依旧是最省心的那个。
