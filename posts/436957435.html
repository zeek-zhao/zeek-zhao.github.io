复制与高可用

ℹ️本节目标
掌握 OpenLDAP 复制机制（syncrepl 与 Delta-syncrepl），能搭建主从复制与多主复制架构，并理解高可用方案选型。

为什么需要复制¶

目录服务的典型特征：读多写少。生产环境单点 slapd 一旦故障，所有认证与查询全部中断。复制带来的核心价值：

  • 读扩展：多个只读副本分摊查询压力
  • 容灾：主节点故障时副本可切换
  • 就近访问：分支机构使用本地副本
  • 备份：副本可作为一致性快照来源

复制机制¶

OpenLDAP 2.4+ 推荐使用 syncrepl（Synchronization Replication）作为 provider/consumer 模型。

关键术语：

  • Provider：提供复制的服务端（原 master）
  • Consumer：接收复制的客户端（原 replica）
  • Sync Provider：向消费者推送变更
  • RefreshAndPersist：先全量刷新，再持续接收增量

然后 consumer 使用 accesslog 作为增量源，配合 checkpoint 定期收敛。

高可用方案选型¶

方案 写支持 复杂度 适用
主从复制 单写 低 大多数企业认证场景
多主复制（MirrorMode） 多写 中 双机房互备
Keepalived + 虚拟 IP 单写 中 透明切换
共享存储 + 单实例 单写 低 小规模

MirrorMode 需要配合 olcMirrorMode: TRUE 与双向 syncrepl，并启用 accesslog 防止冲突。

监控要点¶

  • 复制延迟：对比主从条目的 entryCSN
  • 日志关键字：syncrepl_entry、rid=001
  • 定期校验：slapcat -n 0 检查配置一致性
⚠️常见误区
复制不是备份：误删条目会同步传播；务必另配时间点快照备份策略。
