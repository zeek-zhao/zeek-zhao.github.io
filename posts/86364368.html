Blob Store 与存储

[!abstract] 数据怎么落盘
Blob Store 是 Nexus 的数据桶：隔离不同仓库、设配额、加密或迁移到云存储。

1. Blob Store 类型

类型 说明
File 本地文件系统目录
S3 AWS S3（含 MinIO/兼容）
Azure Blob 微软云存储
Google Cloud Storage GCS
CloudFront/OCI 对象存储扩展

[!note] 默认 Blob
安装后自动建 default（文件型）。生产建议按用途拆 Blob。

3. 配额（Quota）

配额类型 作用
软配额 达到阈值后只读，阻止写入
配额限制 上限，触发告警/限制
预警阈值 接近配额提前通知

[!warning] 注意
配额满了仓库变只读，构建会失败；务必设置告警与清理任务（10-Cleanup与任务调度）。

4. 仓库绑定 Blob

创建仓库时选择 Blob Store；已创建仓库不可改 Blob，需迁移（见下）。

6. 加密与合规

  • File Blob 支持加密（配置密钥文件）；
  • 审计：对象存储版本控制/生命周期管理；
  • 备份策略：Blob 目录纳入备份（12-备份恢复）。

7. 查看占用

[!tip] 清理联动
Blob 只增不减是常态；Cleanup 任务删除的是组件索引，Blob 空间通过”compact blob store”任务回收（10-Cleanup与任务调度）。

[!warning] 常见误区

  • 清理组件 ≠ 立即释放磁盘，需 Compact Blob Store 任务；
  • 不要手动删 Blob 目录文件（索引不一致）。
