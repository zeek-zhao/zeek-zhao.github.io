50-仿真平台对比与Gazebo-LGSVL实战

发表于2026-10-25|apollo
|浏览量:

[!info] 本节目标
一篇打通自动驾驶仿真：先理解仿真原理与类型，再用系统化方法选平台，最后落地 Gazebo 与 LGSVL 两个开源平台的实战操作（安装、传感器、场景、与 ROS/Apollo 集成）。

1. 仿真原理与类型

1.1 为什么必须仿真

自动驾驶安全验证需要数十亿公里级里程，实车测试不可行；接管场景复现、危险场景测试、大规模数据生成，都依赖仿真。

1.2 仿真系统架构

闭环：物理世界模型 ← 环境条件/交互对象/场景管理器 → 传感器模型 → 数据处理 → 控制算法 → 执行系统 → 回到物理世界。

关键传感器模拟原理：

  • 摄像头：图形渲染 + 视角转换 + 光学效果（畸变/景深）+ 噪声。
  • 激光雷达：光线追踪——发射虚拟线束 → 取碰撞点 → 加噪声/材质反射/大气衰减 → 生成点云。
  • 毫米波雷达：电磁波传播 + RCS + 多普勒效应。
  • IMU/GPS：动力学状态 + 偏差噪声 + 信号遮挡模拟。

1.3 类型划分

分类维度 类型
保真度 低（概念验证）/ 中（算法开发）/ 高（系统验证与安全评估）
数据来源 物理模型仿真（游戏引擎）/ 真实数据仿真（回放、增强、重建）/ 混合仿真

混合仿真是当前主流：真实数据构建环境 + 物理引擎添加动态对象 + 传感器模型生成数据。数据生成方法包括 GAN 增强真实数据、模拟器生成、结构化数据增强三类。

2. 平台对比与选择

2.1 主流平台速览

平台 开发方 引擎 集成 特点
CARLA CV 中心 Unreal 4 ROS/Apollo/Autoware 开源、社区最活跃、天气丰富
LGSVL LG 电子 Unity Apollo/Autoware（最优） 高精地图支持、Python API
Gazebo Open Robotics 自研 ROS 原生 物理最强、机器人标准
AirSim 微软 Unreal 4 ROS 无人机+车辆、渲染好
DRIVE Sim NVIDIA 自研 DRIVE 平台 光线追踪、商业闭源、保真度最高

2.2 选型决策树

按场景推荐：感知研发选 CARLA/AirSim/DRIVE Sim；规划决策选 CARLA/LGSVL；控制算法选 Gazebo/AirSim；全系统集成测试选 LGSVL/CARLA；数据生成选 CARLA/DRIVE Sim。

[!note] 2026 年更新
LGSVL（SVL Simulator）自 2022 年起停止官方维护，仓库已归档。仍在使用需自行维护 fork；新项目替代方案：CARLA（开源首选，社区持续活跃）、NVIDIA DRIVE Sim（商业高保真）、51Sim 等国产平台。与 Apollo 10.0 的仿真对接也转向 CARLA 桥接为主。

多平台协同策略：低保真快速迭代 → 中保真筛选 → 高保真最终验证；用 OpenSCENARIO 标准格式跨平台复用场景；统一中间件接口层屏蔽 API 差异。

3. Gazebo 实战

3.1 安装与配置

要求：Ubuntu 18.04/20.04、8GB+ 内存、OpenGL 3.3+ 显卡。渲染问题尝试 export SVGA_VGPU10=0。

3.2 模型与传感器

模型目录包含 model.config（元数据）与 model.sdf（物理+视觉定义，XML 格式）；ROS 用户可用 URDF + <gazebo> 扩展标签，用 gz sdf -p my_robot.urdf > my_robot.sdf 手动转换。

URDF 中添加 RGB 相机与激光雷达传感器示例（节选）：

支持多物理引擎（ODE/Bullet/Simbody/DART），插件系统用 C++ 扩展自定义传感器与行为。

3.3 世界与仿真操作

  • .world 文件（XML）保存完整环境配置：gazebo my_world.world 或 roslaunch gazebo_ros empty_world.launch world_name:=...。
  • 交互：左键拖动旋转、中键平移、滚轮缩放；Space 暂停、Ctrl+R 重置。
  • 复杂模型用 Blender 建模导出 .dae；批量模型用脚本生成 SDF。

3.4 与 ROS 集成

Gazebo 与 ROS 原生互通：传感器数据直接发布为 ROS 话题，控制指令通过话题/服务下发，TF 提供坐标变换。典型闭环：Gazebo 发布 /camera/image_raw、/scan、/odom → SLAM/导航节点处理 → /cmd_vel 回到 Gazebo 驱动机器人。

[!tip] 适用边界
Gazebo 物理引擎强、适合控制与底层算法开发，但渲染质量一般、道路场景构建繁琐——做自动驾驶交通流仿真不如 CARLA/LGSVL 便捷。

4. LGSVL 实战

4.1 安装与初始化

要求：GTX 1080+（6GB 显存）、16GB+ 内存、30GB 磁盘。首次启动访问 Web UI（http://127.0.0.1:8080）创建账户、下载地图与车辆资源、配置集群。

预置地图：BorregasAve（城市）、SanFrancisco（复杂城市）、Shalun（混合道路）、CubeTown（基础测试）等；支持 HD Map（Apollo 格式）与 OpenDRIVE 导入。

4.2 传感器配置

在 Web UI 车辆配置中用 JSON 定义传感器（位置由 transform 的 x/y/z 与 pitch/yaw/roll 控制）：

支持 RGB/深度/语义分割相机、激光雷达、毫米波雷达、GPS/IMU、超声波、碰撞检测器；Compensated: true 表示内置运动补偿。环境参数可调雨/雾/湿度/云量（0-1）与一天时间（0-24h）。

4.3 与 Apollo 集成闭环

流程：

  1. Web UI 创建仿真：选地图（如 SanFrancisco）、车辆、运行时（Interactive/API Only）；
  2. 车辆传感器配置中设置桥接为 Apollo bridge，topic 按上面 JSON 中的 /apollo/sensor/... 通道命名；
  3. 启动 Apollo（如 5.0+）与 dreamview，启动 LGSVL 仿真，二者经桥接建立数据循环。

手动驾驶可用 WASD 控制，Tab 切换手动/自动模式——自动模式即 Apollo 接管。

4.4 Python API 与场景测试

Python API 可程序化创建仿真、控制车辆、读取传感器，用于批量回归测试：

测试要点：脚本化生成边缘场景（行人横穿、加塞、鬼探头），批量运行并自动判分（是否碰撞、是否违规、接管次数）。

5. 实战建议

  1. 新项目（2026 年视角）：首选 CARLA 起步，需要 Apollo 闭环可参考社区 CARLA-Apollo 桥接；对保真度有要求且有预算选 DRIVE Sim 或国产 51Sim。
  2. 存量 LGSVL 工程：归档仓库自行 fork 维护，冻结版本避免依赖漂移。
  3. 场景管理：统一 OpenSCENARIO 描述，跨平台复用；把仿真测试纳入 CI，每次代码提交自动回归核心场景。
  4. 仿真到现实差距（Sim2Real）：仿真结果需在封闭场地标定验证，特别是传感器噪声模型与车辆动力学参数。
