21-Groovy与Gradle构建

发表于2026-10-25|groovy
|浏览量:

[!info] 本节目标
Gradle 是 Groovy 生态的核心构建工具，学习构建脚本与项目配置。

1. Gradle 与 Groovy 的关系

Gradle 是 JVM 生态的构建自动化工具，构建脚本默认使用 Groovy DSL（build.gradle），Groovy 开发者对构建脚本零学习成本。

Gradle 支持 Groovy 与 Kotlin 两种 DSL，Groovy DSL 更简洁灵活，适合脚本化构建逻辑。

2. 初始化 Groovy 项目

gradle init 生成项目骨架，选择 Groovy 应用或库模板。标准布局包含 src/main/groovy 与 src/test/groovy 目录。

build.gradle 配置插件、依赖与任务，settings.gradle 配置项目名称与仓库。

3. Groovy 插件

应用 groovy 插件启用 Groovy 编译支持，联合 java 插件管理源码集。compileGroovy 任务编译 Groovy 源码，与 Java 源码联合编译。

groovydoc 任务生成 API 文档，groovyc 编译配置可以指定版本与联合编译选项。

4. 依赖管理

dependencies 块声明依赖，implementation、testImplementation 等配置控制作用域。仓库用 repositories 配置 Maven Central、Gradle Plugin Portal 等。

Groovy 相关依赖如 groovy-all、spock-core、groovy-json 直接从仓库引入。

5. 任务与生命周期

任务用 tasks.register 或 DSL 语法定义，dependsOn 表达依赖。build 任务执行完整构建，check 执行测试与校验。

自定义任务可以用 Groovy 闭包实现逻辑，访问项目属性与文件集合。

6. Gradle 实践建议

优先使用 Gradle Wrapper 锁定版本；构建逻辑保持声明式；多模块项目用 settings 的 include 组织。

构建速度优化：增量编译、缓存、并行任务；CI 环境使用 –no-daemon 与缓存目录策略。

7. Gradle 构建实战

自定义任务用闭包实现复制、替换、校验等构建步骤，任务依赖关系明确后，构建过程可编排可缓存。

多环境配置用不同 properties 文件与构建变量切换，打包时按环境注入配置，部署更灵活。

构建脚本保持声明式与可读性，复杂逻辑抽取到 src 目录下的 Groovy 类中，避免 build.gradle 膨胀。

开启构建缓存与配置缓存，CI 环境下构建速度显著提升，配合 –scan 分析构建耗时热点。

延伸阅读与实践

Gradle 的守护进程与并行执行缩短构建时间，CI 中配合测试并行分片加速反馈。

构建产物按版本号与提交号标记，追溯来源清晰，发布审计有据可查。
