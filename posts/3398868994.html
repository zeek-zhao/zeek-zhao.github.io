Obsidian Vault 工程管理方案

版本：v1.0 | 日期：2026-10-24
定位：配套《Obsidian AI 知识库 + Hexo 发布工程设计方案》（设计稿），解决”建成后如何长期管好、用好”的问题。
原则：一切内容可流转、可查询、可追溯；入口唯一，出口唯一。

1. 管理对象与总纲

对象 范围 管理要点
内容流 00-Inbox → 10-灵感 → 30-永久笔记 / 40-发布 流转状态用 Frontmatter status 驱动，不靠记忆
素材流 50-发布信息收集 → 30-永久笔记 每条素材必须有 source，避免无出处引用
元数据 Frontmatter 统一规范 必填字段校验，AI 补全，门禁拦截
自动化 Obsidian Git / Actions 流水线 失败告警，禁止手动绕过
数据视图 91-数据库（Dataview） 四个核心看板，日常只看视图不看目录

三条铁律：

  1. Inbox 不停留超过 7 天——收集箱是中转站，不是仓库。
  2. 发布只走门禁——published: true 只能由质检通过后设置，禁止手改直发。
  3. 一个事实一个来源——同一知识只允许一份成稿，其他位置只放链接引用。

2. 内容流转管理（核心工作流）

2.1 状态机

每次状态变更 = 修改 Frontmatter status 字段，配合 Obsidian Git 自动提交，天然形成变更历史（可追溯）。

2.2 每种状态的”进入条件 / 退出条件”

状态 进入条件 退出条件
collected（已收集） 有 source + 原文/要点 AI 提炼出 note 要点 → refined
refined（已提炼） 有 note 摘要 + 关联 topic 被 draft 文章引用 → used
spark（灵感） 一句话想法入 Inbox 后提升 补充上下文、可写性评估 → developing
developing 明确选题方向 素材足够（≥2 条 refined 素材或可独立成文）→ ready
draft（草稿） 按文章模板成文，字段齐全 通过 AI 质检清单 → review
review（待发） 质检清单全绿 人工确认 → 改 published: true, status: published

2.3 流转例程（见 §5 节奏表）

  • 每日：清 Inbox（分类/提升/删除三选一）。
  • 每周：灵感回顾 + 素材池整理。
  • 每月：永久笔记回顾 + 标签治理 + 视图校对。

3. 元数据与命名管理

3.1 Frontmatter 必填字段（按内容类型）

类型 必填字段
文章（40） title, date, updated, tags(≥2), categories, description, status, published
素材（50） title, source, date, status, topic, note
灵感（10） title, date, status, topic
永久笔记（30） title, date, tags, source（来源或推导依据）

管理规则：字段缺失由 AI 插件（Templater/Copilot）在创建时自动补全；未补全的文件会被 Dataview “异常视图”捕获并列入待修复清单。

3.2 命名规范（沿用设计稿并补充）

  • 文章：YYYY-MM-DD-短横线标题.md
  • 素材：YYYY-MM-DD-来源-标题.md
  • 灵感/笔记：主题-要点.md（禁止”新建笔记””未命名”）
  • 附件：assets/YYYY-MM-描述.png，禁止无日期散图

3.3 标签治理

  • 两级标签：一级≤10 个（如 #tech、#life、#product），二级自由扩展（#tech/ai）。
  • 每月检查一次孤儿标签（无文章引用）与同义标签（合并）。

4. 质量门禁管理

4.1 发布门禁清单（AI 质检 + 人工确认）

检查项 方式
错别字、语病 AI Review
标题吸引力 + description SEO AI 生成 → 人工定稿
tags ≥ 2、categories 非空 脚本/Dataview 校验
图片路径有效、均为本地 assets 脚本校验
无遗留 TODO / 双花括号占位符 正则扫描
与既有文章查重（避免重复发布） Smart Connections 相似度检查

4.2 内容质量分级（月度抽查）

  • A：概念清晰、有个人洞察、可独立引用 → 提升为 30-永久笔记候选。
  • B：合格成稿，正常发布。
  • C：信息过期或质量差 → 归档 99-Archive/，不删除（保留可追溯性）。

5. 运营节奏（例程管理）

频率 动作 用时参考
每日 清 Inbox：每条记录”提升 / 转素材 / 删除”三选一 10-15 min
每日 发一篇时：走 §4.1 门禁清单 随写作
每周一 灵感回顾：10-灵感 更新状态；ready 灵感排入本周写作 30 min
每周五 素材池整理：50 区 collected→refined，标记 topic 20 min
每月末 ① 标签治理 ② 99-Archive 归档过期内容 ③ 视图/模板回归检查 ④ 备份验证 1 h
每季度 30-永久笔记回顾：合并相似卡片、修正过时知识 半天

6. 数据视图与仪表盘（91-数据库）

日常管理只看视图，不翻目录。四个核心视图（Dataview）：

  1. 待处理视图：Inbox 内全部文件 + 超过 7 天未处理的高亮 → 驱动每日例程。
  2. 发布管线视图：draft / review / published 三列看板 → 掌握内容供给。
  3. 素材池视图：50 区按 topic 分组，collected/refined 状态统计 → 选题决策依据。
  4. 异常视图：必填字段缺失、命名不合规、TODO 残留文件清单 → 月末修复。

补充视图（按需）：本月产出统计、灵感转化率（spark→published 漏斗）、发布频率趋势。

7. 版本、备份与安全管理

层 机制 检查
实时备份 Obsidian Git 自动 commit+push（间隔 15 min） 每月末验证远端最新 commit 时间
发布回滚 Hexo 产物在 gh-pages 分支，回滚 = revert 对应 commit 重跑流水线 —
灾难恢复 任何机器 clone source 分支 + .obsidian 配置即可重建环境 .obsidian 关键配置纳入 git（插件列表），缓存类除外
权限 仓库私有；Pages 仅公开 published: true 内容 每季检查仓库可见性
敏感内容 个人隐私类笔记放 98-私人/，并在 .gitignore 中排除 月末检查 git status 是否泄漏

8. 风险管理

风险 影响 对策
Inbox 堆积成”垃圾抽屉” 收集失效 铁律一 + 每日例程 + 待处理视图超期高亮
AI 打标/摘要质量漂移 元数据污染 月末抽查 10 篇 AI 补全的 Frontmatter，纳入异常视图
流水线静默失败（Actions 报错未察觉） 发布中断 Actions 失败邮件通知开启；月末验证最新 commit 已上线
标签失控（碎片化） 检索失效 两级标签 + 月度治理
素材与成稿混淆 结构退化 50 与 40 严格分离，流转靠 status 而非复制粘贴
Vault 膨胀无人用 系统废弃 季度回顾时同时审视例程本身是否还需保留，流程也要做减法

9. 落地检查清单（M5 后启用本方案）

  • 四个 Dataview 视图就位，异常视图能捕获缺字段文件
  • Templater 模板（文章/灵感/素材）内置必填字段与 status 默认值
  • Obsidian Git 自动提交开启，失败可感知
  • Actions 失败邮件通知已开启
  • 99-Archive/、98-私人/ 目录建立，私人目录进 .gitignore
  • 每日/每周例程写入日历或任务工具（可配自动化提醒）
  • 首月结束时做一次全流程复盘，修订本方案版本号
