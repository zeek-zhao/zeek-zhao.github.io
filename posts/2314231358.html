Rebase merge 线性历史 要求线性的团队

门禁（Branch Protection）¶

常见坑¶

  1. PR 过大：>500 行难评审，拆小。
  2. CI 红灯仍合入：门禁必须强制执行。
  3. 评审只走过场：无实质评论即 approve，质量失控。
  4. 合入策略不一致：团队统一 squash/merge 策略。
  5. 描述为空：无法追溯，用模板强制填写。

最佳实践¶

  • PR 模板 + 分支保护 + CI 门禁。
  • 评审时效约定（24h 内）。
  • 与 Git Hooks（06-Git Hooks）、提交规范（09-提交信息规范）配合。
