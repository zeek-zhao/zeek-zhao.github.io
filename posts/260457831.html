1. 硬件门槛：内存 32G 起步¶

项 最低配置 推荐配置
CPU Intel Core i7-6700K 及以上 Intel Xeon W-2133 及以上
内存 32GB 64GB
硬盘 500GB SSD 1TB SSD（预留 50GB+ 给镜像与缓存）
显卡 NVIDIA GTX 1080 RTX 2080 Ti / Tesla T4 及以上

这张表是 Apollo 官方文档给的开发机基线，配置老旧（i7-6700K 是 2015 年的 U），不用当成硬门槛——我按这个级别跑通过，内存给足比 CPU 型号更关键。真要上车载平台，工业级 PC 配 NVIDIA AGX Xavier/Orin 是另一回事。

系统支持 Ubuntu 18.04/20.04/22.04 和 CUDA 11.8，9.0 起还支持 AMD ROCm 5.1 与 ARM Orin 平台。10.0 起可以物理机直接安装，不再强制依赖 Docker。不过 Docker 仍是可复现性最好的开发环境，这篇以它为主线。

3. 一条命令拉起容器¶

Apollo 提供 dev 和 runtime 两类镜像，开发阶段用 dev 镜像：

dev_start.sh 会自动拉取与源码版本对应的镜像并挂载源码目录。脚本里能调容器内存和 CPU 参数，常见可选参数包括挂载额外数据目录、指定镜像 tag 等。

容器内外这样配合：源码目录以挂载方式共享，容器里改的文件宿主机立刻可见。容器只提供统一的编译运行环境，随时能销毁重建而不损失源码——这也是我推荐 Docker 的核心原因。

5. 磁盘和镜像别忽略¶

  • 查看镜像/容器：docker images、docker ps
  • 清理无用镜像与缓存：docker system prune
  • 配置镜像加速：在 /etc/docker/daemon.json 中设置 registry-mirrors 后重启 docker 服务
  • 清理后重建容器：dev_start.sh 会按需重新拉取镜像，无需手工干预

Apollo 镜像与构建缓存很占空间，建议预留 50GB 以上。官方镜像本身体积就不小，加上 Bazel 缓存与构建产物，磁盘不足是新手最常遇到的环境问题。如果主机显卡驱动较新、容器内内核模块对不上，可能出现 GPU 不可用，这时去查官方文档确认驱动版本要求。

6. 网络不稳就配代理¶

开发常需访问 GitHub 与 Docker Hub，网络不稳时建议配代理。容器内要同步设置 http_proxy 与 https_proxy 环境变量，Docker 构建期的代理得单独配置。镜像拉取失败可切换镜像源，源码下载失败可用镜像仓库。排查顺序是先确认 DNS 与连通性，再检查代理与防火墙。

7. 开发阶段不用真车传感器¶

本篇面向开发环境搭建，不需要真实车辆与传感器。真要部署到实车，还得配置传感器系统（激光雷达、相机、毫米波雷达、RTK/IMU、CAN 卡）并完成驱动接入与标定，那属于后期专题。开发阶段的仿真测试（Sim Control、record 回放）无需任何硬件，就能覆盖绝大多数学习场景。

8. 报错先查这三样¶

问题 解决方法
权限不足 将用户加入 docker 组：sudo usermod -aG docker $USER
端口冲突 修改 dev_start.sh 中的端口映射
挂载目录失败 确认源码目录路径与权限正确
GPU 不可用 检查主机驱动版本与 nvidia-docker2 安装
容器内命令不可用 先执行 source /apollo/scripts/apollo_base.sh
磁盘空间不足 docker system prune 清理旧镜像
镜像拉取超时 配置 registry-mirrors 或使用代理

环境搭建是一次性成本，但版本匹配与网络问题占了新手报错的绝大多数。遇到报错先做三件事：确认源码与镜像版本一致、确认 GPU 驱动可用、确认网络代理生效，大部分问题会随之消失。环境就绪后进 05-源码编译与部署 编译第一个目标。后续若升级 Apollo 版本，本篇的验证清单要整条重跑一遍。

代码示例与实现细节¶

操作步骤 / 使用流程¶

  1. 核对硬件：对照上方清单，确认 CPU/内存/GPU/磁盘达标。
  2. 装驱动：安装 NVIDIA 驱动（470+），nvidia-smi 能正常显示。
  3. 装 Docker 与 NVIDIA Docker：按上面 1、2 步执行。
  4. 拉源码：git clone 后切到目标 tag，参见 02-版本发展与架构演进。
  5. 启动容器：dev_start.sh 拉镜像并建容器，dev_into.sh 进入。
  6. 验环境：./apollo.sh check 确认无缺失。
  7. 编译：执行 apollo.sh build，参见 05-源码编译与部署。
  8. 开 DreamView：./scripts/bootstrap.sh 后浏览器访问控制台，参见 14-调试与可视化工具-DreamView。

注意事项与常见坑¶

  1. 驱动版本过低：NVIDIA Driver 低于 460 会导致容器内 GPU 不可用，先升级驱动。
  2. docker 用户组未生效：usermod -aG docker 后需重新登录或 newgrp docker。
  3. 镜像与源码 tag 不匹配：老源码配新镜像可能编译失败，保持一致。
  4. 磁盘空间不足：全量编译 + Docker 镜像轻松吃掉 100GB+，预留充足空间。
  5. 代理配置：GitHub/Docker Hub 拉取慢，需配置代理或镜像源。
  6. 容器内改动丢失：dev_start.sh 重建容器会清空容器内数据，源码挂载目录外的改动要备份。
  7. 别用 root 直跑：Apollo 脚本设计为普通用户 + sudo，全程 root 会引发权限错乱。
  8. nvidia-docker 源错误：distribution 变量取值不对会导致源不可用，核对 /etc/os-release。
  9. 中文社区反爬：知乎等链接需登录，仅作延伸参考。
  10. WSL/虚拟机：不支持 GPU 直通的环境跑不了感知模块，建议物理机 Ubuntu。
