性能调优

[!abstract] 调优方向
性能 = 索引合理 + 查询高效 + 写入批量 + JVM/OS 到位。先定位瓶颈，再对症下药。

1. JVM 与系统层

项 建议
堆内存 Xms/Xmx 系统内存 50%，不超过 32GB（压缩指针）
禁止 swap bootstrap.memory_lock: true
文件描述符 ulimit -n 65535
磁盘 SSD + 独立数据盘，避免与系统盘抢 IO

2. 索引设计优化

  • 分片数不过度（单分片 30-50GB，见 09-集群与分片）；
  • 字段够用即可：enabled: false 跳过不需要检索的字段（省磁盘/内存）；
  • 关闭不需要的 _source（极少用 _source 时可关，省空间）；
  • 日志场景用 ILM 自动滚动与合并（forcemerge 降段数）。

3. 写入调优

  • 批量 5MB 左右或 1000-5000 条/批；
  • refresh_interval 调大（如 10s-30s，日志场景可接受秒级延迟）；
  • 大批量灌数据时临时 number_of_replicas: 0，灌完再开副本。

4. 查询调优

  • 尽量用 filter 上下文（缓存、不算分）：精确匹配放 bool.filter；
  • 避免 wildcard 通配开头、* 全扫描；前缀搜索用 edge_ngram 分词；
  • 深分页用 search_after，不用大 from；
  • 聚合字段用 keyword/数值，避免 text 聚合；
  • 常用聚合预热：eager_mapping 或预构建统计索引。
