Ubuntu忘记密码修复指南

这份指南覆盖 Ubuntu 14.04/16.04/18.04/20.04/22.04 等版本的密码恢复，虚拟机和物理机都适用。我判断优先级很清楚：能用 Recovery 模式重置就别改 GRUB 参数，能改 GRUB 参数就别上 Live CD——方法越靠前风险越低；如果启用了加密用户目录或全盘 LUKS，务必先确认恢复密钥还在，否则改密码也进不去数据。

准备工作¶

在开始密码恢复过程前，请确保：

  • 您有物理访问虚拟机或实体机的权限
  • 您有足够的权限进入恢复模式或修改启动参数
  • 如果使用了加密的用户目录，请确保记住加密密钥
  • 备份重要数据(如果可能)

方法一最稳妥：Recovery 模式拿到 root 终端后直接 passwd¶

这是最标准、最安全的方法，适用于大多数Ubuntu版本。

1. 进入GNU GRUB菜单¶

  1. 启动计算机/虚拟机
  2. 重要提示：系统启动时，立即点击屏幕以确保鼠标焦点在Ubuntu启动画面上
  3. 立即按住键盘上的Shift键不放（物理机通常是长按ESC键）
  4. 持续按住直到出现GNU GRUB菜单界面

图 1：GNU GRUB菜单界面

如果您看到以下界面，说明没有成功进入GRUB菜单，请重新启动尝试：

图 2：普通启动界面（需要重试）

2. 选择恢复模式¶

  1. 在GNU GRUB菜单中，使用方向键选择”Ubuntu高级选项“，然后按Enter键
  2. 在弹出的子菜单中，选择带有”(recovery mode)“标记的选项
    • 通常选择最新的内核版本（列表中最上面的选项）
    • 两种恢复模式选项都可以使用

图 3：选择recovery mode选项

3. 进入Recovery Menu¶

  1. 系统将以恢复模式启动，可能需要等待一段时间
  2. 启动完成后，您将看到Recovery Menu（恢复菜单）
  3. 使用方向键选择”root“选项（用于获取root终端）
  4. 按Enter键确认选择

图 4：Recovery Menu恢复菜单

4. 重置用户密码¶

  1. 系统可能会要求您输入root密码（如果之前设置过）。如果没有设置过，直接按Enter继续
  2. 进入root终端后，首先需要以读写模式重新挂载文件系统：
  3. 使用passwd命令更改指定用户的密码： 将”用户名”替换为您需要重置密码的实际用户名
  4. 系统会提示您输入新密码并确认
  5. 看到”password updated successfully”（密码更新成功）的提示后，密码重置完成

图 5：Root终端界面

5. 恢复正常启动¶

  1. 输入exit命令返回到Recovery Menu
  2. 在Recovery Menu中，使用方向键选择”resume“选项
  3. 按Enter键确认
  4. 在确认界面再次按Enter键
  5. 系统将继续正常启动过程，最终进入登录界面
  6. 使用新设置的密码登录系统

图 6：选择resume选项继续正常启动

方法二：改 GRUB 启动参数，直接落进 bash shell¶

这种方法通过修改启动参数直接进入bash环境，适用于Recovery模式无法正常工作或需要修复系统文件的情况。

1. 进入GRUB菜单¶

与方法一相同，开机时长按Shift键(或ESC键)进入GRUB菜单。

2. 选择高级选项¶

选择”Ubuntu 高级选项”并按Enter键进入。

3. 编辑GRUB启动参数¶

  1. 选择Recovery模式选项（带有recovery mode字样的）
  2. 按下e键进入编辑模式
  3. 找到包含”ro recovery nomodeset”的行
  4. 将”ro recovery nomodeset”替换为”quiet splash rw init=/bin/bash”

4. 启动修改后的系统¶

按下F10或Ctrl+X以应用更改并启动系统。系统将直接启动到bash shell，无需用户验证。

进不去 GRUB、拿不到 root、只读错误等常见问题有固定解法¶

无法进入GRUB菜单¶

  • 尝试使用ESC键而不是Shift键
  • 在系统完全关闭后再启动，反复点按Shift键或ESC键
  • 如果使用双系统，GRUB菜单可能会自动显示
  • 对于较新的UEFI系统，可能需要通过BIOS/UEFI设置调整启动顺序

无法获取root访问权限¶

  • 检查是否正确选择了recovery mode选项
  • 部分系统可能启用了root密码，需要使用方法二或三
  • 检查/etc/sudoers文件是否损坏(需使用Live CD修复)

如果遇到”Read-only file system”错误，确保执行了:

GRUB启动参数不同¶

  • 不同Ubuntu版本的GRUB参数可能略有不同
  • 查找包含”linux”和”root=”的行进行修改
  • 确保添加”rw”参数以启用读写模式

加密用户目录¶

如果使用了eCryptfs加密用户目录，更改密码后可能需要:

  1. 确保记住原密码或恢复密钥
  2. 使用ecryptfs-recover-private命令恢复访问
  3. 更新加密密钥以匹配新密码

改完密码之后，还要补上加密密钥、凭据和备用账户¶

  1. 定期备份重要数据：密码恢复过程通常不会影响数据，但事故总是无法预料
  2. 使用密码管理器：如KeePassXC、Bitwarden等工具管理复杂密码
  3. 考虑设置密码提示：在不泄露密码的前提下，设置能帮助记忆的提示
  4. 重置密码后立即更新：
    • 更新加密密钥(如果使用加密目录)
    • 更新保存的WiFi密码和其他凭据
    • 更新密钥环密码(如果使用)
  5. 设置可恢复方式：创建额外的管理员账户作为备用
  6. 提高GRUB安全性：设置GRUB密码防止未授权修改

总结¶

上面几种方法基本能覆盖 Ubuntu 密码遗忘的场景。我的建议是始终选最简单、风险最低的方法（通常是方法一），只在必要时才上 GRUB 编辑或 Live CD；真正避免这类事故的是定期备份数据和使用密码管理器。
