安装部署 - Omnibus

用官方 Omnibus 包在单台 Linux 服务器上装好 GitLab，并完成基础配置与 HTTPS 启用。
📅 2026-11-18· 更新于 2026-11-18 · 836 字 · 约 3 分钟 ✍ zeek.zhao #GitLab#安装#Omnibus

安装部署 - Omnibus

上一篇 01-GitLab简介与架构 把 GitLab 的组件拆开讲了一遍，真要落地，最省事的还是官方 Omnibus 包——它把 Nginx、PostgreSQL、Redis、Gitaly 这些全打进一个安装包，我们只要备一台干净服务器。这篇就走一遍从安装到启用 HTTPS 的完整流程，适合单机起步。

先备一台干净服务器，组件都在安装包里¶

按团队规模选配置，下面是我常参考的基线：

规模 CPU 内存 磁盘
小型团队（≤100 用户） 2 核 4 GB 100 GB SSD
中型团队（≤500 用户） 4 核 8 GB 500 GB SSD
⚠️系统要求
官方仅支持受支持的发行版（如 Ubuntu 20.04/22.04、Rocky 8/9、Debian 11/12）。关闭 SELinux 或按官方文档配置策略，否则 Git 操作可能异常。

装 gitlab-ce，关键是把 EXTERNAL_URL 设对¶

安装完成后 GitLab 会自动 reconfigure 并启动。EXTERNAL_URL 是关键，决定 Web 地址与生成的证书域名。我一般直接用官方仓库装，省得手动下 rpm/deb 包再处理依赖。

改完 gitlab.rb 记得 reconfigure 才生效¶

修改 /etc/gitlab/gitlab.rb 后执行 gitlab-ctl reconfigure 生效。常见配置项：

🔥首次登录
首次访问 https://gitlab.example.com 使用 root 用户与 /etc/gitlab/initial_root_password 中的初始密码（或上面设置的自定义密码）登录，登录后务必立即修改。

我的习惯是装完先把 signup 关掉、root 初始密码改掉，再谈别的配置。

生产环境用 Let’s Encrypt 替掉自签名证书¶

Omnibus 默认生成自签名证书。生产环境推荐使用 Let’s Encrypt：

📝自定义证书
已有商业证书时：将证书放到 /etc/gitlab/ssl/，命名为 <域名>.crt 与 <域名>.key，并设置 nginx['redirect_http_to_https'] = true 后 reconfigure。

我基本都上 Let’s Encrypt，自签名证书浏览器老报错，不适合生产。

记住这几条 gitlab-ctl 命令就够日常用¶

⚡注意
gitlab-ctl reconfigure 会重写配置并可能重启服务，应在维护窗口执行；修改 gitlab.rb 前先备份该文件。

reconfigure 放进维护窗口、改配置前先备份 gitlab.rb，单机部署最容易踩的坑基本就这两条。
