事务与锁

[!info] 本页概览
本文讲解数据库事务：ACID、事务隔离级别、MVCC 原理、锁类型（行锁/间隙锁/表锁）、死锁排查与事务最佳实践，配可运行示例。

核心概念

  • 事务：一组不可分割的数据库操作，要么全部成功要么全部回滚。
  • ACID：原子性（Atomicity）、一致性（Consistency）、隔离性（Isolation）、持久性（Durability）。
  • 隔离级别：读未提交（RU）< 读已提交（RC）< 可重复读（RR）< 串行化（Serializable）。
  • MVCC：多版本并发控制，通过版本链 + 快照实现读写不互斥。
  • 锁：用于保证并发访问正确性；粒度：行锁 > 间隙锁 > 表锁。

事务使用

隔离级别与并发问题

隔离级别 脏读 不可重复读 幻读
读未提交 RU 可能 可能 可能
读已提交 RC 否 可能 可能
可重复读 RR（MySQL 默认） 否 否 否（InnoDB 间隙锁防）
串行化 否 否 否

[!note] MVCC 快照
RR 下普通 SELECT 是快照读（一致性读），不阻塞写；当前读（UPDATE/SELECT FOR UPDATE）读取最新已提交版本并加锁。

常见坑

  1. 大事务：长时间持有锁+undo 膨胀；拆小事务、避免事务内远程调用。
  2. 长查询与 DDL 冲突：online DDL 也要短暂元数据锁；低峰执行。
  3. 事务内 SELECT 后判断再写：默认快照读可能读到旧数据，用 SELECT … FOR UPDATE。
  4. 隐式提交：DDL（ALTER/CREATE）会隐式提交当前事务。
  5. 锁等待超时：innodb_lock_wait_timeout 默认 50s，超时报锁等待超时。
  6. RR 下无索引 UPDATE 锁全表：WHERE 列必加索引。

最佳实践

  • 业务默认用 RR（MySQL 默认）或 RC（高并发团队常用）。
  • 事务尽量短小：快速提交，减少锁持有时间。
  • 统一加锁顺序，避免死锁。
  • 更新前用当前读确认数据版本。
  • 结合 04-索引与执行计划 保证 WHERE 走索引，缩小锁范围。
