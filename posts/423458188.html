08-设备驱动模型与开发实践

通读驱动子系统时最容易晕的地方，是结构体多、名字又像——kobject、device、driver、bus_type 一层套一层。
📅 2026-11-13· 更新于 2026-11-13 · 3305 字 · 约 9 分钟 ✍ zeek.zhao #Linux#概念

设备驱动模型与开发实践

通读驱动子系统时最容易晕的地方，是结构体多、名字又像——kobject、device、driver、bus_type 一层套一层。我的办法是先按“总线负责匹配、设备描述硬件、驱动实现操作”这三句话把模型立住，再回头看每个结构体在里头扮演什么角色。

下面从设备模型讲到字符、块、网络和平台设备，再顺着注册初始化、设备树、并发控制、中断与 DMA，最后落到调试手段和一套能直接改的开发模板。

1. 驱动子系统是应用与硬件之间的桥梁¶

Linux设备驱动子系统是Linux内核中负责管理硬件设备的核心组件，它为应用程序提供了统一的接口来访问各种硬件设备，隐藏了硬件的复杂性和差异性。

我一般把驱动子系统理解成一层翻译：上面是统一的系统调用与 VFS，下面是形态各异的硬件，驱动负责把两边对上。

1.1 驱动夹在 VFS 与硬件之间¶

flowchart TD A[用户空间应用] --> B[系统调用接口] B --> C[VFS文件系统] C --> D[设备驱动子系统] D --> E[硬件抽象层] E --> F[物理硬件] G[进程管理] -.-> D H[内存管理] -.-> D I[网络协议栈] -.-> D
ℹ️设备驱动子系统是连接上层应用和底层硬件的桥梁，约占Linux内核代码的70%左右。

2. 统一设备模型由总线、设备、驱动三要素构成¶

Linux采用统一设备模型，使用总线、设备、驱动三大核心元素构成设备驱动框架。

2.1 总线匹配，设备描述硬件，驱动实现操作¶

设备驱动三要素

【总线】
总线(Bus)是设备和驱动的载体，负责将设备与驱动进行匹配。常见总线类型包括PCI、USB、I2C、SPI等。

【设备】
设备(Device)代表系统中的物理或虚拟硬件，包含设备信息、资源和属性。

【驱动】
驱动(Driver)实现了操作设备的具体代码，提供标准接口供上层调用。

我习惯先用总线、设备、驱动这三个词把模型立住，再看 kobject 这层公共底座，不然很容易被一堆结构体绕晕。

2.2 kobject 是公共底座¶

classDiagram class kobject { +name +kset +ktype +parent } class kset { +kobject +list +ktype +uevent_ops } class ktype { +release() +sysfs_ops +default_attrs } class device { +kobject +bus +driver +platform_data } class driver { +name +bus +probe() +remove() } class bus_type { +name +match() +uevent() +probe() } kobject <|-- device kobject <|-- driver kobject <|-- bus_type kobject --o kset kset --> ktype kobject --> ktype device --> bus_type driver --> bus_type

字符设备是最基础的设备类型，以字节流方式进行访问。

3.2 块层负责缓存与 I/O 调度¶

块设备以固定大小的块为单位进行I/O操作，如磁盘设备。

📝块设备特点
块设备通常具有随机访问能力，并使用缓冲区提高性能，是文件系统的底层载体。

3.4 无自动发现，靠 probe 初始化¶

平台设备是嵌入式系统中常见的设备类型，通常集成在SoC中，缺乏自动发现机制。

平台设备注册流程

  2. 注册平台设备资源
  3. 定义平台驱动结构
  4. 实现probe和remove函数
  5. 注册平台驱动

我踩过的坑是以为 insmod 完设备就能用，其实还要等总线匹配成功、probe 返回 0，设备才算真正就绪。

4.2 匹配走总线策略，成功才调 probe¶

当系统加载驱动或发现新设备时，总线会尝试进行匹配。匹配成功后调用驱动的probe函数完成设备初始化。

🔥驱动匹配
驱动与设备的匹配基于不同总线有不同策略，如PCI使用厂商ID和设备ID，Platform设备使用名称匹配。

5. 设备树只描述硬件，靠 compatible 匹配驱动¶

设备树是描述硬件配置的数据结构，广泛应用于ARM等平台。

我一般先把 compatible 属性对清楚，再看 reg 和 interrupts，这样设备树和驱动的对号关系一眼就能看出来。

⚠️设备树只描述硬件，不包含驱动程序代码。驱动通过compatible属性与设备树节点进行匹配。

6. 短锁自旋、长锁睡眠，读写另算¶

Linux设备驱动中的并发控制机制：

我选锁时只看一条：临界区会不会睡眠。会睡眠用 mutex，不会而且很短就用 spinlock。

并发控制

【自旋锁】
自旋锁(spinlock)适用于短时间持有的锁，等待时会持续消耗CPU。

【互斥锁】
互斥锁(mutex)适用于可能长时间阻塞的场景，持有者会睡眠而非自旋。

【读写锁】
读写锁允许多个读者同时访问，但写者需要独占访问。
