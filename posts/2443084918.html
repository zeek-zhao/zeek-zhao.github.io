04-查询DSL

把 Query 与 Filter 的分界讲清楚，从 match、bool 到高亮和分页，串起一套能直接用的检索写法。
📅 2026-11-16· 更新于 2026-11-16 · 657 字 · 约 2 分钟 ✍ zeek.zhao #elk#工具

查询 DSL

文档增删改那套走完 03-文档操作，终于到检索。查询 DSL 是 ES 的 JSON 检索语言，核心是分两层：Query 上下文（算分）和 Filter 上下文（缓存、不算分）。我习惯先把这个分界想明白再动手写查询，不然很容易把该缓存的条件写成算分的。

match_all 是所有查询的起点¶

match 用来搜分词后的文本¶

match 对 text 字段分词后检索，默认是 OR 关系；想要求全部词命中，就加 "operator": "and"。

精确匹配放进 filter 里更省¶

精确过滤用 filter，能缓存又不算分；相关度检索才用 query，两者用 bool 组合起来。我基本都把状态、时间这类条件塞进 filter，省得白算分。

bool 查询里 must、should、filter 各管各的¶

子句 语义
must 必须匹配（算分）
must_not 必须不匹配（不算分）
should 加分项，可选择性匹配
filter 必须匹配（不算分，可缓存）

范围和存在判断用 range 与 exists¶

通配符查询别拿星号开头¶

wildcard 前缀通配会全表扫描，生产环境禁止以 * 开头；要模糊匹配，优先用 ngram 分词或 match_phrase。

要顺序命中就用 match_phrase¶

排序和分页注意深分页的天花板¶

from 超过 1 万条就别再往后翻了，改用 search_after 或 PIT 游标；导出全量数据才用 _scroll，7.x 以后也推荐 search_after。查询之上还能做统计，接着看 05-聚合分析。
