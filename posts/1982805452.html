项目与组管理

[!info] 本篇目标
掌握 GitLab 中组（Group）、项目（Project）的层级关系、可见性级别、Fork 与导入导出，形成清晰的组织结构。

1. 组与项目的层级

GitLab 的组织模型是 组 -> 项目 的两级结构（组内可嵌套子组）：

  • 组：用于组织项目集合、统一授权、统一可见性控制。
  • 项目：承载 Git 仓库、Issue、MR、CI/CD、Wiki 的最小单元。
  • 权限可以 从组继承到子组再到项目，也可在项目层单独覆盖。

[!tip] 命名规范建议
组名使用小写短横线风格，如 backend-services；项目名与代码仓库保持一致，避免中文与空格，便于 URL 与脚本引用。

2. 可见性级别

级别 说明 适用
Private 仅成员可见 公司内部项目（默认推荐）
Internal 登录用户可见 全公司共享的基础库
Public 所有人可见 开源项目、对外文档

[!warning] 可见性风险
Public 项目允许匿名克隆与浏览（除非额外开启登录限制）。误设 Public 可能造成源码泄露，建议在组级别统一收紧默认可见性。

3. 创建组与项目

[!note] API 令牌
个人访问令牌（Personal Access Token）在 用户头像 -> Preferences -> Access Tokens 中创建，权限勾选 api 即可调用上述接口。

4. Fork 与 Merge 上游

Fork 用于在不直接修改原项目的情况下派生副本，常见于贡献模式：

  • 个人 Fork：适合开源贡献、实验。
  • 组内 Fork：适合外包协作、隔离风险。
  • Fork 后需定期同步上游：git remote add upstream <原仓库地址> 后 git pull upstream main。

5. 项目导入与导出

  • 导出：项目 Settings -> General -> Export project，生成包含仓库+元数据的 tar.gz。
  • 导入：新建项目 -> Import project -> GitLab export，选择 tar.gz。
  • Git 仓库迁移：直接 git remote set-url 配合 git push --mirror 可迁移裸仓库历史。

[!danger] 导入导出限制
导出文件不含 CI 变量、Runner 注册信息等敏感配置；跨实例导入前需重新配置这些项。

6. 项目内常用设置

  • Protected branches：保护 main，禁止直接推送，强制走 MR。
  • Merge checks：要求至少 1 个审批人、流水线通过后才允许合并。
  • Webhooks / Integrations：对接企业微信、钉钉、Slack 等通知。
  • Project badges / topics：项目标签便于检索与统计。
