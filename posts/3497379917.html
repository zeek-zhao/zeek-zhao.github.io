权限与组

权限这块说白了就是「谁 + 在哪里 + 能做什么」：Gerrit 用组定义谁、用引用（refs）定义哪里、用权限项定义能做什么。项目建好之后（接着上一篇 04-项目创建与manifest），我做的第一件事就是把组和权限基线配上。

先建组再把人加进去¶

系统组里 Administrators 是全权限，Registered Users 是所有已注册用户，Anonymous Users 是匿名。我一般会把匿名组排除在 Read 之外，别让私有评审裸奔。

权限从 All-Projects 往下继承¶

Projects → web-frontend → Access 可配置继承（Inherit）或覆盖（Override）。

把权限项拆成读、推、评、合四类¶

权限 说明 典型授予
Read 可读项目 全员
Push 可推 refs/for 评审 开发组
Create Reference / Push Signed Tag 直接建分支/打标签 维护者
Code-Review 评审打分 评审组
Verified CI 验证标签 CI 账号
Submit 合入变更 维护者/发布组
Owner 管理项目配置 项目 Owner

Submit 只给维护者和发布组这类最小集合，Owner 则严格绑到项目责任人，权限一旦铺开很难收。

按 refs 前缀划出推送和合入边界¶

refs/heads/*

  • Push dev-web 开发组可评审推送
  • Create Reference maintainers 可直建分支
  • Code-Review -2..+2 reviewers 评审人可打分
  • Submit maintainers 可合入

refs/heads/release/*

  • Push release-team 仅发布组可评审推送
  • Submit release-team
  • Code-Review -2..+2 reviewers

refs/heads/release/* 限定发布分支，refs/tags/* 管标签，refs/meta/* 管元数据分支。我习惯用前缀匹配把发布线和开发线隔开，省得发布分支被随手改。

打分靠 Code-Review 和 Verified 两个标签¶

Gerrit 内置 Code-Review（-2..+2）与 Verified（-1..+1）：

Code-Review +2 评审通过（可合入）
Code-Review +1 基本认可
Code-Review -1 有意见，修改后再审
Code-Review -2 阻止合入
Verified +1 CI 验证通过
Verified -1 CI 验证失败

合入的通常规则是至少一个 +2、无 -2、Verified +1，要改可以用 set-project --submit-rule 自定义。

需要额外门禁就加自定义标签¶

Anonymous Users 默认无 Read（私有评审），Submit 权限只给最小集合，还要定期到 Projects → 项目 → Access 看实际生效矩阵。权限就绪后走一遍完整评审：06-Code-Review-全流程。
