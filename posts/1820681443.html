ROS 与 Docker

[!info] 本节目标
掌握使用 Docker 构建 ROS1 开发/运行环境、镜像制作与常见部署方式。

1. 为什么用 Docker

优势 说明
环境隔离 不同 ROS 版本/依赖共存
快速部署 一键拉取镜像即用
可复现 团队统一环境
干净卸载 删除容器即可

2. 基础镜像

镜像标签 内容
ros:noetic-ros-core 最小核心
ros:noetic-ros-base 基础工具
ros:noetic 完整桌面

[!tip] 国内加速
网络慢时配置 Docker 镜像加速器（如 daocloud 等），或使用国内源构建基础镜像。

3. 运行交互容器

[!warning] 图形界面
容器内运行 rviz/Gazebo 需共享 X11（Windows 用 WSLg 或 X server + -e DISPLAY）与 GPU 支持。

5. 构建与推送

[!tip] 多阶段构建
构建环境与运行环境分离（构建装编译器、运行只装库），显著减小镜像体积。

6. 容器内 ROS 通信（同宿主）

容器与宿主共享网络即可互通：

[!warning] 端口映射
用 -p 映射需同时注意 ROS XMLRPC/TCPROS 的双端口特性；--network host 最省事但安全性差（见 29-rosbridge与Web端 的安全建议）。

7. 多容器编排（docker-compose）

[!tip] compose 优势
把 master、底盘、导航、可视化拆成独立服务，日志/重启/扩展统一管理。

8. 常见坑

问题 解决
容器内 no roscore 未启动 master 或网络隔离
GUI 无法显示 DISPLAY/X11/GPU 配置
依赖缺失 镜像内 apt 安装后重新构建
数据卷权限 挂载目录权限（uid/gid）

Docker 环境下的多机/云部署见 36-产品化实践；容器内调试日志见 18-日志与调试。
