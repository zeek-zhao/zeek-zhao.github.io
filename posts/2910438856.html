Docker 用户指南

我写这篇的出发点很直接：Docker 的价值不在概念多漂亮，而在于它把”环境一致”这件事变成了可复制的操作。所以下面从安装一直写到排障，命令和配置都给全，照着敲就能用。

Docker 用容器把”在我机器上能跑”变成”到处都能跑”¶

Docker 是一个开源的应用容器引擎，让开发者可以打包他们的应用以及依赖包到一个可移植的容器中，然后发布到任何流行的 Linux 或 Windows 机器上。

Docker 的优势¶

  • 一致的环境: “在我机器上可以运行” → “在任何地方都可以运行”
  • 隔离性: 应用程序彼此隔离运行，互不干扰
  • 可移植性: 可以在任何支持 Docker 的平台上运行，无需重新配置
  • 微服务架构: 适合现代微服务开发模式，每个服务独立部署
  • 版本控制: 容器镜像可以版本化管理，易于回滚和追踪
  • 高效资源利用: 比传统虚拟机更轻量，启动更快，资源消耗更少
  • 快速部署: 从开发到测试到生产，保持环境一致性
  • 回滚容易: 可以快速回滚到之前的镜像版本

按平台把 Docker 装起来再验证¶

Linux (Ubuntu)¶

macOS¶

  1. 下载并安装 Docker Desktop for Mac
  2. 完成安装后，Docker 图标将出现在状态栏中
  3. 打开终端，运行 docker --version 确认安装成功

Windows¶

  1. 下载并安装 Docker Desktop for Windows
  2. 确保在 BIOS 中启用了硬件虚拟化
  3. 完成安装后，Docker 图标将出现在任务栏中
  4. 打开 PowerShell 或 CMD，运行 docker --version 确认安装成功

daemon.json 是调整 Docker 行为的主入口¶

Docker 守护进程(daemon)的配置文件用于自定义 Docker 的行为。在不同系统上，配置文件位置如下：

  • Linux: /etc/docker/daemon.json
  • Windows: C:\ProgramData\docker\config\daemon.json
  • macOS: ~/Library/Containers/com.docker.docker/Data/daemon.json

镜像、容器、Dockerfile 和 Registry 构成 Docker 的四块基石¶

镜像 (Image)¶

镜像是一个只读模板，包含创建 Docker 容器的指令。

  • 分层结构: 镜像由多个层(layer)组成，每层代表Dockerfile中的一条指令
  • 共享机制: 相同的层在不同镜像间共享，节省存储空间
  • 可继承性: 镜像可以基于其他镜像创建，形成父子关系
  • 版本控制: 通过标签(tag)进行版本管理
  • 分发方式: 存储在Registry中，可推送和拉取

容器 (Container)¶

容器是镜像的运行实例，可以被创建、启动、停止、删除和暂停。

  • 独立环境: 每个容器都是相互隔离的运行环境
  • 轻量级: 容器共享宿主机内核，比传统虚拟机更轻量
  • 可连接性: 容器可以连接到多个网络，进行互相通信
  • 状态管理: 容器有多种状态(运行、停止、暂停等)
  • 资源控制: 可限制容器使用的CPU、内存等资源

Dockerfile¶

Dockerfile 是一个文本文件，包含构建 Docker 镜像的所有命令。

基本指令说明

指令 说明
FROM 指定基础镜像，必须是第一条指令
WORKDIR 设置工作目录，影响后续指令
COPY/ADD 将文件从构建上下文复制到镜像中
RUN 执行命令并创建新的镜像层
ENV 设置环境变量
EXPOSE 声明容器监听的端口
CMD 指定容器启动时执行的命令
ENTRYPOINT 指定容器启动时执行的入口程序
VOLUME 创建挂载点
USER 指定运行容器时的用户
ARG 定义构建时的变量

Docker Registry¶

Registry 是存储和分发 Docker 镜像的服务。

  • 公共注册表: Docker Hub、GitHub Container Registry、Google Container Registry
  • 私有注册表: 可自行搭建，如Harbor、Nexus等
  • 身份验证: 支持用户权限管理和镜像访问控制
  • 安全扫描: 部分Registry支持安全漏洞扫描功能

构建、安全和生产部署各有必须守住的底线¶

我的判断是：镜像优化和容器安全不是锦上添花，而是上生产前就必须做完功课，否则后面排障成本会成倍上升。

镜像构建优化¶

  1. 使用官方镜像: 优先使用官方维护的基础镜像，确保安全性和更新
  2. 选择alpine版本: 使用alpine基础镜像显著减少镜像大小
  3. 多阶段构建: 分离构建环境和运行环境，减少最终镜像大小
  4. 最小化层数: 合并RUN命令减少镜像层数
  5. 优化缓存: 先复制依赖文件，安装依赖后再复制应用代码
  6. 清理不必要文件: 删除缓存、临时文件和不需要的包
  7. 使用.dockerignore: 排除不需要的文件和目录，减少构建上下文大小

容器安全实践¶

  1. 非root用户运行: 使用USER指令切换到非特权用户
  2. 只读文件系统: 使用--read-only标志运行容器
  3. 限制资源使用: 设置CPU和内存限制
  4. 扫描镜像漏洞: 使用Trivy、Clair等工具扫描安全漏洞
  5. 使用安全选项: 如--security-opt=no-new-privileges
  6. 保持镜像更新: 定期更新基础镜像和依赖
  7. 使用内容信任: 启用Docker Content Trust签名验证
  8. 最小化暴露表面: 只安装必要的软件包

生产环境部署¶

  1. 使用专用网络: 为不同应用组创建隔离网络
  2. 命名容器和卷: 使用有意义的名称便于管理
  3. 实施健康检查: 通过HEALTHCHECK确保服务可用性
  4. 合理的日志策略: 配置日志轮转防止磁盘填满
  5. 使用Docker Secrets: 安全管理敏感数据
  6. 设置重启策略: 如--restart=always确保服务可用
  7. 备份卷和数据: 定期备份重要数据
  8. 监控容器: 使用cAdvisor、Prometheus等监控解决方案
  9. 使用编排工具: 生产环境使用Kubernetes、Docker Swarm等
  10. 容器生命周期管理: 定期清理未使用的容器和镜像
