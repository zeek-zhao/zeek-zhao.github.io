性能优化

[!abstract] 目标
构建快、调度稳、不排队。从资源规划 → 调度策略 → 构建本身三层优化。

1. 资源与 JVM

[!note] 内存
Jenkins 主进程内存主要吃在构建历史、控制台输出、插件；长期运行需配合 Log Rotation 控制日志膨胀。

2. 队列与并发

  • 正确设置每个节点 Executors（09-代理节点）；
  • 用 Quiet Period（静默期）合并连续代码推送触发的重复构建：
  • 防止并发冲突：
  • Throttle Concurrent Builds 插件按标签/Job 限制全局并发。

3. 构建提速

  • 浅克隆：git depth: 1
  • 增量编译/缓存：Maven -o 离线 + 本地仓库复用；npm npm ci 配缓存目录
  • 并行 Stage：
  • 构件缓存：共享库/依赖缓存放到 Agent 持久卷或企业源（如 Nexus3）

4. 日志与存储

  • 控制台输出上限：Manage Jenkins → System → Console Output 设 1MB；
  • 定期清理老构建：
  • 大文件产物不要堆在 Controller 磁盘，归档到 Nexus3 / 对象存储。

5. 规模监控

指标 工具
队列长度/执行器利用率 Jenkins 页面 + Prometheus 插件
JVM 堆/GC JMX 导出 → Grafana
构建时长分布 Stage View / Pipeline 统计插件

[!warning] 常见瓶颈

  • Controller 单点：构建全部跑在 Controller → 迁移到 Agent；
  • SCM 轮询过密 → Webhook；
  • 插件过多/过旧 → 精简升级；
  • 构建历史无限增长 → 磁盘写满（/var/lib/jenkins 监控告警）。
