编译与链接

[!info] 本页概览
从源码到可执行文件经历预处理、编译、汇编、链接四个阶段。理解编译与链接的机制，才能解决”undefined reference”等经典链接错误。本文讲解编译流程、目标文件、符号表与链接原理。

核心概念

  • 编译单元（translation unit）：一个源文件 + 其包含的头文件展开后的整体。
  • 目标文件（.o / .obj）：编译单元生成的可重定位机器码，包含符号表与未解析引用。
  • 链接（link）：把多个目标文件与库合并，解析符号引用，生成可执行文件。
  • 声明 vs 定义：声明告诉编译器”符号存在”，定义提供实现。头文件放声明，源文件放定义。

经典链接错误

  1. **undefined reference to add**：链接器找不到 add 的定义。原因：忘了编译 add.c；或 add 定义被 static 限定为文件内可见。
  2. **multiple definition of add**：同名函数在多个编译单元中都定义了（非 static 全局函数）。头文件里定义函数体导致每个包含它的源文件各生成一份。
  3. 声明与定义不一致：头文件声明 int add(int,int)，实现却是 int add(int,float)，链接时符号名（C++ 中 mangled name）不匹配。

C++ 名称修饰（Name Mangling）

C++ 支持重载，符号名由函数名+参数类型编码，如 int add(int,int) 在 g++ 下可能为 _Z3addii。这也是 extern “C” 的由来：

C 与 C++ 互调时，C++ 侧包含 C 头文件必须用 extern "C"，否则找不到符号。

常见坑

  1. static 全局函数：static 限定函数仅在当前文件可见，跨文件调用报 undefined reference。
  2. 头文件放定义：结构体函数体、全局变量定义写在头文件里，被多个源文件包含后产生重复定义。
  3. 忘记链接库：用了 sqrt 却忘加 -lm；用了 pthread 忘加 -lpthread。
  4. -O2 优化后行为变化：未定义行为在优化下表现不同，调试用 -O0 -g。

最佳实践

  • 头文件只放声明与类型定义，实现放 .c/.cpp；用 include guard。
  • 全局变量用 extern 声明（头文件）+ 定义（一个源文件）。
  • 大型项目用构建工具（见 12-Make与CMake）而非手工 gcc 命令。
  • 链接错误先看符号名与编译命令，再用 nm、ldd 等工具定位。
