组合式 API

[!info] 本页概览
本文讲解 Vue 3 组合式 API 核心：<script setup>、ref/reactive、toRefs、响应式原理（Proxy）、与选项式对比，以及如何组织组合式逻辑。

核心概念

  • 组合式 API（Composition API）：按逻辑关注点组织代码，替代选项式（data/computed/methods 分块）。
  • **<script setup>**：SFC 语法糖，顶层变量/函数自动暴露模板。
  • ref：基本类型/任意值响应式（.value）；reactive：对象深层响应式。
  • 响应式基于 Proxy 代理，深层对象自动追踪。

响应式原理简述

实际开发不需要手写，理解即可：

  • 模板渲染函数收集依赖。
  • 数据变化触发重新渲染（虚拟 DOM diff）。
  • 深层对象（reactive）按需递归代理（Vue 3 Proxy 懒代理）。

逻辑复用（组合函数雏形）

常见坑

  1. ref 忘记 .value：模板自动解包，但 JS 中必须 count.value；在对象/数组嵌套中取 arr.value[i]。
  2. reactive 解构丢响应：const { name } = reactive({...}) 是非响应式副本；用 toRefs。
  3. reactive 替换对象：整体 form = newObj 失效；用 Object.assign(form, newObj)。
  4. reactive 包装 ref：reactive({ count: ref(0) }) 自动解包，但数组内 ref 不解包。
  5. <script setup> 中 await 顶层：Suspense 边界语义复杂；慎用，推荐函数内 await。
  6. this 不可用：组合式 API 无 this，直接使用导入的响应式 API。

最佳实践

  • 新代码统一 <script setup> + 组合式 API。
  • 按业务抽取 composables（useAuth/useTable/useFetch），代码复用最大化。
  • 表单等嵌套对象用 reactive；可整体替换/简单值用 ref。
  • 组合函数命名 useXxx，返回对象便于解构。
  • 复杂组件拆分多个组合函数，保持 setup 顶层可读。
