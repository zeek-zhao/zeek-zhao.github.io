六个核心模块加一圈外围支撑，先把谁给谁喂数据弄明白，后面逐个读源码才不会迷路。本篇接着 05-源码编译与部署 往下，也是入门阶段的收尾。

1. 六个核心模块与外围支撑¶

Apollo 核心模块分为六类：高精地图（HD Map）、定位、感知、预测、规划、控制。

模块 输入 输出
高精地图 地图数据 车道、信号灯、路网信息
定位 传感器 + 地图 车辆位姿
感知 相机/激光/雷达 障碍物、车道线、红绿灯
预测 感知结果 障碍物轨迹预测
规划 定位 + 预测 + 地图 行驶轨迹
控制 规划轨迹 车辆控制指令

外围还有支撑模块：Cyber RT（通信框架）、Routing（全局路径规划）、Canbus（底盘适配）、Transform（坐标转换）、Guardian（安全兜底）、Dreamview（可视化人机界面）。

2. 数据从传感器一路流到底盘¶

各模块通过 Cyber RT 的发布/订阅消息解耦。典型城市道路场景下的完整链路是这样：定位融合 RTK/IMU/激光输出位姿，地图加载车道与信号灯信息，感知识别障碍物与车道线，预测估计障碍物未来轨迹，规划综合所有信息生成安全轨迹，控制把轨迹转成方向盘与油门刹车指令下发给底盘。任何一个环节异常都会拖累下游输出。

3. 各模块职责速记¶

3.1 高精地图（Map）¶

提供厘米级精度的结构化道路信息：车道（中心线、边界、限速、拓扑关系）、道路、交叉路口、交通标志与信号灯、停车区域。基于 Protocol Buffers 定义数据格式，支持分块加载与查询。它是全局先验，从感知一直贯穿到规划。

3.2 定位（Localization）¶

三种定位方法，可单独或组合使用：

  • RTK：GNSS + IMU 融合，厘米级，依赖 GPS 信号
  • 激光雷达定位：点云与高精地图匹配，不依赖 GPS
  • MSF 多传感器融合：结合各方法优势，可靠性最高

Apollo 11.0 把定位重构成了 RTK + SLAM + 视觉 + 轮速计的融合方案，厘米级精度，专门适配功能车在园区、隧道这类 GPS 遮挡环境下的运行。

3.3 感知（Perception）¶

识别和理解周围环境：障碍物检测与跟踪（激光点云分割聚类 + 相机深度学习检测）、交通信号灯检测与状态识别、车道线检测与分类，最后多传感器融合输出。Apollo 10.0 的感知升级为 BEV + Transformer + 占据栅格网络，从单视角检测走向统一鸟瞰空间表征。

3.4 预测（Prediction）¶

预测动态障碍物的未来轨迹与意图。方法涵盖三类：基于物理模型（运动学）、基于规则（状态机，适合路口等结构化场景）、基于学习（深度学习，适合复杂交互场景）。

3.5 规划（Planning）¶

生成安全、舒适、可行的轨迹。流程为：参考线生成 → 路径决策 → 速度决策 → 轨迹生成与平滑。算法以基于优化的方法（QP、MPC）为主，辅以采样与规则方法；支持车道保持、变道、路口通行、泊车等场景。

3.6 控制（Control）¶

将规划轨迹转为控制指令：

  • 横向控制：LQR / MPC，转向跟踪
  • 纵向控制：PID / MPC，油门刹车
  • 控制前进行轨迹预处理与误差计算，输出前做平滑与安全检查

3.7 路由（Routing）与 Canbus¶

  • Routing：基于图论算法在道路网络中搜索起点到终点的最优路径，考虑道路通行条件、交通规则与偏好设置，输出结果供规划生成参考线；支持根据交通状况动态重规划。
  • Canbus：车辆底盘适配层，将控制指令转换为 CAN 报文下发，并将底盘状态（车速、加速度、转向角、故障码）反馈给上游。适配新车型需实现车辆工厂类、车辆控制器与协议转换类，涉及安全策略（命令越界拒绝、人工接管优先）。

3.8 Cyber RT 框架¶

Apollo 的实时计算框架，替代早期 ROS。核心概念：

  • Component（组件）：功能单元，通过 DAG 配置加载
  • Node / Channel：通信单元，发布/订阅模式
  • Scheduler：协程调度，支持优先级

常用命令行工具：cyber_monitor（查看通道）、cyber_recorder record/play（录制回放）。

4. 决策模块的算法谱系¶

给后面深入留个坐标，预测、规划两大决策模块，外加控制的算法谱系：

层次 算法类别 代表方法
预测 物理模型 匀速模型、恒定转向模型
预测 行为模型 状态机、意图驱动

5. 代码目录长这样¶

每个模块的标准结构为 conf（配置）、dag（DAG 图）、launch（启动）、proto（协议）、src（源码）五个子目录。

6. 依赖关系与联调顺序¶

模块依赖关系：

  • 定位为规划与控制提供坐标基准
  • 感知质量直接决定预测与规划效果
  • 地图是全局先验，贯穿各模块
  • 控制是执行层，严格依赖规划轨迹

我习惯的联调顺序是由下至上：先确认传感器数据话题正常，再看定位位姿稳不稳，然后逐级验证感知、预测、规划、控制的输出。Dreamview 可视化配合 cyber_monitor，基本能快速锁定问题落在哪一环。

操作步骤 / 使用流程¶

  1. 理清数据契约：先记住六大模块的输出话题（见上方清单）。
  2. 起基座：确认 Cyber RT 与 Dreamview 可用，参见 11-Apollo-Cyber-RT框架。
  3. 自底向上联调：传感器 → 定位 → 感知 → 预测 → 规划 → 控制，逐环验证。
  4. 用工具观测：cyber_monitor 看通道，cyber_recorder 录回放，Dreamview 看可视化。
  5. 注入地图与路由：加载地图（07-高精地图HD-Map）并给定起终点得到 Routing。
  6. 闭环验证：在 Dreamview 中选路线、启动模块，观察车辆轨迹与控制输出。

注意事项与常见坑¶

  1. 话题名不匹配：上下游话题名不一致导致数据断流，用 cyber_monitor 逐一核对。
  2. 时间戳不同步：感知/定位时间戳错位会使融合结果漂移。
  3. 坐标系混用：全局与车体坐标未转换，轨迹与控制全错，参见 31-Cyber-Transform与坐标变换。
  4. 地图未加载：规划查询车道失败，先确认 --map_dir 与地图格式。
  5. Guardian 误触发：控制指令越界被拦截，检查控制参数与车辆限制。
  6. Routing 未给路径：规划没有参考线，先确认起点终点与路由模块输出。
  7. 组件加载失败：DAG 中 so 路径错误，参见 25-Cyber启动系统详解。
  8. 模块启动顺序：依赖模块未起会导致订阅无数据，按依赖顺序启动。
  9. 日志级别过高：默认 INFO 看不到细节，调试时临时开 DEBUG。
  10. 端到端混淆：模块化与端到端是不同范式，参见 38-端到端自动驾驶与大模型。
