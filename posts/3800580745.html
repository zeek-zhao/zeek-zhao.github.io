SPI总线原理与驱动实战

SPI 这东西看着就是四根线，真上手调才知道门道全在时钟模式和数据手册的时序要求里。我在嵌入式项目里用它接过 Flash、传感器和屏幕，最深的体会是协议本身很简单，翻车几乎都翻在 CPOL/CPHA 和片选时序上。这篇把 SPI 的原理、模式、硬件连接、编程实例和排错思路一次性捋清楚，照着章节顺序看就能搭起完整框架。

一图看懂：SPI 四线全双工，靠移位寄存器交换数据，四种时钟模式。

graph LR M[主设备] -->|MOSI| S[从设备] S -->|MISO| M M -->|SCK 时钟| S M -->|CS 片选| S S --> MODE["四种时钟模式 CPOL CPHA"]

1. 四线全双工总线：SPI 的定位与演进¶

我给 SPI 下的定义很简单：一根时钟线加两条数据线，主从靠片选配对——先记住这个骨架，后面那些模式和变种都是在这上面加东西。

SPI（Serial Peripheral Interface，串行外设接口）是一种同步串行通信接口规范，由摩托罗拉（Motorola）公司在1980年代开发，目前被广泛应用于嵌入式系统中各种芯片之间的通信。作为四线全双工串行通信总线，SPI以其简单高效的特性，成为连接微控制器与外设（如传感器、存储器、显示器等）的重要桥梁。

1.1 SPI的发展历史¶

  • 1980年代：摩托罗拉开发SPI协议，最初用于其68000系列微处理器与外设通信
  • 1990年代：随着单片机的普及，SPI被更广泛地应用于各种嵌入式应用
  • 2000年代：随着IoT和嵌入式系统的爆发式增长，SPI成为标准通信接口之一
  • 现在：几乎所有主流微控制器都支持SPI接口，大量传感器、存储芯片、显示驱动等外设采用SPI通信

1.2 SPI的基本特性¶

SPI是一种简单而灵活的通信协议，具有以下主要特性：

  • 同步通信：通过时钟信号同步数据传输，发送方在时钟信号的控制下发送数据，接收方在时钟信号的控制下接收数据
  • 全双工通信：可以同时进行发送和接收数据
  • 主从架构：一个主设备（通常是微控制器）控制一个或多个从设备（传感器、存储器等）
  • 可变速率：支持高速数据传输，常见速率从几百kHz到几十MHz
  • 灵活的数据帧格式：不限定数据帧格式，通常采用8位或16位数据传输
  • 低复杂度：协议实现简单，可以用软件模拟或硬件实现
  • 无地址机制：通过片选信号选择特定的从设备
  • 无应答机制：不像I²C那样有内置的应答机制

SPI由于简单高效，特别适合需要高速数据传输且设备间距离较近的应用场景。尽管其缺少标准化规范，但基本原理和操作方式已被广泛接受和采用。

2. 移位寄存器交换：SPI 的四线信号与时钟¶

我调 SPI 时最先确认的永远是这四根线的方向，MOSI 和 MISO 接反是初级但高频的错误，尤其要对着从设备手册看 DI 和 DO 到底对应哪根。

2.1 SPI总线信号线¶

SPI总线通常由四条信号线组成：

  1. **SCLK (Serial Clock)**：

    • 由主设备生成的时钟信号
    • 控制数据传输的时序
    • 所有数据传输都与此时钟信号同步

  2. **MOSI (Master Out Slave In)**：

    • 主设备数据输出、从设备数据输入的信号线
    • 主设备通过该线向从设备发送数据

  3. **MISO (Master In Slave Out)**：

    • 主设备数据输入、从设备数据输出的信号线
    • 从设备通过该线向主设备发送数据

  4. **SS/CS (Slave Select/Chip Select)**：

    • 片选信号，用于选择要通信的特定从设备
    • 通常为低电平有效
    • 主设备可以有多个SS/CS线，分别连接不同的从设备

这种四线设计支持全双工通信，即主设备和从设备可以同时发送和接收数据。

2.2 SPI通信基本原理¶

SPI通信的基本过程如下：

  1. 初始化：主设备配置SPI控制器（设置时钟频率、模式等）
  2. 选择从设备：主设备将目标从设备的SS/CS线拉低，激活该从设备
  3. 数据交换：
    • 主设备生成时钟信号(SCLK)
    • 主设备通过MOSI线发送数据
    • 同时，从设备通过MISO线发送数据
    • 每个时钟周期传输一个比特
  4. 结束通信：主设备将SS/CS线拉高，停止与该从设备的通信

SPI通信使用移位寄存器原理，每个时钟周期，主设备和从设备的移位寄存器各移出一位数据，同时各移入一位数据。经过8个或16个时钟周期（取决于帧长度），完成一个完整数据帧的交换。

2.3 SPI时钟模式¶

SPI定义了四种不同的时钟模式（Mode 0-3），由两个参数决定：

  • **CPOL (Clock Polarity)**：时钟极性

    • CPOL=0：空闲状态时，SCLK为低电平
    • CPOL=1：空闲状态时，SCLK为高电平

  • **CPHA (Clock Phase)**：时钟相位

    • CPHA=0：在SCLK第一个跳变沿采样数据
    • CPHA=1：在SCLK第二个跳变沿采样数据

四种模式组合：

  • **Mode 0 (CPOL=0, CPHA=0)**：空闲时SCLK为低，数据在SCLK上升沿采样
  • **Mode 1 (CPOL=0, CPHA=1)**：空闲时SCLK为低，数据在SCLK下降沿采样
  • **Mode 2 (CPOL=1, CPHA=0)**：空闲时SCLK为高，数据在SCLK下降沿采样
  • **Mode 3 (CPOL=1, CPHA=1)**：空闲时SCLK为高，数据在SCLK上升沿采样

不同的SPI设备可能支持不同的模式，正确选择模式对于成功通信至关重要。

3.3 SPI引脚电气特性¶

SPI接口的电气特性通常符合以下特点：

  • 逻辑电平：通常与连接设备的工作电压一致（3.3V或5V系统）
  • 驱动能力：主设备需要具有足够的驱动能力
  • 上拉电阻：MISO线通常需要弱上拉电阻（10kΩ左右）
  • 最大总线长度：由于无标准定义，通常限制在几十厘米内
  • 信号完整性：高速SPI（>10MHz）需考虑信号完整性问题

4. 四种时钟模式：采样沿与切换沿的组合¶

模式选错是 SPI 最典型的翻车点：极性或相位差一个边沿，数据看着在动但全是错的，所以每次换芯片我都先翻数据手册确认 Mode。

4.1 四种工作模式时序图¶

4.1.1 Mode 0 (CPOL=0, CPHA=0)

  • 空闲时SCLK为低电平
  • 数据在SCLK上升沿采样
  • 数据在SCLK下降沿切换

4.1.2 Mode 1 (CPOL=0, CPHA=1)

  • 空闲时SCLK为低电平
  • 数据在SCLK下降沿采样
  • 数据在SCLK上升沿切换

4.1.3 Mode 2 (CPOL=1, CPHA=0)

  • 空闲时SCLK为高电平
  • 数据在SCLK下降沿采样
  • 数据在SCLK上升沿切换

4.1.4 Mode 3 (CPOL=1, CPHA=1)

  • 空闲时SCLK为高电平
  • 数据在SCLK上升沿采样
  • 数据在SCLK下降沿切换

4.2 工作模式选择考虑因素¶

选择合适的SPI模式时需考虑以下因素：

  1. 从设备要求：首先查阅从设备数据手册，了解其支持的SPI模式
  2. 数据稳定性：某些情况下，特定模式可能提供更好的数据稳定性
  3. 时钟频率：不同模式在高频下的表现可能有差异
  4. 多设备兼容性：当多个不同从设备连接到同一SPI总线时，需选择所有设备都支持的模式
  5. 硬件限制：某些微控制器的SPI外设可能仅支持特定模式

大多数SPI设备默认使用Mode 0或Mode 3，因为数据在时钟稳定期间进行采样，提供更好的稳定性。

5. 位序、帧长与速率：SPI 数据传输的四个变量¶

位序和帧长必须跟从设备手册对齐，我见过 MSB 和 LSB 配反导致数据整体镜像的情况，这比时钟问题更隐蔽。

5.1 数据位顺序¶

SPI通信中，数据传输的位顺序通常有两种：

  • MSB优先：最高有效位先传输，大多数SPI设备默认使用此种顺序
  • LSB优先：最低有效位先传输，少数设备使用此种顺序

位顺序必须与从设备的要求匹配，否则会导致数据错误。

5.2 数据帧大小¶

SPI协议本身对数据帧大小没有固定要求，常见的数据帧大小有：

  • 8位：最常见的数据帧大小，适用于大多数应用
  • 16位：通常用于高精度传感器、ADC/DAC等设备
  • 可变长度：某些高级SPI控制器支持可变长度的数据帧

5.3 传输速率¶

SPI理论上支持非常高的传输速率，具体取决于以下因素：

  • 主设备时钟频率限制
  • 从设备最大工作频率
  • 信号完整性和传输线长度
  • 环境干扰

常见的SPI时钟频率范围：

  • 低速模式：100kHz-1MHz
  • 中速模式：1MHz-10MHz
  • 高速模式：10MHz-50MHz
  • 超高速模式：>50MHz（需要特殊设计）

5.4 连续传输与突发传输¶

SPI支持两种传输模式：

  1. 连续传输：

    • CS线保持低电平，持续发送多个数据帧
    • 适用于大量数据传输，如读写存储器
    • 提高传输效率，减少CS切换开销

  2. 突发传输：

    • 每传输一个数据帧后，CS回到高电平
    • 适用于需要间断通信的场景
    • 增加传输开销，但提供更清晰的数据边界

6. 选型边界：SPI、I²C 与 UART 怎么分¶

我的选型习惯是板级高速设备走 SPI，GPIO 紧张又要挂多个低速设备走 I²C，只是打日志或连 PC 就用 UART。

6.1 SPI与I²C对比¶

特性 SPI I²C
速度 更快（可达数十MHz） 较慢（标准模式100kHz，快速模式400kHz，高速模式3.4MHz）
通信方式 全双工（同时收发数据） 半双工（交替收发数据）
信号线数量 4+n条（n为从设备数量） 固定2条（SDA和SCL）
寻址方式 使用独立CS线选择从设备 使用设备地址进行寻址
主设备数量 单一主设备 支持多主设备
从设备数量 理论无限（受主设备GPIO限制） 受地址空间限制（标准模式下128个）
协议复杂度 简单，无标准化格式 较复杂，有标准化格式
应答机制 无内置应答机制 有内置应答机制
距离限制 较短（通常数十厘米） 较长（可达数米）
功耗 相对较高 相对较低
硬件复杂度 简单 较复杂

6.2 SPI与UART对比¶

特性 SPI UART
速度 高（MHz级别） 低至中（通常≤115200bps）
通信方式 同步，全双工 异步，全双工
信号线数量 4+n条 固定2条（RX和TX）
时钟信号 有独立时钟线 无独立时钟线，使用内部波特率发生器

6.3 各协议适用场景¶

  • SPI适用场景：

    • 需要高速数据传输
    • 设备距离较近
    • 全双工通信
    • 存储器访问（Flash、EEPROM）
    • 高速传感器接口

  • I²C适用场景：

    • 多设备连接但GPIO资源有限
    • 中等速度要求
    • 需要标准化协议
    • 短距离通信总线
    • 低速传感器和配置接口

  • UART适用场景：

    • 点对点通信
    • 中长距离连接
    • 异步通信需求
    • 调试接口
    • 与计算机通信

7. 从 Flash 到传感器：SPI 的典型落地场景¶

    • 成本较低，容量较大

  • SPI EEPROM：

    • 如Microchip 25LC系列、ST M95系列
    • 用于存储配置和参数数据

8. 硬件控制器、软件模拟与 DMA 三条实现路径¶

有硬件 SPI 就别用软件模拟，除非引脚被占满了——模拟方式速度上不去还吃 CPU，我一般只在应急时用。

8.1 硬件SPI控制器¶

大多数现代微控制器都内置了SPI控制器，具有以下特点：

  • 专用硬件移位寄存器：高速数据传输
  • 可配置时钟分频器：灵活控制通信速率
  • 多种工作模式支持：适应不同设备需求
  • DMA支持：减轻CPU负担
  • 中断机制：事件驱动处理
  • 多CS管理：简化多设备控制

硬件SPI控制器通常包含以下寄存器：

  • 控制寄存器：配置工作模式、位序、帧大小等
  • 状态寄存器：指示当前状态（忙、空闲、错误等）
  • 数据寄存器：用于数据发送和接收
  • 时钟配置寄存器：设置SPI时钟频率
  • 中断控制寄存器：配置各种中断触发条件

10. 通信不稳与数据错位：SPI 的排查工具链¶

我排查 SPI 的顺序是先量 CS 有没有拉低，再看时钟频率是不是超了，最后才上逻辑分析仪对解码参数，大部分问题卡在前两步。

10.1 常见问题与解决方法¶

10.1.1 通信失败或不稳定

症状：读写数据错误或不可靠

可能原因：

  • 时钟频率过高
  • 错误的SPI模式设置
  • 信号完整性问题
  • 电源不稳定

解决方法：

  • 降低SPI时钟频率
  • 核对数据手册，确认正确的SPI模式
  • 缩短信号线长度，使用适当阻抗匹配
  • 检查电源稳定性和噪声
  • 在信号线上增加上拉/下拉电阻

10.1.2 多设备冲突

症状：某些设备工作不正常，数据混乱

可能原因：

  • 片选信号控制错误
  • 多个设备共享数据线时序冲突
  • 总线负载过重

解决方法：

  • 检查CS信号的控制逻辑
  • 确保多设备操作之间有足够的时间间隔
  • 减少连接到同一SPI总线的设备数量
  • 如使用菊花链连接，检查数据流向是否正确

10.1.3 数据错位或乱码

症状：收到的数据与预期不符，但有一定规律

可能原因：

  • 数据位序错误（MSB/LSB优先设置错误）
  • 数据帧长度不匹配
  • 时钟相位或极性设置错误

解决方法：

  • 检查并修正位序设置
  • 确认主从设备的数据帧长度一致
  • 验证CPOL和CPHA设置是否与从设备要求匹配

10.2 调试与测试工具¶

10.2.1 逻辑分析仪

逻辑分析仪是调试SPI通信的强大工具：

  • 可同时捕获多个信号（SCLK、MOSI、MISO、CS）
  • 可解码SPI协议数据
  • 可测量时序参数
  • 可识别通信异常

使用逻辑分析仪时的注意事项：

  • 正确配置SPI解码参数（极性、相位、位序）
  • 使用足够高的采样率（至少SPI时钟频率的5倍以上）
  • 确保探头接地良好

10.2.2 示波器

对于信号完整性问题，示波器是不可或缺的工具：

  • 可观察信号波形质量
  • 可测量上升/下降时间
  • 可检测过冲、振铃和反射

10.2.3 回环测试

简单但有效的自测方法：

  • 将MOSI连接至MISO
  • 发送测试数据并接收回传数据
  • 比较发送和接收的数据是否一致

10.3 提高SPI通信可靠性的措施¶

10.3.1 硬件设计考虑

  • 电路布局：

    • 尽量缩短SPI信号线长度
    • 避免信号线交叉和并行走线
    • 采用正确的阻抗匹配和终端电阻

  • 电源设计：

    • 为敏感设备提供独立电源滤波
    • 使用足够容量的去耦电容
    • 考虑在高速应用中使用铁氧体磁珠

  • 接口保护：

    • 在需要高可靠性的场合使用缓冲器或隔离器
    • 考虑添加ESD保护元件

10.3.2 软件设计考虑

  • 健壮性：

    • 实现通信超时检测
    • 添加数据校验机制（如校验和）
    • 实现错误恢复策略

  • 性能优化：

    • 批量传输代替单字节传输
    • 使用DMA减轻CPU负担
    • 根据实际需求选择适当的时钟频率

11. QSPI、DDR 与 RTOS 下的 SPI 高级用法¶

RTOS 下多任务访问同一路 SPI 一定要加互斥锁，否则两个任务同时操作片选，数据会莫名其妙错乱。

11.1 高速SPI变种¶

随着数据传输需求增加，传统SPI已发展出多种高速变体：

11.1.1 QSPI (Quad SPI)

  • 使用4条数据线并行传输
  • 理论带宽是标准SPI的4倍
  • 支持单/双/四线模式切换
  • 广泛应用于高速Flash存储
  • 使用相同的时钟和片选机制

11.1.2 DSPI (Dual SPI)

  • 使用2条数据线并行传输
  • 理论带宽是标准SPI的2倍
  • 常见于中速Flash存储器

11.1.3 SPI DDR (Double Data Rate)

  • 在时钟的上升沿和下降沿都传输数据
  • 理论带宽是标准SPI的2倍
  • 需要更高的信号完整性要求

11.2 SPI与其他技术结合¶

11.2.1 SPI与DMA

  • 通过DMA实现零CPU干预数据传输
  • 适用于大量数据传输场景
  • 可实现背景数据传输
  • 结合中断实现高效异步通信

11.2.2 SPI与RTOS

在实时操作系统中使用SPI的考虑：

  • 多任务访问SPI总线的互斥保护
  • 通信超时和错误处理
  • 异步通信和事件通知机制

11.3 资源管理与优化¶

在复杂嵌入式系统中，SPI资源管理对于系统稳定性和性能至关重要。

11.3.2 性能优化策略

在资源受限的嵌入式系统中，SPI通信性能优化尤为重要：

  1. 批量传输：

    • 多个小数据包合并为大数据包传输
    • 减少片选切换开销
    • 提高总线利用率

  2. 双缓冲：

    • 准备下一传输数据时，当前传输正在进行
    • 减少CPU等待时间
    • 提高数据吞吐量

  3. DMA链：

    • 多个DMA传输自动链接执行
    • 无需CPU干预
    • 高效连续数据传输

  4. 并行处理：

    • 多线程/任务协同工作
    • 数据处理与传输并行
    • 降低总体延迟

  5. 中断优化：

    • 使用传输完成中断而非轮询
    • 合理设置中断优先级
    • 最小化中断处理程序

12. 无加密的 SPI 总线：物理风险与加固方案¶

SPI 本身没有任何加密或认证，传密钥类数据必须在应用层自己做加密，我一般把密钥放安全芯片而不是走 SPI 明文。

12.1 物理安全风险¶

SPI通信在物理安全方面存在一些潜在风险：

  1. 总线窃听：

    • SPI信号线可以被物理探测器捕获
    • 无内置加密机制
    • 敏感数据可能被窃取

  2. 恶意设备：

    • 恶意硬件可以伪装为合法SPI设备
    • 可能进行数据篡改或注入攻击
    • 可能导致系统故障或安全漏洞

  3. 旁路攻击：

    • 通过功耗分析或电磁辐射分析推断数据
    • 可能泄露加密密钥等敏感信息

12.2 安全增强方案¶

针对SPI通信的安全性问题，可以采取以下措施：

  1. 数据加密：
    • 传输敏感数据前进行加密
    • 使用安全的对称加密算法(AES, ChaCha20等)
    • 保护加密密钥

  1. 消息认证：

    • 使用HMAC等消息认证码验证数据完整性
    • 防止中间人攻击和数据篡改
    • 确保通信双方身份

  2. 安全启动：

    • SPI Flash存储安全启动代码
    • 使用加密签名验证固件完整性
    • 防止固件被篡改或替换

  3. 安全芯片解决方案：

    • 使用专用安全元件(如安全加密芯片)通过SPI连接
    • 利用硬件加密引擎处理敏感操作
    • 将密钥存储在防篡改硬件中

12.3 漏洞防护¶

在开发过程中，应注意防范以下SPI相关漏洞：

  1. 缓冲区溢出：

    • 严格验证SPI接收数据长度
    • 使用安全的数据处理函数
    • 实施边界检查

  2. 命令注入：

    • 验证SPI命令的有效性
    • 实施命令白名单机制
    • 防止恶意命令执行

  3. 定时攻击防护：

    • 使操作时间恒定，不依赖于数据内容
    • 添加随机延时
    • 实施抗定时攻击的算法实现

13. 低功耗与无线模块：SPI 在 IoT 中的用法¶

电池供电场景我会尽量降低 SPI 时钟、批量传输后立刻让传感器和 MCU 回休眠，唤醒次数才是耗电大头。

13.1 低功耗IoT设备中的SPI¶

在电池供电的IoT设备中，SPI通信需要特别考虑功耗优化：

  1. 低功耗设计策略：

    • 降低SPI时钟频率
    • 最小化传输数据量
    • 使用休眠模式
    • 批量传输减少唤醒次数

  2. 间歇性通信模式：

    • 仅在需要时启用SPI
    • 利用SPI设备的低功耗模式
    • 使用中断而非轮询

13.2 无线模块集成¶

14. 事实标准下的互操作：SPI 的标准化现状与走向¶

SPI 至今没有强制标准，跨厂商混用时我习惯把模式、位序、帧长都显式写进驱动配置，不依赖默认值。

14.1 当前标准化状况¶

SPI协议的标准化历程：

  1. 历史状况：

    • SPI最初由摩托罗拉定义，但没有完整标准规范
    • 不同厂商实现差异显著
    • 互操作性挑战

  2. JEDEC标准：

    • JESD216系列定义了串行Flash发现协议
    • 标准化了xSPI和QSPI接口部分特性
    • 未覆盖所有SPI应用场景

  3. 事实标准：

    • 行业普遍采用的常见做法
    • 形成了未成文的兼容性规范
    • 仍存在实现差异

14.2 最新发展¶

SPI技术近期的创新和发展：

  1. 超高速SPI变种：

    • OPI (Octal SPI)：使用8条数据线
    • xSPI：扩展的SPI接口标准
    • HSPI (Hyperbus SPI)：双倍数据速率接口

  2. 智能SPI控制器：

    • 集成缓存和DMA功能
    • 在控制器级别实现协议解析
    • 自动化命令处理

  3. 多主机SPI：

    • 允许多个主设备共享总线
    • 引入仲裁机制
    • 提高系统灵活性

14.3 未来趋势展望¶

SPI技术未来可能的发展方向：

  1. 更高集成度：

    • 单芯片集成更多SPI外设
    • 增强的安全功能
    • 系统级优化

  2. 智能化与自适应：

    • 自动检测和适应从设备特性
    • 动态调整参数优化性能
    • 自愈和诊断功能

  3. 低功耗创新：

    • 用于可穿戴和IoT设备的超低功耗模式
    • 智能休眠和唤醒机制
    • 能量收集系统集成

  4. 标准化推进：

    • 更全面的行业标准
    • 提高互操作性
    • 认证和兼容性测试

15. 落地建议：先把模式钉死，再谈优化¶

真要动手做 SPI，我的顺序是先把从设备数据手册里的模式、位序、帧长和最大时钟抄进驱动配置，再用逻辑分析仪确认时序对上了，然后才考虑 DMA 和批量传输这些优化。这三件事钉死，后面绝大多数「通信不稳定」都不会出现。
