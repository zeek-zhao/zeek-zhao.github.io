与AD集成

[!info] 本节目标
了解 OpenLDAP 与 Microsoft Active Directory 的差异与集成方式，能实现跨目录用户同步、联合认证与迁移。

LDAP 与 AD 的差异

AD 本质是 LDAP 的一种专有实现，但存在显著差异：

维度 OpenLDAP Active Directory
配置 cn=config（olc） 图形界面 / PowerShell
默认端口 389/636 389/636（GC 3268/3269）
用户属性 uid + userPassword sAMAccountName + UnicodePwd
组 groupOfNames group / universal group
密码策略 ppolicy overlay GPO / Fine-Grained
复制 syncrepl 站点拓扑自动复制

集成场景一：联合认证（AD 为权威）

业务系统直接对接 AD 做 LDAP 认证，OpenLDAP 中保留本地服务账号：

AD 查询要点：

  • 使用全局编录端口 3268，一次查询全林
  • 搜索过滤器：(&(objectCategory=person)(sAMAccountName={0}))
  • 建议使用服务账户 svc_ldap_read 做只读查询，避免泄露域管权限

集成场景三：密码同步

密码同步是最敏感环节。两种策略：

  • 保持单向：所有登录都打到 AD，OpenLDAP 不存密码（推荐）
  • 双向同步：使用 Password Sync 服务把 AD 密码变更推送到 OpenLDAP（需加密通道）

  • DN 结构重映射（dc 变为 CN=Users 容器）
  • objectClass 转换（inetOrgPerson -> user）
  • 密码散列不可移植，需强制重置或使用迁移工具（如 ADMT/ldap-toolkit）

排错要点

  • 时间同步：Kerberos 对时钟漂移敏感，先 w32tm /resync
  • 端口可达：Test-NetConnection ad.example.com -Port 3268
  • 权限不足：确认服务账户在根域 OU 有 read 权限
  • 大小写：sAMAccountName 不区分大小写，但过滤器要写正确

[!warning] 安全提醒
任何跨目录脚本中的 AD 凭据禁止明文入库，建议使用 Windows 凭据管理器或加密文件，并定期轮换服务账号密码。
