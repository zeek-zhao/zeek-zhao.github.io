dnsmasq 简介与适用场景

dnsmasq 简介与适用场景

ℹ️本篇目标
理解 dnsmasq 是什么、它的核心功能与适用场景，并能在多款同类工具中正确选型。

1. 什么是 dnsmasq¶

dnsmasq 是一款轻量级的 DNS 转发器 / 缓存服务器 / DHCP 服务器，单进程即可同时提供 DNS 与 DHCP 服务。它由 Simon Kelley 开发并持续维护，广泛内置于 Linux 发行版、OpenWrt 路由器、树莓派与各类嵌入式系统。

核心特点：

  • 轻量：内存占用常年在 1-2 MB 级别，可在低配设备上常驻。
  • 全能：DNS 转发缓存、本地域名解析、DHCP 地址分配、TFTP/PXE 引导一应俱全。
  • 易配：单配置文件 /etc/dnsmasq.conf 或命令行参数，无需额外数据库。
  • 内网友好：自动把 DHCP 主机名写入 DNS 解析，实现”设备名即域名”。

2. 核心功能¶

功能 说明
DNS 转发 将查询转发给上游 DNS（8.8.8.8、114.114.114.114 等）并缓存结果
DNS 缓存 缓存解析结果，显著减少局域网对外查询
本地域名解析 支持 /etc/hosts、addn-hosts、local=/域名/ 提供内网解析
DHCP 服务 分配 IP、下发网关/DNS/NTP/搜索域等 option
TFTP/PXE 提供无盘启动（PXE boot）引导文件服务
上游策略 按域名条件转发到指定上游（实现国内/国外分流等）

3. 适用场景¶

  • 家庭/小办公室路由器：OpenWrt 默认内置 dnsmasq，承担 DNS+DHCP。
  • 内网开发环境：把 dev.example.com 解析到本机，配合 Nginx 反向代理。
  • 实验室网络：PXE 批量装机、无盘工作站、设备自动分配 IP。
  • DNS 分流：透明代理场景下按域名走不同上游，降低污染与延迟。
  • 缓存节点：小规模网络中缓存 DNS，减少出口流量。
🔥一句话定位
dnsmasq 是”内网 DNS + DHCP 的一体化轻量服务”，它不追求权威 DNS 的高性能，而追求小巧、易用、省资源。

4. 与同类工具对比¶

工具 定位 DNS DHCP 资源占用
dnsmasq 轻量转发/缓存/DHCP 转发+缓存 是 极低
BIND9 权威+递归 DNS 权威/递归 否 较高
Unbound 递归解析器 递归 否 中
CoreDNS 云原生 DNS 插件化 否 中
Kea DHCP 专业 DHCP 否 是 中
📝选型建议
内网规模小、需要 DNS+DHCP 一体 -> dnsmasq；需要权威 DNS 管理域 -> BIND9/PowerDNS；需要强缓存与 DNSSEC 验证 -> Unbound（可与 dnsmasq 配合：dnsmasq 转发给本地 Unbound）。

5. 安装前需要知道的事¶

  • dnsmasq 默认监听 53 端口（DNS）与 67 端口（DHCP），需确保端口未被占用。
  • 若系统自带 systemd-resolved，需先禁用其 53 端口监听，避免冲突。
  • DHCP 功能默认未开启，配置 dhcp-range 后才生效。
⚠️端口冲突
许多桌面 Linux 的 systemd-resolved 默认占用 127.0.0.53:53。安装 dnsmasq 前先确认 ss -lntup | grep :53，必要时 systemctl stop systemd-resolved 并 mask。
