14-中断管理与临界区

发表于2026-10-24|FreeRTOS
|浏览量:

[!info] 本节目标
掌握中断安全编程与临界区保护机制。

1. 中断与内核交互

中断服务程序 ISR 运行于中断上下文，不能调用普通阻塞 API。FreeRTOS 提供 FromISR 后缀安全接口，用于通知任务与传递数据。正确区分中断安全 API 是稳定性的基础。

2. 中断安全 API

队列、信号量、事件组、任务通知与缓冲均有 FromISR 版本。ISR 中操作通过高优先级任务唤醒机制，将耗时处理推迟到任务上下文。ISR 应短小精悍，只做必要状态保存与通知。

3. 临界区保护

临界区通过关中断或挂起调度器保护共享数据。taskENTER_CRITICAL 关闭中断，适用于极短临界代码；vTaskSuspendAll 挂起调度器，允许中断但仍禁止任务切换。临界区过长影响实时性。

4. 临界区嵌套与退出

临界区支持嵌套，退出时恢复到最初状态。中断优先级与内核配置相关，超过配置阈值的优先级不参与临界区管理。临界区内部禁止调用阻塞 API，避免死锁。

5. 中断优先级配置

中断优先级按内核裁剪配置，低于阈值的中断可被临界区屏蔽。中断优先级分组与内核依赖架构。配置不当导致中断响应异常或系统崩溃，需按平台规范设置。

6. 中断到任务模式

经典模式：ISR 快速处理硬件状态，通过队列或信号量通知任务，任务执行业务逻辑。通知使用 FromISR 版本，必要时唤醒高优先级任务立即处理。此模式解耦硬件与业务。

7. 实践要点

ISR 保持最小化，耗时操作移交任务；共享数据用临界区或队列保护。跟踪工具分析中断延迟与唤醒开销。中断嵌套与临界区配合调试工具验证，确保响应指标满足需求。
