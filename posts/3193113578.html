参数服务器

[!info] 本节目标
理解 ROS1 参数服务器的原理，掌握 rosparam 命令、rospy/roscpp 参数读写与 launch 中参数注入。

1. 什么是参数服务器

参数服务器（Parameter Server）由 roscore 的 Master 维护，是全局的键值存储，供所有节点读写共享配置。

特点：

  • 全局可见：任何节点都可读写（带权限约束）。
  • 类型丰富：支持数字、字符串、布尔、数组、字典。
  • 非持久：重启 Master 后丢失，除非 dump/load 或 launch 注入。

2. 参数类型与格式

类型 YAML 示例
整数 port: 11311
浮点 gain: 0.5
字符串 name: "robot"
布尔 use_sim_time: true
数组 ids: [1,2,3]
字典 gains: {x: 1.0, y: 2.0}

3. rosparam 命令

[!tip] 路径规则
参数名以 / 开头是绝对路径；不带 / 是相对当前命名空间。launch 中常用相对路径配合节点命名空间。

4. rospy 参数读写

[!note] 私有参数
~ 前缀表示节点私有参数，存在 /节点名/参数 下，launch 里用 <param name="~xxx"> 注入。

5. roscpp 参数读写

[!warning] getParam 与 param
getParam 失败只返回 false 不设默认值；param<T>(key, default) 失败时自动使用默认值，更常用。

6. launch 中注入参数

[!tip] 动态参数
运行中 rosparam set 修改后，节点若实时读取会立即生效；但多数节点只在启动时读取一次，需重启节点。

7. 动态参数配置（dynamic_reconfigure）

ROS1 提供 dynamic_reconfigure 支持运行时动态调整参数：

[!note] 典型应用
导航代价地图、相机曝光等参数动态调整，不需要重启节点。

8. 参数持久化

[!danger] 丢失陷阱
直接 rosparam set 的参数在 roscore 重启后丢失。生产系统应在 launch 中通过 <rosparam> 声明，保证每次启动一致。

9. 参数 vs 配置文件

方式 特点 适用
launch <param> 启动时声明、易读 固定配置
rosparam 文件 批量、结构化 复杂配置
运行时 set 即时生效 调试/动态调参
dynamic_reconfigure 运行时动态 GUI 在线调优
代码读配置文件 灵活但需自行解析 特殊场景

[!note] 延伸
launch 文件的参数注入细节见 16-launch启动文件；多机器人场景命名空间与参数隔离见 28-多机器人协同。
