1. Gerrit简介

Gerrit是一款基于Web的代码审查和项目管理工具，专为Git版本控制系统设计。它为团队协作开发提供了强大的代码审查功能和权限控制机制，广泛应用于开源项目和企业开发环境。

1.1 Gerrit的核心价值

1.2 Gerrit与GitHub/GitLab比较

特性 Gerrit GitHub/GitLab
代码审查粒度 基于提交(commit)级别 基于分支(pull/merge request)级别
审查工作流 更严格、结构化的工作流 更灵活的工作流
权限控制 非常细粒度的权限控制 相对简单的权限模型
集成CI 可深度集成Jenkins等CI工具 提供webhook和集成API
学习曲线 较陡峭 较平缓
部署维护 需要一定的维护成本 SaaS服务或自托管选择

1.3 Gerrit的核心概念

  • Change: Gerrit中的代码审查单元，基于单个Git提交
  • Patch Set: 一个Change可以有多个补丁集，代表对同一Change的迭代更新
  • Review Labels: 审查标签，如Code-Review(+2/-2)和Verified(+1/-1)
  • Submit Requirements: 合并代码的前提条件，确保代码满足质量要求
  • Submit Record: 记录一个Change是否可被合并的状态信息

2. Gerrit安装与配置

Gerrit的安装方式主要有三种：Docker容器部署、WAR包直接安装和发行版包管理器安装。

2.1 系统要求

  • Java JRE 11或更高版本
  • Git 2.14.0或更高版本
  • 现代Web浏览器
  • 数据库支持(H2、MySQL、PostgreSQL或Oracle)
  • 最低2GB内存(建议4GB以上)
  • 足够的磁盘空间(取决于代码库大小)

5. Gerrit代码审查工作流

5.1 Gerrit工作流概述

5.2 典型的代码审查流程

  1. 开发阶段：

    • 从master分支拉取最新代码
    • 创建本地功能分支
    • 实现功能或修复bug
    • 提交代码到本地仓库

  2. 推送代码进行审查：

    注意：refs/for/master是特殊的引用，告诉Gerrit这是一个待审查的提交

  3. 代码审查过程：

    • 审查者查看代码，提供意见和建议
    • CI系统自动构建和测试代码
    • 投票：代码质量(Code Review)和功能验证(Verified)

  4. 修改与再次提交：

    • 开发者根据反馈修改代码
    • 修改现有提交（而不是创建新提交）

  5. 最终审批与合并：

    • 审查者给予最终批准(+2)
    • 代码满足所有提交要求后被合并到目标分支

5.3 Gerrit投票系统

Gerrit使用标签(Labels)来表示审查结果，最常用的两种标签是：

Code Review标签

值 含义
+2 批准代码，可以提交
+1 代码看起来不错，但需要其他人最终审核
0 不表达意见
-1 代码需要改进，但不阻止提交
-2 代码有严重问题，不应该提交（否决权）

Verified标签

值 含义
+1 验证通过，代码可以工作
0 未验证
-1 验证失败，代码存在问题

默认情况下，代码需要至少一个Code Review +2和Verified +1才能被提交。

6.2 在Jenkins中安装Gerrit Trigger插件

  1. 登录Jenkins管理界面
  2. 进入”系统管理” > “插件管理” > “可选插件”
  3. 搜索并安装”Gerrit Trigger”插件
  4. 重启Jenkins

6.3 配置Jenkins与Gerrit的集成

6.3.1 在Gerrit中创建Jenkins用户

  1. 创建名为jenkins的用户

  2. 为Jenkins用户生成SSH密钥

  3. 将Jenkins用户添加到Non-Interactive Users组

  4. 在Gerrit中添加Jenkins用户的SSH公钥

6.3.2 在Jenkins中配置Gerrit连接

  1. 在Jenkins中，进入”系统管理” > “Gerrit Trigger” > “添加新服务器”
  2. 配置Gerrit服务器信息：
    • 名称: Gerrit
    • 主机名: gerrit.example.com
    • 前端URL: https://gerrit.example.com/
    • SSH端口: 29418
    • 用户名: jenkins
    • SSH密钥文件: /var/lib/jenkins/.ssh/id_rsa

6.3.3 创建Jenkins Job并配置Gerrit触发器

  1. 创建新的Jenkins Job
  2. 在”构建触发器”部分，选择”Gerrit事件”
  3. 选择触发事件类型：
    • Patchset Created
    • Change Merged
  4. 配置Gerrit项目：
    • 项目: project-pattern (例如: ^myproject$)
    • 分支: branch-pattern (例如: ^master$)

9.2 常见问题及解决方案

9.2.1 推送错误：”需要先压缩提交”

问题描述：尝试推送具有相同Change-Id的多个提交时出现错误。

解决方案：

  1. 使用交互式rebase压缩提交

  2. 标记要压缩的提交为”squash”或”fixup”

  3. 保存并继续rebase

  4. 再次推送到Gerrit

9.2.2 “non-fast-forward”错误

问题描述：提交基于旧版本的代码，无法直接合并。

解决方案：

  1. 获取最新代码

  2. 将您的更改rebase到最新代码上

  3. 解决可能的冲突

  4. 再次推送到Gerrit

9.2.3 合并冲突

问题描述：提交时出现合并冲突。

解决方案：

  1. 在本地rebase到最新代码

  2. 手动解决冲突

  3. 继续rebase

  4. 推送更新的patch set到Gerrit

9.2.4 移除提交中的敏感信息

问题描述：意外提交了密码或其他敏感信息。

解决方案：

  1. 在本地修改提交

  2. 删除敏感信息

  3. 强制推送更新的patch set

10. 总结

Gerrit是一个功能强大的代码审查系统，为团队协作开发提供了坚实的基础。通过本文介绍的安装、配置和最佳实践，您可以:

  1. 建立高效的代码审查流程
  2. 提高代码质量
  3. 加强团队协作
  4. 简化版本控制管理
  5. 与CI/CD系统无缝集成

正确使用Gerrit需要团队成员的共同努力和适应，但长期收益远超过初期投入的学习成本。
