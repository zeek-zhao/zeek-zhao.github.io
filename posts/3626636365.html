gitlab 安全加固

安全加固

ℹ️本篇目标
从身份、网络、应用、数据四个层面加固 GitLab，覆盖 2FA、访问控制、安全扫描、密钥保护与基线检查。

1. 身份层加固¶

  • 强制 2FA：Admin -> Settings -> Sign-in restrictions，勾选 Enforce two-factor authentication，全员二次认证。
  • 关闭注册与密码找回风险项：Admin -> Settings 关闭公开注册、限制密码重置。
  • 管理员账号最小化：仅 1-2 个实例管理员，均开 2FA + 强密码策略。
⚡管理员 = 核心资产
管理员可读取所有项目与密钥。开启 2FA 是管理员账号的第一道硬门禁，参见 09-SSO-LDAP集成 保持外部身份 + 本地逃生通道。

2. 网络与访问层¶

  • HTTPS 全覆盖：禁用 HTTP，Nginx 强制跳转（见 02-安装部署-Omnibus）。
  • SSH 加固：/etc/ssh/sshd_config 禁用密码登录，仅密钥；限制 Git SSH 端口暴露范围。
  • 防火墙/安全组：仅开放 80/443/SSH 管理端口，管理界面限制来源 IP：
  • 反向代理 + WAF：前置 Nginx/Cloudflare 可加 WAF 规则防护 Web 攻击面。

3. 应用层加固¶

  • 审计事件：Admin -> Audit Events 开启并定期导出；企业版可对接 SIEM。
  • 受信 Runner 与镜像：共享 Runner 仅允许白名单镜像与项目，privileged 慎重启用（见 06-Runner部署）。
  • 禁用不需要的功能：如公开 Snippets、公开 Pages、开放 API 的匿名访问。

4. 数据层加固¶

  • 密钥管理：gitlab-secrets.json 权限收紧并离线备份（见 10-备份恢复）。
  • 数据库与存储加密：磁盘加密（LUKS）、数据库备份加密、对象存储 SSE。
  • 日志保护：访问日志脱敏后归档，保存期限满足合规要求。

5. 安全扫描（EE 高级能力）¶

  • SAST：静态分析源代码漏洞（MR 内报告）。
  • DAST：动态应用安全测试，扫描运行中的服务。
  • Dependency Scanning：依赖库已知漏洞（CVE）。
  • License Compliance / Secret Detection：依赖许可合规与密钥泄露检测。
🔥漏洞治理闭环
扫描结果在 MR 中展示 -> 审批规则要求高危漏洞不得合并 -> 修复后重新扫描，形成”扫描-阻断-修复”闭环（见 07-代码评审与MR）。

6. 安全基线自检清单¶

📝迭代而非一次到位
加固是持续过程。优先做”身份（2FA）+ 访问（HTTPS/防火墙）+ 数据（密钥/备份）”三层，再逐步接入扫描与合规框架。
