接着上一篇 01-Hexo简介与核心概念 往下，这篇动手。好消息是环境这块没多少弯弯绕：装好 Node.js 和 Git，三条命令初始化站点，五分钟内就能在浏览器里看到第一个本地预览。

先把 Node.js 和 Git 装好¶

Hexo 依赖这两个基础工具，动手前先确认：

  • Node.js（建议 LTS 版本）：Hexo 和全部插件都跑在 Node.js 之上。
  • Git：用于版本管理，也是 Git 部署方式的基础。

Windows 用户直接从官网下安装包；Linux/macOS 用包管理器。以 Ubuntu 为例，建议通过 NodeSource 装较新版本：

三条验证命令都输出版本号就能继续。如果 node -v 显示的版本太旧，新版 Hexo 插件可能出现语法兼容问题，我的习惯是先升级 Node 再说，别在这上面省事。

想隔离环境就用 Docker¶

如果要在服务器上搭写作环境，或者想保持宿主机干净，可以用 Docker 把 Hexo 装进容器。先建一个 Dockerfile：

执行 docker-compose up 就起来了：目录为空时自动 hexo init，已有站点就直接装依赖并启动预览。之后所有 Hexo 命令都能用 docker-compose exec hexo hexo <命令> 在容器里跑。

Node.js 18+ 现在是 Hexo 生态的主流基线，走 Docker 的话我一般选 node:18-alpine 或更新的基础镜像，兼容性和体积都比较合适。
