自定义消息与 srv

[!info] 本节目标
掌握 .msg 与 .srv 文件的定义语法、编译配置与代码使用，能为业务数据定制通信类型。

1. 为什么需要自定义

标准消息（std_msgs、geometry_msgs 等）覆盖通用场景，但业务数据往往需要组合字段，如：

  • 机器人状态：位置+速度+温度+状态码
  • 目标点：坐标+方向+优先级
  • 检测结果：类别+置信度+包围盒

自定义 msg/srv 让通信类型贴合业务语义，且跨语言共享。

2. msg 文件语法

字段类型速查：

类型 说明
bool / int8 / int16 / int32 / int64 整型
uint8 / uint16 / uint32 / uint64 无符号整型
float32 / float64 浮点
string 字符串
time / duration 时间/时长
std_msgs/Header 标准头（时间戳+frame）
其他包/自定义消息 嵌套引用
[] 后缀 数组，如 float64[] values

srv 内不能嵌套其他 srv，只能使用 msg 类型；action 文件三段式见 08-动作通信actionlib。

建议 原因
字段命名清晰 跨语言/跨团队可读
带 Header 便于时间戳与 frame 对齐
小消息高频 避免大对象序列化开销
版本演进谨慎 消息变更影响所有订阅者
枚举用常量 避免魔法数字

[!warning] 兼容性
给已有消息增删字段会导致新旧节点不兼容。生产系统先发布新消息类型（如 v2），再逐步迁移，不要原地改字段。
